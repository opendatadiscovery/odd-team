## Description

`/features/management/namespaces` **returns 404 live** (WebFetched 2026-05-27 — confirmed). The parent `/features/management` page mentions namespaces only as a workflow phrase ("Create a namespace before authoring tags or terms that should be scoped to a particular team or domain"); no dedicated sub-page exists. The 5 NamespaceController endpoints (`NamespaceController.java`) + `NamespaceServiceImpl.getOrCreate` (`NamespaceServiceImpl.java:36-40`) are unanchored in docs.

**Why a new page (Cornerstone 5 — one canonical home per content type):** "Namespace" is a first-class management concept with its own lifecycle (create / update / soft-delete / details / list), its own permission triplet (NAMESPACE_CREATE / UPDATE / DELETE), AND a load-bearing structural quirk — **a 4-sister-service auto-create side-door** that mints namespace rows from four other resource-creation endpoints. The parent `/features/management` page cannot carry that detail without losing focus; existing peer sub-pages (`/features/management/policies`, `/features/management/roles`) establish the precedent for per-resource sub-pages.

**Facet 1 — Lifecycle (F-028a, the missing page).** `NamespaceController` exposes 5 endpoints (list / details / create / update / soft-delete); `NamespaceServiceImpl.java` implements them as thin proxies over the repository. Reads (list + details) are ungated (any-authenticated; anonymous under DISABLED). Soft-delete sets `deleted_at` and relies on a partial-unique-index to enable name re-use after deletion (V0_0_64 pattern, same as Owner). The platform-tier cascade-on-delete guard is at the application layer: a namespace cannot be deleted if it has live `DataSource`, `Collector`, `Term`, or non-deleted `DataEntity` references — but this guard isn't surfaced anywhere operator-facing.

**Facet 2 — The 4-sister-service side-door (F-028b — PRIMARY DRIFT).** `NamespaceServiceImpl.getOrCreate(name)` (lines 36-40) is `getByName.switchIfEmpty(createByName(name))`. Four OTHER services call it from non-namespace endpoints — minting namespace rows WITHOUT `NAMESPACE_CREATE`:
  1. `DataSourceServiceImpl.java:57, 75` — `POST /api/datasources` + `PUT /api/datasources/{id}` (gated by DATA_SOURCE_CREATE / UPDATE).
  2. `TermServiceImpl` — `POST /api/terms` (gated by TERM_CREATE).
  3. `CollectorServiceImpl` — `POST /api/collectors` (gated by COLLECTOR_CREATE).
  4. `DataEntityGroupServiceImpl` — `POST /api/dataentitygroups` (gated by DATA_ENTITY_GROUP_CREATE).

A caller holding any of those 4 parent permissions supplies a never-seen `namespace_name`; the service silently inserts a NAMESPACE row; the new namespace appears in `GET /api/namespaces` immediately. **The `/permissions` page describes `NAMESPACE_CREATE` as the gate for namespace creation** — operators discover the four side-doors only when their namespace directory proliferates with junk rows (typos, organic operator typing of distinct strings for the same intent).
