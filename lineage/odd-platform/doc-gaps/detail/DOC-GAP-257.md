    - **The operator-trap narrative**: an operator running ODD in production observes a transient burst of HTTP 500 errors on `PUT /api/dataentities/{id}/description` calls. Their assumption is "the description-update failed; let's retry". They retry; the same 500 occurs. They build a retry loop with exponential backoff. Behind the scenes, EVERY retry succeeds at the description-update layer (the FTS-vector rebuild + the description text save commit successfully), but EVERY retry fails at the activity-write layer (because the underlying transient issue is on the `activity` partition, not the `data_entity` table). The whole TX rolls back every time. The operator's retry loop runs 1000+ times until they manually investigate. They Google "ODD description update fails", get no result. They file a support request. The TRUE state is that the description was actually successfully updated and rolled back 1000+ times — a phantom-success failure mode.
    - **The blast-radius amplifier**: under the ingestion path, a single activity-write failure rolls back the WHOLE batch. An operator's collector pushing 5000 entities in a 30-second window receives a 500 on the entire batch; their collector retries; the same 500 occurs (activity-write still failing); the collector's retry loop puts the same 5000 entities in a poison-pill cycle. For collectors using ODD as their primary observability tool, this is a complete observability blackout until the activity-write transient resolves.

Severity is NOT MEDIUM because the operator-trap is reliable when the transient issue does occur, and the failure mode is reproducible at production scale (the ingestion blast-radius dimension makes a single bad partition into a multi-hour platform-wide ingestion outage). The HIGH-CRITICAL distinction: CRITICAL is reserved for data loss or security exposure on a default deployment; this is operator-experience-cliff for a deliberate-by-design behaviour. The single-admonition doc-side fix is the highest-leverage action for the audit-or-fail contract communication.
