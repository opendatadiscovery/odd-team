## Description

The demo stand's Step-1 command now **blocks** until the Platform is healthy, because `docker/demo.yaml`
gained a healthcheck the enricher waits on (`condition: service_healthy`). Measured: `up -d
odd-platform-enricher` returns in 2s on the old stand and 62-86s on the new one. That is the fix working —
but with no word about it on the page, a reader who opens `localhost:8080` while the command is still
running sees an empty catalog and reasonably concludes the demo failed.

Authored and committed on the train (not merely drafted):

- **branch** `docs/CTRIB-063-demo-stand-first-run`, off `origin/release/1.0.0` @ `379baf3`
- **commit** `b270da6` — *"docs(trylocally): the first run waits for the Platform, and it takes about a minute"*

Two edits:

1. **A Step-1 hint block** naming the wait, its cause (the Platform applies its whole migration set against
   an empty database before serving), and the line between expected and broken: *an empty catalog while you
   wait is expected; an empty catalog after the command returns is not.*
2. **Prerequisites** stops saying "preferably the latest docker-compose" and names the real floor —
   `docker compose` v2 (any), or `docker-compose` 1.27.0+, because the long-form `depends_on` condition was
   only re-supported by V1 from 1.27.0. "Preferably" is not a version constraint, and a reader on an older
   binary silently gets the old racing behaviour back.

**The page's "10 predefined data sources" line is deliberately NOT edited.** It was always the intent; the
shipped stand delivered 9 because `08_s3_ingestion.json` named a data source `datasources.json` does not
define. The code fix on this same release makes the existing sentence true. Recorded in `CTRIB-063` as an
accepted, time-boxed falsehood whose expiry is this release gate — if #1870 does not ship in 1.0.0, the
correct move flips to correcting the number on docs `main`.
