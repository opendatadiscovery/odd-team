## What

The GenAI "Ask a question about your data" feature unwraps the external AI service's HTTP response by stripping leading/trailing double-quote characters and unescaping Java escape sequences, then handing the result back to the user as `GenAIResponse.body`. This silently assumes the external service always returns a **bare JSON-quoted string** (e.g. `"42 datasets match"`). If the configured `genai.url` service instead returns a structured JSON object - `{"answer":"42 datasets"}` - the quote-trim has nothing to strip from the ends of `{...}`, so the **raw JSON object is passed through verbatim** and the user sees `{"answer":"42 datasets"}` rendered as their answer, with an HTTP 200. The failure is silent: no error, no log, just a wrong-looking answer. The response-shape contract the platform requires of the external service is also undocumented.

## Where

`odd-platform-api/src/main/java/org/opendatadiscovery/oddplatform/service/genai/GenAIServiceImpl.java:46-47`

```java
.bodyToMono(String.class)
.map(item -> new GenAIResponse()
    .body(StringEscapeUtils.unescapeJava(CharMatcher.is('\"').trimFrom(item))))
```

`CharMatcher.is('"').trimFrom(item)` only removes `"` characters from the two ends of the string - correct for a bare quoted string `"x"`, a no-op for an object `{"answer":"x"}`. The result is then `unescapeJava`'d and stored directly on the response body (`GenAIResponse.body` is a plain `String`, contract `requiredMode = NOT_REQUIRED`).

## Why it matters

Silent and user-facing. Any operator who points `genai.url` at an AI backend whose `/query_data` endpoint replies with a JSON envelope (a very common shape - OpenAI-style, LangChain-style, and most "structured output" services wrap the answer in an object) gets raw JSON shown to end users instead of prose, with no signal that anything is wrong. Because the unwrap encodes an **undocumented** expectation about the response shape, an integrator has no way to know what contract their service must satisfy. Severity is low because it only manifests against a non-bare-string backend and produces an ugly-but-non-destructive answer (no data loss, no security exposure) - but it is a genuine correctness trap for the integration story.

## Suggested fix

Parse the external response as a `JsonNode` (or a small typed DTO) rather than quote-trimming a raw `String`, and extract the answer field explicitly - then **document the required `/query_data` response contract** on the GenAI page so integrators know exactly what shape the platform expects. Concretely: deserialize the body, pull the answer text from the agreed field, and fall back gracefully (or raise a clear `GenAIException`) when the shape is unexpected rather than leaking the raw payload. Open to alternatives on the exact contract (bare string vs `{ "answer": ... }`) - the key point is that the contract should be explicit and enforced, not implied by a quote-trim.
