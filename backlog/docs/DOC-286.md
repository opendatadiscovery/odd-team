## Description

`data-discovery/entity-description.md` tells readers that the before/after description text is **NOT** part of the `DESCRIPTION_UPDATED` activity event, and steers anyone who wants the old/new text to query `data_entity_history` instead. The code does the opposite: the `DESCRIPTION_UPDATED` event captures the **full old description AND the full new description** in its payload — the Activity Feed already IS a content diff for description edits.

The current text sends an operator down an unnecessary (and possibly inaccessible) path — querying internal history tables — to recover information the feed event already contains. It also undersells the audit surface: a reader auditing description changes would believe the feed only tells them *that* a change happened, not *what* changed, when in fact both are present. This is Critical because it is actively incorrect about what the audit trail records.

**Failure shape**: code-doc drift (inverted claim) — the page asserts a payload field is absent that the code populates.
