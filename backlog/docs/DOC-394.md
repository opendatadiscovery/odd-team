## Description

The live Query Examples page states (`query-examples.md:13`):

> **Author and edit** snippets with a name, description, and the query body. The description doubles as a "prompt"-style explanation of intent.

This is wrong on the field model. A Query Example has **no `name` field**:
- The create/edit form (`QueryExampleForm.tsx:79-113`) has exactly two `Controller`s — `definition` (labelled "Definition") and `query` (labelled "Query", a Markdown editor). There is no name input.
- The OpenAPI schema `QueryExampleFormData` (`odd-platform-specification/components.yaml:2799-2808`) declares only `definition` and `query` (both required) — no `name` property.

So the snippet is identified in the UI by its numeric **id** (the list page renders each row by its number, and the details URL is `/data-modelling/query-examples/{id}`), not by a name. What line 13 calls "name" does not exist; what it calls "description" is the `definition` field. The lower half of the same page already documents the two-field model correctly (the Overview tab "shows the snippet's `definition` ... and the `query` body", ~lines 60-68) — line 13 is the lone stale claim and contradicts the page's own later text.

An operator reading line 13 expects to name their snippets and to search/identify them by name; they then find no name field in the form and no name column in the list, an avoidable contradiction on a published page.

DOC-232 (done) added the XSS / dirty-form / tab-navigation caveats to this page but did **not** touch line 13's field-model claim, so the correction is still outstanding.
