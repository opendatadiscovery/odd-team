## What

Eight UI defects on the Term Detail page composition + the three reverse-lookup tabs (Linked Entities / Linked Columns / Linked Terms) + the per-tab error/empty-state handling. These ship as a single hardening epic because they all share state-management patterns that need unification.

**Defect 1 - Term Overview double-fetches the 12-JOIN hot path (F-151a).** `TermDetails.tsx:37-45` dispatches `fetchTermDetails({termId})` on mount via Redux thunk. The Overview sub-route (the default landing per `TermDetailsRoutes.tsx:46`) fires its own `useGetTermByID({termId})` via tanstack-query (`Overview.tsx:19-21`). Both endpoints route through `ReactiveTermRepositoryImpl.getTermDetailsDto` - the 12-JOIN + 7 jsonArrayAgg + 4 countDistinct HOT PATH. Every Term URL open hits this query TWICE.

**Defect 2 - Tabs auto-hide on zero count obscures capability discoverability (F-151b).** `TermDetailsTabs.tsx:24, 30, 36` set `hidden: !termDetails?.entitiesUsingCount` etc. A Term with zero linked entities silently has NO "Linked entities" tab; same for columns / terms. Operators new to ODD cannot tell whether linking IS supported until at least one link exists. The Query Examples tab is ALWAYS shown - correct shape; the three reverse-lookup tabs disagree.

**Defect 3 - Overview TERMS panel duplicates Linked-Terms tab with inconsistent affordances (F-151c).** Overview tab carries a TERMS mini-panel with Add/Delete affordances (`Overview.tsx:65-72`). Linked-Terms tab (`TermLinkedTermsList.tsx:15-100`) shows the same data with search but no Add/Delete. Operators learn one affordance set on Overview and cannot perform Add/Delete on the tab where they look for bulk operations.

**Defect 4 - LinkedColumnsList InfiniteScroll `next={() => {}}` - pagination silently broken (F-153a - LSN-024-class silent-empty).** `LinkedColumnsList.tsx:77` wires `<InfiniteScroll next={() => {}}>`. Hook `useGetTermLinkedColumns` does not expose `fetchNextPage` (`:22-27` calls single-page args `{termId, page: 1, size: 50, query}`). Worse: `hasMore={pageInfo.hasNext}` (line 78) is forwarded honestly - UI promises more pages but trigger does NOTHING. A Term with 51+ linked Dataset Fields silently truncates at column 50. Compare LinkedTermsList.tsx:24-31 (working `useInfiniteQuery` + `fetchNextPage` pattern).

**Defect 5 - LinkedTermsList synthesises bogus `status: 500` for ALL errors (F-152a; FIXME on line 87 confirms author awareness).** When `!isLinkedListFetched`, the component renders `<AppErrorPage>` with synthesised `{status: 500, ...}` regardless of real HTTP code. A 403 renders as "Internal Server Error"; a 404 same; error fires on initial mount before first query completes producing a brief error flash.

**Defect 6 - LinkedTermsList renders "No linked entities" empty-state on the LINKED TERMS tab (F-152b; copy-paste).** `LinkedTermsList.tsx:81` - `EmptyContentPlaceholder text="No linked entities"` on the LINKED TERMS tab.

**Defect 7 - LinkedTermsList search has no debounce + no Enter handler (F-152c).** `LinkedTermsList.tsx:42-50` - search input updates state on keystroke but `refetch()` only on icon click. Sibling LinkedEntitiesList does fire on Enter (`:62-68`). Inconsistent pattern; operators expecting type-to-search behaviour see no response.

**Defect 8 - Three sibling tabs use TWO state-management patterns (F-152d - ADR-DRAFT candidate).** LinkedTermsList = tanstack-query (`useInfiniteQuery`); LinkedEntitiesList = redux thunks (`fetchTermLinkedList`); LinkedColumnsList = tanstack-query (`useGetTermLinkedColumns`). State-shape and cache-invalidation drift across three sibling components in the same parent. Mid-migration drift; operator-invisible but a maintenance defect.

## Why it matters

Operator-visible impact, sorted by severity:

- **Defect 4 (LSN-024-class silent-empty pagination)**: a glossary-governance scenario (compliance team auditing "what columns reference the term 'PII'?") silently truncates after 50 - the truncation IS the failure mode.
- **Defect 1 (latency doubling)**: heavily-linked Terms double the platform's most expensive backend query for every page open. Operators tuning PostgreSQL miss the amplification factor.
- **Defects 5 / 6 / 7**: per-tab UX hazards that erode trust in the surface.
- **Defect 8 (state-pattern drift)**: a maintenance defect - the team is mid-migration from redux to tanstack-query; the drift is visible across siblings.

Severity is CRITICAL (Defect 4 is the LSN-024 silent-empty class on a documented public surface); the cluster collectively represents the Term Detail page's overall hardening state.

## Suggested fix

Recommend three PRs:

### PR-1 - Pagination + double-fetch (Defects 1 + 4)

**Defect 1 - share the shell-level cache:**

```tsx
// Option A: Overview reads from redux-cached termDetails (already loaded by shell)
// Option B: shell + Overview share the same tanstack-query queryKey
// Option C: document the double-fetch as intentional with the latency contract (cheap, but bad)
```

Recommend Option B - migrate the shell-level fetch to tanstack-query with `['term', termId]` key; Overview reads from same key.

**Defect 4 - migrate LinkedColumnsList to `useInfiniteQuery` + wire `fetchNextPage`:**

```tsx
// LinkedColumnsList.tsx
- const { data, ... } = useGetTermLinkedColumns({termId, page:1, size, query});
+ const { data, fetchNextPage, hasNextPage, ... } = useInfiniteGetTermLinkedColumns({termId, size, query});
- <InfiniteScroll next={() => {}} hasMore={pageInfo.hasNext} ... />
+ <InfiniteScroll next={fetchNextPage} hasMore={hasNextPage} ... />
```

Mirror `LinkedTermsList.tsx:24-31`. Add an `useInfiniteGetTermLinkedColumns` factory in the API client.

### PR-2 - Per-tab UX hygiene (Defects 5 + 6 + 7)

**Defect 5 - propagate the real status (or fix the trigger):**

```tsx
// LinkedTermsList.tsx - match the LinkedEntitiesList.tsx:148-152 pattern
- {!isLinkedListFetched ? <AppErrorPage status={500} ... /> : ...}
+ {error ? <AppErrorPage status={error.status} statusText={error.message} ... /> : ...}
```

**Defect 6 - one-line fix:**

```tsx
// LinkedTermsList.tsx:81
- <EmptyContentPlaceholder text="No linked entities" />
+ <EmptyContentPlaceholder text={t('No linked terms')} />
```

**Defect 7 - add Enter handler + debounced refetch:**

```tsx
// LinkedTermsList.tsx - align with TermSearch.tsx + LinkedEntitiesList.tsx
+ const debouncedRefetch = useDebouncedCallback(refetch, 300);
+ <Input onKeyDown={(e) => e.key === 'Enter' && refetch()} onChange={(v) => { setQuery(v); debouncedRefetch(); }} />
```

### PR-3 - Auto-hide vs empty-state + state-pattern unification (Defects 2 + 3 + 8)

**Defect 2 - empty-state instead of hidden:**

```tsx
// TermDetailsTabs.tsx - show tabs always; render empty-state inside
- { label: 'Linked entities', hidden: !termDetails?.entitiesUsingCount, ... }
+ { label: 'Linked entities', count: termDetails?.entitiesUsingCount ?? 0, ... }
// each LinkedXxxList component renders empty-state hint with the "how to link" pointer
```

**Defect 3 - Overview TERMS panel consolidation:**

Either:
- (a) Overview panel becomes a summary + "see all" link to the tab; tab carries all affordances (Add/Delete/Search).
- (b) Document the dual-surface intent (rename Overview panel to "Recent linked terms"; clarify in UX that Linked-Terms tab is the canonical surface for browse, Overview panel for quick-add).

**Defect 8 - state-pattern unification ADR:**

The team is mid-migration from redux thunks to tanstack-query. Complete the migration: LinkedEntitiesList -> tanstack-query (mirroring LinkedTermsList + LinkedColumnsList). Document the chosen pattern in an ADR (`adrs/ui-state-management.md`) to prevent further drift.
