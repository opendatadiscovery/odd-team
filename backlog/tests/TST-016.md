## Description

`Search.tsx` builds its facet-update debouncer by wrapping `useDebouncedCallback` inside a `React.useCallback`, with the debounced fn keyed on `[searchId, searchFacetParams]` and configured `{ leading: true }` (`Search.tsx:50-65`):

```tsx
const updateSearchFacets = React.useCallback(
  useDebouncedCallback(
    () => { dispatch(updateDataEntitiesSearch({ searchId, searchFormData })); },
    1500,
    { leading: true }
  ),
  [searchId, searchFacetParams]   // ← deps include searchFacetParams
);

React.useEffect(() => {
  if (!searchFacetsSynced) { updateSearchFacets(); }
}, [searchFacetParams]);
```

Because `searchFacetParams` is in the `useCallback` dependency list, a NEW `useDebouncedCallback` instance is created every time the facet selection changes — and the class-type tabs (Datasets / Transformers / etc.) are facet selections. Each rapid tab switch mutates `searchFacetParams`, which (a) re-creates a fresh debouncer (its internal 1500ms timer does not carry over from the previous instance) and (b) re-fires the `useEffect`. With `{ leading: true }`, a freshly-created debouncer invokes on the LEADING edge immediately, so the debounce window that is supposed to collapse N rapid switches into one PUT is reset on each switch — N rapid tab switches can fire up to N `updateDataEntitiesSearch` PUTs instead of one.

This inherits the F-017 recreated-debouncer defect class. It is a SIBLING of PLT-017 but a DISTINCT site: PLT-017 is filed against `TermSearch.tsx` (the terms search), whereas this is `Search.tsx` (the main data-entity search) — confirmed two separate lazy-loaded components, `Search` and `TermSearch`, at `App.tsx:34-35`. The Search.tsx site has no filed home.

**Typed gate: characterization-pin (LSN-029).** This pins the CURRENT (incorrect) behaviour: rapid class-tab switching fires more than one `updateDataEntitiesSearch` PUT because the debouncer is recreated per facet change. The test asserts the observed PUT cardinality TODAY (> 1 for N rapid switches) and goes RED the instant the debouncer is hoisted/stabilised so that N rapid switches collapse to a single trailing PUT (the planned fix). It is NOT `@Disabled` — it is a GREEN tripwire over the live defect.
