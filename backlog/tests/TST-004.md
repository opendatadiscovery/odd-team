## Description

`PolicyServiceImpl.update` is a non-transactional read-then-write (lost-update race), while the sibling `RoleServiceImpl` IS `@ReactiveTransactional` (F-006/H-007) — the asymmetry is the oversight. Separately, the policy cascade-delete check + soft-delete are two non-transactional R2DBC calls, so a concurrent role-bind may race into the orphan-binding state the defence advertises it prevents (F-006/H-011).

Per the pin-known-bugs idiom (LSN-029) and the no-code-change-now posture, this PINS the current state with a characterization test that asserts `PolicyServiceImpl.update` is NOT annotated `@ReactiveTransactional` (and/or that its read-then-write is non-atomic) — GREEN today, RED the instant the annotation/atomicity is added (the planned fix) or the structure changes. The operator-facing caveat is documented in DOC-329; the code fix (add `@ReactiveTransactional` to the policy update + cascade path) is a follow-up upstream PLT.
