## What

All three surfaces derive their auth-mode disclosure the same way:

```ts
const { data: appInfo } = useAppInfo();
const isShared = appInfo?.authType === 'DISABLED';
```

`useAppInfo` is a plain `useQuery` and the app sets **`retry: false`** globally (`index.tsx:41`). So a single
failed or slow `GET /api/info` leaves `data` undefined, `isShared` false, and the surface renders its
**non-shared** wording — on an instance where favorites really are a shared, instance-wide bucket.

The disclosure therefore **fails open**: the state that needs a warning is the one that silently loses it.

## Why it matters

Under `auth.type=DISABLED` every caller reads and writes one shared favorites bucket — anyone on the network
can see and remove anyone's stars. The `(shared)` label and (on the ST-7 filter) its inline-help tooltip are
the only in-product disclosure of that. If `/api/info` blips, a user is shown a personal-looking "Favorites"
affordance over a shared bucket.

## Why it is NOT fixed in CTRIB-061

Two reasons, both deliberate:

1. **It is pre-existing and shared.** Two of the three call sites shipped before ST-7; the ST-7 filter is the
   third and follows the established convention. Diverging on one surface would create exactly the
   parallel-surfaces-with-drift problem the docs pillar warns about — three sibling surfaces disclosing the
   same fact by two different rules, with no stated reason.
2. **The correct semantics are a real decision, not an oversight to patch.** Neither default is obviously
   right: assuming *shared* when the auth mode is unknown shows an alarming and wrong warning on a healthy
   OAUTH2 instance during a network blip; assuming *not shared* is today's silent failure. The likely answer
   is a third rendering (unknown/degraded) or making `useAppInfo` retry for this specific query — either of
   which is a shared-component decision that deserves its own change rather than a rider on a search-filter
   slice.

## Acceptance Criteria

- [ ] A single decision on the unknown-auth-mode rendering, applied to **all three** surfaces (not one).
- [ ] A test that drives the failure path — `useAppInfo` erroring / pending — and asserts the surface does not
      present the non-shared wording. This is a rendered-state assertion; a catalog or type check cannot see it.
- [ ] If retry is the chosen remedy, confirm it does not regress the app's global `retry: false` posture.
