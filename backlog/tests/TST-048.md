## What

`run-suite.sh` builds the working-tree SUT and exports `ODD_PLATFORM_IMAGE=odd-platform:odd-team-sut`, and the
SUT-agnostic convention (`build-sut.sh` header, LSN-033) is that compose stacks reference that env var. Only
**two** of the eight probe-stack composes actually do:

| Compose | Platform image line | Honours SUT? |
|---|---|---|
| `odd-minimal.docker-compose.yml` | `${ODD_PLATFORM_IMAGE:-ghcr…:latest}` | YES |
| `odd-ingestion.docker-compose.yml` | `${ODD_PLATFORM_IMAGE:-ghcr…:latest}` | YES |
| `odd-minio.docker-compose.yml` | **FIXED by CTRIB-013** -> `${ODD_PLATFORM_IMAGE:-…}` | YES (now) |
| `odd-ldap.docker-compose.yml` | `ghcr…/odd-platform:latest` (hardcoded) | **NO** |
| `odd-loginform.docker-compose.yml` | `ghcr…/odd-platform:latest` (hardcoded) | **NO** |
| `odd-notifications.docker-compose.yml` | `ghcr…/odd-platform:latest` (hardcoded) | **NO** |
| `odd-notifications-ha.docker-compose.yml` | `ghcr…/odd-platform:latest` (hardcoded, x2) | **NO** |

So the `multi-stack` suite specs that bring up those stacks — **IT-009** (LOGIN_FORM auth boundary), **IT-010**
(LDAP RBAC), **IT-011/IT-012** (notifications WAL), **IT-123** (LOGIN_FORM), **IT-124** (LDAP) — run against
`ghcr.io/opendatadiscovery/odd-platform:latest` (the published release), **NOT the working-tree SUT under
review**. A green there is the LSN-032 false-green: it cannot validate (or regress-guard) a fix that is not yet
released. Any CTRIB that "verified via multi-stack" for these stacks did not actually exercise its own SUT.

## Why it matters

The integration regression gate (G-C2) is only as honest as the SUT wiring. For the auth + notifications
stacks, `ODD_SUT=working` (the default — "test what I'm building") is silently ignored; `ODD_SUT=ref:main` /
`published` (the RED proof) is equally ignored. The gate has been measuring `:latest` for those six specs.

## Fix

Change the hardcoded `image: ghcr.io/opendatadiscovery/odd-platform:latest` to
`image: ${ODD_PLATFORM_IMAGE:-ghcr.io/opendatadiscovery/odd-platform:latest}` in the four composes (both
occurrences in `odd-notifications-ha`), mirroring `odd-minimal` / `odd-ingestion` / `odd-minio`. Then re-run the
`multi-stack` suite with `ODD_SUT=working` and confirm the specs exercise the built `odd-platform:odd-team-sut`
(e.g. a known working-tree-only change is observed). One-line edits; no spec changes.

## Scope note

Out of scope for #1741 / CTRIB-013 (that PR fixes only `odd-minio`, which it needs for the IT-008 region
assertion). This item covers the other four composes — a workspace-harness correctness fix, not an
odd-platform code change.
