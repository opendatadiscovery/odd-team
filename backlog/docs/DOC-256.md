## Description

The live `/integrations/integrations/integration-wizard` page (WebFetched 2026-05-27, 200 OK) documents the META-INF/wizard mechanism, warns about the `platform_url` placeholder default, and describes the wizard's snippet-rendering behaviour. It is **silent on the authorization posture of the wizard endpoints**.

**Caveat — NO RBAC permission for `/api/integrations*`; any authenticated user reads the full wizard surface (F-033b).** Grep `/api/integrations` in `SecurityConstants.java` returns **zero matches**. `IntegrationController.java` has no `@PreAuthorize` on either endpoint. Both `getIntegration` and `getIntegrationPreviews` fall through to the `AuthorizationCustomizer` catch-all `.authenticated()`. **Any authenticated user reads the full wizard surface** including the `platform_url` rendered into each integration's content_blocks. Under `auth.type=DISABLED` the registry is anonymously readable. Operators expecting the wizard to be admin-only (matching the "Management → Integrations" UI placement) discover any-authenticated-user reach via API enumeration.

The five existing F-033 facets (`installed: false` hardcoded dead field, 204-on-missing-id, default `platform_url` placeholder, case-insensitive id-collision merge, boot fail-fast on corrupt YAML) are already covered by DOC-GAP-277..281 — not re-emitted by this item.
