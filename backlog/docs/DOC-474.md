## What

#1763 / CTRIB-025 hardens the Alerts view to match the Activity view (ships with odd-platform 0.29.0). The
alerting docs must be updated **on the `release/0.29.0` train** (publishes at the 0.29.0 release gate — the live
manual must keep describing the latest *published* release until then). This DOC item is the release-gate tracker.

This corrects the previously-accurate DOC-291 statement ("the global tabs list open alerts only; resolved history
is read per-entity") — which is true of 0.28.0 but no longer of 0.29.0.

## Required edits — `alerting.md`

- **"Alert views" section:** 3 tabs (All / My Objects / Dependents) → **4 tabs (All / My Objects / Downstream /
  Upstream)**; document the **filter panel** (Period, Datasource, Namespace, Tag, Owner, Status). "Dependents"
  was downstream-only; it is now split into explicit **Downstream** + **Upstream** lineage tabs.
- **The "open-only" hint (the DOC-291 correction):** rewrite → the global views **default to OPEN**, and the
  **Status filter** makes RESOLVED / RESOLVED_AUTOMATICALLY alerts **reachable on the global page** (the #1763
  fix). The per-entity tab still shows all statuses by default (+ now has Period/Status filters).
- **Lifecycle table** ("both resolved statuses remove the alert from the global All/My/Dependents tabs"):
  correct → resolved alerts are filtered out of the *default* (Open) view but reachable via the Status filter.
- **Retire the now-moot caveats:** "Listing constraints today" (per-entity + global "no filter UI / no status
  selector / hardcoded size-30") — the global + per-entity views now have filters; the "Known UX limitations"
  bullets "bare /alerts redirects to /alerts/all" and "/alerts/my and /alerts/dependents URLs remain mounted"
  are moot (tabs are query-param driven now, no per-tab routes). (Bulk-resolve / export remain out of scope —
  keep those caveats.)
- **API references** (lines ~70, ~206): `getAllAlerts`/`getAssociatedUserAlerts`/`getDependentEntitiesAlerts` +
  `getAlertTotals` → the new `getAlertsList` + `getAlertCounts`; note the legacy endpoints are **deprecated**.

## Required edits — `api-reference/alerts.md`

- Document the new endpoints: `GET /api/alerts/list` (`getAlertsList`, type + filters → `Alert[]`),
  `GET /api/alerts/counts` (`getAlertCounts` → `AlertCountInfo`), `GET /api/dataentities/{id}/alerts/list`
  (`getDataEntityAlertsList`).
- Mark the legacy `getAllAlerts` / `getAssociatedUserAlerts` / `getDependentEntitiesAlerts` / `getAlertTotals` /
  `getDataEntityAlerts` as **deprecated** with the **migration note**:
  `getAllAlerts` → `getAlertsList?type=ALL&status=OPEN`; `getAssociatedUserAlerts` → `…?type=MY_OBJECTS`;
  `getDependentEntitiesAlerts` → `…?type=DOWNSTREAM` (+ new `UPSTREAM`); `getAlertTotals` → `getAlertCounts`;
  `getDataEntityAlerts` → `getDataEntityAlertsList`.
