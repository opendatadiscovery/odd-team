# auth.type=LOGIN_FORM gate on LoginFormSecurityConfiguration.java:31 — semantic understanding

## understanding

`@ConditionalOnProperty(value="auth.type", havingValue="LOGIN_FORM")` at line 31 gates the entire `LoginFormSecurityConfiguration` class — when set, Spring instantiates a `SecurityWebFilterChain` that authenticates UI/API traffic against an in-memory `MapReactiveUserDetailsService` populated from the comma-separated `auth.login-form-credentials` string. The configuration is the lightweight built-in auth path: every authenticated user is granted ADMIN authorities (the `getAuthorities(true)` call at line 81), CSRF is disabled, and credentials live in plain text inside the YAML/env value. The class also reads `auth.login-form-redirect` (post-login redirect URI) and `auth.s2s.enabled` (whether to additionally mount the S2S filter alongside form auth); both are sibling config-key-consumer nodes whose runtime effects materialize entirely inside this class. **Critical finding (confirms REFACTOR-073)**: this `SecurityWebFilterChain` does NOT call `.authorizeExchange(new AuthorizationCustomizer(...))` — unlike `OAuthSecurityConfiguration.java:98` and `LDAPSecurityConfiguration.java:145`, LOGIN_FORM mode runs WITHOUT the Policies/Permissions/Roles framework; the only gate is `.authenticated()` at line 57.

## performance

- **hot_paths**:
  - "Form-login filter on every request: `MapReactiveUserDetailsService` lookup is O(N) over the configured credential count (N = number of `user:password` pairs in the config string). For dev-scale N (1-10), this is negligible." — evidence: LoginFormSecurityConfiguration.java:68-86 (MapReactiveUserDetailsService backing — Spring's stock implementation iterates its internal map)
  - "S2sAuthenticationFilter (when enabled) on every request: invokes `s2sTokenProvider.isValidToken(...)` once per request; behaviour depends on the token-provider implementation (out of scope for this node)." — evidence: LoginFormSecurityConfiguration.java:61-63 + S2sAuthenticationFilter.java:26-28
- **throughput_characteristics**:
  - "Stateless per-request auth check with session-bound state for form-login (session cookie); reactive-stack non-blocking via WebFlux."
  - "BCrypt password encoding via `PasswordEncoderFactories.createDelegatingPasswordEncoder()` (line 72) is invoked ONCE per credential at bean construction (line 79 `passwordEncoder(pe::encode)`), not per request — so encoding cost amortises over JVM lifetime."
- **resource_allocation**:
  - "In-memory `MapReactiveUserDetailsService` (line 85) — bounded by credential count, negligible at dev scale. No external store, no connection pool, no DB round-trip."
  - "Constructor injects `S2sAuthenticationFilter` (line 36) regardless of `auth.s2s.enabled`, so the filter bean exists in the Spring context even when `auth.s2s.enabled=false` — small memory cost, no runtime cost when disabled (the filter is only mounted to the chain inside `if (s2sEnabled)` at line 61)."
- **scaling_characteristics**:
  - "Stateless across replicas only if a shared session store is used. With the shipped `session.provider: IN_MEMORY` (per `application.yml:30`), session state lives in JVM heap — replicas do NOT share session state, so a load-balanced deployment may force users to re-authenticate on each replica switch (unless sticky sessions are configured at the LB layer). LOGIN_FORM is dev-only per docs, so this is acceptable for the documented intent." — evidence: LoginFormSecurityConfiguration.java:53-66 + application.yml:28-30 (`session.provider: IN_MEMORY`)
  - "Credential set is static per JVM — adding a user requires restart (re-parsing `auth.login-form-credentials` at bean construction). No runtime credential management API."
- **known_performance_gaps**:
  - "No connection-throttling / brute-force protection on form-login: an attacker can submit unlimited login attempts against the in-memory store. BCrypt encoding adds a ~100ms cost per attempt, which is the only natural rate-limit." — evidence: LoginFormSecurityConfiguration.java:53-66 (no rate-limit filter, no lockout) — severity: LOW
