#### Finding F-162e: useCallback misuse causes per-render Handlebars.compile — measurable cost on large manifests; minor inefficiency, not a correctness defect
- **Verdict**: STATIC-INFERRED · `missing-caveat` · LOW severity · ontology-confirmed
- **Source-of-truth**: `Ontology[F-162:observed_vs_expected.facet=handlebars_compile_misuse_via_usecallback_invoked_at_render_time_not_memoised]` → `Repo[odd-platform-ui/src/components/Management/Integrations/Integration/IntegrationContent/IntegrationCodeSnippetWithForm/IntegrationCodeSnippetWithForm.tsx:22-24]`
- **What the doc says**: silent.
- **What the code does**: Line 22-24: `const compiledTemplate = useCallback(Handlebars.compile(snippet.template), [snippet.template])`. The semantic intent appears to be "memoise the compiled template across renders" — but `useCallback(value, deps)` memoises a CALLBACK function reference, not an arbitrary value. Here `Handlebars.compile(snippet.template)` is invoked on EVERY render BEFORE useCallback receives the result. The compiled template happens to be a function (Handlebars returns a render function), so useCallback's signature accepts it without typecheck error, but the memoization is a no-op — the compile runs every render.
- **Operator-visible consequence**: Latent — invisible to the operator unless the manifest is huge OR the operator's browser is on a slow device. Per-keystroke re-compile across the React form state cascade is wasteful.
- **Suggested fix**: Replace with `const compiledTemplate = useMemo(() => Handlebars.compile(snippet.template), [snippet.template])`. One-line code fix.
- **Dedup**: NEW.
