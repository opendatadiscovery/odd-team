## Description

The Dataset Field per-Column Annotation surface — operator-visible as the Structure-tab column editor that lets you edit per-column description / tags / glossary terms / enum values / business-name — is **completely undocumented**. WebFetch on 2026-05-27 confirms: `/features/data-discovery` parent page does not list per-column annotation editing; `/features/data-modelling` covers Query Examples + Relationships only. The composition shell (`DatasetFieldOverview.tsx`) is the operator-observable entry-point to a backend chain with three high-severity defects + two UI-tier hazards.

**Five facets need a new canonical home (Cornerstone 5):**

**Facet 1 — Two SecurityConstants wiring bugs at adjacent lines (F-047a; HIGH).** Verified verbatim at `SecurityConstants.java:295-299`:
- **Bug 1 — line 295-296**: `new SecurityRule(ALERT, new PathPatternParserServerWebExchangeMatcher("/api/alerts/{alert_id}/status", PUT), DATASET_FIELD_ADD_TERM)`. The **ALERT status PUT** is gated by `DATASET_FIELD_ADD_TERM`. Anyone holding the field-scope term-add permission can resolve alerts on any entity.
- **Bug 2 — line 297-299**: `new SecurityRule(DATASET_FIELD, new PathPatternParserServerWebExchangeMatcher("/api/datasetfields/{dataset_field_id}/terms", POST), DATA_ENTITY_ADD_TERM)`. The **dataset-field term-add POST** is gated by `DATA_ENTITY_ADD_TERM` (the entity-scope permission) instead of the documented `DATASET_FIELD_ADD_TERM`.

The UI/server mismatch on Bug 2 is operator-visible silent 403: UI uses `DATASET_FIELD_ADD_TERM` for the field-level Add-term button → button is ENABLED for users with that permission → click → server rejects with 403 → `TermItem` catch swallows the error silently (per substrate F-047 ui-review-K finding 5) → operator sees the button work-ish but the term doesn't appear.

**Facet 2 — `createEnumValue` is BULK-REPLACE not CREATE (F-047b; HIGH).** `EnumValueServiceImpl.java:91-122`: items with `id != null` → bulkUpdate; items with `id == null` → bulkCreate; rows whose id is NOT in `idsToKeep` → `softDeleteExcept(datasetFieldId, idsToKeep)`. OpenAPI operationId says `createEnumValue` (singular CREATE verb). The schema name `BulkEnumValueFormData` is honest but the operation name hides it. A third-party API consumer (or a future UI refactor) sending only one new item to a field with three existing items **soft-deletes the other two silently**. The DatasetFieldEnumsForm UI at lines 90-105 correctly sends the FULL `data.enums` array (avoiding the trap); the UI is the only protection.

**Facet 3 — `updateDatasetFieldTags` is delete-all-then-recreate (F-047c; HIGH).** `DatasetFieldServiceImpl.java:117-132` calls `deleteDatasetFieldInternalRelations(datasetFieldId)` first — **UNCONDITIONAL DELETE** filtered by `origin = INTERNAL` (per `ReactiveTagRepositoryImpl.java:289-295`) — then re-inserts the submitted set. Submitting `tags: []` clears every INTERNAL tag silently. EXTERNAL_STATISTICS tags survive — but the operator may not realise the surviving rows belong to a different channel. Unlike `TagServiceImpl.updateRelationsWithDataEntity` which computes a true diff.

**Facet 4 — Composer no-unsaved-changes-warning on field switch (F-192a; MEDIUM).** `DatasetFieldOverview.tsx:54-98` mounts sub-editors unconditionally. When an operator clicks a different field row while a sub-editor (e.g. `TagsEditForm`) is open, the dialog stays open but `selectedFieldIdAtom` updates. The dialog's internal `useForm` state was initialised from the previous field's tags. Submit on this dialog might submit the previous field's tags against the new field's id — depends on closure-capture vs re-render timing. Latent data-corruption hazard on fast-switching workflow. (`ui_unverified: true` per substrate — pending runtime probe.)

**Facet 5 — Composer uses split state management (F-192b; LOW).** Description / tags / enums dispatch Redux thunks; business-name / term-add / term-delete use React Query mutations. Mixed-paradigm composition within a single feature surface. Optimistic-update + error-rollback semantics differ across sub-editors; stale-cache risk if Redux update succeeds but React Query cache is unaware.
