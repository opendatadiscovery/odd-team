## Description

When an operator approves one owner-association request, the platform silently transitions **all other PENDING requests for the same Owner** to `REQUEST_MANUALLY_DECLINED`. This is invisible in the confirmation dialog, the UI, and the docs (F-171/H-006). Two operator-visible consequences:

1. Legitimate requesters whose requests targeted the same Owner are silently rejected — they receive no signal that their request was auto-declined as a side effect of someone else's approval.
2. The audit/history shows DECLINED decisions the operator never explicitly made — a forensic reader infers the operator declined N requests when they only approved one.

This may be **intended** single-binding enforcement (one approved binding per Owner ⇒ competing requests are mutually exclusive). The immediate operator protection is to document the behaviour so triagers understand what an Approve actually does. A code-side "surface this in the dialog / confirm the auto-decline" is a follow-up upstream item (see Implementation Notes); we are not changing platform code in this pass.
