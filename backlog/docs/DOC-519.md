## Description

`docs/configuration-and-deployment/trylocally.md` Step 2 → Result tells the reader:

> You should be able to see a new data source with the name you've passed into the collector_config.yaml file
> (Default is `Sample demo data source`). Overall you should see 11 data sources in the list.

The shipped file it points at says something else:

```
odd-platform/docker/config/collector_config.yaml:6
    name: postgresql-step2-test
```

and the repo's own copy of the same instructions agrees with the code:

```
odd-platform/docker/README.md:65
(Default is `postgresql-step2-test`). Overall you should see 11 data sources in the list
```

**`Sample demo data source` has never existed in the odd-platform repository** — `git log -S "Sample demo data
source" -- .` over the whole tree returns nothing, while `git log -S "postgresql-step2-test"` returns the two
commits that put the real value into `collector_config.yaml` and the README (`413a1d75` "Update docker/README.md
(#1344)", `fa44fd27`). On the docs side the wrong value arrives with `853abe4` "Migrate GitBook docs from ODD
Platform repository" and has never been touched since. So the two copies of the same instruction diverged and
only the repo one was ever corrected.

## User-facing impact

Small but real, and on the onboarding path. A reader doing Step 2 for the first time is told the exact string to
look for in `/management/datasources`. They will not find it — the row is called `postgresql-step2-test`. The
count they are also given (11) is right, so the likely reading is "the collector created the wrong thing" or "I
mis-pasted the token", on the one page whose whole job is a frictionless first run. This is the second published
promise on this page that the shipped stand does not keep (the first, `10 predefined data sources`, is being
made true in code by CTRIB-063 / odd-platform#1870 rather than by editing the docs).
