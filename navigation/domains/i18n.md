# i18n / Multilingual UI

Six-language UI bootstrapped via `react-i18next` at app start. Default `en`; user choice persists in `localStorage('i18nextLng')`. No server-side rendering of locale.

## Code Entry Points (odd-platform — UI only; no server-side localization)

### Bootstrap
- `odd-platform-ui/src/locales/i18n.ts` — `i18n.use(initReactI18next).init({ resources, lng, fallbackLng })`. `lng = localStorage.getItem('i18nextLng') || 'en'`. Fallback chain `['en', 'es', 'ch', 'fr', 'ua', 'hy']`.
- `odd-platform-ui/src/index.tsx:24` — `import 'locales/i18n';` (side-effect import; runs at app start before `<App />` renders).

### Translation resources (one JSON per locale, key-string pairs)
- `odd-platform-ui/src/locales/translations/en.json` — English (default; complete)
- `odd-platform-ui/src/locales/translations/es.json` — Spanish
- `odd-platform-ui/src/locales/translations/fr.json` — French
- `odd-platform-ui/src/locales/translations/ua.json` — Ukrainian
- `odd-platform-ui/src/locales/translations/hy.json` — Armenian
- `odd-platform-ui/src/locales/translations/ch.json` — Chinese

### Display names + locale type
- `odd-platform-ui/src/lib/constants.ts:158` — `LANGUAGES_MAP` (locale code → human-readable name shown in `<SelectLanguage>`)
- `odd-platform-ui/src/lib/interfaces/shared.ts:17` — `type Lang = keyof typeof LANGUAGES_MAP` (the typed locale-code union)

### UI surface — language switcher widget
- `odd-platform-ui/src/components/shared/elements/AppToolbar/SelectLanguage/SelectLanguage.tsx` — the dropdown.
- `odd-platform-ui/src/components/shared/elements/AppToolbar/AppToolbar.tsx` — mounts `<SelectLanguage>` inside the user menu (anchored on the toolbar profile button); reads `i18n.language` to render the currently-active locale name via `LANGUAGES_MAP`.

### Translation consumption pattern
- `useTranslation()` hook from `react-i18next` is the canonical access point in components. Example: `AppToolbar.tsx:3 — import { useTranslation } from 'react-i18next'`.
- Translation keys are referenced as `t('Select language')`, `t('Logout')`, etc. Keys without a translation fall through the `fallbackLng` chain.

## Caveats (consumer-read audit, 2026-05-08)

- **localStorage persistence is the only choice memory.** Cleared storage / new browser / incognito session → user reverts to default `en` silently. No server-side per-user preference.
- **No build-time check that translation files are complete.** A key added to `en.json` and not added to the other 5 locales falls back to `en` at runtime — no warning surfaces. Contributors adding a new key must manually update all 6 files.
- **No locale-aware routing or `<html lang="...">` attribute switching.** SEO + a11y (screen readers signalling page language) are not addressed by the current bootstrap.
- **Six-language scope is fixed at build time.** Adding a seventh locale requires: adding `translations/<lang>.json`, adding a `LANGUAGES_MAP` entry, adding the import + resource map entry in `i18n.ts`, and (optionally) extending the `fallbackLng` chain. No runtime extension point.
- **`fallbackLng` is the full locale list.** If a key is missing from the user's locale, `react-i18next` walks the chain in order; in the worst case it tries all 6 locales before returning the key itself.
