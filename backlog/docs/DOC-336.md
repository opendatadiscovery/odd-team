## Description

This item **reopens / retracts** the GitHub `admin-groups` match-semantic claim shipped under **DOC-235 / DOC-238** (and the NO-OP "fix" instruction in **PLT-081**). The live, published `oauth2-oidc.md` page currently tells operators — in a coloured admonition and in the admin-detection matrix — that GitHub `admin-groups` is a **case-insensitive SUBSTRING** match. That is **factually wrong** and actively dangerous in the over-grant direction: an operator who reads "`admin-groups: [admins]` matches `team-admins`, `admins-readonly`, `data-admins`" will pick a longer, "safer" token than they need, and may wrongly believe a short token silently widens ADMIN to unrelated teams.

The code truth is **full case-insensitive equality, no substring**:

- `GithubUserHandler.determineAdminUser` collects the user's team names and promotes to ADMIN via `anyMatch(userTeam -> containsIgnoreCase(provider.getAdminGroups(), userTeam))` (`GithubUserHandler.java:119`).
- `OperationUtils.containsIgnoreCase(collection, element)` is `collection.stream().anyMatch(element::equalsIgnoreCase)` (`OperationUtils.java:9`) — i.e. the **whole** team name must equal a configured token, case ignored. There is no `contains`/substring call anywhere on this path.

Therefore `admin-groups: [admins]` matches a team literally named `admins` / `Admins` / `ADMINS`, and does **NOT** match `team-admins`, `admins-readonly`, or `data-admins`. The admonition's central example is inverted, and its closing sentence "A platform-side fix to use exact equality is tracked upstream" is false — exact equality **is** the shipped behaviour, so PLT-081's instruction to "fix" this is a NO-OP that would change nothing or, if acted on, risk re-introducing a real substring bug.

The correct semantic is already stated on the sibling page `admin-promotion.md` (rows 19, 33; decision-guide §lines 51-53, 64) — "GitHub `admin-groups` is a full team-name match … `admins` does **not** match `team-admins`." So this is a reconcile-to-the-already-correct-SoT, not new research.
