## What

`GithubUserHandler.java` has two security-posture defects:

**Defect 1 — admin-principals BYPASSES org-name gate (F-084b).** Lines 54-67 return early at line 62 (`return Mono.just(new DefaultOAuth2User(...))`) BEFORE the org-name check at line 68 when `provider.getAdminPrincipals()` is non-empty. An operator configuring `organization-name: my-corp` + `admin-principals: [external-consultant]` grants ADMIN to `external-consultant` even though they are NOT a member of `my-corp`. A typo in `admin-principals` matching a username an attacker can register on github.com becomes a platform-ADMIN backdoor.

**Defect 2 — GHES STRUCTURALLY LOCKED OUT (F-084c).** Line 39 hard-codes `WebClient.create("https://api.github.com")` with no `@Value`, no operator override. GitHub Enterprise Server deployments at `https://github.example.com/api/v3` cannot use the handler; every login fires DNS/cert errors. The live oauth2-oidc docs imply GitHub provider support is generic; GHES is an undocumented limitation.

## Why it matters

**Defect 1** — operator mental model "the org-gate is the outermost guard" diverges from actual order "admin-principals overrides it". A typo in admin-principals (a username an attacker can register on github.com) becomes a platform-ADMIN backdoor. Compounding with the substring overpromotion (PLT-081): an operator with both `admin-principals: ['external-consultant']` (typo) AND `admin-groups: ['admins']` (substring overpromotion) has a dual-attack surface.

**Defect 2** — GHES operators encountering "User doesn't belong to organization" or DNS errors find no doc path to discover the hard-code. Self-hosted enterprise GitHub deployments are excluded from ODD's OAuth2 support without acknowledgement.

## Suggested fix

**Thread A — Reorder gates so org-name fires FIRST, then admin-principals only for org members (Defect 1):**

```java
// Pseudo-code; verify against current handler signature
return githubApi.fetchUserOrgs(userLogin)
    .flatMap(orgs -> {
        if (provider.getOrganizationName() != null 
            && !orgs.contains(provider.getOrganizationName())) {
            return Mono.error(new AccessDeniedException("User not in organization " + provider.getOrganizationName()));
        }
        // Org membership verified — NOW evaluate admin-principals
        if (provider.getAdminPrincipals().contains(userLogin)) {
            return adminUser(userLogin);
        }
        return regularUser(userLogin);
    });
```

The order matters: org membership is the outermost gate; admin-principals refines the role within that gate. Today's order treats admin-principals as a bypass.

Migration note: operators relying on the bypass today (admin-principals overriding org-membership) WILL break. Document the change in CHANGELOG; recommend operators verify their admin users are org members before the new release.

**Thread B — GHES config knob (Defect 2):**

```java
@Value("${auth.oauth2.client.{registrationId}.github-base-uri:https://api.github.com}")
private String githubBaseUri;

private final WebClient webClient = WebClient.create(githubBaseUri);
```

Doc-side: cross-link from `oauth2-oidc.md` GitHub section to the new config knob. Verify the GHES path conventions (typically `https://github.example.com/api/v3`); the platform should NOT rewrite the operator-supplied URI.
