> (warn) **SECURITY - confirmed, responsible disclosure.** This is a **CONFIRMED, exploitable SQL-injection** (working PoC below). Do **not** open it as a public GitHub issue and do **not** publish the vector in the docs until a fix ships. File via the repo's **private GitHub Security Advisory**. The paired doc item (`backlog/docs/DOC-313.md`) is deliberately disclosure-constrained for the same reason.

## What

The search-result **highlight** endpoint builds a raw SQL string by interpolating the **user-supplied search query** (as `tsQuery`) directly into a `ts_headline(...)` call, then runs it as a jOOQ plain-SQL field with no bind parameters:

```java
// ReactiveDataEntityRepositoryImpl.java:801-802 (@ ede5d277) - getHighlightedResult()
final String sql = "ts_headline('english', '%s', to_tsquery('%s'), 'HighlightAll=true')"
    .formatted(text, tsQuery);
```

`tsQuery` is derived from the user's persisted `search_facets.query_string` via `JooqFTSHelper.tsQuery()`, which only `split(" ")`s and appends `:*` - **it never escapes single quotes**, so a crafted query breaks out of the `to_tsquery('...')` literal and injects arbitrary SQL on the read connection.

**Scope (refined by the 2026-05-30 PoC):** only the **query / `tsQuery`** path is injectable. The co-interpolated `text` (catalog document content) is **not** exploitable - `DataEntityHighlightConverter.searchableString()` doubles single quotes (`'` -> `''`) before that value reaches here. Narrow the claim to the query path.

## Confirmed - live exploit (2026-05-30, maintainer)

Stood up the published stack (`docker compose -f docker/demo.yaml up`, `odd-platform:latest`, `auth.type=LOGIN_FORM`, admin:admin), loaded one entity, exploited end-to-end through the real REST API:

1. **Arbitrary SQL execution (time-based):** baseline benign highlight -> HTTP 200 in 0.026s; after planting a `pg_sleep(8)` payload -> HTTP 200 in **8.03s**.
2. **In-band data theft (UNION):** the API response returned `data_entity.external_name = <b>odd-platform@ZRr2VcJW1zSLSQpKHxe23Oysa3d5L8WnDx6Mdx7q</b>` - i.e. `current_user` **plus a real ingestion token read out of the `token` table**.

**Reachability chain (no special privilege):**
`POST /api/search` (persists the query verbatim) -> `PUT /api/search/{id}` (overwrites `query_string`) -> `GET /api/search/{id}/data_entities/{id}/highlights` -> `getHighlightedResult()` runs the interpolated `ts_headline`. Any authenticated user can do this; under the shipped default `auth.type=DISABLED` it is **anonymous**. The same endpoint backs the UI's search-result highlighting, so normal UI usage reaches the sink too.

**PoC payload** (private advisory only - `/**/` for whitespace, `--` kills the trailing `:*`):
```
x'),'HighlightAll=true')/**/from/**/pg_sleep(8)/**/x--
```

**Two operational nuances the PoC established:**
- The `PUT /api/search/{id}` returns HTTP 500 (the facet recompute feeds the bad string to `to_tsquery` as a bind param and errors) - **but `SearchServiceImpl` (`:41`) is not `@Transactional`, so the malicious `query_string` is already committed**. The 500 is cosmetic; the attack lands on the subsequent highlight call.
- `getHighlightedResult` is the **lone raw-interpolation sink**. The sibling FTS call sites correctly parameterise: `JooqFTSHelper.ftsCondition` (`:103` `field("? @@ to_tsquery(?)", vectorField, query)`) and `ftsRankField` (`:158` `"ts_rank(?, to_tsquery(?))"`) both use jOOQ bind params.

## Why it matters

Confirmed unauthenticated (under the default `auth.type=DISABLED`) arbitrary read-side SQL via catalog search, demonstrated exfiltrating an ingestion token from the DB in the API response. Network-reachable, no privilege required, high confidentiality impact (and the token enables further ingestion-API abuse). This is the "guidance is the cliff" class at its worst - catalog search is assumed safe.

## Suggested fix

- In `getHighlightedResult`, stop interpolating. Pass the query (and text) as **bind parameters** - mirror the sibling `ftsCondition`/`ftsRankField` which already use `field("... to_tsquery(?) ...", ..., query)`. Build the `ts_headline` expression as a parameterised jOOQ plain-SQL field (`DSL.field("ts_headline('english', ?, to_tsquery(?), 'HighlightAll=true')", text, query)`), or use jOOQ's tsquery/ts_headline DSL.
- Add a regression test: a query containing `'`, `;`, `--`, `)` is treated as data (e.g. assert a `pg_sleep`-style payload does not delay, and a UNION payload does not leak extra columns).
- Repo-wide audit for other `String.format`/`.formatted(`/concatenation SQL assembly (grep `\.formatted(` near `"ts_`/`"select`/`"SELECT`). The PoC confirmed the other two FTS sinks are clean; confirm nothing else interpolates.
