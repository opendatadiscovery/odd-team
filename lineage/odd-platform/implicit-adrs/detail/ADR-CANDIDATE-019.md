- **ADR-CANDIDATE-019** (NEW 2026-05-10A): Data Collaboration is shipped disabled-by-default (`datacollaboration.enabled: false`); the controller is gated by `@ConditionalOnDataCollaboration` so every route returns 404 when disabled
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`postMessageInSlack`) — parallels ADR-CANDIDATE-004 (GenAI disabled-by-default), confirming a cross-feature pattern for "outbound-integration features ship off"
  - **Surfaced by**:
    - `odd-platform__java__DataCollaborationController__controller-method__postMessageInSlack.md:implicit_adrs.[1]` ("Data Collaboration ships disabled-by-default, opt-in via a single property." — intent_anchor: `enabled: false` as the application.yml default coupled to the `Conditional` reading `featureEnabled` from `datacollaboration.enabled`)
  - **Decision statement**: The Data Collaboration feature (in-platform Discussions tab + Slack message bridge) is shipped with `datacollaboration.enabled: false` as the verbatim YAML default (`application.yml:205`). The controller class carries `@ConditionalOnDataCollaboration` (`DataCollaborationController.java:21`), backed by `DataCollaborationFeatureCondition.java:18-22` reading `datacollaboration.enabled`. When disabled, the controller bean is not registered and **every route on the controller returns 404 Not Found** — there is no degraded-mode fallback, no error message, no "feature disabled" payload. Combined with ADR-CANDIDATE-018 (Slack OAuth token fail-fast), the deployment story is: feature off → operator turns it on → operator MUST provide the OAuth token or the platform refuses to boot.
  - **Wisdom test**: PASS. The verbatim `enabled: false` (not relying on Java primitive default) is the rationale anchor; the `@ConditionalOnDataCollaboration` annotation + the 404-when-disabled UX are deliberate. Structural for the deployment-architecture posture.
  - **Evidence**:
    - postMessageInSlack.md says: "application.yml:205 + DataCollaborationFeatureCondition.java:18-22"
  - **Existing ADR**: none. (Parallel to ADR-CANDIDATE-004 GenAI; folding both into a unified "outbound-integration deployment posture" ADR family is a maintainer triage option.)
  - **Co-surfaced gaps** (link from `refactoring-scopes.md`): None directly defending the disabled-by-default; the gaps for this feature (REFACTOR-046..051) are about authorization, body validation, audit logging, rate-limiting that the disabled-by-default posture does NOT address — once enabled, all those gaps apply.
