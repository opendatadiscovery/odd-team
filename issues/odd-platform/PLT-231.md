## What

`useQueryParams<T>(defaultVal)` (the shared FE hook for URL-backed view state) returns the page
defaults ONLY when the query string is empty. As soon as the URL carries ANY query string, it
returns ONLY the parsed URL params, with NO merge of `defaultVal`:

```
// odd-platform-ui/src/lib/hooks/useQueryParams.ts:41-46
const queryParams = React.useMemo(
  () => location.search
    ? (createQueryParams(location.search) as QueryParams<Params>)  // URL params only -- no merge
    : defaultVal,                                                   // defaults only when search is empty
  [location.search, defaultVal]);
```

So a partial / deep-linked / bookmarked URL (e.g. `/alerts?status=RESOLVED`) yields
`{ status: 'RESOLVED' }` and DROPS every other field the caller assumed was defaulted -- including
structural pagination params like `size`. A caller that forwards `queryParams` straight into a
generated API client throws synchronously on the missing REQUIRED param, the page renders the error
boundary, and no request is ever issued. This is invisible to `tsc` / `eslint` -- only driving the
real page surfaces it.

## Where / evidence

- Root cause: `odd-platform-ui/src/lib/hooks/useQueryParams.ts:41-46` (the `location.search ? parsed : defaultVal`
  branch -- no merge).
- Confirmed instance (now FIXED): the alerts-view hardening (#1763 / PR #1795 / CTRIB-025). On
  `/alerts?status=RESOLVED` the page threw on the missing required `size` and showed "Unknown Error".
  Fixed there by sending `size` explicitly in the global (`AlertsList.tsx`) and per-entity
  (`DataEntityAlerts.tsx`) fetches -- a per-call workaround, not the shared-hook root cause.

## Latent risk (the reason to track)

Every OTHER `useQueryParams(defaults)` caller that (a) reads a field which is only ever set via the
default, AND (b) forwards it to a generated client that requires it, is exposed to the same crash on a
partial/deep-linked URL. Candidates to audit: Activity (`useQueryParams<ActivityQuery>`), and any other
filterable list that keeps state in the URL. The alerts fix did not touch the hook, so the class is
still open.

## Suggested fix (class-level, not per-call)

Make the hook merge the defaults so a partial URL keeps the structural defaults:
`location.search ? { ...defaultVal, ...createQueryParams(location.search) } : defaultVal`. This is the
root-cause fix (it makes every present-and-future caller safe) rather than chasing per-call `size`
patches. Caveat: a shared-hook change touches every consumer -- before merging, confirm no caller
relies on the current no-merge semantics to express "this field is intentionally cleared" (e.g. an
"All statuses" option that clears `status`); for those, an explicitly-undefined value in the URL must
still beat the default. Verify with an FE pass over the URL-backed list views.
