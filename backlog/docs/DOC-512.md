# DOC-512 — the caption was fixed; the screenshot it describes was not

## What the figure shows vs what its caption says

`docs/data-discovery.md:13` embeds `.gitbook/img/search-facets.png` on the **pillar landing page** for Data
Discovery. Opening the image (checked pixel-by-pixel, not inferred from the filename) shows the pre-ST-4 UI:

- **The nine-tab class strip across the top of the results** — `All 453 · My Objects 11 · Datasets 105 ·
  Transformers 4 · Data Consumers 0 · Data Inputs 0 · Quality Tests 335 · Groups 1 · Relationships 8`.
  ST-4 (#1838, merged) removed seven of those tabs; **CTRIB-062 / ST-8 removes the last one and deletes
  `SearchResultsTabs.tsx` outright.**
- **A Filters sidebar with only** Datasource / Namespace / Owner / Groups / Statuses — no **Asset type**
  control, no **Data entity type** control, and no **My data** group.

The caption CTRIB-062 rewrote (closing the re-review's C2) now reads:

> "Catalog Search results — the Filters left-rail carries the aggregated facets (Datasource / Namespace /
> Owner / Tag / Groups / Statuses), **the Asset-type and Data-entity-type filters** that scope by kind and
> class, **and the My data scope**. …"

Every control the caption names as being in the left rail is **absent from the picture**, and the control the
caption no longer mentions is the most visually dominant thing in it.

## Why this is worth its own item rather than a note

The re-review raised C2 as a **blocker** in exactly these terms — *"the pillar landing page for the very page
this change rewrites will tell a reader to look for a strip that is gone."* The Phase-G fix corrected the
sentence and left the figure making the identical wrong claim, more vividly than prose could: a reader who
skims the page sees the picture, not the caption.

It is filed separately rather than folded into CTRIB-062 because the work is genuinely separable and broader
than that slice:

- the fix is a **screenshot re-capture on a populated stack**, not a text edit — different tooling, and it
  cannot be done from the diff;
- the image is **already wrong for ST-4**, a merged sibling slice, so this is not solely CTRIB-062's residue;
- CTRIB-062's own gates all pass and it is GATE-2-ready — holding a verified full-stack slice for a PNG would
  be the wrong trade.

## Fix direction

Re-capture `search-facets.png` on a 1.0.0 stack with a populated catalog, signed in as an owner-bound user so
the **My data** group renders (it is hidden under `auth.type=DISABLED` by spec R7 — a capture on the default
`odd-minimal` stack will reproduce the wrong sidebar again). The frame should show: no tab strip, the result
count in the results header, and the full sidebar the caption already describes. The caption then needs no
change.

**Sweep done with this finding:** the other figures on the pages CTRIB-062 touched were checked —
`catalog-overview.png` (`data-discovery/catalog-overview.md:11`) and `directory.png`
(`data-discovery/directory.md:20`) depict different surfaces and are not affected by the tab retirement.
`search-facets.png` is the only stale figure in the change's blast radius.
