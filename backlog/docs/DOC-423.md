## Description

The 2026-06-08 harvest flagged the `POST /ingestion/metrics` row in the `enable-security/README.md` deployment matrix (line 105: OPEN / OPEN / SESSION-gated) as a **possible phantom** — the reasoning being that the ingestion endpoints are generated from the external `ingestion-contract-server` (not checked out into odd-platform's own `openapi.yaml`/controllers), so the path could not be confirmed and the row might describe an endpoint that does not exist.

**Verification result (2026-06-08): the row is correct and the endpoint is real.** `POST /ingestion/metrics` is a genuine ingestion write endpoint, backed by the generated ingestion-contract model and exercised by the platform's own ingestion test suite:

- `IngestionFilterPathCoverageTest.java:58-71` (UC-02/PLT-003) explicitly enumerates `POST /ingestion/metrics` as a "real ingestion WRITE sibling that the flag does NOT protect" and asserts `gates(IngestionDataEntitiesFilter, POST /ingestion/metrics) == false` — i.e., the endpoints filter leaves it uncovered. That is *exactly* the **OPEN** classification the matrix gives the row under `DISABLED` / `OAUTH2` / `LDAP`. The matrix row is not just real — its OPEN behaviour is test-corroborated.
- `BaseIngestionTest.java:90-93` POSTs a `MetricSetList` to `/ingestion/metrics`; `MetricsIngestionTest.java` and `PrometheusMetricsIngestionTest.java` are full end-to-end ingestion tests against it.
- The `MetricSetList` payload type is imported from `org.opendatadiscovery.oddplatform.ingestion.contract.model` — the generated ingestion-contract package. The path "not in odd-platform's own openapi.yaml" is the **expected** shape of the pull/push ingestion-contract pattern (the contract is resolved as a dependency and code-generated), not evidence of a phantom.
- `active-platform-features/metrics-ingestion.md:14,20,28` documents `POST /ingestion/metrics` as the canonical inbound push surface.

The harvest's verify-or-drop therefore resolves to **keep the row, make no change to the matrix**, and record that the suspected-phantom concern is closed. This item is the on-disk audit trail for that verification (the harvest required a tracked artefact; the resolution is "verified real" rather than "drop"). It also reinforces the workspace rule: do not conclude an endpoint is absent from a shallow openapi/controller probe — the ingestion endpoints live in the generated contract.
