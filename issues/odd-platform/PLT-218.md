## What

`odd-platform-specification/components.yaml` declares `GraphRelationshipAttributes` with
properties `name` and `value`, but its `required` list says `field` and `value`:

```yaml
    GraphRelationshipAttributes:
      type: object
      properties:
        name:
          type: string
        value:
          type: string
      required:
        - field
        - value
```

`field` does not exist in `properties`. Under OpenAPI/JSON-Schema semantics a required
property that is absent from `properties` is still enforced as "must be present" by
strict validators, while the actually-rendered `name` property is NOT required - so:

- strict client-side validators reject every real payload (the platform serializes
  `{name, value}` via `GraphRelationshipMapper.mapGraphAttributes`, never `field`);
- generated models mark `name` optional when it is in practice always present.

## Where

```
odd-platform-specification/components.yaml (GraphRelationshipAttributes, near the other
  relationship schemas; properties name/value vs required [field, value])
odd-platform-api/src/main/java/org/opendatadiscovery/oddplatform/mapper/GraphRelationshipMapper.java:36-41
  // serializes .name(entry.getKey()).value(entry.getValue()) - 'field' never exists
```

## User-facing impact

No UI impact (the generated TS client does not enforce `required` at runtime). The trap
is for SDK consumers generating strict models/validators from the published spec: graph
relationship details payloads fail validation against the spec's own schema.

## Suggested fix

One-line rename in `required`: `field` -> `name`. Non-breaking for the platform itself
(the wire payload is unchanged); strictly corrects generated models.

## How discovered

CTRIB-006 (the #1752 Relationships-hardening contribution) read the relationship schemas
in `components.yaml` while adding the `relationship_id` contract descriptions; the
`required: [field, value]` mismatch sits directly under the edited
`GraphRelationshipDetails` schema. Deliberately excluded from that PR (generated-model
nullability blast radius is its own small change).
