## What

Three defects on the chrome surface that share the AppInfoMenu / Additional-Links theme. All three are small-surface fixes; ship together.

**Defect 1 — `AdditionalLinkProperties` has no validation (Java).** `AdditionalLinkProperties.java:6-10` is `record AdditionalLinkProperties(List<Link> links) { record Link(String title, String url) {} }` — no `@NotBlank` / `@URL` / `@Pattern` / `@Validated` / `@PostConstruct validate()`. Accepts: missing title (renders invisible-but-clickable phishing-vector menu item), missing url (`<a href=null>`), `javascript:alert(1)` (React 17+ neutralises but warns), `data:text/html,<script>...</script>` (browser sandboxes), `file:///etc/passwd` (browser refuses), `wiki.internal` (relative-path interpretation). None fails at config-load — bad operator-supplied data ships silently into the UI.

**Defect 2 — `AppInfoMenu` reverse-tabnabbing on 5 link sites (frontend security).** `AppInfoMenu.tsx:41,61,95,103,112` — 5 link sites render `target='_blank'` without `rel='noopener noreferrer'`. An attacker controlling any destination (compromised wiki, future XSS, operator-supplied bad link from Defect 1) can `window.opener.location = "phishing.example.com"` from JS — replaces the parent ODD tab. Compound with Defect 1: an unvalidated operator-link becomes a workspace-wide reverse-tabnab vector.

**Defect 3 — `AppInfoMenu` keyboard-inaccessible despite declaring ARIA support (WCAG 2.1 SC 2.1.1 violation).** `AppInfoMenu.tsx:78-82` — icon button declares `aria-haspopup='true'` (line 80) + `aria-controls={menuId}` (line 79) but wires ONLY `onMouseEnter` (line 81). NO `onClick`, NO `onKeyDown`, NO `onFocus`. Touch users (iOS Safari, Android Chrome) generate no mouseenter; AT users (screen-reader + keyboard) cannot open the menu. Documentation / Slack / Feedback / Version / operator-link surface inaccessible to keyboard + touch.

## Why it matters

**Defect 1** is operator-trust + security: the `odd.links` config is operator-authored, but the platform offers no input validation. Operators trusting "the platform will reject bad input" discover the gap when a junior teammate's PR adds a malformed entry that ships to production.

**Defect 2** is the security amplifier — most browsers default `target='_blank'` to `noopener` since 2020, but compatibility-trailing browsers + the React Router `<Link>` abstraction may not honour the modern default. Adding `rel='noopener noreferrer'` explicitly is the correct hardening.

**Defect 3** is WCAG-violation in shipped code. ODD deployments serving accessibility-required audiences (US federal, EU public sector, enterprise compliance frameworks) cannot meet accessibility standards with the current AppInfoMenu. The Documentation / Slack / Feedback / Version / operator-link surface is inaccessible to keyboard-only + screen-reader users.

Severity MEDIUM (each defect individually) because:
- Defect 1 is operator-supplied input — limited blast radius (no random-attacker path)
- Defect 2 is most browsers' default — defense-in-depth, not a primary vulnerability
- Defect 3 is a compliance gap, not a runtime defect

Combined the three give a tight UI / config-validation hardening PR.

## Suggested fix

### Defect 1 — validation on AdditionalLinkProperties

```java
// AdditionalLinkProperties.java
@Validated
@ConfigurationProperties("odd.links")
public record AdditionalLinkProperties(
    @Valid List<Link> links
) {
    public record Link(
        @NotBlank String title,
        @NotBlank @Pattern(regexp = "^https?://.*", message = "url must be http or https")
        String url
    ) {
        // Additional defensive validation in compact constructor:
        public Link {
            if (url != null
                && (url.toLowerCase().startsWith("javascript:")
                    || url.toLowerCase().startsWith("data:")
                    || url.toLowerCase().startsWith("file:")
                    || url.toLowerCase().startsWith("vbscript:"))) {
                throw new IllegalArgumentException(
                    "odd.links url scheme not allowed: " + url);
            }
        }
    }
}
```

Boot fails-fast on bad operator input; reports the specific bad URL.

### Defect 2 — rel="noopener noreferrer" on the 5 AppInfoMenu link sites

```tsx
// AppInfoMenu.tsx — apply to each of lines 41, 61, 95, 103, 112
- <Link to={url} target="_blank">{label}</Link>
+ <Link to={url} target="_blank" rel="noopener noreferrer">{label}</Link>
```

Five mechanical edits. Could be made a project-wide lint rule (`react/jsx-no-target-blank`) in a follow-up PR.

### Defect 3 — keyboard handlers on the AppInfoMenu icon button

```tsx
// AppInfoMenu.tsx:78-82
<IconButton
  aria-controls={menuId}
  aria-haspopup="true"
- onMouseEnter={handleOpen}
+ onClick={handleOpen}
+ onKeyDown={(e) => {
+   if (e.key === 'Enter' || e.key === ' ') {
+     e.preventDefault();
+     handleOpen(e);
+   }
+ }}
+ onMouseEnter={handleOpen}
>
```

Keep `onMouseEnter` for hover-discoverability; add `onClick` + `onKeyDown` for keyboard + touch. Menu close logic should likewise be reachable via Escape (`onKeyDown` on the Menu component itself).
