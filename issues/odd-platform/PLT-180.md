## What

When the Data Quality dashboard's single aggregate fetch (`GET /api/dataqatests/runs`) fails with a 4xx or 5xx, the page does **not** show an error — it shows three grey "No data" donuts that are pixel-identical to a healthy empty catalog. The dashboard hook seeds `react-query` with an all-zeros `initialData` envelope and the content component reads only `{ data, isSuccess }` — it never reads `isError`. On a failed request, `data` stays at the all-zeros `initialData`, `isSuccess` is whatever the cached/initial state implies, and the rings render zeros. An operator therefore cannot tell "the catalog genuinely has no DQ runs" from "the request to the server failed" — both look like an empty, all-grey dashboard.

## Where

The content component destructures only `data` and `isSuccess` from the hook — `isError` is never read or rendered:

`odd-platform-ui/src/components/DataQuality/DataQualityContent.tsx:24`
```tsx
const { data, isSuccess } = useGetDataQualityDashboard(filterState);
```

The hook always supplies an all-zeros `initialData`, so `data` is never undefined even on failure:

`odd-platform-ui/src/lib/hooks/api/dataQuality.ts:34-72` (the all-zeros envelope) and `:77-81` (where it is wired into `useQuery`)
```ts
return useQuery({
  queryKey: ['dataQualityDashboard', params],
  queryFn: async () => dataQualityRunsApi.getDataQualityTestsRuns(params),
  initialData,                       // all-zeros DataQualityResults — never undefined
});
```

`initialData` (lines 34-72) sets every table-health, monitored-tables, and per-category status count to `0`, which is exactly what an empty catalog returns — so the failed-fetch view and the empty-catalog view are indistinguishable. The downstream chart memos (`DataQualityContent.tsx:53-73`) all key off `data?...` and happily render the zeros.

## Why it matters

This is a silent failure on an operational dashboard. A backend outage, an expired session producing a 401, a 500 from one of the three server-side CTE queries, or a network error all present as a clean, all-zero "No data" dashboard with no retry affordance. An operator monitoring data-quality health sees "everything is empty/quiet" and may conclude there is nothing wrong, when in fact the page failed to load. Medium severity: not data-loss or a security issue, but it converts a loud failure (the fetch errored) into a silent, misleading success-looking state on a surface operators use to decide whether their pipelines are healthy.

## Suggested fix

Read `isError` from the hook and render an explicit error state (with a retry) when the fetch fails, instead of falling through to the zero-valued rings:

1. In `DataQualityContent.tsx:24`, also destructure `isError` (and ideally `refetch`) from `useGetDataQualityDashboard`.
2. When `isError` is true, render an error panel ("Couldn't load the data quality dashboard") with a retry button, rather than the donut rings seeded from `initialData`.
3. Consider whether the all-zeros `initialData` (`dataQuality.ts:34-72`) should be dropped in favour of a normal loading state, so an in-flight first load is not also indistinguishable from an empty catalog. Open to alternatives.
