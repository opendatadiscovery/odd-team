## What

A full sweep of single-quoted `t('...')` literals across `odd-platform-ui/src` finds **70
distinct translation keys referenced by components but absent from ALL SIX locale catalogs**
(`en/es/ch/fr/ua/hy.json`) -- after odd-platform#1748 fixed the three toolbar-tab keys
(Data Quality / Data Modelling / Master Data), which were instances 71-73 of the same class.
Because the i18n layer uses the natural-keys pattern with no missingKey handler, every one of
these renders the raw English literal under every non-English locale, silently.

This is the consolidated whole-class item: #1748's issue scoped itself to the three top-level
navigation tabs and explicitly left the remainder out; this item carries the remainder, so the
class converges in ONE more pass instead of 70 single-key issues.

## User-facing impact

User: any non-English (es/ch/fr/ua/hy) operator. Each key above renders as raw English in an
otherwise-translated UI -- confirmation dialogs ('Are you sure you want to delete this lookup
table?'), dashboard headlines ('Table Health', 'Test Results Breakdown'), buttons ('Add query
example'), empty states. The mechanism was live-verified during #1748's reproduction (the
three tab literals rendered verbatim under the ua locale on the running stack); the remaining
70 share the identical lookup path. Per-string severity is low; the aggregate -- 70 strings x
5 non-English locales = 350 user-visible English fragments -- makes the localisation look
half-finished everywhere beyond the chrome.

## Why it matters

Same trust mechanics as #1748 but in the page bodies: a non-English operator meets untranslated
fragments on every feature surface, and every FUTURE locale contribution inherits the gap
(nothing to translate when the key does not exist). The docs page
(docs.opendatadiscovery.org/features/multilingual-ui, Known-caveat section) now states 'about
70 code-referenced keys are absent' -- fixing this item must also update that sentence.

## Suggested fix

1. Add all 70 keys to `en.json` (key === value, the natural-keys convention) and a translated
   value to each of the five non-English catalogs -- same motion as #1748, one PR.
2. Add a CI key-parity guard so the class cannot regrow: a small script (node or python) that
   extracts `t('...')` literals from `src` and fails when any is absent from `en.json` (and,
   stricter, when the six catalogs' key sets diverge). Free + self-hosted: wire it into the
   existing `run-pr-tests.yaml` (or the `tests/` lint job) -- no new infrastructure. Without
   the guard this is the third recurrence of the class (the catalogs drifted, #1748, this).
3. Keep dynamic call sites (`t(variable)`) out of scope for the guard's failure mode (warn,
   not fail) -- the sweep regex covers literal keys only.
