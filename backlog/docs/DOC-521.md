## Description

**Failure shape: conceptual drift / dead admonition — a caveat that is true today and false on the day the
release it rides publishes.**

The manual documents unfixed platform defects as admonitions, each written in the present tense against the
*currently published* release. That is correct and load-bearing: an operator on 0.29.0 needs the warning. But
the caveat's truth has an expiry date — the release that carries the fix — and **nothing in the release
process retires them.** The `release/{version}` train merges, the fix and the stale warning publish in the
same minute, and the manual starts telling operators to work around a defect that no longer exists.

### The proven instance (measured this review)

`docs/data-discovery/statuses.md:37-39` — an `{% hint style="info" %}` block authored by `DOC-338`:

> **Known defect — the `status_updated_at` timestamp is not refreshed on non-`DELETED` status transitions.**
> A guard in the platform's status mapper (`DataEntityMapperImpl.applyStatus`) tests the new status id
> against a value it has just overwritten with that same id, so the branch that re-stamps
> `status_updated_at` never runs.

**The guard was fixed.** `odd-platform-api/.../mapper/DataEntityMapperImpl.java:253-268` now captures
`previousStatus` *before* `pojo.setStatus(...)` and stamps `statusUpdatedAt` when they differ — the code even
names the item that fixed it (`// PLT-027 (CTRIB-053)`).

Release arithmetic, measured:

| Fact | Evidence |
|---|---|
| The fix landed 2026-07-04 | `git log -1 -S'previousStatus' -- .../DataEntityMapperImpl.java` -> `a3d849cc` |
| It is NOT in `0.28.0` (tagged 2026-06-17) | `git merge-base --is-ancestor a3d849cc 0.28.0` -> false |
| It is NOT in `0.29.0` (tagged 2026-06-25) | `git merge-base --is-ancestor a3d849cc 0.29.0` -> false |
| It IS on `origin/main`, so it ships in `1.0.0` | the fix is present at the `969a5d5b` base of every current contributor branch |
| The train carries the caveat unchanged | `git diff origin/main origin/release/1.0.0 -- docs/data-discovery/statuses.md` -> EMPTY |

So the caveat is **correct on docs `main` today** and becomes **false the moment `release/1.0.0` merges**.

### The class, sized

A mechanical sweep of `documentation/docs/**` for pending-fix language finds the caveat pattern on **~30
pages**, ~50 hits in total:

```
grep -rn 'Known defect\|Known limitation\|until the fix lands\|until the platform-side fix\|The upstream fix\|upstream platform-side fix\|is on the roadmap\|doc-side caveat' docs/
```

Highest-count pages: `enable-security/authorization/permissions.md` (9), `active-platform-features/notifications.md`
(6), `configuration-and-deployment/odd-platform.md` (4), plus `management.md`, `schema-diff.md`,
`per-column-annotation.md`, `custom-metadata.md`, `genai.md`, `alerting.md`, `activity-feed.md`,
`integrations/**`, `developer-guides/api-reference/**`.

An unknown subset of those is fixed in the 0.29.0..1.0.0 delta — this workspace alone has merged CTRIB-053
and a long series of sibling fixes since 0.29.0 was tagged. Each stale survivor is a published falsehood
carrying a mitigation an operator will actually perform (reverse-proxy rules, SQL fix-ups, staggered bulk
operations) against a defect that is gone.

## Acceptance criteria

- [ ] The sweep is a **step in `playbooks/release-train-merge.md`** (readiness half), not a one-off: for each
      `Known defect` / `Known limitation` / `until the fix lands` / `The upstream fix` caveat in
      `documentation/docs/**`, resolve the cited code symbol against the release tag being cut and record
      `still-true` / `RETIRE` with the `file:line` that decided it.
- [ ] `statuses.md`'s `status_updated_at` hint is **retired on the train** (removed, or rewritten as
      "fixed in 1.0.0" if the historical note earns its place) — citing `DataEntityMapperImpl.java:253-268`.
- [ ] Every other caveat whose fix is contained in the `1.0.0` tag is retired in the same train commit;
      every caveat that survives is listed with the evidence that it survives, so the next release starts
      from a checked baseline rather than re-deriving all ~50.
- [ ] Post-merge, `curl -sL` each retired caveat's page and confirm the admonition is gone from the live HTML
      (not just from the source) — `playbooks/live-site-verification.md`.
