## What

#1835 (PR #1850) fixed the **data-entity Search** facet chips so a selected chip renders the RAW facet value
(`DRAFT`, `DATA SET`), matching its sidebar dropdown option — via a shared `formatFacetName`. Two **sibling**
filter-chip renderers on other surfaces still run the value through lodash `capitalize()` (the old
`TextFormatted` path) and so keep the exact same chip-vs-dropdown divergence #1835 closed:

- **Term search filters** — the chip capitalizes; the dropdown renders raw. A tag/owner/namespace facet value
  like `PII` shows as `Pii` in the chip but `PII` in the dropdown.
- **Activity / Alerts filters** — the removable chip capitalizes the selected option name.

Because #1835 was (correctly) scoped to the data-entity search overhaul, the fix leaves a **cross-surface
inconsistency**: data-entity search chips now render raw while Term-search and Activity chips still capitalize.

## Where (verified first-hand @ odd-platform main `e27bf131`)

- **Term chip** — `odd-platform-ui/src/components/Terms/TermSearch/TermSearchFilters/TermSearchFilterItem/MultipleFilterItem/SelectedFilterOption/SelectedFilterOption.tsx:35`
  → `<TextFormatted value={filterName} />` (lodash `capitalize`).
- **Term dropdown (raw, the target)** — `.../TermSearchFilterItem/MultipleFilterItem/MultipleFilterItemAutocomplete/MultipleFilterItemAutocomplete.tsx:133`
  → `<span>{option.name}</span>` (raw).
- **Activity chip** — `odd-platform-ui/src/components/shared/elements/Activity/ActivityFilterItems/MultipleFilter/SelectedFilterOption/SelectedFilterOption.tsx:43`
  → `<TextFormatted value={selectedOption.name} />` (capitalize).
- **The fix to reuse** — `odd-platform-ui/src/components/Search/Filters/formatFacetName.ts` (added by #1835): returns
  the raw value; `types` keep `_`→space. The Term facet map has no `types`, so a Term-side reuse renders every
  value verbatim.

## User-facing impact

On the Term search and the Activity feed, a selected filter chip disagrees with the dropdown it came from for any
non-title-case value (uppercase tags, `SCREAMING_SNAKE` values, all-caps acronyms) — the same "one value, two
labels" bug #1835 was filed for, on two more surfaces.

## Recommendation

Route the Term-search and Activity `SelectedFilterOption` chips through the same raw formatter (reuse
`formatFacetName`, or lift it to a shared location if Activity's option shape differs), so chip and dropdown agree
on every filter surface. Add a small unit test per surface (RED on the current capitalize path). Low priority
(cosmetic), but it is the completion of #1835's intent across the app.

## How discovered

`/review` of CTRIB-051 (#1835). The item's Phase-B note "the chip is the ONLY non-raw facet-value renderer" was
scoped to `components/Search/Filters` (true there); a repo-wide `TextFormatted` sweep during review found the two
sibling renderers above. Out of scope for #1835 (the data-entity search overhaul) → tracked here rather than
widening the CTRIB-051 PR (G-C5 scope-bounding).
