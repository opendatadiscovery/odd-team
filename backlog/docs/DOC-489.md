## Description

ODD's run-status enum distinguishes **FAILED** (the test ran and the data failed the assertion) from
**BROKEN** (the test machinery itself errored / produced no clean verdict) — proven by the Great Expectations
adapter (`odd-great-expectations` mapper: GE `success:false → FAILED`, never `BROKEN`). But this distinction is
defined **nowhere user-facing** (verified by odd-sme across the wire contract `odd_models`, the spec
`components.yaml`, and the live test-run-history page).

That undocumented gap is the root cause of the platform's surfaces **diverging on BROKEN**: alerting treats
`BROKEN == FAILED` (both fire a DQ-test-failed alert), SLA ignores BROKEN (counts only Success/Failed), and
Table Health (post-#1794) rates BROKEN as Warning. An operator cannot reconcile these without a definition.

## Acceptance
- A short user-facing **run-status glossary** (what each of Success / Failed / Skipped / Broken / Aborted /
  Running / Unknown means — especially FAILED vs BROKEN), cross-referenced from the dashboard +
  test-run-history pages.
- Not release-gated — a general documentation improvement on docs `main` (no behaviour change).
