## Description

Parallel-surfaces-with-drift editorial finding surfaced during the `/review` of CTRIB-010
(odd-platform#1657 activity User-vs-Owner clarity).

The CTRIB-010 train doc rewrite (`release/0.28.0` commit `3a4f6ad`) correctly updated the
Activity-feed detail page to an **eight**-facet panel — it adds the third actor filter
("Made by (user)") alongside Owner and "Made by (owner)":

- `documentation/docs/active-platform-features/activity-feed.md:13` (train): "…with an **eight-facet**
  filter panel…"
- `documentation/docs/active-platform-features/activity-feed.md:28` (train): "…narrow the feed by **eight** facets:"

But the one-page feature index still summarises the global panel as **seven** facets, and it
cross-links the very page that now says eight:

- `documentation/docs/Features.md:126` (train, verbatim): "See the dedicated [Activity Feed]
  (active-platform-features/activity-feed.md) page under [Active platform features]
  (active-platform-features.md) for the **seven facets on the global filter panel**, the full
  event-type catalogue …, and the configuration entry for retention partitioning."

On `main` (live 0.27.x) both surfaces say "seven" — consistent. The drift exists only on the
`release/0.28.0` train and would publish at 0.28.0. The train *did* touch `Features.md` (the
multilingual-UI 6→7-locale change) but did not propagate the activity facet count.

**Failure shape:** parallel surfaces with drift (same fact — the global Activity panel's facet
count — stated on two pages, now inconsistent on the train).

## Acceptance Criteria

- [ ] On `release/0.28.0`, `Features.md:126` reads "eight facets on the global filter panel"
      (matching `activity-feed.md`).
- [ ] No other Features.md / index summary of the Activity panel facet count remains at "seven"
      on the train (re-grep `seven facet|eight facet`).
- [ ] Verified at the 0.28.0 release gate alongside DOC-451 (the paired activity-feed item).
