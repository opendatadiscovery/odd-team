## Description

`audit-trail-scope.md` opens by declaring itself "the single reference for compliance auditors, security reviewers, and operators with SOX / HIPAA / GDPR / SOC2 obligations who need to know what the platform records, what it does not record" (page intro, lines 7-9). Its negative half enumerates the unrecorded mutation streams: "RBAC mutations, owner lifecycle, term lifecycle, namespace lifecycle, datasource lifecycle, collector lifecycle".

The page contains **zero mentions** of housekeeping, hard-deletion, or purges (grep verified 2026-06-11: `housekeeping|hard-delet|purge|permanent` → no hits). Yet the housekeeping subsystem permanently deletes data every 15 minutes — resolved alerts, search-facet history, soft-deleted entities with ~25 cascading child tables including object-storage attachments, empty partitions — and emits **no audit event of any kind** (no Micrometer metric, no structured record, DEBUG-only logs below the shipped default level). That fact is now documented as an operator caveat on the config page (`odd-platform.md` § Housekeeping Settings Configuration, DOC-361, merged 2026-06-11 @ documentation `4cc197e`) with the explicit statement that a "deletions are logged/audited" compliance requirement is **not** satisfied out of the box.

Failure shape: **cross-audience absence**. The fact exists on the operator/config surface but is missing from the dedicated compliance-audience surface that promises completeness. A SOC2/HIPAA reviewer reading only the audit-scope page — its stated purpose — would conclude the negative half is limited to the six listed mutation streams and miss that the platform's own reaper deletes data with no recoverable trace of what was deleted, when, or how many rows.
