## Description

The live `/permissions` page enumerates 11 Management permissions that are exclusively write/mutate verbs (`OWNER_CREATE`, `NAMESPACE_DELETE`, `COLLECTOR_TOKEN_REGENERATE`, ...) and has no entry naming any `*_READ` permission, nor a caveat that withholding `*_CREATE` does not restrict the corresponding `*_READ`. The actual implementation (`SecurityConstants.SECURITY_RULES`, verified `SecurityConstants.java:98-170` on 2026-05-27) contains zero `*_READ` SecurityRule entries; the seven Management GET list endpoints (`/api/owners`, `/api/datasources`, `/api/collectors`, `/api/titles`, `/api/namespaces`, `/api/owner_association_request/activity`, `/api/owners/providers`) all fall through to `AuthorizationCustomizer.java:29-30`'s catch-all `.pathMatchers("/**").authenticated()`.

Operator-visible consequence: a team grants `NAMESPACE_CREATE` to a single principal expecting them to be the only one who can read the namespace catalog. Every authenticated user can still GET `/api/namespaces` and enumerate every namespace name. The PII / org-structure leak surface is the union of seven Management directories.
