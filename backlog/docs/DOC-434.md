## Description

The docs give two values for the number of `odd-collector` pull adapters:

- **Precise `41`** — sourced to code (`PLUGIN_FACTORY` in `odd_collector/domain/plugin.py`):
  - `integrations/collectors/odd-collector.md` frontmatter (line 2), body (line 11), the supported-adapters lead-in (line 17 — "The 41 adapters ... the remaining 38 are catalogued ..."), the per-adapter-reference lead-in (line 230 — "remaining 38 adapters"), and the feature matrix (line 240, line 1240 — "41-adapter set").
  - `integrations/README.md` line 19 — "41 generic adapters: databases, BI tools, streams, MLOps".
- **Vague `40+`** — `main-concepts.md` line 23: "The canonical implementation is `odd-collector` with **40+ bundled pull adapters**".

`40+` is not *wrong* (41 satisfies "40+"), but it is a soft precise-vs-vague mismatch on the same fact across pages a reader cross-navigates (main-concepts.md ↔ integrations/README.md ↔ odd-collector.md). A reader who lands on main-concepts.md first and then sees an exact `41` (with `41 = 3 spotlights + 38 remaining` arithmetic) on the collector page has to reconcile the two. Since odd-collector.md ties `41` to the actual `PLUGIN_FACTORY` registration count and itemises the breakdown, the integrations surfaces are the load-bearing, code-cited authority; main-concepts.md's `40+` is the lone approximation.

Low severity (consistency / precision, not a misleading runtime claim).
