## What

The platform stores operator-authored Markdown verbatim (no `Jsoup.clean`, no `Encode.html`, no length cap, no allowlist) and renders it via `@uiw/react-md-editor`'s Markdown component with `rehype-raw` enabled and `rehype-sanitize` **NOT** configured. The pattern spans 6 surfaces. Surfaces 1-3 share `Markdown.tsx:113-124` as a single SPA-tier fix anchor - one config-line change closes all three. Surfaces 4-6 have separate fix anchors and live on companion issues.

## Defensive partial-mitigation envelope (what's currently happy-accident)

The platform currently relies on:
- Chromium's CSP-default + script-execution restrictions to block raw `<script>` tags from executing.
- React's attribute-value filtering to block raw `onerror=` / `onload=` / `onclick=` handlers on standard HTML tags.

Both are **happy accident**, not app-layer policy. The following vector classes are unmeasured:
- `<svg><animate onbegin=...>` style event-attribute injection inside SVG (not all React filters cover SVG events).
- `<img src="javascript:..." />` or `<a href="javascript:..." />` URL-scheme injection.
- CSS-expression injection (older browsers).
- `<style>` block injection that exfiltrates via background-image URL.

## How to reproduce (surface 1 - entity description)

1. As an authenticated user with `DATA_ENTITY_DESCRIPTION_UPDATE`, navigate to any entity's Overview tab.
2. Click "Edit" on the Description panel. The MDEditor opens.
3. Paste a payload: `<img src=x onerror="alert(1)">` (or any of the unmeasured vector classes above).
4. Save. The PUT body is stored verbatim via `setInternalDescription`.
5. Read-back via `GET /api/dataentities/{id}` returns the verbatim string.
6. UI Preview renders via `Markdown.tsx` with `rehype-raw` enabled and no sanitiser. Outcome depends on the specific vector class; common attribute vectors are happy-accident-blocked; SVG / URL-scheme vectors are unmeasured.

## Suggested fix

**Option A (recommended) - one-line SPA-tier hardening at `Markdown.tsx:113-124`.** Add `rehype-sanitize` to the `rehypePlugins` configuration:

```typescript
import rehypeSanitize from 'rehype-sanitize';
// inside rehypePlugins:
rehypePlugins: [rehypeRaw, rehypeSanitize]
```

This closes surfaces 1-3 (entity / dataset-field / term-definition) in one place because all three render via this component. Surfaces 4 (Query Examples - separate MDEditor.Markdown call site) need the equivalent fix on PLT-018; surface 5 (Lookup Tables - verbatim Char render) needs `Encode.html` at storage on PLT-019; surface 6 (Slack mrkdwn) needs `MrkdwnUtils.escape` at `SlackMessageGenerator.markdownText:77` on PLT-016.

**Option B - write-time `Jsoup.clean` at the three storage call sites.** More invasive (3 files) and incurs storage normalisation cost; rejected in favour of Option A for leverage.

The fix should ship with a `rehype-sanitize` allow-list tuned to the platform's actual Markdown corpus - start with the package default + ODD's `[[Namespace:Term]]` term-mention syntax (see DOC-177 / F-002b) + the standard Markdown subset.
