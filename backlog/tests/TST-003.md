## Description

Two attachment-subsystem security/correctness defects the feature-reflection pass surfaced, neither covered by the existing attachment epic PLT-086 (cross-entity mutation escalation + MinioConfig unset region):

- **Filename injection (F-027/H-007)** — the uploaded filename is propagated RAW into the LOCAL storage path (path traversal via `..`/absolute paths) and into the `Content-Disposition` response header (CRLF/header injection); there is no sanitisation — no `..`/NUL/scheme/length checks, no RFC-6266 header quoting. The 2026-06-01 reflection emitted probe P-196 but no PLT was filed.
- **Chunk corruption (F-027/H-003)** — same-index chunk retry is last-writer-wins with no write isolation (silent corruption); a stray non-integer chunk filename aborts the whole upload via `NumberFormatException`.

Per the maintainer's no-code-change-now posture and the pin-known-bugs idiom (LSN-029), these are PINNED with characterization tests that assert the CURRENT (incorrect) behaviour as GREEN tripwires — they go RED the instant the behaviour is fixed (or further regresses), guaranteeing no unplanned change to a live security defect ships silently. The corresponding upstream code fix (filename sanitisation + RFC-6266 quoting + write-then-rename chunk persistence + non-integer-filename filter) is a follow-up upstream PLT (see Implementation Notes) — these tests pin the defect until that fix is scheduled.

## Acceptance Criteria
- [ ] A characterization test asserts the CURRENT filename handling: a filename containing `..` (or a path separator / CRLF) is NOT sanitised on the storage path / `Content-Disposition` header (assert the raw propagation that exists today), with an in-source comment naming the path-traversal + CRLF risk and the LSN-029 flip protocol.
- [ ] A characterization test asserts the CURRENT chunk behaviour: a same-index chunk retry overwrites last-writer-wins (no isolation), and a non-integer chunk filename triggers `NumberFormatException` aborting the upload.
- [ ] Each test carries `@pins` (the eventual upstream fix id) + `@Tag("known-bug")` + full in-source documentation: why it exists, that it asserts the wrong behaviour on purpose, the references (F-027/H-007 + H-003, P-196), and the flip protocol (on RED: intentional fix → invert to assert sanitisation + `@regresses`; unplanned → stop and investigate).
- [ ] Tests run in CI as GREEN tripwires; they do not break the build and are not `@Disabled`.
- [ ] The upstream code-fix is logged as a follow-up PLT (filename sanitisation + chunk write-isolation) so the pin has a tracked counterpart.
