## What

The catalog **Overview** page - the first surface a user lands on after login - has unbounded Cumulative Layout Shift (CLS). Its loading skeleton is gated on only **two** of the page's data sources (identity fetch + popular tags). The moment those two resolve, the skeleton is replaced by the real layout, but four of the six page regions (`Domains`, `DataEntitiesUsageInfo`, `Directory`, and the conditional `OwnerAssociation`) fetch their own data **independently** and render with zero height until their requests return - so they pop in afterward and push everything below them down. On top of that, the skeleton reserves no space for the hero, so when `MainSearch` mounts it reflows the top of the page as well. The result is a visible, multi-step jump-and-reflow on the platform's landing page on every load.

## Where

`odd-platform-ui/src/components/Overview/Overview.tsx` - the loading gate watches only identity + tags:

```tsx
// Overview.tsx:29 - isLoading depends on ONLY two of the page's data sources
const isLoading = React.useMemo(
  () => isIdentityFetching || isTagsFetching,
  [isIdentityFetching, isTagsFetching]
);

if (isLoading) {
  return (
    <S.Container>
      <SkeletonWrapper
        renderContent={({ randWidth }) => <OverviewSkeleton width={randWidth()} />}
      />
    </S.Container>
  );
}
```

But the rendered tree has six regions, four of which self-fetch and are not represented in `isLoading` (and the hero is not reserved in the skeleton):

```tsx
// Overview.tsx:44 - real layout: MainSearch hero + 6 regions
return (
  <S.Container>
    <Grid container justifyContent='center' sx={{ pt: 4, pb: 5 }}>
      <MainSearch mainSearch />                  {/* hero - not sized in skeleton -> reflows in */}
    </Grid>
    <S.TagsContainer container>{tags && <TopTagsList tags={tags} />}</S.TagsContainer>
    <Domains />                                  {/* self-fetching -> pops in late */}
    <DataEntitiesUsageInfo />                     {/* self-fetching -> pops in late */}
    <Directory />                                 {/* self-fetching -> pops in late */}
    {isShowOwnerAssociation && (                  {/* conditional + self-fetching -> pops in late */}
      <WithPermissionsProvider ... Component={OwnerAssociation} />
    )}
  </S.Container>
);
```

Only `TopTagsList` is bound to `isLoading` (via `isTagsFetching`); `Domains`, `DataEntitiesUsageInfo`, `Directory`, and `OwnerAssociation` each manage their own fetch and start at zero height.

## Why it matters

CLS on the landing page is a **loud, every-user, every-load** UX defect: it is the first impression of the product, the page jumps under the cursor while the user is reaching for search or a domain card (a mis-click hazard), and unbounded CLS directly tanks the Lighthouse / Core Web Vitals score for the entire app's entry point. It is intermittent in magnitude (worse on a slow network or a cold catalog, where the secondary fetches lag the primary two the most), which makes it under-reported but consistently present. No data risk; pure but high-visibility UX regression on the platform's front door. Severity high.

## Suggested fix

Reserve layout in the skeleton for **all** regions so the page occupies its final height before any data resolves, eliminating the shift:

1. Extend `OverviewSkeleton` to include placeholders sized to match the hero (`MainSearch`) and each of `Domains`, `DataEntitiesUsageInfo`, `Directory`, and (when `isShowOwnerAssociation`) `OwnerAssociation` - so the skeleton's footprint equals the loaded page's footprint.
2. Either fold those regions' fetch states into the page-level `isLoading` gate, **or** (preferred, to keep the hero/tags painting fast) have each region render its own fixed-height local skeleton while its data is in flight, so a slow secondary fetch never changes the surrounding geometry.

The principle: nothing on this page should change height after first paint. Open to alternatives on whether the reservation lives in the shared `OverviewSkeleton` or in per-region local skeletons; either removes the CLS.

## How discovered

Surfaced during the 2026-06-08 contradiction-harvest (feature-reflection triage), from the F-141 reflection's product-owner read of the catalog-overview surface - the gap between "skeleton present" and "page fully painted without shifting" is a reader-flow/UX defect that only shows up when the page is reasoned about end-to-end. No prior skeleton/CLS item exists for this surface; this is the first tracker for it.
