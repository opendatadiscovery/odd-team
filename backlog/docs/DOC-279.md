## Description

DOC-277 shipped a `description:` frontmatter line on `collectors-secrets-backend.md` that names **Vault** as a supported provider:

> `description: Configure a collector to load sensitive values (Platform token, database passwords, cloud credentials) from an external secrets backend — AWS SSM Parameter Store, Vault, or another supported provider — instead of plaintext YAML.`

The body of the page contradicts this on line 11:

> | Provider | `secrets_backend.provider` value |
> | -------- | -------------------------------- |
> | AWS Systems Manager Parameter Store | `AWSSystemsManagerParameterStore` |
>
> **Only one provider is available today**; additional providers can be plugged in via the `BaseSecretsBackend` abstract class in `odd-collector-sdk`.

`grep -rnE "Vault|hashicorp" docs/` confirms the term "Vault" appears **nowhere else** in the entire published doc tree. The description fabricates a Vault integration that does not ship.

This matters because GitBook renders `description:` as the `<meta name="description">` SEO tag, the card-tile subtitle on parent landings, and the hover tooltip on cross-links. An operator Googling "ODD Vault secrets backend" lands on a page that explicitly says only AWS SSM is supported — trust-eroding even before they read the body.

This is a Gate 9 (factual claim provenance) violation introduced by DOC-277's mechanical frontmatter sweep. The implementer's IR for DOC-277 said `Sources: none (frontmatter metadata; each description summarises the existing first paragraph of its page)` — but this particular description does not summarise the existing first paragraph; it introduces a new factual claim that the page contradicts.
