## Description

The live Catalog Overview page (and the parent Search page) describe `exclude_from_search` as a hide signal, and frame the Popular column as if it were a first-class surface with column-specific behaviour. Both framings are operator-visible-false against the platform code as verified at primary source.

**Caveat 1 — Nine list-shape consumers ignore `exclude_from_search` (F-003a; extends DOC-GAP-101).** The shared SQL helper `ReactiveDataEntityRepositoryImpl.cteDataEntitySelect:909-939` applies only `addSoftDeleteFilter` (line 916) and `DATA_ENTITY.HOLLOW.isFalse()` (line 918). It does **not** apply an `EXCLUDE_FROM_SEARCH` predicate. The helper is consumed by 9 distinct list-shape methods (`listPopular`, `listByOwner`, `listByTerm`, `getDEGExperimentRuns`, `getDimensions(id|oddrns|ids)`, `getDetails(id)`, `getQuerySuggestions`) — all of them are affected. The filter IS applied at the search-FTS path (`findByState` via `JooqFTSHelper.resultFacetStateConditions:149`) and at the count/statistics path (`getDataEntityDefaultConditions:974`) only. An operator who toggles `exclude_from_search=true` on a staging/internal entity expecting it hidden from `My Objects`, By-Term lists, DEG-experiment runs, the Popular strip, and direct entity-detail GETs discovers it leaks via every one of those surfaces. DOC-GAP-101 captures the Popular surface specifically; the nine-consumer extension is the actual platform behaviour.

**Caveat 2 — Popular column is the fourth column of `OwnerEntitiesList`, not a standalone surface (F-003b).** No dedicated `PopularStrip.tsx` exists. `OwnerEntitiesList.tsx:99-105` renders a single `<DataEntityList>` per column for all four columns: Popular / My Objects / Upstream / Downstream. The Popular column has NO column-specific behaviour: no per-column refetch, no per-column filter, no per-column sort, no per-column count, no per-column "view more". A contributor planning a per-column UX change (e.g. pagination to mitigate the popularity-feedback inflation loop documented in DOC-166 / F-001) discovers the symmetric-4-column constraint mid-PR.

Both caveats are operator-visible by the strongest definition: the published doc describes platform behaviour that the platform does not exhibit.
