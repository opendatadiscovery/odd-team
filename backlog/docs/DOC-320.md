## Description

The Layer-4b reflection over the Lineage traversal feature (F-005) surfaced five net-new operator-facing behaviours the live data-lineage docs do not name. These are correctness/UX surprises an operator hits while reading the lineage canvas — not security issues. Cluster them as operator caveats on the lineage doc page(s). Each is traced to code `@ ede5d277`.

The depth/cross-owner/cycle behaviours from F-005 are already tracked elsewhere (PLT-100, PLT-042, DOC-293, DOC-226) — this item covers only the five **net_new** caveats below.

## Acceptance Criteria

- [ ] **DEG (Group) lineage shows only inter-member edges** (F-005 H-005): document that opening Group lineage shows only edges where BOTH endpoints are members of the group — producers/consumers outside the group are silently dropped, so a busy group can look like an island disconnected from its real upstream/downstream. Evidence: `ReactiveLineageRepositoryImpl.java:112-119` (`PARENT_ODDRN.in(oddrns).AND(CHILD_ODDRN.in(oddrns))`); `LineageServiceImpl.java:71-75` also strips nested-DEG edges. Distinct from DOC-225 (empty-DEG 404 / param-absence / cross-owner) — this is the boundary-edge-drop behaviour.
- [ ] **Click-through overrides the chosen depth** (F-005 H-006): document that clicking a node title opens that node's view at the CLICKED NODE'S depth (`d = node.depth`), discarding the depth the user selected in the dropdown; repeated drilling compounds depth. Evidence: `Node.tsx:46-52`.
- [ ] **Diamond-reachable nodes render twice** (F-005 H-008): document that a node reachable via two paths (a diamond) is drawn twice (d3-hierarchy tree layout, no visited-set), obscuring convergence and amplifying render cost on large graphs. Evidence: `generateGraph.ts:68-76, 108-116` + `LineageGraph.tsx:84-110`.
- [ ] **No collapse affordance; long sessions grow client memory** (F-005 H-010): document that `Load N more` accumulates nodes monotonically with no collapse / eviction / max-size cap (reset only on root-entity navigation), so a long exploration session grows browser memory until the page is left. Evidence: `dataEntityLineage.slice.ts:30-48, 206-220, 285-299`. (Probe P-225 will quantify the memory ceiling; the no-collapse fact is static.)
- [ ] **Share-link limits** (F-005 H-011): document that the lineage view state (depth, expansions, zoom) lives in the URL and is shareable, but (a) very-heavily-explored views silently truncate past Chrome's ~2K URL limit (~200 expansions) and (b) a hand-corrupted `?t=` transform crashes the canvas (`JSON.parse` with no try/catch). Evidence: `interfaces.ts:75-85` + `ZoomableLineage.tsx:28-31` + `LineageGraph.md` security gap [4].
- [ ] `Sources:` footer cites each `file:line @ ede5d277` above and the F-005 reflection (`lineage/odd-platform/feature-reflections/detail/F-005.yaml` H-005/H-006/H-008/H-010/H-011).
