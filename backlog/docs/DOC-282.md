## Description

`active-platform-features.md` enumerates **six** opt-in active-platform subsystems in its description (newly authored under DOC-280) and in its Subsections list:

| # | Subsystem | Subsection link |
|---|---|---|
| 1 | Alerting | `active-platform-features/alerting.md` |
| 2 | Notifications | `active-platform-features/notifications.md` |
| 3 | Activity Feed | `active-platform-features/activity-feed.md` |
| 4 | Data Collaboration | `active-platform-features/data-collaboration.md` |
| 5 | GenAI assistant | `active-platform-features/genai.md` |
| 6 | Metrics Ingestion | `active-platform-features/metrics-ingestion.md` |

The description (L2), L9 ("ODD covers active platform features through **six** independently-configured subsystems"), and L34 ("every one of the **six** subsystems has a dedicated section under Configure ODD Platform") all carry the correct count.

But three narrative lines downstream still say **five**:

- **L32** (under "Why this is a separate pillar" → "opt-in per subsystem"): *"A deployment can run with all **five** off and still serve the catalog — none is required."*
- **L40** (Where to next bullet): *"For the operator-side configuration keys behind the **five** subsystems → see Configure ODD Platform."*
- **L41** (Where to next bullet): *"For the API surface behind the **five** subsystems → see API Reference."*

These three "five" lines were correct before Metrics Ingestion landed as the sixth subsystem (under DOC-196 commit `2614e64` 2026-05-27). When that page was added to the Subsections enumeration, the three downstream "five" lines were not updated alongside it. The DOC-280 description rewrite ("Six opt-in subsystems") makes the drift more pointed — the new authoritative-statement directly contradicts three body lines on the same page.

**Failure shape**: internal contradiction (count drift in narrative on a page whose subsection-list is the ground truth).
