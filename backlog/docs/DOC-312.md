## Description

The OAuth2/OIDC page's GitHub section was rewritten in the 2026-05-29 wave and now carries the GHES-unsupported and admin-principals-bypass caveats — but **not** the username-rename hazard. ODD identifies a GitHub user by the mutable `login` string (the default `user-name-attribute: login`), not the stable numeric GitHub `id`. The `(username, "github")` tuple is the compound key for `USER_OWNER_MAPPING`. When a user renames their GitHub login, they sign in as a **new identity** (`alice2, github`); the prior `(alice, github)` mapping row is orphaned — their **My Objects** goes empty and their ownership is stranded under the old name. There is no `id`-based fallback and no migration tool. (GitHub releases the old login after 90 days, so a third party could later claim it.)

**Failure shape**: missing operational caveat — a silent data-integrity gap an operator hits when a team member renames their GitHub account.
