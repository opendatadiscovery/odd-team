> **2026-06-07 correction (IT-112 live characterization).** The original draft below called this NPE
> "unreachable in production" at severity **low**, on the assumption that `S2sAuthenticationFilter` is
> "conditionally registered only when `auth.s2s.enabled=true`". **That assumption is false.**
> `S2sAuthenticationFilter` is annotated `@Component implements WebFilter` with **no** `@ConditionalOnProperty`
> (S2sAuthenticationFilter.java:17-19). In Spring WebFlux, any `WebFilter` bean is **auto-registered into the
> global filter chain regardless of which `SecurityWebFilterChain` is active** — so the filter runs on every
> request even under `auth.type=DISABLED`, where the security config never calls `addFilterAt(...)`.
> Verified live against the shipped `odd-minimal` default (`AUTH_TYPE=DISABLED`, `auth.s2s` unset): a request
> carrying **any** `X-API-Key` header returns **HTTP 500** on every endpoint (whoami and a plain reference
> endpoint that is 200 without the header). Any unauthenticated caller can turn any endpoint into a 500 by
> adding one header → a trivial **unauthenticated denial-of-service** on the default configuration. Severity
> raised to **high**; the "unreachable" framing is retracted. Regression pin: `integration-tests/protocols/IT-112-s2s-api-key-admin-grant.md` (asserts the current 500; goes RED when the null guard lands).

## What

`S2sTokenProvider.isValidToken(String token)` dereferences the internal `s2sToken` field without a null check. When `auth.s2s.enabled=false` / unset, the `@Value("${auth.s2s.token:#{null}}")` binding leaves `s2sToken` null, and `s2sToken.equals(token)` on line 20 throws `NullPointerException` for any non-blank `token`.

The sole caller, `S2sAuthenticationFilter`, is a global Spring WebFlux `WebFilter` (auto-registered for all auth modes — see the correction note above), so the NPE is reachable on the shipped `auth.type=DISABLED` default: a request with any `X-API-Key` header fails with HTTP 500.

## Where

`odd-platform-api/src/main/java/org/opendatadiscovery/oddplatform/auth/S2sTokenProvider.java:15-21`

```java
public boolean isValidToken(final String token) {
    if (StringUtils.isBlank(token)) {
        return false;
    }

    return s2sToken.equals(token);   // NPE when s2sToken is null
}
```

The `@Value` bindings (`s2sToken` defaults to `null`; `s2sEnabled` defaults to `false`) are declared on lines 10–13.

## Why it matters

- **Reachable on the shipped default (corrected).** On `auth.type=DISABLED` (the default) with `auth.s2s` unset, any request carrying an `X-API-Key` header returns HTTP 500 — verified live. This is an unauthenticated denial-of-service: a caller needs no credential and no knowledge of any token; one arbitrary header value crashes the request, on every endpoint.
- **The fix is a one-line change with zero behavioral risk** (for `auth.s2s.enabled=true`, behaviour is unchanged; for the unconfigured case, the filter correctly becomes a pass-through instead of crashing).
- Defensive null handling on a public method that handles authentication is a baseline expectation for a security-sensitive component.
- A deeper fix (out of scope for the one-liner) is to gate `S2sAuthenticationFilter`'s registration on `auth.s2s.enabled` so the filter does not run at all when S2S is off — eliminating the per-request overhead and the surface entirely under DISABLED.

## Suggested fix

Guard the null explicitly, or swap to a null-safe comparison:

```java
public boolean isValidToken(final String token) {
    if (StringUtils.isBlank(token) || StringUtils.isBlank(s2sToken)) {
        return false;
    }
    return s2sToken.equals(token);
}
```

Or, equivalently:

```java
public boolean isValidToken(final String token) {
    if (StringUtils.isBlank(token)) {
        return false;
    }
    return java.util.Objects.equals(s2sToken, token);
}
```

Either form preserves existing behavior for `auth.s2s.enabled=true` and returns `false` (instead of NPE) for the unreachable-today path.
