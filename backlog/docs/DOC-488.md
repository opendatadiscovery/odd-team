## Description

`data-quality/dashboard.md` documented the pre-0.29.0 behaviour: Table Health as **three** slices
(Healthy / Warning / Error, with *broken* folded into Error), and the Test Results Breakdown's `Running`
total as always **0** (in-flight runs not counted). CTRIB-037 / odd-platform#1794 changes both:

- **Table Health** is now a **four**-slice priority cascade — Error = any `Failed`; Warning = any `Broken`
  (no Failed); **Unknown** = any `Unknown` (no Failed/Broken); Healthy = none of those
  (`Success`/`Skipped`/`Aborted`/`Running`).
- The **Test Results Breakdown** now counts **in-flight RUNNING** runs.

The page edit landed on the **`release/0.29.0`** train (`documentation@aa5e21a`) — unreleased behaviour, so it
publishes at the 0.29.0 release gate, not on docs `main`.
