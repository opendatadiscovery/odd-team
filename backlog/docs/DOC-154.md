## Description

Editorial-audit finding from `/review DOC-150` (2026-05-07): DOC-149's reverse-link inventory under-counts the actual sites in the doc tree. DOC-149 enumerates **22 reverse-link instances across 5 files** (data-discovery.md + 4 detail pages); a `grep -rn 'Features\.md#' docs/` post-DOC-149-merge would still leave **16 additional reverse-link sites** un-cleaned across audience surfaces DOC-149 does not target.

The 16 missed sites span **seven distinct audience surfaces** that DOC-149's scope (Data Discovery + Data Lineage subtree) does not reach:

1. **A Management-bucket landing carrying the same `## Other {bucket} features` H2 pattern** that DOC-149 removes from data-discovery.md — `management.md` L31-37 has 3 reverse-link bullets (M2M tokens, Custom navigation links, Alternative Secrets Backend). This is the most prominent miss; without removing this H2 the cornerstone update DOC-150 will be visibly contradicted on the Management bucket landing.
2. **A Data Discovery sub-feature detail page** — `data-discovery/directory.md` L33 + L48 reverse-link to `Features.md#catalog-overview-page` (same shape as DOC-149's data-discovery.md L9 + L56 fixes).
3. **An Active Platform Features detail page** — `active-platform-features/alerting.md` L47 reverse-links to `Features.md#recommended-panel-on-the-main-page`.
4. **API-reference pages** — `developer-guides/api-reference/glossary.md` L22 + `developer-guides/api-reference/alerts.md` L53.
5. **Configuration-and-deployment pages** — `s2s.md` L3 + `collectors-secrets-backend.md` L3 + `odd-platform.md` L743 + L881.
6. **Use-case pages** — `viz-preparation.md` L10 + `dc-data-compliance.md` L8.
7. **The vocabulary surface** — `main-concepts.md` L94 + L104 alias-table "Where it's used" cells targeting `Features.md` anchors.

DOC-149's AC line 91 (`grep -rn 'Features\.md#' docs/` returns only entries on `Features.md` itself) WOULD catch these at completion-check time — but the implementer working DOC-149 might assume the listed inventory is exhaustive and treat the un-listed sites as out-of-scope. This item makes the additional inventory explicit so the gap is closed deliberately, not by accident.

## Context

- **Why this is high priority.** Without this cleanup, the cornerstone update DOC-150 + the partial cleanup DOC-149 leave the doc tree in an incoherent state: `data-discovery.md` is cleaned but `management.md` still carries the same offending H2 pattern; configuration pages and api-reference pages still reverse-link. An operator reading the doc product encounters a half-applied rule, which is worse than no rule.
- **Why this is parallel/follow-on to DOC-149, not blocking.** DOC-149's scope (5 files in Data Discovery + Data Lineage) was the user-flagged batch's defect surface. The additional 16 sites surfaced in `/review DOC-150`'s editorial audit by the post-cornerstone grep sweep. Bundling them into DOC-149 mid-flight would balloon DOC-149 beyond its original scope; carving them as a parallel item lets DOC-149 stay focused while DOC-154 gets its own pre-authoring stance check on the broader canonical-home decisions (especially the api-reference content migrations).
- **Several items couple to DOC-149's placement decisions.** `directory.md`, `main-concepts.md` aliases, `odd-platform.md` L881, and the use-case pages all reference content (Catalog Overview / Data Entity Attachments / metadata-storage) whose canonical home DOC-149 chooses. This item must follow DOC-149's choices, not pick its own.
- **Two items are content-migration not link-rewriting.** api-reference/glossary.md L22 and api-reference/alerts.md L53 are Cornerstone-5 finds — API-reference content embedded on Features.md should migrate to api-reference; the link rewrites are downstream of that migration. These belong in this item or a separate Cornerstone-5 cleanup item; the implementer decides.
- **Why the editorial audit caught this and DOC-149's authoring did not.** DOC-149 was authored from the user-flagged batch's evidence (PR #65 + PR #66 detail pages + `data-discovery.md`'s `## Other Data Discovery features` H2). The grep sweep across the entire `docs/` tree — DOC-149's AC line 91 final check — would have caught the additional sites at completion time, but the inventory was authored from the batch's known scope rather than from the grep. The `/review DOC-150` editorial audit ran the grep sweep proactively as part of verifying the cornerstone update's downstream coverage. The lesson: inventory the rule's complete blast radius at rule-codification time, not at cleanup-implementation time. (See LSN-012 for the parallel framework-rule-validation lesson.)
