## Description

Author the top-down backbone ADR for the **auth-mode architecture**: `auth.type` selects exactly one
of four mutually-exclusive `SecurityWebFilterChain` beans (DISABLED / LOGIN_FORM / OAUTH2 / LDAP) via
`@ConditionalOnProperty`; DISABLED is the shipped default; S2S composes additively on the real modes;
CSRF is disabled cross-mode. Absorbs the 0029-0036 candidate cluster as facets of this one decision.

## DISCLOSURE DECISION (ledger 🔒⚖ — surfaced for /review)

This is the most security-sensitive ADR in the backbone. The Gate A3 call I made:

- **ON the page (DECISION + protective warning):** the four-mode enum-by-construction architecture;
  that DISABLED is the default; and a LOUD operator warning that **DISABLED performs no authentication
  AND enforces none of the ADR-0002 permission rules — fully open — so it is local-eval-only and any
  networked/production deployment must set a real mode.** This is *protective-direction* disclosure:
  it warns operators, matches what the enable-security docs already say, and is standard security-docs
  practice. LOGIN_FORM-grants-ADMIN-to-every-credential is stated as a protective consequence (authn,
  not per-user authz) — verified `GrantedAuthorityExtractor.java:13-14`.
- **OFF the page (GAP → refactoring-scopes, Gate A1/A3):** the DISABLED-bypasses-SECURITY_RULES
  *weakness* framing (`REFACTOR-185`, 11-sidecar triangulated) and the S2S-grants-ADMIN-across-all-/**
  / LOGIN_FORM-missing-AuthorizationCustomizer gaps (`REFACTOR-108` / `REFACTOR-099`). The ADR records
  the *decision*; the REFACTORs record the *gaps*. No exploit recipe on the public manual.

**/review should confirm this disclosure boundary** (decision-vs-exploit) reads correctly on the live page.
