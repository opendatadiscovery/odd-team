## Review (2026-05-31, session: adr-review-notifications-A)

**Verdict: BLOCKED — Gate A2 FAIL (two wrong `file:line` citations). Status flipped `review-ready` → `blocked`.**

The decision is real and load-bearing — notifications DO ship `enabled: false` gated by one `@ConditionalOnNotifications` meta-annotation, verified in code. The page is descriptive, frontmatter parses, it is live with no jargon, and layout is correct. But Gate A2 ("Each cited `file:line` is opened and confirmed to still embody the claim... This is exactly the LSN-002 class (a claim that must trace to the exact locus). The page must be corrected and re-reviewed before it can flip to `done`.

### Gate A2 — FAIL (the blocker)

Re-verified every locus at substrate `ede5d277`:

1. **`application.yml:175` — WRONG (off by 2).** Cited (in both `realises:` frontmatter and page Evidence) for `enabled: false` under `notifications:`. Actual layout:
   - L172 `notifications:`
   - L173 `  enabled: false`  ← the actual shipped default
   - L174 `  message:`
   - L175 `    downstream-entities-depth: 1`  ← what `:175` actually points at (an unrelated key)
   The correct citation is **`application.yml:173`** (`notifications:` key at L172). VERIFIED via `grep -n "enabled: false"` (→ `173:  enabled: false`) + `awk` lines 172-176.

2. **`NotificationsFeatureCondition.java:18-22` — WRONG (past EOF).** Cited (both `realises:` and page Evidence) for the `getProperty(NOTIFICATIONS_ENABLED_PROPERTY, Boolean.class, false)` default-false read. The file is **15 lines long**; lines 18-22 do not exist. The actual default-false read is at **lines 11-13** (`return context.getEnvironment().getProperty(FeatureResolver.NOTIFICATIONS_ENABLED_PROPERTY, Boolean.class, false);`). The correct citation is **`NotificationsFeatureCondition.java:8-14`** (class) / **`:11-13`** (the read). VERIFIED via read (full file, 15 lines) + `wc -l` (15).

### Gate A2 — secondary inaccuracies (fold into the same fix)

3. **Three-consumer citations point one line high.** Page Evidence cites `NotificationSubscriberStarter.java:14` and `AlertNotificationMessageProcessor.java:14` for the `@ConditionalOnNotifications` application. Actual annotation lines: `NotificationConfiguration.java:27` ✓ (correct), `NotificationSubscriberStarter.java:` **17** (`:14` = `@Component`), `AlertNotificationMessageProcessor.java:` **15** (`:14` = `@Component`). These land on the class's annotation stack one-to-three lines above `@ConditionalOnNotifications`, so they are near-misses rather than wrong-construct, but should be corrected to the exact annotation line (`:17` and `:15`) in the same edit. VERIFIED via `grep -n "@ConditionalOnNotifications\|@Component\|@Configuration"`.

4. `ConditionalOnNotifications.java:9-14` — file is 13 lines; the `@interface` block with `@Conditional(NotificationsFeatureCondition.class)` (L11) spans L9-12. Citing `9-14` overshoots EOF by one line but covers the correct construct. Tighten to `:9-12` while fixing the above. VERIFIED via read + `wc -l` (13).

**Required to unblock:** correct citations 1 and 2 (mandatory — wrong locus), and fold in 3 and 4 (precision) in both the page Evidence section AND the `realises:` frontmatter, re-push, then re-review (live re-fetch not needed for line-number-only edits unless prose changes, but a re-render check is cheap).
