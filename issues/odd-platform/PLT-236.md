## Description

Carved out of the Term Detail hardening epic (#1754 / PLT-058, Defect 8). The three sibling reverse-lookup tabs
in the same parent run on **two different state-management stacks**:

- `TermLinkedEntitiesList/LinkedEntitiesList.tsx` → **redux thunks** (`fetchTermLinkedList`, `getTermLinkedList*`
  selectors).
- `TermLinkedColumnsList/LinkedColumnsList.tsx` → **tanstack-query** (`useGetTermLinkedColumns`).
- `TermLinkedTermsList/LinkedTermsList.tsx` → **tanstack-query** (`useGetTermLinkedTerms`, `useInfiniteQuery`).

State-shape and cache-invalidation drift across three components rendered side-by-side; the team is mid-migration
from redux to tanstack-query. Operator-invisible, but a maintenance defect — and the root of the drift that
surfaced as Defects 4/5/7 (resolved in CTRIB-028, each conforming to its own sibling pattern rather than a shared
one).

**This needs an ADR before code** (the chosen pattern is a backbone decision) → `adrs/drafts/ui-state-management.md`.
It is deferred from CTRIB-028 for that reason.

## Suggested direction (to be confirmed by the ADR)

Complete the migration to tanstack-query: port `LinkedEntitiesList` (and its `fetchTermLinkedList` thunk +
selectors) to a `useInfiniteQuery` hook mirroring `useGetTermLinkedTerms`. Document the chosen pattern + the
migration policy in the ADR so future list surfaces conform.

## Acceptance

- An accepted ADR (`adrs/drafts/ui-state-management.md` → published ADR-log) states the standard FE list-state
  pattern + the redux→tanstack migration policy.
- The three term reverse-lookup tabs use one consistent pattern (per the ADR), with no behaviour regression
  (search/pagination/empty/error parity).
