## Description

User feedback during `/review batch:feature/state-doc141-ia-refactor-2026-05-07` (2026-05-07): the cross-link approach used by recent batches violates the doc product's intended IA principle.

**The principle the user named:**

> *"Features/Overview is an index of all the features with brief description to grasp the entire functionality of the platform and it should have links to the detailed explanations of the features in the dedicated sections — not vice versa where we have references for index from some dedicated pages — this is crazy and stupid."*

**Restated as a binding rule:** `Features.md` is the **index**. Cross-link direction is one-way: **`Features.md` → detail pages**. Detail pages, bucket landings, and any other "below the index" surface MUST NOT link back to a `Features.md` anchor for canonical reference. The reverse direction inverts the index/detail relationship and signals that the doc product treats the index as a peer page when it is not.

This rule supersedes the "Other {bucket} features" sub-list pattern that was added to `pillars/documentation/cornerstones.md` Cornerstone 2 in commit `62a5011` (2026-05-07). DOC-150 captures the cornerstone update; this item captures the doc-side cleanup of the existing reverse-links.

## Context

- **Why this is critical.** The user spotted this on a `/review` and called the inverse direction "crazy and stupid" — strong language that flags an emotional/structural defect, not a stylistic preference. Holding this rule preserves the doc product's information architecture: Features.md as the discovery surface, bucket landings as the canonical-home pivot, detail pages as the authoritative reference. Letting the inversion stand teaches future authoring sessions that bucket landings can punt to Features.md, which is exactly the failure mode the new rule prevents.
- **Why DOC-150 (cornerstone update) blocks this.** Without the cornerstone change first, the implementer doing this fix has no documented authority to remove the "Other Data Discovery features" H2 — Cornerstone 2 today (per commit 62a5011) explicitly endorses that pattern. The cornerstone update has to ship first; this fix follows.
- **Why this blocks DOC-141/142/143/144/145.** All five of those items had Gate 7 (IA hierarchy sanity) flagged FAIL during `/review` because of the reverse-links they contain. They are blocked until this fix lands.
- **Why DOC-146 (Data Glossary) and DOC-147 (Data Quality) flipped to done.** Their pages — `data-glossary/business-glossary.md`, `data-quality/{test-results-import,dashboard,sla-statuses}.md` — contain no reverse-links to Features.md anchors. They cleared all gates including Gate 7.

## Implementation Notes

- Recommend bundling the doc-side fix as one commit on a single branch, paired with the state-side cornerstone update from DOC-150 in a coordinated batch.
- Pre-authoring stance check on each affected sub-section: confirm the right canonical home for each "feature currently inline on Features.md" before deciding the cross-link target. Local optimization ("just remove the link") is the failure mode here — the right move is the placement decision, then the cross-link follows.
- After this lands, the Features.md in-page TOC at L5-38 still mixes carved-out features (which point at dedicated pages) and inline-on-Features features (which point at Features.md anchors — index-internal navigation, which is correct). Don't touch those — they are on the index, not on a detail surface.
