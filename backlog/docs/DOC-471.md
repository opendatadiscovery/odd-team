## What

Two doc-completeness gaps surfaced by the `/review` of CTRIB-023. Both live on the documentation
`release/0.29.0` train (the same train DOC-470 retires the lookup-tables caveats on) and must be fixed
there BEFORE the 0.29.0 release-gate live verification — otherwise the published 0.29.0 pages are
internally inconsistent (finding 1) and incomplete (finding 2). Neither blocks the odd-platform code
PR #1792 (the code is correct + tested); both block DOC-470/DOC-471 reaching `done` at the release gate.

### Finding 1 — `lookup-tables.md` "Six behaviours" intro count is now stale (Gate 7, change-introduced)

`## Known operator caveats` opens with: *"**Six** behaviours of the Lookup Tables surface are non-obvious
from the UI alone. Each item below states what an operator might assume..."* — then lists the caveat
`{% hint %}` blocks.

- **Before** fb03ce3: 7 hint blocks = 6 gotcha-style (2 `danger` + 4 `warning`) + 1 `info`
  (Delete-removes-both-halves). The "**Six**" matched the 6 gotcha caveats.
- **After** fb03ce3 retired the list-truncation + rename-audit-silence `warning` blocks: 5 hint blocks =
  4 gotcha-style (2 `danger` + 2 `warning`) + 1 `info`. The intro **still says "Six"** — but only 4
  gotcha caveats remain. The caveat-retirement commit removed 2 counted items without decrementing the
  count.
- **Fix:** change "**Six**" → "**Four**" (the gotcha-caveat convention the original count used), on
  `release/0.29.0`. (If the author intends to count the `info` block too, "**Five**"; match whichever
  convention, but the rendered list and the prose number must agree.)

### Finding 2 — `activity-feed.md` "## Event types" enumeration omits the new `LOOKUP_TABLE_RENAMED` (Gate 6 / G-C10)

CTRIB-023 D2 adds `LOOKUP_TABLE_RENAMED` to the public `ActivityEventType` and renders it on the **global**
Activity feed (odd-team IT-137 UC-001 asserts the renamed table appears on `/activity`). `activity-feed.md`
carries a deliberately-exhaustive `## Event types` section — *"The Event type filter on the global Activity
page exposes the following event types, grouped here by the area of the metadata they describe"* — that
even documents dead enum values (`CUSTOM_METADATA_*`) and hidden internal types. After 0.29.0 ships, this
enumeration will be missing the new lookup-table rename event.

- **Fix:** add a `LOOKUP_TABLE_RENAMED` entry (e.g. a "Master Data / Reference Data" group, or alongside
  the existing groups) describing "a lookup table was renamed (old → new display name)", on
  `release/0.29.0`. Confirm whether the event is exposed in the global **Event type filter** dropdown (vs
  feed-render-only) and word the entry to match — the page distinguishes filter-exposed vs hidden types.
