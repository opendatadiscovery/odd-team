## Description

The `lookup-tables.md` "Direct database access" section documents `spring.custom-datasource.{url,username,password}` and explains that lookup tables live in a `lookup_tables_schema` schema. What it does NOT say is that the platform **rewrites** the custom-datasource URL to force that schema, and that the schema name is **hardcoded and non-configurable**.

`R2DBCConfiguration.getCustomSchemaDBUrl(...)` takes whatever URL the operator supplies (or falls back to the primary `spring.datasource.url`) and appends `?schema=lookup_tables_schema` via `UriComponentsBuilder.queryParam(SCHEMA_PART_FOR_CUSTOM_DB_URL, VALUE_PART_FOR_CUSTOM_DB_URL)` (`R2DBCConfiguration.java:116-117`), where those constants are `"schema"` and `"lookup_tables_schema"` (`R2DBCConfiguration.java:24-25`). There is no property that overrides the injected schema name.

This only bites in the **separate-database** case — i.e., when an operator sets `spring.custom-datasource.url` to a DB *other* than the primary one (e.g., to keep lookup-table rows off the primary instance, or to expose them to a BI tool's own database). In that case the operator must ensure the target database actually owns a schema named `lookup_tables_schema` (or arrange for the relevant tables to be reachable there); pointing at a separate DB and expecting the tables in `public`, or expecting the URL's own `?schema=` / search_path to be honoured, will fail because the platform overwrites it.

How it misleads: an operator following the documented "Direct database access" path to a separate DB has no signal that the connection is silently re-scoped to `lookup_tables_schema`, and will see "relation does not exist" / empty results without an obvious cause. DOC-038 surfaced this in its Gate 5 review note internally (`R2DBCConfiguration.java:112-120` forces the schema), but no operator-facing caveat was published. (Distinct from DOC-077, which covers the misleading "default value" framing of the `spring.custom-datasource.*` keys themselves — DOC-410 is about the injected schema, not the key defaults.)
