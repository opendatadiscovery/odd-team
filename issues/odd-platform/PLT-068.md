## What

The `Feature` set has two related defects: the SPA navigation chrome does NOT consume the feature-flag set (top-level tabs visible regardless of flag); the backend `FeatureResolverImpl` captures the @Value-injected booleans into a final Set ONCE in the constructor (runtime mutation via actuator/refresh is silently ignored).

**Defect 1 — Chrome-invariant (F-034a).** `App.tsx:49` dispatches `fetchActiveFeatures()` on SPA mount; the resulting `Feature` set is stored in Redux. `ToolbarTabs.tsx:34-82` builds the 9-tab navigation row in a `useMemo` with NO `useAppSelector(getActiveFeatures)` read, NO `WithFeature` wrapping. Sub-page affordances DO use `WithFeature` (`Message.tsx:59`, `MainThreadMessage.tsx:36`, `DataEntityDetailsHeader.tsx:132`). Disabling `datacollaboration.enabled=false` does NOT hide the Data Modelling tab; users click it and land on Query Examples surface where feature-gated affordances are wrapped but the tab is still visible.

**Defect 2 — Boot-immutable (F-034b).** `FeatureResolverImpl.java:14, 16-31` captures `@Value`-injected booleans into a `private final Set<Feature>` ONCE in the constructor. Endpoint name `getActiveFeatures` and the prose "active features" promise runtime-current view; reality is boot-snapshot.

## Why it matters

User-observable promise vs behaviour: doc implies platform-feature gating is consistent across the UI; reality is that the chrome layer is invariant. Operator toggling features in `application.yml` + actuator-refresh sees `/api/features/active` return the OLD boot-time set until process restart.

## Suggested fix

**Thread A — Thread feature-flag selector through ToolbarTabs:**

```tsx
// ToolbarTabs.tsx
const activeFeatures = useAppSelector(getActiveFeatures);

const tabs = useMemo(() => {
    return [
        { label: 'Catalog', path: '/' },
        // …
        activeFeatures.has('DATA_COLLABORATION') && { label: 'Data Modelling', path: '/data-modelling' },
        // …
    ].filter(Boolean);
}, [activeFeatures]);
```

`WithFeature` wrap is overkill for top-level tabs — the chrome already has access to the Redux store; an inline filter on the tab list is cleaner.

**Thread B — Refresh-aware FeatureResolverImpl:**

Option B1 — Spring `@RefreshScope`:

```java
@Component
@RefreshScope
public class FeatureResolverImpl {
    @Value("${datacollaboration.enabled:false}")
    private boolean dataCollaborationEnabled;
    // … on actuator/refresh, Spring re-instantiates the bean
}
```

Option B2 — re-read the @Value-bound properties on each call:

```java
public Set<Feature> getActiveFeatures() {
    Set<Feature> features = new HashSet<>();
    if (dataCollaborationEnabled) features.add(Feature.DATA_COLLABORATION);
    // …
    return features;
}
```

Recommended Option B1 — cleaner Spring-idiomatic semantics + the @RefreshScope contract is explicit.
