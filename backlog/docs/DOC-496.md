## Description

**Failure shape: parallel surfaces with drift (transitional).** Surfaced by the mandatory doc-product editorial
audit during `/review CTRIB-048` (ST-1a of the #1825 search overhaul).

After ST-1a ships in 1.0.0, the two search surfaces document **divergent share models**, and a reader comparing
them sees an unexplained inconsistency:

- `data-discovery/search.md` (release/1.0.0 @ `61cd0a8`) — the **Data Entity catalog** search is now a
  shareable, bookmarkable, **recipient-scoped, durable** `/search?q=<query>` link; the server-side session is
  an internal detail; the link "does not expire."
- `data-glossary/business-glossary.md:38` — the **Dictionary / term** search is still a **mutable, session-shared**
  `/termsearch/{uuid}` link ("sharing the URL gives them the same session view ... and lets them mutate the
  session by changing those filters").

**Neither page is wrong today.** ST-1a was correctly bounded (G-C5) to the DE catalog search; term search was
deliberately not touched. This is a *real product state* of the incremental search-overhaul rollout — but it is
an undocumented transitional divergence that an operator can reasonably trip over (why is catalog search
shareable-by-query but term search shareable-by-session?).

## Acceptance Criteria

- [ ] Decide the transitional framing for 1.0.0: either (a) add a one-line forward-note to the divergent surface
      (e.g. on `search.md` and/or `business-glossary.md:38`) acknowledging that the Dictionary search still uses
      the session-URL model and will move to the param-URL model as the search overhaul lands; or (b) accept the
      divergence silently for 1.0.0 and reconcile when the overhaul reaches term search.
- [ ] Track the lockstep dependency: when a later #1825 slice moves the term/Dictionary search to the param-URL
      model, `business-glossary.md:38` is rewritten in the same release (mirrors what ST-1a/DOC-495 did for `search.md`).
