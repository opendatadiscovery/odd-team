## Description

`entity-detail-page.md` (shipped in batch-11 via DOC-263) cross-links FROM its Overview-tab composition table to six per-aspect pages:

| Aspect page | Cross-linked from entity-detail-page.md? | Cross-links BACK to entity-detail-page.md? |
|---|---|---|
| statuses.md | yes | yes (already cross-linked through DOC-262) |
| tagging.md | yes | **no** |
| business-names.md | yes | **no** |
| groups-domains.md | yes | **no** |
| attachments.md | yes | **no** |
| metadata-stale.md | yes | yes (already cross-linked through DOC-264) |

Four pages (tagging, business-names, groups-domains, attachments) reference NO entity-detail-page.md in their `Where to next` sections.

This is a bidirectional cross-link defect introduced when DOC-263 shipped: the umbrella page references the aspect pages (Cornerstone-2 hierarchy: umbrella → detail), but the aspect pages do not reference the umbrella back. Operators landing on tagging.md from a search hit and wanting to understand "where do tags appear on the entity surface" see the Search facet, Top tags strip, and Activity Feed in the cross-links — but not the per-entity detail page's sidebar Tags panel as the actual rendering surface they will see when clicking a tag.

The fix is one-line-per-page, adding entity-detail-page.md to each aspect page's `Where to next`.
