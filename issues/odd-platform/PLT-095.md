## What

Three UX defects on the entity detail page's header authoring surface - DELETED-state silently hides every edit affordance with no banner explaining recovery; the status badge renders in non-interactive mode without a lock indicator for users missing the `DATA_ENTITY_STATUS_UPDATE` permission; the Share-to-Slack button is silently absent when the `datacollaboration` feature flag is off (the default).

**Defect 1 - DELETED-state silently hides edit affordances; no info banner (F-178a - MEDIUM).** Two `!isStatusDeleted` gates on the detail header (`DataEntityDetailsHeader.tsx:87, :123`) hide the business-name edit button (:87) and the Edit-group button (:123). Sibling Overview-tab gates hide the Tags Edit button (`OverviewTags.tsx:39`, and again in the empty-state branch at `:104`) and the Groups Add button (`OverviewGroups.tsx:33`, again at `:92`). Across the header + Overview composition the user loses every edit affordance on a DELETED entity; no info banner is rendered, so the user assumes a permission failure rather than an intentional read-only state. (Correction from the original draft: there is no third header gate "disabling the parent layout container" - `DataEntityDetailsHeader.tsx:47/:48` is the `isStatusDeleted` selector hook, not a gate. The two real header gates are `:87` and `:123`.)

**Defect 2 - Read-only status badge is visually identical to interactive; no lock signal (F-178c - LOW).** `DataEntityDetailsHeader.tsx:113-122`: `<WithPermissions permissionTo={Permission.DATA_ENTITY_STATUS_UPDATE} renderContent={({ isAllowedTo }) => <EntityStatus entityStatus={status} selectable={isAllowedTo} isPropagatable={isDEG}/>}/>`. Users without the permission see the badge in non-interactive mode - same chip, same colour, same text - clicks do nothing; no `cursor: not-allowed`, no lock icon, no tooltip.

**Defect 3 - Share-to-Slack silent when DataCollaboration disabled (F-178d - LOW).** `DataEntityDetailsHeader.tsx:132-144`: `<WithFeature featureName={Feature.DATA_COLLABORATION}>...Share button...</WithFeature>`. When `datacollaboration.enabled=false` (the default per F-038) the button is silently absent - no "Configure Slack to enable" hint pointing operators at the config knob.

## User-facing impact

Verified 2026-06-10 by reading every cited component.

- **Defect 1 (MEDIUM, load-bearing) HOLDS.** On a DELETED entity, all edit affordances disappear: business-name edit (`DataEntityDetailsHeader.tsx:87`), Edit-group (`:123`), Tags edit (`OverviewTags.tsx:39`/`:104`), Groups add (`OverviewGroups.tsx:33`/`:92`). No info banner or read-only explanation is rendered anywhere in the header or Overview - confirmed by reading the full header JSX (`:72-148`). A user without `DATA_ENTITY_STATUS_UPDATE` cannot even discover the restore path from the UI. This is the genuine hidden-procedure trap.
- **Defect 2 (LOW) HOLDS, refined.** `EntityStatus` renders `SelectableEntityStatus` when `selectable=true` and `DefaultEntityStatus` when `false` (`EntityStatus.tsx:20-24`). `DefaultEntityStatus.tsx` shows no lock icon and no permission tooltip; for a normal (non-time-sensitive) status it renders a bare chip with no tooltip at all (`:73-77`). Time-sensitive statuses (DRAFT/DEPRECATED/DELETED with a switch time) do get an AppTooltip, but it explains deletion timing, not the permission boundary. So a permission-lacking user gets no signal that the badge is non-interactive-by-permission. ("Visually identical to interactive" is slightly strong - the selectable variant differs - but the no-lock / no-permission-tooltip point is accurate.)
- **Defect 3 (LOW) HOLDS.** `DataEntityDetailsHeader.tsx:132-144` wraps the Share affordance (`CreateMessageForm`, button text `Share`, Slack icon - the draft's "ShareToSlackButton" is the same affordance under a different name) in `<WithFeature featureName={Feature.DATA_COLLABORATION}>`. `WithFeature` with children and no `renderContent` returns `null` when the feature is off (`WithFeature.tsx:31-33`), so the button is silently absent on a default deployment with no "configure Slack" hint.

## Why it matters

- **Defect 1 is a hidden-procedure trap.** The user lands on a DELETED entity, sees no edits, files a support ticket, learns "restore the entity first." Recovery requires `DATA_ENTITY_STATUS_UPDATE` permission - operators without it cannot even read the restore procedure from the UI.
- **Defect 2 is a discoverability trap.** Operators assume the badge is broken, the browser hung, or they need to refresh. The fix is one tooltip.
- **Defect 3 is a configuration-discoverability gap.** An operator deciding "I want to add Slack sharing" reads the [Data Collaboration documentation](../active-platform-features/data-collaboration.md), configures the bot, restarts the platform, then refreshes the entity page expecting the Share button. If they missed the `enabled: true` step, the button is still absent - and there is no UI signal pointing at the missing config knob.

Severity MEDIUM as a cluster (Defect 1 is the load-bearing); each individual defect is LOW.

## Suggested fix

### (a) Defect 1 - DELETED-state info banner

```tsx
// DataEntityDetailsHeader.tsx - render above the affordance row when status is DELETED:
{isStatusDeleted && (
  <Alert severity="info" sx={{ mb: 1 }}>
    {t('This entity is in DELETED state and is read-only.')}{' '}
    <WithPermissions permissionTo={Permission.DATA_ENTITY_STATUS_UPDATE} renderContent={({ isAllowedTo }) =>
      isAllowedTo
        ? <Link onClick={openRestoreDialog}>{t('Restore to make it editable')}</Link>
        : <span>{t('Ask an administrator with DATA_ENTITY_STATUS_UPDATE permission to restore it.')}</span>
    }/>
  </Alert>
)}
```

Operators see "this is intentional + here's recovery" instead of inferring from absence.

### (b) Defect 2 - Status badge lock indicator + tooltip

```tsx
// EntityStatus.tsx (the child component) - when selectable=false:
<AppTooltip title={t('You don\'t have permission to change status.') /* DATA_ENTITY_STATUS_UPDATE */}>
  <S.StatusBadge $disabled={!selectable}>
    {!selectable && <LockOutlinedIcon fontSize="small" sx={{ mr: 0.5 }}/>}
    {status}
  </S.StatusBadge>
</AppTooltip>
```

`cursor: not-allowed` on the disabled state via styled-components props. The lock icon makes the permission boundary visible without hover.

### (c) Defect 3 - "Feature disabled" placeholder

```tsx
// DataEntityDetailsHeader.tsx - replace silent WithFeature with a placeholder-or-button pattern:
<WithFeature
  featureName={Feature.DATA_COLLABORATION}
  fallback={
    isAdmin && (
      <AppTooltip title={t('Configure Slack via datacollaboration.enabled to enable sharing')}>
        <S.DisabledShareButton disabled>{t('Share to Slack (disabled)')}</S.DisabledShareButton>
      </AppTooltip>
    )
  }
>
  <ShareToSlackButton ... />
</WithFeature>
```

Operators with admin permissions see the disabled affordance + tooltip naming the config key; non-admins see nothing (no signal-to-noise loss for casual users).
