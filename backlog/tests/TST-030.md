## Description

Six small behavioural pins harvested 2026-06-08. Each guards an observable behaviour that is currently un-tested; several pin a known defect (characterization-pin, LSN-029) and one validates intended behaviour. Each is probe-gated by a `PENDING-F-*` skeleton — the probe arrange/act/observe/assert must be filled before the pin is asserted as a green tripwire.

1. **Re-submit guard (F-025).** `QueryExampleForm`'s submit button is `type='submit'` and is disabled ONLY on `!formState.isValid` (`QueryExampleForm.tsx:124`); it is NOT disabled while the create/update mutation is in flight (`isCreating`/`isUpdating` feed `isLoading` on the dialog at `QueryExampleForm.tsx:138`, not the button's `disabled`). A double-click before `onSubmit`'s promise resolves can fire the mutation twice. **Gate: characterization-pin** — assert the CURRENT behaviour (button stays enabled during the in-flight mutation); RED when a `disabled={isCreating || isUpdating}` guard is added.

2. **Markdown render (F-025).** The query field renders through the `Markdown` editor component (`QueryExampleForm.tsx:105`). **Gate: validates-feature** — assert the query value round-trips through the Markdown editor (`onChange` → `field.onChange`); pins the rendering path against regression.

3. **Stale-on-tab-switch (F-131).** `QueryExampleDetailsContainer` reads `tab` from `searchParams` and switches content on it (`QueryExampleDetailsContainer.tsx:26-31`, render at lines 74-93) while `queryExampleDetails` is fetched once via `useGetQueryExampleDetails`. **Gate: characterization-pin** — assert the CURRENT tab-switch render behaviour against the single fetched payload; RED if a refetch-on-tab is introduced.

4. **Scroll-loss-on-collapse (F-132).** `OverviewTags` renders the overflow tags inside `<Collapse ... unmountOnExit>` (`OverviewTags.tsx:68`) toggled by `viewAll` (`OverviewTags.tsx:24`, button at line 88). `unmountOnExit` drops the expanded DOM on collapse, losing scroll/render state. **Gate: characterization-pin** — assert the CURRENT behaviour (expanded tag nodes are unmounted when `viewAll` goes false); RED if `unmountOnExit` is removed / state is preserved.

5. **Stale-nodeSize lineage context (F-146).** `LineageProvider`'s `providerValue` memo (`LineageProvider.tsx:58-66`) omits `nodeSize` from its dependency array (`LineageProvider.tsx:67` = `[full, fn, renderedLinks, highLightedLinks]`), even though `nodeSize` is recomputed from `titleHeight`/`oddrnHeight` (`LineageProvider.tsx:53-56`). When `nodeSize` changes but `full`/`fn`/links do not, consumers receive a STALE `nodeSize`. **Gate: characterization-pin** — assert the CURRENT stale-context behaviour; RED when `nodeSize` is added to the memo deps (the fix).

6. **Layout-stale-on-data-change (F-208).** `DEGLineageLayouter` runs `layoutDEGLineage(...)` inside a `useLayoutEffect` with an EMPTY dependency array (`DEGLineageLayouter.tsx:39` opening, `:56` `}, []`), so the graph is laid out once on mount and does NOT re-layout when `nodes`/`edges` change. **Gate: characterization-pin** — assert the CURRENT mount-once behaviour; RED when the deps are widened to re-layout on data change. (Companion observation: `DataEntityStaleDetector.java:16` computes `is_stale` live from `stalePeriod` + `lastIngestedAt`; the F-208 "cache freezes is_stale" concern is that a UI/transport cache can pin a stale `is_stale` — capture in the probe if it surfaces, do not assert against the detector itself which recomputes correctly.)

For every characterization-pin: it asserts the CURRENT (incorrect) behaviour and goes RED when the bug is fixed (LSN-029) — never `@Disabled`. On RED, invert to pin the corrected behaviour and re-tag `@regresses`.
