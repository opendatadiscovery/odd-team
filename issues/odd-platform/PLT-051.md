## What

Three security/integrity defects on `POST /ingestion/metrics` that expose a default-config deployment to unauthenticated metric injection from any network-reachable caller. Doc-side mitigation ships as DOC-202; structural hardening is this PLT.

**Defect 1 - `/ingestion/metrics` is whitelisted under ALL auth modes.** `SecurityConstants.java:96` - `/ingestion/**` in WHITELIST_PATHS. `IngestionDataEntitiesFilter.java:28` - exact-match `/ingestion/entities` only. NO filter matches `/ingestion/metrics`. An operator hardening with all three auth knobs enabled STILL leaves the endpoint anonymously reachable.

**Defect 2 - Tenant isolation NONEXISTENT on default INTERNAL_POSTGRES.** `odd.tenant-id` is appended as a Prometheus label only - extractor-tier coupling on the PROMETHEUS path. Postgres tables `metric_series` / `metric_point` / `metric_entity` have NO `tenant_id` column. Two unrelated deployments writing to a shared Postgres conflate metrics namespaces; operator's `odd.tenant-id=teamA` setting silently does NOTHING.

**Defect 3 - No payload-side ODDRN existence validation.** `InternalIngestionMetricsServiceImpl.java:87` (`registerMetricEntityOddrns`) creates `metric_entity` rows BY ODDRN regardless of whether a `data_entity` row exists. No FK from `metric_entity.entity_oddrn` to `data_entity.oddrn`. Combined with Defect 1, any caller mints arbitrary `metric_entity` rows / Prometheus series for non-existent ODDRNs (cardinality blast on `metric_label_value`).

## Why it matters

Three operator profiles affected: (1) security-conscious operators enabling all three auth knobs believe their `/ingestion/*` is gated, but `/ingestion/metrics` is not; (2) multi-tenant operators reading "set `odd.tenant-id=teamA`" reasonably assume isolation but get silent cross-tenant conflation (LSN-001/LSN-002 sibling); (3) phantom `metric_entity` rows from typo'd ODDRNs linger forever (no GC; cardinality blast).

Severity HIGH: Defect 1 enables anonymous-write on default config; Defect 2 is a multi-tenant data-leak invited via the `tenant-id` config; Defect 3 is data-integrity hygiene.

## Suggested fix

**Defect 1 - close auth gap (Option A):**
```java
// IngestionDataEntitiesFilter.java
- private static final String INGESTION_PATH = "/ingestion/entities";
+ private static final String INGESTION_PATH_PREFIX = "/ingestion/";
// widen matcher; closes alertmanager + metrics + stats gap.
```

**Defect 2 - tenant_id on Postgres metric tables:**
```sql
ALTER TABLE metric_entity ADD COLUMN tenant_id TEXT;
ALTER TABLE metric_series ADD COLUMN tenant_id TEXT;
ALTER TABLE metric_point ADD COLUMN tenant_id TEXT;
-- propagate from extractor; filter all reads WHERE tenant_id = currentTenantId()
```

**Defect 3 - payload-side existence check:**
```java
final var existingOddrns = dataEntityRepository.existsByOddrns(request.metricRelatedOddrns());
final var validSubset = request.metricRelatedOddrns().stream()
    .filter(existingOddrns::contains)
    .toList();

```
