## Description

`entity-detail-page.md` introduces the **Sidebar list truncation (Tags / Terms / Groups)** section and covers two of the three panels with admonitions:

- **Tags ordering is not importance-stable across the truncation cap** — covers `OverviewTags.tsx:54-56` (`.slice(0, 20).sort(tagsCompare)` — sort defeated by slice).
- **The Groups panel's visible-window ordering is undefined** — covers `OverviewGroups.tsx:49-51` (bare `.sort()` with no comparator yields no-op via `toString` stringification).

The **Terms** panel has the **same** bare `.sort()` no-comparator defect (`OverviewTerms.tsx:48-50`, verified 2026-05-27):

```tsx
{terms
  .slice(0, visibleLimit)
  .sort()
  .map(linkedTerm => (...))}
```

`LinkedTerm[]` is `{ term: { id, ... }, ... }[]` — same stringification pattern as `DataEntityRef[]`. The default `.sort()` on `LinkedTerm[]` is a no-op. The visible 20 are in collector-insertion order with no documented contract.

The page section title names **all three** panels (Tags / Terms / Groups) but the admonition silently leaves Terms uncovered. An operator reading the section concludes Terms ordering is fine, when it has the same defect as Groups.
