# Dataset schema diff — doc understanding

This page is the operator-facing surface for the dataset Structure tab and the per-revision schema diff, plus a developer reference for the three dataset-version read endpoints behind it. It documents: the Structure tab (Fields / Data types / Statistics), the revision-history browser (a new `dataset_version` row is created on each structure-changing re-ingest, compared by `(field_oddrn, type)` — invariant:dataset-field-versioning-by-reference-no-soft-delete-orphan-accumulation), the side-by-side compare viewer (feature **F-191**, `DatasetStructureCompare` at `/dataentities/{id}/structure/compare`), the backend revision-history + diff endpoint family (feature **F-045**, `GET /api/datasets/{id}/structure[/{version_id}|/diff]`), the Backwards-incompatible schema-change `Alert` raised on a removal or type-change, and the Activity-feed surfacing of schema changes (`Activity Feed`). Audience is operator (the diff/revision surface, the caveats) + developer (the endpoint-level "Known limitations" hints). The diff endpoint itself maps to operation:get-data-set-structure-diff and the by-version read to operation:get-data-set-structure-by-version-id.

This page is exceptionally code-accurate: all three "Known limitations and operator caveats" hint blocks are confirmed against the substrate with `file:line` evidence (see the ALIGNED `doc_claim_vs_code` entries). The danger hint (cross-dataset `version_id` leak — `data_entity_id` is a documentation-only path component, SQL filters on `dataset_version.id` only) maps to the HIGH-severity invariant:datasetcontroller-per-entity-scoping-bypass-data-entity-id-not-enforced-at-sql-batch-w; the warning hint (diff 500-on-missing-version-id vs 400-on-identical) maps to the bare `RuntimeException` at DatasetVersionServiceImpl.java:69-71 vs the typed guard at L59-61; the info hint (latest = max(`version`), not max(`created_at`)) maps to F-045 and the correctly-scoped `getLatestDatasetVersion` subquery (the one structure endpoint that DOES enforce `data_entity_id`). One LOW-severity page omission remains: a parent-struct rename cascades to every child field as DELETED+CREATED in the diff (getParentOddrnChangedPojos, DatasetVersionServiceImpl.java:156-180) — operation:get-data-set-structure-diff explicitly flags this as undocumented at this page; logged above as a missing-caveat DOC-GAP candidate.

No CodeNode was bound directly: the underlying Java nodes (DatasetController, DatasetVersionServiceImpl, ReactiveDatasetVersionRepositoryImpl, the DatasetStructureCompare TS family) did not surface via graph-search CodeNode for the page's terms, and Rule 2 forbids writing an unconfirmed `node_id`. The verbatim `file:line` evidence for every claim above lives inside the bound operation/invariant/feature concept nodes, which is sufficient for the diff findings and for doc-gap triage.
