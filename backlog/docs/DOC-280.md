## Description

A mechanical survey of every `description:` frontmatter value in `docs/**/*.md` surfaced **25 pages over 200 chars** (24 in this item + 1 fixed under DOC-279 fixup commit `b0ddfee`). GitBook silently truncates the live render at exactly 200 chars in **four** independent surfaces:

| # | HTML location | Operator-visible? |
|---|---|---|
| 1 | `<meta name="description" content="..."/>` (head) | Indirect — Google search snippets, link previews |
| 2 | `<meta property="og:description" content="..."/>` (head) | Indirect — Facebook / LinkedIn / Slack unfurls |
| 3 | `<meta name="twitter:description" content="..."/>` (head) | Indirect — Twitter / X cards |
| 4 | `<p>...</p></header>` (BODY — subtitle directly under H1) | **DIRECT — every operator opening the page in any browser sees this mid-word cut as the page subtitle** |

Surface #4 is the load-bearing one — operators see truncated text on the rendered page subtitle on every page view, not only in third-party SEO contexts. The 24 pages in this item ship truncated subtitles to every visitor.

**Canonical incident**: 2026-05-28 user spot-check after `/implement DOC-279` shipped a 253-char description that was still truncating ("with a pluggable interface for" cut mid-clause). The user asked "Why we do not check it during the review process?" — answered in `retrospectives/LSN-027-meta-description-truncation-not-caught-by-webfetch.md`.

## Implementation Notes

This is a 24-page batch. Each rewrite is independent. Recommend implementing as a single batch on one branch (`feature/docs-description-truncation-fix`) — mechanical class of change, consistent shape per page (read body → compose ≤200-char lede preserving operator framing). Per-page effort is small; batch effort is medium.

The Pre-authoring stance check per page should ask: **what is the most load-bearing operator concept on this page?** — that's what survives the cut. Drop the secondary clauses. Avoid trailing "instead of X" or "for Y" payoffs that consume the budget on a verbose framing the reader can absorb from the body's first paragraph.

Sample rewrites (illustrative, not authoritative):
- `multilingual-ui.md` (285 → target 180): drop the third-clause example; keep "what" + "where it appears" + "operator implication".
- `management/namespaces.md` (282 → target 180): name the concept + the operator action; drop the rationale clause.
- `alerting.md` (275 → target 180): name the trigger surface + the dispatcher surface; drop the per-channel enumeration (that's body content).

Validation per-page: after writing, run `head -3 file.md | grep '^description:' | sed 's/^description: //' | wc -c` — must be ≤200. Pre-merge live-site check via `curl -sL` per the four-surface verification command in `playbooks/live-site-verification.md` step 3.
