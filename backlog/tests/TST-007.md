## Description

The OAuth logout flow (F-086) has a per-provider asymmetry that is operator-observable and security-relevant (sign-out on shared/public workstations): Google + GitHub actively revoke the IdP-issued token; Azure + Cognito + ODD_IAM invalidate only the local session. The routing is `OAuthLogoutSuccessHandler.onLogoutSuccess` (`OAuthLogoutSuccessHandler.java:30-48`), a matrix with no guard:

- `if (authentication instanceof OAuth2AuthenticationToken)` → resolve `providerId` → `getLogoutHandler(provider)` streams the 5 `LogoutSuccessHandler` beans and `.filter(h -> h.shouldHandle(provider)).findFirst()` (lines 44-48) → `.map(handler.handle(...))` **or** `.orElseGet(defaultOidcLogoutHandler::onLogoutSuccess)` (line 38 — fall-through #1, the Okta/Keycloak/non-enum'd path);
- `else` → `defaultOidcLogoutHandler.onLogoutSuccess(...)` (lines 39-41 — fall-through #2, the non-OAuth2-token path).

The `defaultOidcLogoutHandler` bean is `OidcClientInitiatedServerLogoutSuccessHandler` (`OAuthSecurityConfiguration.java:180-183`). The behaviour to guard: **each provider resolves to its own handler (and exactly that handler performs / omits revocation), and an un-enum'd provider falls through to the default OIDC handler** — so any handler can silently regress (a provider re-routed, a `shouldHandle` predicate broadened, revocation dropped) with the build green.

Confirmed by read on 2026-06-08: `find odd-platform-api/src/test -iname '*Logout*'` returns **zero** matches — six production classes (5 provider handlers + the `OAuthLogoutSuccessHandler` dispatcher; `LogoutSuccessHandler` base + `OAuthLogoutSuccessHandler`), zero tests. F-086's `test_matrix.unit` is `GAP` and all 11 promises are `coverage: unverified` (use_case_coverage 0/11 — the textbook LSN-030 hole: even the one CONFIRMED promise, Google/GitHub revoke, has no regression guard).

TYPED GATE: mixed, declared per test:
- **validates-feature** for the dispatch matrix + the actively-revoking handlers — assert Google POSTs `oauth2.googleapis.com/revoke` (`GoogleLogoutSuccessHandler.java:43-54`), GitHub issues `DELETE /applications/{client_id}/grant` (`GithubLogoutSuccessHandler.java:51-63`), each provider selects its own handler, and an un-enum'd provider falls through to `defaultOidcLogoutHandler`.
- **characterization-pin** (LSN-029) for the contradicted-but-shipped behaviours — assert Cognito does NOT call `/oauth2/revoke` (`CognitoLogoutSuccessHandler.java:33-50`) and Azure issues no revocation call (`AzureLogoutSuccessHandler.java:31-48`). These pins assert the CURRENT (session-only) behaviour and go RED if revocation is later added (tracked PLT-073 for Cognito) — at which point they flip per LSN-029. Not `@Disabled`.

## Acceptance Criteria

- [ ] A `OAuthLogoutSuccessHandlerTest` (Mockito) drives the dispatcher with a stubbed `List<LogoutSuccessHandler>` + a mock `defaultOidcLogoutHandler` and asserts: (a) an `OAuth2AuthenticationToken` for each provider routes to the handler whose `shouldHandle(provider)` returns true (verify `handle` is invoked on exactly that handler, never another); (b) an un-enum'd provider (no `shouldHandle` match) falls through to `defaultOidcLogoutHandler.onLogoutSuccess` (fall-through #1); (c) a non-`OAuth2AuthenticationToken` Authentication falls through to `defaultOidcLogoutHandler` (fall-through #2).
- [ ] A `ProviderLogoutSuccessHandlerTest` with **WireMock** stubbing the outbound revocation endpoints asserts: Google `handle(...)` POSTs to the `/revoke` endpoint; GitHub `handle(...)` issues `DELETE /applications/{client_id}/grant`; both with the expected token/credential in the request (use StepVerifier on the returned `Mono<Void>` and verify the WireMock request was received).
- [ ] Characterization assertions (clearly annotated as pins of CURRENT behaviour, RED-on-fix per LSN-029): Cognito `handle(...)` issues a 302 to the Cognito `/logout` end-session URL and invalidates the session but makes **no** outbound `/oauth2/revoke` call (assert WireMock saw zero revoke requests); Azure `handle(...)` issues the end-session redirect + session invalidation with **no** outbound revocation call.
- [ ] Each characterization test carries an in-source note: why it exists, that it pins an open gap on purpose, the F-086 reference, the tracked PLT (PLT-073 for Cognito), and the LSN-029 flip protocol (on RED → revocation added → invert to assert the revoke call + retag as a regression guard).
- [ ] The suite is GREEN as a tripwire, runs in CI (via the local `scripts/run-platform-tests.sh` gate which mirrors CI's `build` incl. checkstyle), and is not `@Disabled`.
