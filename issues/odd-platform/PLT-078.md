## What

`SecurityConstants.java:95-96` `WHITELIST_PATHS` contains `/actuator/**` - reachable BEFORE auth in EVERY mode, not just DISABLED. `application.yml:226-242` enables `management.endpoint.env.enabled=true` + `show-values=WHEN_AUTHORIZED` + a wide `management.endpoints.web.exposure.include` set.

An attacker scraping `/actuator/env` under any deployment learns the SCHEMA of configured credentials: which OAuth2 providers are wired (Google/Azure/Cognito key prefixes), whether LDAP is configured, whether REMOTE attachment storage is set up, the JDBC URL `host:port:dbname`. Network-level mitigation (firewall / separate management port) is required; platform default does NOT provide it.

Combined with the shipped-default `spring.datasource.password=odd-platform-password` (PLT-080), an operator who forgets to override deploys a one-line-away-from-full-compromise system.

## Why it matters

LSN-001 family: silent insecure default; doc-only warning absent; no programmatic guardrail. Cross-cuts every auth mode (the bypass is upstream of the SecurityWebFilterChain). Deployments that take the platform's shipped default trust the `/actuator/**` reachability - a passive scan over a network range with port 8080 open returns full credential-schema fingerprints.

## Suggested fix

**Thread A - Tighten default exposure.**

```yaml
# application.yml
management:
  endpoints:
    web:
      exposure:
        include: health, prometheus    # was: env, info, health, prometheus, ...
  endpoint:
    env:
      enabled: false                   # require explicit opt-in
```

Operators opting in for `env, info` get them explicitly. Production-shaped defaults out-of-the-box.

**Thread B - Document `management.server.port` separation.**

The cleanest fix is BOTH platform-side default tightening AND operator-side `management.server.port` separation (run actuator on a separate port routed to an internal network). Doc-side guidance from DOC-242 already covers this; PLT-078's responsibility is the platform default.

**Thread C - Remove `/actuator/**` from WHITELIST_PATHS (stretch).**

Move `/actuator/health` and `/actuator/prometheus` to a narrower whitelist (only the two endpoints, not the wildcard). Keep `/actuator/env`, `/actuator/info`, etc. gated by the same auth chain as the rest of the platform. Useful for deployments that can't easily route to a separate port.

Recommended Thread A + B together - Thread A is the immediate operator-load-bearing default fix; Thread B is the doc-side guidance already shipping. Thread C is a follow-up.
