## What

`/actuator/env` is exposed and enabled by default and, under the default quick-launch auth posture, is reachable without authentication. Spring's default value mask hides keys named `password`, but it does NOT mask the JDBC URL or arbitrary URL-valued keys — so `spring.datasource.url` (DB host / port / database name), the LDAP bind password (bound as a plain `String` under `auth.ldap.password`, not a key Spring masks), and the Slack / generic-webhook URLs are returned verbatim over the HTTP port.

This is shipped via three defaults that compound:
- `management.endpoints.web.exposure.include: health,prometheus,env,info` (env exposed),
- `management.endpoint.env.enabled: true` (env enabled),
- under `auth.type=DISABLED` (the shipped default), `DisabledAuthSecurityConfiguration` is `.anyExchange().permitAll()` — so the actuator surface is anonymous.

Sources: HARVEST-012, HARVEST-016, HARVEST-022 (doc-understanding harvest, 2026-05-29). Doc caveat tracked at `backlog/docs/DOC-292.md`.

## Why it matters

The deployment docs warn operators about HTTP-vs-HTTPS transport but stop at the transport layer. They do not warn that the platform's own credential surface is anonymously reachable in the same default posture. An operator who stands up the quick-launch / demo stack on a public LoadBalancer (mitigated only by source-ranges) exposes the DB endpoint location, the LDAP bind password, and the Slack/webhook URLs to anyone who can reach the HTTP port — without authenticating. That is a direct path from "follow the quick-launch guide" to "leak production infrastructure coordinates", the LSN-001/002 class (a default with consequence that the guidance does not flag). The LDAP bind password is especially severe — it is a real secret returned in cleartext.

## Suggested fix

- Restrict the default `management.endpoints.web.exposure.include` to `health,prometheus` (drop `env` and `info`) so the credential-bearing endpoint is opt-in, not default.
- If `env` must stay available for operability, gate the actuator path so it is never anonymous even under `auth.type=DISABLED` (a dedicated actuator security chain rather than `permitAll()`), and add the LDAP bind password + datasource URL to the sanitised-keys set so they are masked when `env` is reachable.
- Document the residual exposure on the demo/quick-launch deployment options next to the existing HTTP-only caveat.
