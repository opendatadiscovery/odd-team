## Description

The Layer-4b reflection over the Batch Ingestion / S2S surface (F-008) surfaced three net-new operator-facing caveats about how `POST /ingestion/datasources` behaves for custom-collector authors. The destruction-replace, default-off-auth, plaintext-token, cluster-fragility, and audit-silence findings are already covered (DOC-004, DOC-195, PLT-085, PLT-074, PLT-062); the silent name/description overwrite is filed as PLT-135. This item covers only the three **net_new** doc caveats below.

## Acceptance Criteria

- [ ] **S2S datasource update is name + description only** (F-008 H-003): document that re-`POST`ing an existing datasource via `POST /ingestion/datasources` updates ONLY `name` and `description` — `connection_url`, `type`, `active`, `namespace_id` are preserved from the existing row and silently NOT updated (the response is 200 with no signal of the no-op). A collector whose source hostname changed cannot fix `connection_url` via the documented re-registration flow; only the UI admin endpoint (`PUT /api/datasources`) can. Evidence: `DataSourceIngestionServiceImpl.java:74-92, 86-88` + `DataSourceIngestionMapperImpl.java:9-19`.
- [ ] **Datasource namespace is inherited from the Collector, payload `namespace_name` is ignored** (F-008 H-005): document the collector-scoped-tenancy invariant — `POST /ingestion/datasources` stamps `namespace_id` from the matched Collector's pre-configured namespace and silently drops any `namespace_name` in the payload (a Collector with no configured namespace produces datasources with `namespace_id=null`). This is a sound security property (a stolen Collector A token cannot register into Collector B's namespace) but is operator-invisible, and the UI admin path behaves oppositely (honours `namespace_name`). Evidence: `DataSourceIngestionServiceImpl.java:106`.
- [ ] **Concurrent same-ODDRN registration can 5xx the losing collector** (F-008 H-014): document that two concurrent registration ticks for the same datasource ODDRN (a collector restart in a rolling-deploy / HPA-scale event) can violate the partial unique index mid-transaction and roll back the WHOLE batch with a 5xx — so none of that collector's datasources register on the losing instance until the next restart. Recommend collectors not run two concurrent registration ticks. Evidence: `DataSourceIngestionServiceImpl.java:47, 57, 66` + `V0_0_31:29` (`getDtosByOddrns` has no `forUpdate`). (Probe P-240 will confirm the race width; document the current behaviour now.)
