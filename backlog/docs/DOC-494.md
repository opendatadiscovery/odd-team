# DOC-494 — document the Recently Viewed feature (#1816 / CTRIB-041 S2)

CTRIB-041 ships **Recently Viewed** (#1816): opening any viewable asset records it in the user's recency
history; the user finds it again on the Catalog-Overview home panel, sees a "last viewed" marker + a
remove control on the asset's detail header and on Search result rows, and can remove any entry. Per-user
identity; under `auth.type=DISABLED` a shared instance-wide history labelled "(shared)".

**Routing (G-C11):** unreleased behaviour (1.0.0). **✅ AUTHORED on the `release/1.0.0` documentation train
@ `aa7b651`** (2026-06-29) — the train already existed (DOC-492/493). It publishes when the train merges to
documentation `main` at the 1.0.0 release gate; the live manual is unchanged until 1.0.0 ships.

## What was authored (on release/1.0.0 @ aa7b651)

- **`data-discovery/recently-viewed.md` (NEW)** — the feature page: record-on-open (a deliberate signal,
  distinct from the entity view count), the home-page panel, the cross-surface "last viewed" marker + remove
  on detail headers and Search rows, per-user identity, the `auth.type=DISABLED` shared-bucket caveat, and
  the explicit recency-vs-Popular (view-count) distinction. The retention/trim is described; the standalone
  tab is intentionally not documented (superseded by the Search recency filter, #1825).
- **`data-discovery/catalog-overview.md`** — a `### Recently Viewed` section after `### Favorites` and before
  `### Recommended` (the render order), with the recency-vs-Popular distinction.
- **`SUMMARY.md`** — the Recently Viewed page under Data Discovery, after Favorites.

## Follow-up when the Search recency filter ships (#1825)

The standalone Recently-Viewed tab is superseded by the unified Search recency date-filter (#1825). When
that ships, add the filter to the Search docs (not here) and, if useful, cross-link it from this page's
"Where Recently Viewed appears" — an additive extension, no rewrite.
