## Description

On a term's detail page, the Query Examples sub-tab exposes a single create-path affordance whose labels disagree across the two surfaces the operator sees in sequence:

- The button (the CTA the operator clicks) is labelled **"Link query"** with a link icon — `TermQueryExamples.tsx:39` (`text={t('Link query')}`, `startIcon={<LinkIcon />}`).
- The dialog that opens is titled **"Add query example"** — `AssignTermQueryExampleForm.tsx:45` (`{t('Add query example')}`) — and its submit button is also labelled **"Add query example"** — `AssignTermQueryExampleForm.tsx:65`.

The action is purely a *link* of an **existing** snippet to the term: the form body says "Select a query example from the list" (`AssignTermQueryExampleForm.tsx:52`), the field is a `QueryExamplesAutocomplete` over already-created snippets, and submit calls `useAssignTermQueryExample` with a `queryExampleId` (`AssignTermQueryExampleForm.tsx:32-41`). There is no authoring/definition input. The "Add query example" wording in the dialog title and submit therefore misreads as "create a new query example here", when the only thing it can do is attach one that already exists. An operator who has no snippets yet may open this dialog expecting to author one, find only a picker, and conclude the feature is broken.

This is a copy-alignment caveat, not a behaviour change. The canonical home is the Query Examples page's term-attach flow.
