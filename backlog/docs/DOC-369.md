## Description

The 2026-06-08 harvest flagged the language-persistence behaviour (localStorage `i18nextLng`, resets to English on a new device). **Most of that surface is already documented** — `multilingual-ui.md` already carries a full "Persistence model — per-device, not per-user-account" section covering per-browser storage, survival across logout, no server-side propagation, and no `Accept-Language` honouring. The harvest's referenced `DOC-278` (missing "Multilingual UI" page) and `DOC-171` are therefore largely closed by the existing page.

The **residual, still-missing angle** is narrow and specific: the page documents that the server does not honour `Accept-Language` (a server-side header), but it does **not** state that the SPA itself never consults the browser's own language setting (`navigator.language`) on a first visit. The bootstrap reads `localStorage.getItem('i18nextLng') || 'en'` and falls straight through to the hardcoded `'en'` default — `navigator.language` is never read (`locales/i18n.ts:22`, `defaultLanguage = 'en'` at line 20). So a brand-new browser whose OS/browser locale is, say, Spanish still lands on English, not because of a server header but because the client does no auto-detection at all.

An operator reading the current page could reasonably assume "no Accept-Language" is the only auto-detection gap and that the SPA at least respects the browser's configured language on first load. It does not. This is worth one explicit bullet so the no-auto-detection behaviour is unambiguous.

## Acceptance Criteria
- [ ] The "Persistence model" (or "How users switch") section of `multilingual-ui.md` states that the **first visit always lands on English regardless of the browser's configured language** — the SPA does not read `navigator.language` (or any browser-locale signal) to auto-select a locale; the default is the hardcoded `en`, and the locale only changes once the user picks one explicitly.
- [ ] The wording distinguishes this client-side no-auto-detect behaviour from the already-documented server-side "no `Accept-Language`" point, so the two are not conflated.
- [ ] A re-sweep of all multilingual surfaces returns zero residue: `multilingual-ui.md` is the canonical home; `main-concepts.md`, `Features.md`, and `SUMMARY.md` only alias/link to it and need no first-visit caveat. Confirm none of them asserts browser-locale auto-detection.
- [ ] Live-site verified post-merge: WebFetch `https://docs.opendatadiscovery.org/multilingual-ui` and confirm the first-visit no-auto-detection statement renders.
