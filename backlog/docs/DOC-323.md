## Description

Four net-new operator-facing caveats across the Data Discovery surfaces (Catalog overview, Search facets, Dictionary/Term search, Tag directory), each surfaced by the Layer-4b reflections and each `dedup_status: net_new`. Grouped because they are the discovery-reader's experience. None is a security exposure beyond the already-documented read-collaborative posture.

## Acceptance Criteria

- [ ] **Popular strip shows newest, not most-viewed, on a fresh deployment** (F-001 H-010): document that with `view_count=0` everywhere (a brand-new install) the Popular ranking degenerates to the `id DESC` tiebreaker and silently shows the NEWEST-ingested entities under "Popular" — a misleading first impression with no empty-state. Evidence: `ReactiveDataEntityRepositoryImpl.java:945-967` + `V0_0_10__add_counters.sql` (no `view_count` index/default beyond 0). Home: catalog-overview page (or fold into the existing catalog-overview caveat set).
- [ ] **Per-facet `query` is substring-match, not full-text** (F-017 H-004): add a 7th caveat to the (already-shipped, DOC-260) search page — the per-facet drill-down `query` param does `containsIgnoreCase` substring matching over facet-option labels, NOT the `to_tsquery` full-text matching of the main Search box; typing FTS syntax (a prefix like `cust*` or a quoted phrase) into a facet filter returns "no options." Evidence: `ReactiveSearchFacetRepositoryImpl.java:124, 152, 360, 394, 439` (substring) vs `:182, 267, 469, 582` (the FTS session query).
- [ ] **Dictionary facet-then-Enter race + identical empty-state** (F-024 H-007 + H-013): document (a) that a facet click followed quickly by pressing Enter in the search box can silently drop the just-clicked facet (the text submit ships `filters:{}` and may resolve second), and (b) that the empty-state copy "No matches found" is identical for a fresh catalog and a filtered-zero result, giving first-run operators no onboarding nudge toward "Add term." Fold alongside the existing DOC-178 Dictionary-tab caveats. Evidence: F-024 reflection H-007 / H-013 (UI behaviour; see reflection for the component cites).
- [ ] **GET /api/tags is open-read** (F-018 H-006): document on the permissions page that `GET /api/tags` has no SecurityRule — any authenticated user (anonymous under DISABLED) enumerates the entire global tag directory regardless of `TAG_*` grants, and there is no per-owner/tenant scope. Sibling to the read-collaborative-posture caveat. Evidence: `SecurityConstants.java:138-142` (no GET entry) + `AuthorizationCustomizer.java:29-30`.
- [ ] `Sources:` footer cites each `file:line @ ede5d277` above and the four reflection details (F-001 H-010, F-017 H-004, F-024 H-007/H-013, F-018 H-006).
- [ ] Live-site Gate 8 post-merge: WebFetch each affected page (catalog-overview, search, business-glossary, permissions) and confirm the caveats render.
