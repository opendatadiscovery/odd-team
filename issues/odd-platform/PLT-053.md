## What

Three defects on the Notification Settings dialog + adjacent Resolve/Reopen button. Doc-side mitigation (DOC-201) names them as known limitations; structural fixes are this PLT.

**Defect 1 - Notification Settings dialog has no optimistic concurrency check.** `NotificationSettings.tsx:49-53` submits halt-config without a version field. Two operators submitting simultaneously: A's submission silently overwrites B's (or vice versa). No version, no If-Match, no concurrent-edit detection.

**Defect 2 - Alert Resolve/Reopen button has no confirmation dialog.** `DataEntityAlertItem.tsx:113-118` dispatches `updateAlertStatus` immediately on click. Per the alerting workaround narrative + housekeeping cycle (DOC-200), manually-resolved alerts get **hard-deleted** by housekeeping. An accidental click destroys audit history.

**Defect 3 - Notification Settings dialog hardcoded English copy.** `NotificationSettings.tsx:57, :76-79, :102-104` - three hardcoded strings. PARENT button DOES use `t('Notification settings')` - mid-component i18n inconsistency.

## Where

```
NotificationSettings.tsx:49-53                - handleSubmitForm: no version field; no If-Match
NotificationSettings.tsx:57, 76-79, 102-104   - three hardcoded English strings
DataEntityAlertItem.tsx:113-118               - Resolve dispatch immediate; no confirmation
```

## Why it matters

Defect 1 silently corrupts halt-config in multi-operator workflows. Defect 2 is the most load-bearing: in combination with auto-cleanup hard-delete, a single accidental click destroys audit data the platform itself recommends as the path to compliance retention. Defect 3 is small but represents the same i18n discipline gap flagged in DOC-180 family.

## Suggested fix

**Defect 1 - optimistic concurrency (Option A recommended):** add `version` column on `data_entity_alert_halt_config`; UI submits `If-Match: <version>`; server 412 on stale write; UI surfaces "Configuration was changed by another user - reload."

**Defect 2 - confirmation dialog:**
```tsx
<Button onClick={() => setConfirmOpen(true)}>{t('Resolve')}</Button>
<ConfirmationDialog
  open={confirmOpen}
  body={t('This alert will be retained for {{days}} days then permanently deleted. Use the API workaround to export before resolving. Proceed?', { days: housekeepingDays })}
  onConfirm={dispatchUpdateAlertStatus}
/>
```

**Defect 3 - i18n the strings:**
```tsx
- <Typography>{'Notification settings'}</Typography>
+ <Typography>{t('Notification settings')}</Typography>
// + add entries to en/es/fr/ua/hy/ch.json
```
