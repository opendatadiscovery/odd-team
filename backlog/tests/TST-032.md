## Description

Three TestReport (F-022) behaviour pins harvested 2026-06-08.

1. **Zero-test dataset returns 404, not empty (H-003/H-010).** `DataQualityServiceImpl.getDatasetTests(datasetId)` calls `getDataQualityTestOddrnsForDataset(datasetId)` and on an empty result `switchIfEmpty`s into `NotFoundException("Data quality tests for dataset with id %d not found")` (`DataQualityServiceImpl.java:38-42`). So a dataset that legitimately has ZERO quality tests yields a 404 rather than an empty list — a questionable REST/empty-state choice (a real dataset with no tests is not "not found"). **Gate: characterization-pin (LSN-029)** — assert the CURRENT behaviour (`getDatasetTests` errors with `NotFoundException` when the dataset has no tests); RED when changed to return an empty `DataEntityList` (the likely fix), at which point invert + `@regresses`.

2. **No error boundary on TestReportDetails (H-011).** `TestReportDetails` lazy-loads its Overview and History sub-views via `React.lazy` (`TestReportDetails.tsx:24-29`) and wraps them in a `React.Suspense` fallback (`TestReportDetails.tsx:88`) but has NO error boundary anywhere in the tree — a lazy-chunk load failure or a throw in a lazy child is unhandled and crashes the subtree. **Gate: characterization-pin** — assert the CURRENT behaviour (a throw from a lazy child is NOT caught by any boundary within `TestReportDetails`); RED when an error boundary is added.

3. **Auto-expand-when-<5 hardcoded (H-011).** `TestReportItem` initialises `open=false` then `useEffect`s `if (dataQATestList.length < 5) setOpen(true)` (`TestReportItem.tsx:27-30`). The `< 5` auto-expand threshold is a hardcoded magic number. **Gate: validates-feature / characterization-pin** — assert the CURRENT behaviour: a suite with `< 5` tests auto-expands on mount, a suite with `>= 5` stays collapsed; RED if the threshold changes.

For each characterization-pin: it asserts the CURRENT (incorrect/undocumented) behaviour and goes RED when changed (LSN-029) — never `@Disabled`. On RED, invert to pin the corrected behaviour and re-tag `@regresses`.
