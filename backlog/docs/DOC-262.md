## Description

The live `/data-discovery/statuses` page (WebFetched 2026-05-27, 200 OK) describes the 5 statuses + the soft-delete TTL + the group-level apply choice. It is **silent on every operator-visible consequence of the entity detail header's `isStatusDeleted` gate** — three of the header's edit affordances and two of the Overview tab's sibling affordances disappear silently when the entity is in `DELETED` state, with no info banner explaining why. It is also silent on three sibling header-affordance UX shapes that operators bump into immediately on every entity detail page. Four operator-visible behaviours need a Known Caveats section.

**Caveat 1 — `DELETED`-state silently hides every edit affordance on the detail header AND the Overview tab; no banner explains why (F-178a).** Three `!isStatusDeleted` gates on the detail header itself (`DataEntityDetailsHeader.tsx:47, :87, :123`, verified this run): line 87 hides the business-name edit button, line 123 hides the "Edit group" button, line 47 disables the parent layout container that wraps the header-level edits. Two sibling gates on the Overview tab (`OverviewTags.tsx:39`, `OverviewGroups.tsx:33`, verified this run): the Tags and Groups Edit buttons disappear. The operator opens a DELETED entity and sees: the entity name + class badges + status badge render normally; every "Edit" / "Add" affordance has vanished. There is no info banner saying "this entity is in DELETED state — edits are disabled while soft-deleted, restore it to STABLE/DRAFT/DEPRECATED to edit again." The user assumes their permission failed, or the UI is buggy, or they navigated to a read-only mirror. The fix is operator-side: the entity must be restored (status flip back to non-DELETED) before edits return. Recovery is a hidden-procedure trap.

**Caveat 2 — The business-name edit button label toggles between "Add business name" and "Edit" depending on whether one is set; the affordance is the same dialog (F-178b).** `DataEntityDetailsHeader.tsx:92` (verified this run): `text={internalName ? t('Edit') : t('Add business name')}`. The same modal opens; only the label changes. Sibling pattern on the Overview tab Tags row at `OverviewTags.tsx:43`: `text={tags?.length ? t('Edit tags') : t('Add tags')}`. The toggle is semantically helpful but undocumented — operators training a teammate cannot point at "where to add a business name" without first checking whether the entity already has one. Recommend the doc either name the toggle or recommend harmonised label copy.

**Caveat 3 — The status badge renders in a visually-identical "read-only" mode for users without the `DATA_ENTITY_STATUS_UPDATE` permission; no lock icon, no tooltip explaining the gate (F-178c).** `DataEntityDetailsHeader.tsx:113-122` (verified this run): `<WithPermissions permissionTo={Permission.DATA_ENTITY_STATUS_UPDATE} renderContent={({ isAllowedTo }) => <EntityStatus entityStatus={status} selectable={isAllowedTo} isPropagatable={isDEG}/>}/>`. A user without the permission sees the status badge in non-interactive mode — same colour, same chip shape, same text — but clicking it does nothing. There is no cursor change (no `cursor: not-allowed`), no lock icon, no tooltip. The operator's mental model is "the badge looks like the others; clicking should open the picker" → clicks → nothing happens → assumes the UI is broken or their browser hung. Add either a visual lock indicator OR a "you don't have permission to change status" tooltip on hover.

**Caveat 4 — The "Share to Slack" button on the detail header is silently absent when the `datacollaboration` feature flag is off (the default per F-038); no "configure Slack to enable" hint surfaces (F-178d).** `DataEntityDetailsHeader.tsx:132-144` (verified this run): `<WithFeature featureName={Feature.DATA_COLLABORATION}>...Share button...</WithFeature>`. When `datacollaboration.enabled=false` the entire button is unmounted. Operators reading the [Data Collaboration documentation](../active-platform-features/data-collaboration.md) and expecting the share affordance to be present immediately after enabling Slack have no in-product feedback that the flag is the gating condition — the button just is or isn't, with no "feature disabled" affordance hinting at the configuration knob. Recommend either an operator-facing "feature disabled" hint OR a docs cross-link on the statuses page (and on the data-collaboration page) calling out the gating.
