## What happened (measured, not inferred)

`run-regression.sh ctrib061` built `odd-platform:odd-team-sut-ctrib061` from `main@96d77668` at 20:53:50 +02:00.
`docker images` immediately afterwards:

| tag | image id | created |
|---|---|---|
| `odd-platform:odd-team-sut-ctrib061` | `46d9ae04…` | 20:53:50 |
| **`odd-platform:latest`** | **`46d9ae04…`** | 20:53:50 |
| **`odd-platform:0.0.1-SNAPSHOT`** | **`46d9ae04…`** | 20:53:50 |

At that moment the maintainer's own demo stack (compose project `docker`, `docker/demo.yaml` locally edited to
`image: odd-platform:latest` + `AUTH_TYPE=LOGIN_FORM`) was UP, and its platform container had been created from
`odd-platform:latest` = **`3b34e245…`** (their own build, created 20:21:21). After our build that image was
**dangling** (`RepoTags: []`) and `latest` pointed at ours. The running container was unaffected (a container pins
its image id), but the very next `docker compose up` on the demo stand would have silently run OUR build instead of
THEIRS — a different jar under an unchanged config line, which is exactly the class of surprise the isolation
model exists to prevent (`adrs/drafts/parallel-stream-test-foundation.md`).

Restored by hand in the same session: `docker tag 3b34e245… odd-platform:latest` (verified `latest -> 3b34e245`).
`0.0.1-SNAPSHOT` was left pointing at ours — its prior id is not provable (nothing pins it) and nothing consumes it.

## Why

`odd-platform-api/build.gradle:140` declares `jib { to { tags = ['latest', project.version] } }`. Jib's `--image`
sets `jib.to.image`; `tags` are **additive** to it, so every per-stream build has re-tagged both shared names
since the per-stream tag was introduced (every `odd-team-sut-*` build in the `docker images` history did this).
The isolation was nominal.

## Fix (the class, not the instance)

In `build-sut.sh`'s `jib_from()`:

1. Snapshot the ids of `odd-platform:latest` and `odd-platform:0.0.1-SNAPSHOT` before the build
   (`docker image inspect <tag> --format '{{.Id}}' 2>/dev/null || true`).
2. Build.
3. If either tag's id changed **and** it had a prior id, re-point it: `docker tag <prior-id> <tag>`; if it had no prior
   id, `docker rmi <tag>` (untag only — the image stays reachable via the per-stream tag).
4. Log one line per restored tag so a run-log reader can see it happened.

Prefer this over `-Djib.to.tags=` (an empty override): the Jib Gradle property parser must be verified to accept an
empty list before relying on it, and the snapshot/restore approach is provable from `docker image inspect` alone
and survives a future change to the platform's tag list.

## Acceptance

- [ ] A `build-sut.sh` run into `odd-platform:odd-team-sut-<id>` leaves the ids of `odd-platform:latest` and
      `odd-platform:0.0.1-SNAPSHOT` **unchanged** (assert by `docker image inspect … --format '{{.Id}}'` before/after;
      cite both ids).
- [ ] When no `latest` existed before the build, none exists after it.
- [ ] The run-log (`SUT_DESC` block) states which shared tags were restored, or `none moved`.
