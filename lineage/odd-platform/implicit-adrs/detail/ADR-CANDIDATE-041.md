- **ADR-CANDIDATE-041** (NEW 2026-05-12C; STRENGTHENED 2026-05-12D — Email-channel angle confirms the cross-channel parallel): Each notification channel (Slack, webhook, email) is **independently activated by the presence of its URL/sender key** via `@ConditionalOnProperty(name = "notifications.receivers.X")` on the sender bean methods — there is no single "enable channel" toggle. Absence of a key = no bean = silently no-op for that channel. The pattern is a deliberate ergonomic — operators configure only the channels they want by populating only those keys

  - **Decision statement**: Notification channel activation is **property-presence-driven** rather than feature-flag-gated. The three sender bean methods (`slackNotificationSender`, `webhookNotificationSender`, `emailNotificationSender`) each carry their own `@ConditionalOnProperty(name = "notifications.receivers.{slack.url|webhook.url|email.sender}")`; bean instantiation requires the named key to be set and non-empty. Operators configure only the channels they care about by populating only those keys; absence of a key produces no bean (silent no-op for that channel). The decision has structural consequences: (a) adding a new channel is an add-a-bean-method change with its own `@ConditionalOnProperty`; (b) channel-level activation is OPERATOR-VISIBLE (the key is the toggle) — no separate enabled-flag YAML stanza per channel; (c) channels misconfigured to empty-string get the same no-op treatment as omitted (the empty-string check inside the sender constructor at NotificationConfiguration.java:46-48 / 75-77 is the fail-fast safety net for malformed configs — see ADR-CANDIDATE-018 for the parallel fail-fast pattern). The trade-off: simpler operator UX (one key per channel, set-it-and-it-works) vs. less explicit toggling (an operator who sets the key and gets no notifications has to inspect logs for the empty-string check to fire).
  - **Wisdom test**: PASS. The three parallel `@ConditionalOnProperty` annotations are the intent anchor (a single `notifications.channels: [slack, webhook, email]` list would have been an alternative encoding; the URL-presence pattern is a positive design choice). Structural — adding a new channel requires reusing this pattern. Cross-link with ADR-CANDIDATE-040 (subsystem-level disabled-by-default): the subsystem must be enabled first; THEN per-channel keys activate individual channels.
