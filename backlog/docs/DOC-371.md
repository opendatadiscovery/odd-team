## Description

`disabled-authentication.md` already documents that the DISABLED-mode `whoami` returns a synthetic admin with permissions built from `Permission.values()` and that "any new platform capability added in a future release is automatically granted." What the page does **not** explain is the **global-vs-resource asymmetry** in *how* that synthetic grant is constructed versus how the real authenticated path constructs permissions — and that asymmetry is the actual mechanism behind the symptom operators observe ("every UI control unlocks").

The asymmetry:

- **DISABLED (synthetic) path** — `IdentityController.dummyOwner()` builds the identity with `Permission.values()` (`IdentityController.java:32`): the **entire** `Permission` enum, *including resource-contextual permissions* (those that are normally evaluated per-resource against a policy), is handed to the anonymous admin wholesale.
- **Authenticated path** — `IdentityServiceImpl.whoami()` populates the identity's permissions from `permissionService.getNonContextualPermissionsForCurrentUser(PermissionResourceType.MANAGEMENT)` (`IdentityServiceImpl.java:42`). It only ever computes **non-contextual MANAGEMENT** permissions; resource-contextual permissions are deliberately *not* part of the `whoami` permission list for a real user — they are resolved per-resource elsewhere.

So under DISABLED the synthetic admin is granted a permission set that an authenticated real admin's `whoami` would never even contain (the resource-contextual ones), via a different code path. The "everything unlocks" symptom is symmetric (all controls open); the mechanism behind it is asymmetric (the enum is stuffed wholesale, bypassing the per-resource contextual evaluation that the authenticated path leaves to the policy layer). An operator reasoning about what DISABLED actually short-circuits — and why authoring policies under DISABLED has no effect (the migration section already warns policies "were never consulted") — benefits from seeing that the contextual permission machinery is entirely bypassed, not merely pre-satisfied.
