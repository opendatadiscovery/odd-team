- **DOC-GAP-262**: Registering a data source via `POST /api/datasources` can IMPLICITLY CREATE a namespace as a side effect of the `namespace_name` form field — bypassing the `NAMESPACE_CREATE` permission. A principal holding only `DATA_SOURCE_CREATE` (the gate the live `/features/management` Datasources tab documents) can proliferate namespaces through this side-effect path, even though the explicit namespace endpoint `POST /api/namespaces` is gated by `NAMESPACE_CREATE`. The live docs describe the two permissions (`DATA_SOURCE_CREATE`, `NAMESPACE_CREATE`) independently on the Permissions page and never flag that data-source registration is a second, ungated path to namespace creation. The same side-door applies on the update path (`PUT /api/datasources/{id}` under `DATA_SOURCE_UPDATE`). The namespace is created with NO Activity Event, so the new namespace appears with no audit trail of who created it or why; and a typo in `namespace_name` silently creates a junk namespace rather than erroring.
