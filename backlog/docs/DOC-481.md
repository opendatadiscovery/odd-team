## Description

The #1758 fix (odd-platform `contrib/CTRIB-030-lineage-depth-npe`: `default: 1` on `lineage_depth` in
`odd-platform-specification/openapi.yaml`, generated as `@RequestParam(defaultValue = "1")`) makes an omitted
`lineage_depth` bind to 1 and return the depth-1 graph — matching the api-reference's documented "default depth"
— instead of the primitive-int NPE → HTTP 500. The two lineage pages previously documented the 500 as a caveat
("the endpoints have no default … omitting it returns HTTP 500 … always pass an explicit value"); that is now
false for 0.29.0.

**Authored + pushed on the `release/0.29.0` train** (documentation @ 71f3e53) — publishes when 0.29.0 ships
(per `adrs/drafts/release-train-doc-gating.md`). The `@Max` / unclamped-depth / no-cycle-guard caveats on both
pages are unchanged (PLT-042 / REFACTOR-202 territory — NOT fixed by #1758).

This supersedes the "unset → 500" half of the earlier DOC-293 (status: superseded) lineage-caveat cluster; the
no-RBAC / DISABLED-reachability caveats from that cluster stand (intended behaviour, separate).
