- **ADR-CANDIDATE-035** (NEW 2026-05-12C): The OAuth2 `GrantedAuthoritiesMapper` is fail-CLOSED for role assignment — an authority list that's empty OR that contains no `UserProviderRole` enum member is mapped to `USER` (never accidental ADMIN). The mapper rejects unrecognised authorities by silently dropping them, ensuring that an unauthenticated authority list never accidentally produces an admin role
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`OAuthSecurityConfiguration.auth.type@L71`) — single occurrence but a substantive security-architecture decision; the alternative (fail-open: pass authorities through verbatim) would permit upstream providers (or malicious clients exploiting misconfigured IdPs) to inject `ROLE_ADMIN` into the platform context
  - **Surfaced by**:
    - `odd-platform__java__OAuthSecurityConfiguration__config-key-consumer__auth_type@L71.md:implicit_adrs.[5]` ("Default `GrantedAuthoritiesMapper` assigns the `USER` role when (a) the upstream provider returned no authorities OR (b) none of the returned authorities matches a `UserProviderRole` enum value (lines 142-158). The decision is to fail-CLOSED-by-role-assignment: an unauthenticated authority list never produces an admin role accidentally." — intent_anchor: `if (CollectionUtils.isEmpty(authorities)) { return Set.of(new SimpleGrantedAuthority(USER.name())); } ... if (containsProviderRole) { return authorities; } return Set.of(new SimpleGrantedAuthority(USER.name()));`)
  - **Decision statement**: The OAuth2 user-authority mapping is **fail-closed for role assignment**. The default `GrantedAuthoritiesMapper` at `OAuthSecurityConfiguration.java:142-158` follows a two-stage classification: (1) if the upstream provider returned no authorities, return `Set.of(USER)`; (2) if the provider returned authorities BUT none of them matches the `UserProviderRole` enum (`USER | ADMIN`), STILL return `Set.of(USER)` — the unrecognised authorities are silently dropped. Only when the authority list contains at least one `UserProviderRole`-matching entry does the mapper pass authorities through verbatim. The decision codifies "default to least-privilege when the upstream signal is ambiguous"; a misconfigured IdP that returns `["custom-role-1", "custom-role-2"]` produces USER, not ADMIN, never. This contrasts with the LOGIN_FORM mode where `getAuthorities(true)` hard-codes ADMIN (ADR-CANDIDATE-031) — the OAuth2 mode is the production-mode counterpart with the inverse posture.
  - **Wisdom test**: PASS. The dual-stage classification with explicit `Set.of(USER)` return on both empty + unrecognised-only paths is an unambiguous design choice; the alternative (pass authorities through verbatim) would be both shorter AND less safe. The maintainer's explicit `Stream.of(UserProviderRole.values()).map(UserProviderRole::name).anyMatch(...)` + fallback `return Set.of(USER)` shape is the structural intent anchor. Affects every OAuth2 login.
  - **Evidence**:
    - OAuthSecurityConfiguration.md says: "OAuthSecurityConfiguration.java:142-158 — full GrantedAuthoritiesMapper implementation"
  - **Existing ADR**: none. Contrasts with ADR-CANDIDATE-031 (LOGIN_FORM ADMIN-for-all) — the same maintainer chose opposite postures for the two modes, reflecting the dev-vs-production positioning. Cross-link useful in both ADRs.
  - **Co-surfaced gaps** (link from `refactoring-scopes.md`): None directly; the fail-closed posture itself is the defense. REFACTOR-113 (Okta + Keycloak no provider-specific enrichment) is adjacent — operators relying on Okta's admin-group claim would see USER assignment because no `OktaUserHandler` exists to map the group to `UserProviderRole.ADMIN`. The fail-closed posture amplifies the consequence of REFACTOR-113.
  - **Proposed action**: Promote to `adrs/drafts/oauth-granted-authorities-fail-closed.md` (new ADR). Document the fail-closed rationale. Cross-link with ADR-CANDIDATE-031 (LOGIN_FORM ADMIN-for-all contrast) and REFACTOR-113 (the consequence for Okta + Keycloak deployments without per-provider enrichment).
  - **Severity rationale**: MEDIUM — security-architecture decision affecting every OAuth2-authenticated user. A future PR that proposes "let's pass IdP-supplied authorities through verbatim" must contend with this ADR's least-privilege stance.
