## What

On the **My Objects** alerts view, the tab/badge count is the **platform-wide** number of open alerts, not the number of open alerts on the data entities the current user owns. The list itself is correctly owner-scoped (you only see alerts on objects you own), but the `Page.total` returned alongside that list is computed from an **unscoped** counter. The visible symptom is a contradiction the operator sees directly: the alert list is empty (you own no alerting objects) while the tab still reads, e.g., "Alerts (137)". Conversely, when you do own some, the count is inflated by every other team's open alerts. The number is meaningless to the user it is shown to.

## Where

`repository/reactive/ReactiveAlertRepositoryImpl.java` - `listByOwner(page, size, ownerId)`. The query base is correctly filtered by `OWNERSHIP.OWNER_ID.eq(ownerId)`, but the count passed to `pageifyResult` is the platform-wide `countAlertsWithStatusOpen()` - the **same** counter `listAllWithStatusOpen` uses, with no owner predicate:

```java
// ReactiveAlertRepositoryImpl.java:160 - listByOwner (records ARE owner-scoped)
final SelectConditionStep<Record> baseQuery = DSL
    .select(ALERT.fields())
    .from(ALERT)
    .join(DATA_ENTITY).on(DATA_ENTITY.ODDRN.eq(ALERT.DATA_ENTITY_ODDRN))
    .join(OWNERSHIP).on(OWNERSHIP.DATA_ENTITY_ID.eq(DATA_ENTITY.ID))
    .where(ALERT.STATUS.eq(AlertStatusEnum.OPEN.getCode())).and(OWNERSHIP.OWNER_ID.eq(ownerId)
        .and(DATA_ENTITY.STATUS.ne(DataEntityStatusDto.DELETED.getId())));
...
return jooqReactiveOperations
    .flux(query.getLeft())
    .collectList()
    .flatMap(records -> jooqQueryHelper.pageifyResult(
        records,
        r -> mapRecordToDto(r, query.getRight()),
        countAlertsWithStatusOpen())   // <-- line 177: UNSCOPED count; ignores ownerId
    );
```

Compare the platform-wide list in the same class, which legitimately uses the same counter:

```java
// ReactiveAlertRepositoryImpl.java:142 - listAllWithStatusOpen
...
    .flatMap(records -> jooqQueryHelper.pageifyResult(
        records,
        r -> mapRecordToDto(r, query.getRight()),
        countAlertsWithStatusOpen()    // line 155: correct here - this list IS platform-wide
    ));
```

`countAlertsWithStatusOpen()` counts `ALERT WHERE STATUS = OPEN` with no `OWNERSHIP`/`ownerId` join, so the `Page.total` for the owner-scoped list is the global open-alert total.

## Why it matters

This is a **loud, persistent, always-on** wrong number on a primary navigation surface - the count is visible to every authenticated user the moment they open My Objects, and it disagrees with the rows rendered directly beneath it. It erodes trust in the alerting subsystem (the feature operators rely on to know their pipelines are healthy): a user with zero owned alerts sees a non-zero badge and assumes something is wrong with their objects; a user with real alerts cannot use the badge to gauge their own backlog because it is dominated by unrelated entities. No data is lost, but the alert UX is the operator's health dashboard, and a dashboard that lies about scope is high-impact. Severity high.

## Suggested fix

Add an owner-scoped count and pass it in `listByOwner`, mirroring the existing owner-scoped query shape:

```java
// new sibling of countAlertsWithStatusOpen() - same OWNERSHIP join + ownerId predicate as listByOwner
private Mono<Long> countAlertsWithStatusOpenByOwner(final long ownerId) {
    final SelectConditionStep<Record1<Integer>> query = DSL.selectCount()
        .from(ALERT)
        .join(DATA_ENTITY).on(DATA_ENTITY.ODDRN.eq(ALERT.DATA_ENTITY_ODDRN))
        .join(OWNERSHIP).on(OWNERSHIP.DATA_ENTITY_ID.eq(DATA_ENTITY.ID))
        .where(ALERT.STATUS.eq(AlertStatusEnum.OPEN.getCode()))
        .and(OWNERSHIP.OWNER_ID.eq(ownerId))
        .and(DATA_ENTITY.STATUS.ne(DataEntityStatusDto.DELETED.getId()));
    // ... reactive count
}
```

Then in `listByOwner`, replace `countAlertsWithStatusOpen()` (line 177) with `countAlertsWithStatusOpenByOwner(ownerId)`. Keep the count predicate in lock-step with the list predicate (same `OWNER_ID`, same `STATUS = OPEN`, same `DELETED` exclusion) so the badge always equals the list cardinality. Open to alternatives on the helper name/placement.
