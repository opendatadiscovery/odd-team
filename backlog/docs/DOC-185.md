## Description

There is **no documentation sub-page** for the per-test runs-history endpoint exposed at `/api/dataentities/{data_entity_id}/runs` and mounted in the UI at the `/history` route (page-size 100) + the `/test-report` first-10-runs preview. Per substrate batch ZG: `/features/data-quality/test-results` returns 404; `/features/data-quality/test-results-import` documents the INGESTION side (not the runs-history READ side). Operators discovering the runs-history surface have no canonical doc. Four facets, one new page:

**Surface to document (F-040a — missing-page).** 1 GET endpoint (`/api/dataentities/{data_entity_id}/runs`) + 2 UI mounts (`/history` route page-size 100 in `TestRunsHistory.tsx`; `/test-report` first-10-runs preview). Surfaces the timeline + per-row status + `status_reason` diagnostic text. The new page should cover: endpoint shape, UI surface, pagination, sort, status filter, AND the three caveats below.

**Caveat 1 — HTTP 500 during in-flight test runs (F-040b).** `IngestionTaskRun.java:28-36` declares 7 enum values DB-side; `components.yaml:1407-1415` declares 6 wire-side (no `RUNNING`). The MapStruct mapper `DataEntityRunMapper.java:13-14` uses `Enum.valueOf` for String→enum mapping. **Any result set containing a RUNNING row triggers `IllegalArgumentException` → HTTP 500.** The runs page is UNAVAILABLE exactly when an operator most wants to see it (an in-flight test). Operator-visible: "Data Quality runs page returns 500 when a test is currently running." Code-side fix is one of three: add `RUNNING` to the wire enum (`components.yaml:1407-1415`); MapStruct `@ValueMapping(source=ANY_UNMAPPED, target="UNKNOWN")`; or service-side filter excluding RUNNING before the mapper.

**Caveat 2 — Cross-owner read + status_reason diagnostic-text leak (F-040c).** `SecurityConstants.java:98-355` has no `/api/dataentities/*/runs` entry; `ReactiveDataEntityTaskRunRepositoryImpl.java:160-191` has no OWNERSHIP join. **Any authenticated user reads any DQ test's run history including `status_reason`** — free-form test-framework diagnostic text commonly containing failed-row samples (Great Expectations emits sample failing values; dbt emits table/column names). This is a DISTINCT data-shape leak channel beyond namespaces/owners/tags already exposed by REFACTOR-024 elsewhere. Multi-tenant deployments where DQ test diagnostic text contains team-confidential data shapes see cross-team leak.

**Caveat 3 — NULL end_time ordering puts RUNNING rows undated at top of list (F-040d).** `ReactiveDataEntityTaskRunRepositoryImpl.java:178` issues `ORDER BY end_time DESC` with no `NULLS LAST`. Postgres default for `DESC` is `NULLS FIRST`. RUNNING rows (`end_time IS NULL`) appear at the TOP of the list. The UI labels each row by `startTime` with an empty Duration column when endTime is null — the operator sees an undated-looking row at the top with no signal it's in-flight.
