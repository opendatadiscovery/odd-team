## Description

Three substrate-grade gaps on the DEG-anchored lineage surface that DOC-GAP-159 / DOC-GAP-163 / DOC-GAP-164 / DOC-GAP-165 catalogue piecewise but no doc page resolves end-to-end. The substrate's primary-source re-verification this run confirms all three at line-level (see scanner-feed log SR-20260527T1700Z `clues_consumed[F-016].primary_source_reads`).

**Facet 1 — Sibling DEG-read endpoints disagree on empty-DEG polarity (F-016a, CRITICAL).** `/api/dataentitygroups/{id}/lineage` raises **404 NotFoundException** on empty DEG (`LineageServiceImpl.java:62` — `switchIfEmpty(Flux.error(new NotFoundException("Data entity group", dataEntityGroupId)))`). The sibling `/ingestion/entities/{degOddrn}/children` endpoint returns **200 OK** with an empty `CompactDataEntityList` (`IngestionController.java:75-79` — `getDataEntitiesByDEGOddrn`). Two endpoints on the same platform, same semantic condition (DEG exists but has zero members), **opposite contracts**. A collector author probing both with the same DEG ODDRN writes two different error-handling code paths. The asymmetry IS the contract — but no doc names it.

**Facet 2 — DEG-lineage endpoint has NO `lineage_depth` AND NO `expanded_entity_ids` parameter (F-016b, MEDIUM).** `openapi.yaml:2418-2433` declares ONLY `DataEntityGroupIdParam` (path) for the DEG-lineage operation; the per-entity endpoints at `openapi.yaml:1267` + `1301` carry both `lineage_depth` and `expanded_entity_ids`. Operators familiar with the per-entity API try `?lineage_depth=5` against the DEG endpoint and have it silently ignored. The API reference's lineage page does not name the asymmetry.

**Facet 3 — Pillar page silent on cross-owner read posture for DEG-anchored lineage.** The live `features/data-lineage.md` pillar landing was authored before the explicit cross-owner-enumeration finding (REFACTOR-203 family). The substrate's `doc_silent_on_read_collaborative_posture` facet captures the gap: DEG-anchored lineage walks include children regardless of ownership (no owner JOIN at the repository tier; `LineageServiceImpl.java:59-85`). The page now mentions the dedicated DEG endpoint exists, but is silent on the access-control class — adjacent to DOC-GAP-159 but at the pillar-page surface, not the per-entity sub-page.
