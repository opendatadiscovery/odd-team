## Description

The live `/features/management` Data Sources section (WebFetched 2026-05-27, 200 OK) names the verbs ("View existing sources, audit ingestion timestamps, edit metadata, link to a Collector + Namespace; remove a source no longer ingested"). It is **silent on the namespace_name side-door, the REPLACE-not-MERGE update semantic, the orphan-token-row + FTS-unrefreshed delete semantic, the no-grace token rotation, the plaintext-token-in-response Cache-Control gap, the audit silence, and the non-`@ReactiveTransactional` regenerate path**. Three operator-visible caveats need to land.

**Caveat 1 — `namespace_name` side-door: registerDataSource + updateDataSource silently mint NAMESPACE rows bypassing `NAMESPACE_CREATE` (F-031a — primary).** `DataSourceServiceImpl.java:56-66` (register) does `if (StringUtils.isNotEmpty(form.getNamespaceName())) { return namespaceService.getOrCreate(form.getNamespaceName())...}`. `DataSourceServiceImpl.java:73-78` (update) replicates the side-door. A caller with `DATA_SOURCE_CREATE` only (no `NAMESPACE_CREATE`) proliferates namespaces. The `/permissions` page describes the two permissions as INDEPENDENT; the side-door collapses them. This is the canonical vertex of the 4-sister-service Namespace side-door cluster (DOC-254 Facet 2; DOC-251 Caveat 3 is the Owner sibling).

**Caveat 2 — `deleteDataSource` orphans the TOKEN row + leaves the FTS vector uncleared + is documented as "remove a source no longer ingested" only (F-031b).** `DataSourceServiceImpl.java:85-96` (delete) blocks with `CascadeDeleteException` (HTTP 400) when a live `data_entity` child references the source; otherwise soft-deletes via `UPDATE data_source SET deleted_at = NOW()`. The associated TOKEN row is **orphaned** (TOKEN has no `deleted_at` column; F-020 sibling — DOC-252 Caveat 2 covers the Collector parallel). The FTS `search_entrypoint` vector is **NOT cleared** (asymmetry with the update path, which DOES call `updateSearchVectors`); soft-deleted data-source names persist in catalog search until other events refresh affected entries. Operators searching for a "deleted" data source find it still surfacing in faceted results.

**Caveat 3 — `regenerateDataSourceToken` returns plaintext token + is NOT `@ReactiveTransactional` + emits no audit event (F-031c).** `DataSourceServiceImpl.java:98-106` is the only mutating method on this class WITHOUT `@ReactiveTransactional` (compare lines 52, 69, 86 which all carry it). If the `tokenRepository.updateToken` step fails after the `dataSourceRepository.getDto` read, the partial state is undefined. The 40-char plaintext token returns in the response body with **no `Cache-Control: no-store` header** — intermediate proxies / browser history / corporate inspection appliances may cache. No Activity Feed event emits — the entire data-source lifecycle is invisible to audit.
