## Description

Promote `ADR-CANDIDATE-045`: content cleanup (`housekeeping/`, 15-min ShedLock) and structural
partition creation (`partition/`, nightly ShedLock) are distinct subsystems; their single
intersection — dropping empty partitions — lives in housekeeping (`EmptyPartitionsHousekeepingJob
implements HousekeepingJob`) but delegates to `PartitionService`, naming both concerns at the type level.

## Review (2026-05-31, session: adr-review-activity-lifecycle)

**Verdict: BLOCKED — Gate A2 FAIL.** The page's narrative claim (housekeeping is a separate subsystem from partition management; the one bridge is `EmptyPartitionsHousekeepingJob`) is TRUE and the Decision/Consequences prose is sound — but the **Evidence section cites code that does not exist and line numbers that are systematically wrong**, presented as "re-verified at `ede5d277`". An ADR's Evidence is its load-bearing contract ("here is the code that embodies this"); a contributor who follows these citations lands on import statements and greps for a method that isn't there. Flipped `review-ready` → `blocked`. Substrate re-verified at `ede5d277` (confirmed odd-platform HEAD).

### Gate A2 — Code evidence (HEAVY) — **FAIL**

Opened every cited locus in `EmptyPartitionsHousekeepingJob.java`, `ActivityEmptyPartitionsHousekeepingJob.java`, `PostgreSQLPartitionCreationJob.java`, `HousekeepingJobManager.java`, `HousekeepingJob.java` at `ede5d277` via `nl -ba`. Discrepancies:

1. **Fabricated method name `dropEmptyPartitions` (the worst miss).** Page Evidence bullet 1 (and the `realises:` frontmatter, the Description, and the Candidate-note) state `doHousekeeping(connection)` calls `partitionService.dropEmptyPartitions(getTableName(), connection)`. **No such method exists.** `grep -rn "dropEmptyPartitions" odd-platform-api/.../partition/` → 0 hits; `PartitionService` exposes `getEmptyPastPartitions(...)` (interface :21, impl :83) and `dropPartition(...)`. The actual `doHousekeeping` (`EmptyPartitionsHousekeepingJob.java:17-33`) calls `getEmptyPastPartitions(connection, targetTable, exclusions())` (:21-22) then loops `partitionService.dropPartition(connection, partition)` (:26). The method is `getTargetTable()` (:18,:35), not `getTableName()`. VERIFIED via grep + `nl -ba`. **→ FAIL.**

2. **`EmptyPartitionsHousekeepingJob.java:8-9` is wrong.** Page cites `:8-9` for `abstract class … implements HousekeepingJob` + `private final PartitionService partitionService`. Actual: line 8 blank, line 9 `import static java.util.Collections.emptyList;`. The class declaration is at **line 13**, the field at **line 14**. VERIFIED. **→ FAIL.**

3. **`EmptyPartitionsHousekeepingJob.java:14-15` is wrong.** Page cites `:14-15` for `doHousekeeping`. Actual: `:14` is the `partitionService` field; `doHousekeeping` is at **line 17**; the (mis-described) partition call is at :21-26. VERIFIED. **→ FAIL.**

4. **`ActivityEmptyPartitionsHousekeepingJob.java:6-7` is wrong.** Page cites `:6-7` for `@Component public class … extends EmptyPartitionsHousekeepingJob`. Actual: line 6 `import static …Tables.ACTIVITY;`, line 7 blank; `@Component` is **line 8**, the class declaration **line 9**. VERIFIED. **→ FAIL.**

5. **`PostgreSQLPartitionCreationJob.java:18-19` is wrong.** Page cites `:18-19` for "distinct nightly `@Scheduled` cron + `@SchedulerLock(name = "partitionCreationJob", …)`". Actual: `:18-19` are `@Component` + `@RequiredArgsConstructor`. The `@Scheduled(cron = "0 1 0 * * *")` + `@SchedulerLock(name = "partitionCreationJob", lockAtLeastFor="10m", lockAtMostFor="10m")` are at **lines 40-41**. VERIFIED. **→ FAIL.**

Correct citations (no change needed): `HousekeepingJobManager.java:17-26` (`@Component` + `@ConditionalOnProperty` + `@Scheduled(fixedRate=15,MINUTES)` + `@SchedulerLock(name="housekeepingJob",…)` + `List<HousekeepingJob>`) — EXACT; and `HousekeepingJob.java:5-6` (interface `void doHousekeeping(Connection)`) — EXACT. The implementation note's advisory-lock reasoning is also correct: `PostgreSQLPartitionCreationJob` uses `leaderElectionManager.acquire(...)` (advisory lock) only in `@PostConstruct init()` (:29-31), while the scheduled `run()` (:40-43) uses ShedLock — so the page's *prose* "both scheduled jobs use ShedLock … neither uses a Postgres advisory lock for scheduling" is accurate.

**Required to unblock (re-implement):**
- (a) Replace the fabricated `partitionService.dropEmptyPartitions(getTableName(), connection)` in the page Evidence, the `realises:` frontmatter, the Description, and the Candidate-note with the real shape: `getEmptyPastPartitions(connection, getTargetTable(), exclusions())` + per-partition `dropPartition(connection, partition)` loop.
- (b) Correct all Evidence line numbers to the verified loci: `EmptyPartitionsHousekeepingJob` class decl `:13-14`, `doHousekeeping` `:17` (call body `:21-26`); `ActivityEmptyPartitionsHousekeepingJob` `@Component`+class `:8-9`; `PostgreSQLPartitionCreationJob` scheduled+lock `:40-41`.
- (c) Re-run Gate 8 after the docs re-push (the live page currently renders the wrong Evidence — WebFetch confirmed the live page shows `dropEmptyPartitions(getTableName(), connection)` and `:14-15`).
