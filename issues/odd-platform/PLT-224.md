## Summary

When you create or edit a Lookup Table, the form has a **Description** field. That description is
saved on the lookup-table record but is **never written to the associated catalog Data Entity**, so it
does not appear in the Data Entity overview **About** section. An operator fills in a description during
lookup-table creation and then finds the entity's overview empty - the effort is invisible exactly where
users look for it.

## Where it goes wrong (code)

`ReferenceDataServiceImpl.createLookupTable` / `updateLookupTable` put the form's description on the
lookup-table DTO only:

```
.tableDescription(formData.getDescription())   // -> lookup_tables.description
```

The associated Data Entity is built by `DataEntityMapperImpl.mapCreatedLookupTablePojo(ReferenceTableDto,
DataEntityClassDto)`, which sets `internalName`, `externalName`, namespace, class, type, status ... but
**never `setInternalDescription(...)` nor `setExternalDescription(...)`**. The entity overview "About"
block reads `data_entity.internal_description`, so it is always empty for a lookup-table entity unless
the operator separately re-types the description on the entity's overview.

## Reproduction (live, 2026-06-13)

1. `POST /api/referencedata/table` with `{ "name": "caveat_lt", "description":
   "THIS_DESC_SHOULD_SHOW_IN_ABOUT", "namespace_name": "<ns>" }`.
2. DB state of the result:

```
lookup_tables.description  = "THIS_DESC_SHOULD_SHOW_IN_ABOUT"
data_entity.internal_description = (empty)
data_entity.external_description = (empty)
```

So the description lives only on the lookup table; the catalog entity (and therefore the overview "About"
section) shows nothing.

## User-facing impact

Confirmed end-to-end (maintainer drove the UI; code + DB reproduced above). On the Lookup-Table entity's
overview page the **About** section is empty even though a Description was provided at creation. Operators
either think the description was lost, or duplicate it manually on the entity overview. It is a quiet
waste of curation effort on a surface (master-data reference tables) where description quality matters.

## Proposed fix

Propagate the lookup-table description to the entity's internal description so the catalog reflects it:

- in `mapCreatedLookupTablePojo`, add `.setInternalDescription(tableDto.getTableDescription())`;
- on update (`DataEntityLookupTableServiceImpl.updateLookupDataEntity` / the lookup-table apply path),
  keep the entity's `internal_description` in step with the edited description.

(Decide the sync direction if the entity-overview description and the lookup-table description can both be
edited - simplest is: the lookup-table form is the source of truth and writes through to
`internal_description`.) A unit test on `mapCreatedLookupTablePojo` + an e2e that creates a lookup table
with a description and asserts the overview About renders it would lock it.

## Workaround until the fix

Add the description on the Lookup-Table **entity overview** ("About" -> **Add info / Edit info**), which
writes `internal_description` directly. The Create/Edit-Lookup-Table form's Description field does not do
this today.

## Docs

A caveat is documented on `master-data-management/lookup-tables.md` (docs `main`, released-truth) until
the fix ships: documentation branch `docs/lookup-table-description-caveat`, commit `1bb425a` (a
`{% hint style="warning" %}` in the "Known operator caveats" section + the entity-overview workaround).
