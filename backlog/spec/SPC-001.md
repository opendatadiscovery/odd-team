## Description

The Platform Public API Contract (`openapi.yaml`) has three classes of drift that are visible to every SDK consumer and every Swagger UI viewer:

**Facet 1 — `info.title` is legacy ProspectLog branding (F-029c).** `openapi.yaml:3` declares `title: ProspectLog data catalog HTTP API contract` — the pre-rename internal name. `info.contact.url: https://provectus.com` ties to ODD's origin company; `info.contact.email: ndementev@provectus.com` is a direct individual contact. Every operator running ODD Platform sees the wrong project name in their Swagger UI (`/api/v3/api-docs`).

**Facet 2 — No `securitySchemes` block (F-029a).** Grep across `openapi.yaml` + `components.yaml` for `securitySchemes` returns zero matches (re-verified per substrate batch Z + scanner-feed log). SDK consumers using `openapi-generator-cli` get no authentication code — they must hand-author auth glue (Bearer wiring, session cookie handling, `X-API-Key` injection). This is the easiest place for misconfiguration: SDK consumers cannot discover the platform's four UI auth modes + S2S X-API-Key + Ingestion filter from the spec.

**Facet 3 — 201-vs-200 status-code drift across 7+ controllers (F-029b).** Substrate batch Z cites seven controller pairs with drift at `openapi.yaml:372, 400, 454, 482, 558, 586` (+ sibling pairs). The spec declares 201 (Created), the Java controllers return 200 (OK), or vice versa. Generated SDK clients that branch on the declared response status NEVER reach the success branch. The drift is symmetric (each pair has one direction); the fix is per-controller verification of the actual runtime return code, then aligning the spec.

## Acceptance Criteria

Three separable acceptance criteria; can ship as one commit or three on a single branch:

### Facet 1 (rename — small change)
- [ ] `openapi.yaml:3` `info.title` is renamed from `ProspectLog data catalog HTTP API contract` to `Open Data Discovery Platform API` (or maintainer-preferred phrasing matching `docs.opendatadiscovery.org` branding).
- [ ] `info.contact.url` is updated from `https://provectus.com` to `https://github.com/opendatadiscovery` (or dropped if no organisational contact URL is needed).
- [ ] `info.contact.email` is updated to a team alias OR dropped (`ndementev@provectus.com` should not appear — verify with project maintainer whether an org contact email exists; if not, omit the field).

### Facet 2 (securitySchemes — medium change)
- [ ] `components.securitySchemes:` block is added enumerating:
  - `bearerAuth` — for OAUTH2 / JWT (HTTP `bearer`, format `JWT`)
  - `sessionCookieAuth` — for LOGIN_FORM (apiKey in cookie, name `SESSION`)
  - `s2sApiKeyAuth` — for S2S (apiKey in header, name `X-API-Key`)
  - `ingestionFilterAuth` — for ingestion-side per-collector auth (apiKey in header — verify name against `IngestionAuthFilter`)
- [ ] Per-operation `security:` references are added where appropriate. UI-facing endpoints reference the UI modes; `/ingestion/**` references the ingestion filter; explicit auth-bypass paths (e.g., `/ingestion/alert/alertmanager` per F-007) declare `security: []`.

### Facet 3 (201/200 alignment — medium change, per-controller verification)
- [ ] For each of the 7 cited controller pairs at `openapi.yaml:372, 400, 454, 482, 558, 586` (and the sibling pairs substrate batch Z names), verify the actual runtime return status in the Java controller (e.g., `@ResponseStatus(HttpStatus.CREATED)` vs `ResponseEntity.ok(...)` patterns).
- [ ] Spec is updated to match the runtime return for each controller (or, less commonly, the runtime is updated — but that's a PLT, not a spec change). Default direction: align spec to runtime since most POST-creates-resource endpoints idiomatically return 201 and any 200 cases are likely intentional.

### Cross-cutting
- [ ] Once the spec lands in `opendatadiscovery-specification`, the platform repo's vendored copy needs a sync — coordinate via the spec's release / vendor channel (consult the repo's `README.md` for the protocol).
- [ ] Live-side verification: spawn the platform locally (or stage) and load `/api/v3/api-docs` — confirm the new title renders + `securitySchemes` are present in the rendered Swagger UI.
