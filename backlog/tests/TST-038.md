## Description

The GenAI question feature ships an API surface (`GenaiApi.genAiQuestion`) but has **no in-app UI affordance today** — F-039 / H-012 argues the feature's security gaps (H-001/H-005/H-006/H-011) are therefore *latent, not live*: reachable only by a developer driving the OpenAPI spec / SDK, not by an ordinary end-user clicking through the platform. That "API-only today" posture is a load-bearing assumption behind the deferred-security stance: the gaps must be closed BEFORE a UI consumer ships (F-039 reflection: "API-only today reduces casual exposure but is not a security mitigation").

The only safe way to keep that assumption honest is to make the API-only→UI transition a tripwire. Verified at harvest time (2026-06-08): the generated client `odd-platform-ui/src/generated-sources/apis/GenaiApi.ts` exists and is re-exported from `generated-sources/apis/index.ts:18`, but there are **zero hand-written imports of `GenaiApi`** anywhere under `odd-platform-ui/src` outside `generated-sources/` — i.e. no component, hook, or thunk consumes it. The day someone wires a real UI control to `GenaiApi`, this pin goes RED and forces the reviewer to re-open the deferred GenAI security gaps as live rather than latent.

**Typed gate: characterization-pin** (LSN-029). It asserts the CURRENT structural fact (no application-code GenaiApi consumer) and is designed to go RED the instant that fact changes. It is NOT `@Disabled` — a blind/disabled test would let the UI flip ship unseen, which is exactly the failure this guards. On RED: confirm a real GenAI UI surface is being added → that edit must land WITH the H-001/H-005/H-006/H-011 security gaps closed (or explicitly re-triaged); then update/retire this pin as a conscious reviewed decision.
