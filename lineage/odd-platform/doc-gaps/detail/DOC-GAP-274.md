    - **The reconnaissance utility**:
      - **Step 1**: `curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" https://target/api/identity/whoami` from an attacker host returns one of:

        - `302 https://target/login` → LOGIN_FORM mode
        - `302 https://target/oauth2/authorization/{provider}` → OAUTH2 mode (also discloses the OAuth provider name in the redirect URL)
        - `401 ` → LDAP mode (also discloses LDAP via `WWW-Authenticate: Basic realm=...`)
      - **Step 2 (under DISABLED only)**: `curl https://target/api/identity/whoami` returns `{identity:{username:"admin", permissions:[<full enumeration of 70+ Permission values>]}}` — the attacker now knows: (a) the platform is in DISABLED mode (LSN-001-class production-misconfiguration smell); (b) the platform's full Permission catalog by name (some Permission names hint at platform capabilities — `LOOKUP_TABLE_*` discloses the lookup-table feature exists); (c) the dummy identity is `admin` lowercase (collision surface per sidecar `bugs_limitations_corner_cases.[5]`); (d) the platform's exact Permission enum size (a fingerprint that narrows the version range when combined with `/api/appInfo`'s `projectVersion` disclosure per DOC-GAP-037).
