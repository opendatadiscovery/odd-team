## Description

The `POST /ingestion/metrics` endpoint is **completely undocumented end-to-end** on the live site. Active-platform-features landing enumerates only 5 features (Alerting / Notifications / Activity Feed / Data Collaboration / GenAI assistant) — Metrics Ingestion is absent. The configuration page documents the `metrics.storage` switch + `tenant_id` Prometheus label, but the endpoint itself, its payload shape, response, body-size limit, auth posture, and failure modes have no operator-facing page. Custom-metrics integrators have only the external ingestion-api spec; no operator-facing narrative. Anyone authoring a third-party metrics push uses guesswork.

Three additional operator-trap caveats need canonical homing:

**F-030a — Missing-page (endpoint shape).** Endpoint accepts `MetricSetList` (list of MetricSet each carrying an ODDRN + MetricFamily list — 5 metric types: COUNTER / GAUGE / HISTOGRAM / SUMMARY / GAUGE_HISTOGRAM). Returns 201 Created. Body up to 20MB (application.yml:14-15). Two storage backends dispatched via `@ConditionalOnProperty(metrics.storage)`; default INTERNAL_POSTGRES; invalid value (e.g. ELASTICSEARCH) fails with NoSuchBeanDefinitionException at boot.

**F-030b — Tenant isolation NONEXISTENT on default INTERNAL_POSTGRES (strengthens DOC-GAP-082 META).** Postgres tables `metric_series`/`metric_point`/`metric_entity` have NO `tenant_id` column. The `odd.tenant-id` config is appended as a Prometheus label only (PROMETHEUS extractor path). Operators reading the storage-backend doc and choosing INTERNAL_POSTGRES because it's the default + the tenant_id config exists will reasonably assume multi-tenant isolation. They don't get it. Current "Ignored when INTERNAL_POSTGRES" framing reads as a "minor PROMETHEUS-only feature" not "you cannot multi-tenant the default backend." Sibling to LSN-001/LSN-002 silent-default-data-loss class.

**F-030c — Live security docs imply OAUTH2 protects sibling /ingestion paths; /ingestion/metrics NOT enumerated as uncovered (strengthens DOC-GAP-038).** The enable-security page enumerates uncovered sibling paths verbatim: "All other `/ingestion/*` paths (e.g. `/ingestion/alert/alertmanager`, `/ingestion/entities/degs/children`, `/ingestion/entities/datasets/stats`)". `/ingestion/metrics` is NOT in the enumeration but IS whitelisted via `/ingestion/**` (SecurityConstants.java:96) and matched by no filter. An operator hardening with `auth.type=OAUTH2` + `auth.s2s.enabled=true` + `auth.ingestion.filter.enabled=true` (most-security-conscious config) STILL leaves `/ingestion/metrics` anonymously reachable.

**F-030e — Storage migration one-way.** A deployment running INTERNAL_POSTGRES then switching to PROMETHEUS has existing Postgres metric_series data UNREADABLE (read path queries Prometheus, not Postgres). No operator tooling exists to migrate historical data. Adjacent to LSN-001 silent-default-data-loss class.

**F-030f — Landing-page enumeration gap.** Metrics Ingestion is a real user-observable surface (per-DataEntity "Metrics" tab on entity-detail pages reads from `metric_series`/Prometheus via `GET /api/dataentities/{id}/metrics`; push side is `/ingestion/metrics`). Both visible to operators; neither named on the active-platform-features landing.
