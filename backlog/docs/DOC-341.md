## Description

`data-lineage.md` line 17 (the **Data Objects Lineage** bullet in the Subsections list) describes the per-entity lineage backing endpoint as:

> Backed by `/api/dataentity/{id}/lineage` plus the dedicated group-lineage endpoint.

That route does not exist. It is wrong on two counts:

1. **Singular vs plural collection segment.** The real collection segment is `dataentities` (plural), not `dataentity`. A caller who copies `/api/dataentity/{id}/lineage` gets a 404.
2. **Combined vs stream-split.** There is no single combined `/lineage` endpoint for a data entity. Upstream and downstream are two separate endpoints: `/api/dataentities/{data_entity_id}/lineage/upstream` and `/api/dataentities/{data_entity_id}/lineage/downstream`. (The combined `/lineage` form exists only for *groups* — `/api/dataentitygroups/{data_entity_group_id}/lineage` — which is the "dedicated group-lineage endpoint" the bullet separately, and correctly, alludes to.)

This misleads two readers: an operator scripting lineage queries against the wrong URL (immediate 404), and a doc reader who follows the bullet to its child page `data-lineage/data-objects.md`, which documents the correct split plural endpoints — so the intro contradicts its own child page. This is the same singular/plural + split-stream lineage-endpoint class already corrected on other surfaces by DOC-043, DOC-087, and DOC-226; this is the residual occurrence on the lineage section's intro page.
