## Description

Three small UX/behaviour pins harvested 2026-06-08.

1. **Server-side id-ASC list ordering (F-036, H-006).** The generic reactive CRUD `list(page, size, nameQuery, ids)` paginates with a fixed `OrderByField(idField, SortOrder.ASC)` (`ReactiveAbstractCRUDRepository.java:90-91`), so every entity type backed by this base lists in insertion-id ascending order regardless of any user expectation of name/recency ordering. **Gate: characterization-pin (LSN-029)** — assert the CURRENT default order is id-ASC; RED if the base default ordering changes (e.g. to name or updated-at). This is the intended-but-undocumented ordering contract for all generic lists.

2. **Run list: end-time ordering + class-gate message (F-040, H-007/H-009).** Data-entity runs are paginated by `DATA_ENTITY_TASK_RUN.END_TIME` `SortOrder.DESC` (`ReactiveDataEntityTaskRunRepositoryImpl.java:178-179`) — ordered by END time, not start time, so an in-progress run with a null/late end-time sorts unexpectedly. Separately, `DataEntityRunServiceImpl.getDataEntityRuns` rejects entities whose class is not transformer/quality-test with `BadUserRequestException("Data entity with id %d is not supposed to have runs due to its class")` (`DataEntityRunServiceImpl.java:36-37`, gate at `:42-44`). **Gate: characterization-pin** for the end-time ordering (assert DESC-by-end-time; RED if it changes to start-time) + **validates-feature** for the class-gate (assert the message-quality + that a non-runs class yields `BadUserRequestException`, and a 404 `NotFoundException` for a missing entity at `:33-34`).

3. **Uncontrolled severity select never re-syncs (F-057, H-011).** `TestReportDetailsOverview` renders the severity `AppSelect` with `defaultValue={qualityTest?.severity || DataQualityTestSeverity.MAJOR}` (`TestReportDetailsOverview.tsx:84`) — `defaultValue` (not `value`) makes it UNCONTROLLED. After mount, if `qualityTest.severity` changes (refetch, or another user's update), the select does NOT re-sync to the new value. **Gate: characterization-pin (LSN-029)** — assert the CURRENT behaviour (the rendered select value does not follow a changed `qualityTest.severity` prop); RED when converted to a controlled `value=` (the fix).

For each characterization-pin: it asserts the CURRENT (incorrect/undocumented) behaviour and goes RED when changed (LSN-029) — never `@Disabled`. On RED, invert to pin the corrected behaviour and re-tag `@regresses`.
