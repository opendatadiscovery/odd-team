# DataEntityController#addDataEntityDataEntityGroup — semantic understanding

## understanding

`addDataEntityDataEntityGroup` is the reactive `POST /api/dataentities/{data_entity_id}/data_entity_group` handler — six lines that read the request body as `Mono<DataEntityDataEntityGroupFormData>`, call `dataEntityService.addDataEntityToDEG(dataEntityId, fd)`, and lift the resulting `DataEntityRef` of the parent DEG into `200 OK`. The endpoint binds an arbitrary data entity (any class) as a CHILD member of a manually-created Data Entity Group (DEG / Domain / ML Experiment / DAG / DATABASE_SERVICE / API_SERVICE / KAFKA_SERVICE — all the `DATA_ENTITY_GROUP`-class subtypes per `DataEntityClassDto.java:50`), producing one row in `group_entity_relations(group_oddrn, data_entity_oddrn)`. Authorization is enforced centrally by a `SecurityRule` for `POST /api/dataentities/{data_entity_id}/data_entity_group` that demands the `DATA_ENTITY_ADD_TO_GROUP` permission, evaluated per **parent-data-entity** (the entity being placed into the group, NOT the group itself) through the `DataEntityPermissionExtractor` Policy-resolution pipeline. Unlike the Owner/Title/Tag side-doors in batches F/K and G/REFACTOR-223 family, this endpoint does NOT auto-create the target DEG — `switchIfEmpty(BadUserRequestException("...is not manually created DEG"))` at `DataEntityServiceImpl.java:395-397` rejects the call when the target id is missing or not a manually-created DEG; the maintainer must pre-create the DEG via `POST /api/dataentitygroups` (gated by `DATA_ENTITY_GROUP_CREATE`).
