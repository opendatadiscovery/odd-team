## Description

`data-discovery/business-names.md` states that **both** entity renames and field (column) renames are recorded in the Activity Feed as `BUSINESS_NAME_UPDATED`. That is true for the entity side but **false for the field side**: a dataset-field / column rename emits **`DATASET_FIELD_INTERNAL_NAME_UPDATED`**, not `BUSINESS_NAME_UPDATED`.

The operational consequence is silent: someone who builds an audit or alerting view that filters the Activity Feed on `BUSINESS_NAME_UPDATED` to catch "renames" will catch entity renames but **silently miss every column rename**. Because the missed events still exist under a different type, nothing surfaces the gap — the filter just returns fewer rows than reality. Critical (incorrect documentation that an operator builds an audit filter against).

**Failure shape**: code-doc drift — wrong activity event-type name for the field-rename case.
