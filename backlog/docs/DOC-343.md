## Description

**This reopens the converge-to-zero closure of DOC-036** ("Fix OKTA provider env var copy-paste bug (says 'google')", status `done`). DOC-036 corrected the `PROVIDER=google`-under-an-Okta-client bug on the canonical page `oauth2-oidc.md`, but a **second, orphaned copy of the same snippet still carries the bug**, so the class was not actually driven to zero residue.

The orphaned file is `docs/.gitbook/includes/auth-type-oauth2-oa....md`. Its two tabs disagree with each other:

- **YAML tab (line 12):** `provider: okta` — correct.
- **Environment-variables tab (line 29):** `AUTH_OAUTH2_CLIENT_OKTA_PROVIDER=google` — wrong.

An operator who copies the env-vars tab configures an Okta-keyed client (`okta` registration id, Okta issuer/redirect) but sets its `provider` to `google`. The platform dispatches OAuth2 user handling by the `provider` string: `GoogleUserHandler.shouldHandle(provider)` returns true when `provider.equalsIgnoreCase("GOOGLE")`. So the Okta client is routed through `GoogleUserHandler`, which reads Google-specific ID-token claims (`hd` domain, Google admin-attribute handling) that an Okta token does not carry as Google expects — a broken / mis-routed Okta login.

The file is **an orphaned, drifted duplicate**, not a live include:

- It is referenced by **zero** `{% include %}` directives anywhere in `documentation/docs` (grep confirms no page embeds it).
- It is **absent from `SUMMARY.md`** (never rendered as a standalone page).
- The canonical home for this content, `oauth2-oidc.md`, already carries the corrected Okta examples (YAML `provider: okta` at line 429; env-vars `AUTH_OAUTH2_CLIENT_OKTA_PROVIDER=okta` at line 445).

So it is a Gate 1 (no-duplicates) / Gate 10 (single-home) violation that additionally still ships the DOC-036 bug. DOC-277 (status `done`) recorded a note that this file is "embedded into other pages" — that note is **false** (zero includes reference it) and should be corrected as part of this fix.
