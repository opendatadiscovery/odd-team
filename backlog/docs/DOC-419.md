## Description

Two non-obvious behaviours of the dataset structure-compare viewer are not documented, and both are **distinct from** the security/error caveats already on the schema-diff page (PLT-028 / DOC-192 cover the cross-dataset version-id leak and the 500/400 error-mapping confusion — see `docs/data-discovery/schema-diff.md:57-71`):

1. **"Show changes only" is client-side paint-only.** Toggling the checkbox does not reduce what is fetched or parsed. The compare query's React-Query key is keyed only on `[dataEntityId, firstVersionId, secondVersionId]` (`datasetApi.ts:20`), the `queryFn` always calls `getDataSetStructureDiff` with just the version pair — `showChangesOnly` is **not** passed to the server (`datasetApi.ts:21-26`) — and the full field list is materialised into the complete compare tree by `makeCompareFieldsTree` in the `select` step, with the toggle applied only after the tree is built (`datasetApi.ts:27-32`, where `showChangesOnly` is one of the args to `makeCompareFieldsTree`). So there is **no transfer or parse saving**: the full diff is always over the wire and the full tree is always constructed; the checkbox only changes what is painted. An operator who flips it on a very large schema expecting a lighter/faster fetch gets the same payload.

2. **"Close" lands on the latest structure, not "back".** The Close button calls `handleCloseClick`, which navigates to `datasetStructurePath(dataEntityId)` (`DatasetStructureCompareHeader.tsx:31-33`, invoked from the Close `Button` at `DatasetStructureCompareHeader.tsx:82`). That route is the dataset's current/latest Structure view — not the previous page in history — so the chosen revision pair and the compare context are dropped. Combined with the fact that the compare URL carries the version pair in the query string, leaving via Close (rather than browser-back or copying the URL) loses the comparison the operator had set up. The Data Quality dashboard page already lists "the Dataset Structure compare view" among surfaces whose state resets when you leave through anything that does not preserve the URL (`docs/data-quality/dashboard.md:98`); this item documents the specific Close-button behaviour at the canonical schema-diff home and cross-links it.

Both are UX/performance expectations, not data-loss or security issues. The canonical home is the schema-diff page's existing "Known limitations and operator caveats" section.
