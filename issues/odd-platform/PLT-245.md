## Description

#1776 exposed a blind spot the existing CI i18n guard
(`odd-platform-ui/src/locales/__tests__/i18n-key-parity.test.ts`, from #1751/#1783) does not
cover: it checks **key-set parity** and **unwrapped-literal presence**, but never the
**correctness of a VALUE**. The natural-keys pattern (key == English text) means most values
are safely glossable, but for a **symbolic** key — where the en value deliberately differs from
the key (e.g. `main search placeholder` → "Search data tables, feature group, jobs and ML
models via keywords") — a translator working from the key list alone translates the **key's
words**, not the value. All six non-en catalogs did exactly that in #1776, and CI stayed green.

## Why the issue's proposed check (value == key) is NOT sufficient

#1776's "Suggested fix #3" proposed flagging "any catalog entry whose value case-insensitively
equals its key in a non-en catalog when the en value differs from the key." But the #1776
defects are **not** literal copies of the key string — they are *translations of the key's
meaning* (`espacio para búsqueda principal`, `主搜索占位符`, …). None equals the literal key
`main search placeholder`, so a `value == key` check would have flagged **none** of them. The
prevention needs to detect *"the value tracks the KEY's short meaning rather than the en
VALUE"*, which is harder than string equality.

## Sketch of a workable guard (for the implementer to design)

Candidate approaches (pick/combine after design):
1. **Symbolic-key allowlist + value-shape check.** Maintain the small set of keys where
   `en[value] !== key` (today just `main search placeholder`). For each, assert every non-en
   value has the en value's *structural shape* — e.g. it is a multi-item hint (contains ≥2 list
   separators `,`/`、`), or its length is within a band of en's — not a short key-gloss. (This is
   the heuristic CTRIB-036's unit test uses for the one key; PLT-245 is to generalise it.)
2. **Symbolic-key review gate.** Flag any symbolic key (en value ≠ key) whose non-en value was
   not explicitly reviewed-as-value-translation (an allowlist/annotation the translator ticks).

## Why deferred from #1776 / CTRIB-036

Separable CI-tooling, and the naive check would give false confidence without catching the real
class. CTRIB-036 ships the user-facing value fix + a focused unit guard for the one key; this
generalises the prevention so the next symbolic key cannot silently regress.
