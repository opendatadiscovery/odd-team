## Description

Five of the platform's most-trafficked read/admin surfaces lay their content out with **fixed desktop grids and no responsive breakpoint**, so their behaviour at 360–768px (tablet portrait, split-pane half, phone) is unobservable from static source and currently has zero coverage. The five feature-reflections each independently surfaced this as a `probe-needed` hypothesis (it cannot be graded by reading `.tsx` — the responsive outcome lives in MUI breakpoints + `S.*` styled-component definitions + rendered layout):

- **F-177 — entity detail-page Class/Type badge row.** `DataEntityDetailsHeader.tsx:74-101` renders the badge `<Grid container item lg={7} alignItems='center' flexWrap='nowrap'>` with an unbounded `entityClasses?.map(...)`, sharing the `lg={7}` cell with the `noWrap` entity name and the business-name Edit button. No `sm`/`md` override. On a narrow viewport a multi-class entity's badges, name, and Edit button contend in one non-wrapping cell. (F-177 H-010 → PENDING-F-177-1.)
- **F-191 — dataset Revision Compare viewer.** `DatasetStructureCompareHeader.tsx:85,115` lays the From/To pickers as two `xs={6}` columns and the diff is a side-by-side two-column field layout (`S.FieldWrapper`); the responsive breakpoints are not statically determinable. (F-191 H-010 → PENDING-F-191-2.)
- **F-161 — Management section chrome.** `Management.tsx:13-19` is `<S.Container container wrap='nowrap'>` with a fixed `xs={3}` sidebar + `xs={9}` content and a vertical `AppTabs` (`ManagementTabs.tsx:57-62`) — no `md`/`lg` variant, no hamburger, no collapse. The narrow-viewport crush threshold is unverified. (F-161 H-004 confirmed-structure + H-009 → PENDING-F-161-2.)
- **F-151 — term detail page.** `TermDetails.tsx:55-84` composes a five-tab strip + header CTAs + Overview mini-panels with no breakpoint detail in any sidecar; whether `AppTabs` overflow and the mini-panels reflow vs clip at ~768px is unknown. (F-151 H-013 → PENDING-F-151-2.)
- **F-176 — entity Overview tab.** `Overview.tsx:54,93` declares `<Grid item xs={9}>` + `<Grid item xs={3}>` with no `md`/`sm` overrides — in MUI `xs` applies at every width, so the 25% sidebar never stacks below the main pane on a phone. Desktop-first, undocumented, and inconsistent with the Search/Catalog responsive layouts. (F-176 H-011 → PENDING-F-176-2.)

**Typed gate: characterization-pin (per LSN-029).** These surfaces are NOT going to be made responsive as part of this item (no functional code change is in scope), and the live docs are SILENT on responsive/desktop-only support (verified per each reflection's WebFetch, 2026-06-03). So the ITs pin the **current** degradation: at the narrow viewport each surface today either (a) crushes/clips/overflows or (b) renders usably. Whichever it is, the assertion captures it as the present behaviour and goes RED the instant a responsive fix (or a regression) changes it — making any future `xs={12} md={9}` / collapse-affordance fix a deliberate, test-visible decision rather than a silent change. The probe (PENDING-F-* per surface) sets the exact assertion before the IT is authored; this backlog item is the IT that the probe outcome graduates into.

## Acceptance Criteria
- [ ] An e2e IT (Playwright, viewport driven via `page.setViewportSize`) asserts the **current rendered behaviour** of each of the five surfaces at narrow widths {≈768 tablet portrait, ≈375/360 phone} against a seeded local stack:
  - [ ] **F-177 header badge row** — open a seeded multi-class entity (e.g. ENTITY_GROUP + TRANSFORMER + QUALITY_TEST + SET) at /dataentities/{id}/overview; assert the captured state of the `h0` entity name (visible / zero-width / truncated), the class badges (within viewport / clipped), and the business-name Edit button (reachable / pushed off-screen) — per PENDING-F-177-1.
  - [ ] **F-191 compare viewer** — open the compare page on a dataset with ≥2 revisions; assert the captured state of the two-column diff container (no-overflow / horizontal-scroll / overlap) and that both From/To `xs={6}` pickers are clickable — per PENDING-F-191-2.
  - [ ] **F-161 management chrome** — open /management; assert the captured state of the fixed `xs={3}` sidebar tab labels (legible / crushed) and the `xs={9}` content pane against the dense Datasources/Collectors/Policies rows — per PENDING-F-161-2.
  - [ ] **F-151 term detail** — open a seeded term detail page; assert the captured state of the five-tab strip (all tabs reachable / overflow) and whether the Overview mini-panels reflow or clip — per PENDING-F-151-2.
  - [ ] **F-176 Overview tab** — open an entity Overview; assert the captured state of the `xs={9}`/`xs={3}` two-column grid (sidebar stacked-below / squeezed to 25%) and panel legibility — per PENDING-F-176-2.
- [ ] Each assertion is written as a characterization pin: it documents today's behaviour and is annotated (in-spec comment) with the LSN-029 flip protocol — on RED, if a responsive fix landed, invert the assertion to the responsive expectation; if unplanned, investigate.
- [ ] The IT is GREEN as a tripwire on the canonical suite (`run-suite.sh`), is not skipped/`test.fixme`, and does not break the build.
- [ ] If any surface is found genuinely responsive at narrow width (MUI defaults sufficed), that branch is pinned as the confirmed-good state (still a regression guard), not dropped.
