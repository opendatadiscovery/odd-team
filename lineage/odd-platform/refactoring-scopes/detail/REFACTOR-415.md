- **REFACTOR-415** (NEW 2026-05-19O): `NotFoundException` on unknown datasource/collector surfaces as 5xx (not 401). The parent only catches `AccessDeniedException` to write a 401 response; any other exception (including `NotFoundException` for missing datasource OR missing collector fallback) propagates to the default reactive error handler and surfaces as 500 Internal Server Error. An attacker probing the endpoint with arbitrary payload + valid token can distinguish "datasource exists, wrong token" (401) from "datasource does not exist" (5xx) — minor info-leak. An operator hitting a half-configured collector gets a misleading status code
  - **Category**: error-mapping
  - **Surfaced by**:
    - `IngestionDataEntitiesFilter.md:bugs_limitations_corner_cases.[7]` (LOW info-leak / MEDIUM operator-debug)
  - **Statement**: `IngestionDataEntitiesFilter.java:43-51` throws `NotFoundException("dataSource", oddrn)` when the body's `dataSourceOddrn` doesn't match a known datasource AND `NotFoundException("collector", ...)` when the datasource has no token AND its parent collector also has no token. The parent `AbstractIngestionFilter.filter` at line 40 ONLY catches `AccessDeniedException` to write a 401 response — any other exception propagates to Spring's default reactive error handler and surfaces as 500 Internal Server Error. Consequences: (a) operator-debug-hostile (a misconfigured collector produces 500 instead of 404 or 401); (b) minor info-leak (an attacker probing with arbitrary payload can distinguish "datasource exists, wrong token" → 401 from "datasource does not exist" → 5xx).
  - **Evidence**: `IngestionDataEntitiesFilter.java:43-51` (NotFoundException throws) + `AbstractIngestionFilter.java:40` (only catches AccessDeniedException)
  - **Existing-ADR-or-implied-prescription**: No existing ADR. The exception mapping is an implementation-detail oversight; the maintainer should have either (a) mapped NotFoundException to 401 (or 404) explicitly, or (b) caught all exceptions in the filter and mapped to clear status codes.
  - **Proposed remedy**: Either (a) catch `NotFoundException` in `AbstractIngestionFilter.filter` and write a 401 (or 404) with a generic "unauthorized" message — DON'T leak whether the datasource exists; (b) refactor the filter's exception model: define a single `IngestionAuthFailure` exception type with sub-types (`TokenMissing`, `TokenIncorrect`, `DatasourceUnknown`, `CollectorUnknown`) and map all to 401 with the same generic message. The defensive choice is (a); the architecturally-cleaner choice is (b).
  - **Severity rationale**: LOW (info-leak) / MEDIUM (operator-debug) — minor info-disclosure; operator-confusing status code.
