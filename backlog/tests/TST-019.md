## Description

The integration code-snippet wizard compiles a server-supplied manifest template with Handlebars and renders the result as Markdown. `IntegrationCodeSnippetWithForm` does `Handlebars.compile(snippet.template)` (`IntegrationCodeSnippetWithForm.tsx:3,22-24`), executes it with the user's form args (`templateWithArguments = compiledTemplate(snippetArgs)`, line 26), and passes the output to `<Markdown value={templateWithArguments} />` (`IntegrationCodeSnippetWithForm.tsx:130`).

That `Markdown` component, in non-editor mode, renders via `MDEditor.Markdown source={value}` with a `components` override map and no explicit `rehype`/sanitiser config visible in the component (`Markdown.tsx:113-124`). Whether a careless or hostile manifest `template` (these ship from collector/integration definitions, not necessarily authored by the viewing operator) can smuggle executable script into the page therefore depends entirely on the `@uiw/react-md-editor` default rehype schema — i.e. whether raw HTML / `javascript:` hrefs / event handlers in the markdown source are stripped or passed through. The report flags this as unverified: it depends on the renderer schema, which must be measured, not assumed.

**Typed gate: validates-feature (security regression), probe-gated.** This is a regression tripwire, not a known-bug pin — there is no confirmed exploit yet. The deliverable is PENDING-F-162-1: feed the render path adversarial template payloads (raw `<script>`, an `<img onerror=...>`, an `<a href="javascript:...">`, and a Handlebars triple-stash `{{{x}}}` that emits raw HTML) and assert NO script executes and no dangerous attribute survives. The test locks the current safe behaviour so a future dependency bump or a switch to a raw-HTML render mode that opens an XSS hole goes RED. If the probe instead demonstrates an actual injection today, this stops being a regression test and is re-filed as a SEC-/PLT- bug via follow-up-on-disk before any pin is written.

## Acceptance Criteria
- [ ] PENDING-F-162-1 establishes the renderer's behaviour: render `IntegrationCodeSnippetWithForm` (or `Markdown` directly) with manifest templates containing (a) a literal `<script>` tag, (b) an `<img src=x onerror="...">`, (c) a markdown link with a `javascript:` href, and (d) a Handlebars triple-stash emitting raw HTML, and observe whether any executes or survives in the DOM.
- [ ] A security regression test asserts the SAFE outcome for each payload: no `<script>` node executes, no inline `on*` handler attribute is present on the rendered nodes, `javascript:` hrefs are neutralised, and rendered output contains no live raw-HTML injection — pinning the current behaviour so a regression flips it RED.
- [ ] If the probe shows any payload DOES execute / survive, the test is NOT shipped as a passing regression guard: file a SEC-/PLT- bug capturing the injection (with the payload + render path file:line) and link it here; this item then becomes a follow-up to that bug rather than a green tripwire.
- [ ] The test carries an in-source note: `// validates F-162 render-path XSS posture; pinned from PENDING-F-162-1` + the flip protocol (RED on a dependency/render-mode change that opens injection → triage as a security regression, do not silence).

Medium.
