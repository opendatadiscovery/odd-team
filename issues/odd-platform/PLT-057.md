## What

Two operator-visible defects on the Lookup Tables surface. Both are independent fixes (one UI, one backend) but ship in this single PLT to bound the upstream conversation around the page.

**Defect 1 - Lookup Tables listing silently truncates at 30 rows (one-line DOM-id mismatch).** `LookupTablesList.tsx:51` declares `<ScrollableContainer id='lookup-tables-list'>`. Line 53 declares `<InfiniteScroll scrollableTarget='directory-entities-list'>` - the `scrollableTarget` references the Directory feature's DOM id (copy-pasted from the Directory infinite-scroll site), NOT the local container id. The `react-infinite-scroll-component` library cannot find `directory-entities-list` on this page; falls back to window scroll. The container has `overflow: auto`, so window scroll never fires within it. The 31st row is never requested. The list APPEARS complete (no skeleton at the bottom, no "Load more" button, no pagination indicator), but stops at 30 rows for any tenant with >30 lookup tables. The H1 counter at `LookupTables.tsx:60-62` shows the REAL total (e.g., "250 lookup tables overall") while the list shows 30 - that discrepancy IS the only operator-visible signal, and most won't notice. Per `system-mission.md:125-141` pillar P-03 Master Data Management is intentionally narrow (Lookup Tables is the SOLE child surface today); the listing bug means 100% of P-03's user-facing UX is degraded for any tenant exceeding 30 tables. Highest operator-volume impact in batch-5.

**Defect 2 - Lookup Table rename emits no ActivityEvent.** `ReferenceDataServiceImpl.updateLookupTable` (lines 107-124) has no `@ActivityLog` annotation; no `last_modified_by` column update; no version increment. The `ActivityEventTypeDto` enum (currently 27 values) has no `LOOKUP_TABLE_RENAMED` slot - would become a 28th value if added. Combined with the documented LSN-001-class ALTER-TABLE rename hazard (DOC-182 Caveat 3 - UI rename issues `ALTER TABLE ... RENAME TO` against the documented public `lookup_tables_schema` PostgreSQL surface, silently breaking downstream BI/ETL pipelines), the audit silence amplifies the blast radius: post-mortem investigations on a downstream pipeline break cannot answer "who renamed which table when" from platform logs. Cross-pillar audit-asymmetry pattern: same shape as F-057 (DQ severity audit silence) and F-025a.4 (Query Examples audit silence on DOC-183 Caveat 4) - third operator-mutating surface with no audit emission.

## Why it matters

Combined operator impact:

- **Defect 1** affects every tenant with >30 lookup tables - moderate-sized organisations exceed 30 quickly (country codes, tier mappings, customer enumerations, one table per business-domain). Pillar P-03 is intentionally narrow per `system-mission.md`; degrading the SOLE UI surface for the SOLE feature means the pillar is operationally broken for medium+ deployments.
- **Defect 2** combines with the DOC-182 Caveat 3 + the operator-action LSN-001-class default-footgun (UI metadata edit triggers downstream ALTER TABLE on the documented public schema): the operator's natural diagnostic question after a downstream pipeline break ("who renamed which table when") is unanswerable from platform logs. Forces operators to PostgreSQL `pg_audit` / external audit log + manual cross-reference.

Severity is CRITICAL because Defect 1 silently degrades pillar P-03's entire surface for any non-trivial deployment; Defect 2 is the audit-asymmetry pattern's third instance and compounds with an existing operator-action-layer default-footgun.

## Suggested fix

### Defect 1 - one-line `scrollableTarget` rename

```tsx
// LookupTablesList.tsx:53
- <InfiniteScroll scrollableTarget='directory-entities-list'
+ <InfiniteScroll scrollableTarget='lookup-tables-list'
  ... >
```

Regression-resistance: factor the container id + the scrollable target through a single shared constant (e.g., `const SCROLL_CONTAINER_ID = 'lookup-tables-list'`) so a future copy-paste cannot drift them again. Paired test in **TST-001** asserts scroll fires `fetchNextPage`.

### Defect 2 - emit `LOOKUP_TABLE_RENAMED` activity event

```java
// ActivityEventTypeDto.java - add a 28th enum value
LOOKUP_TABLE_RENAMED("LOOKUP_TABLE_RENAMED"),

// ReferenceDataServiceImpl.java:107-124 - emit on rename
@ActivityLog(event = ActivityEventTypeDto.LOOKUP_TABLE_RENAMED, ...)
public Mono<ReferenceTableDto> updateLookupTable(...) {
    // capture old name + new name into activity context
    ActivityContextInfo.set("oldName", table.getTableName());
    ActivityContextInfo.set("newName", formData.getName());
    // ... existing logic ...
}
```

After landing, the activity feed picks up the rename audit; combined with PR-2 on PLT-019 (LSN-001-class rename warning UI), the LSN-001-class operator-action surface is fully closed.
