## What

Five operator-visible defects on the Dataset Schema Revision History + Compare Viewer surface - three backend, two UI-tier amplifiers that reach the backend defects through normal URL-paste workflows.

**Defect 1 - Cross-dataset version-id leak (backend; F-045a).** `ReactiveDatasetVersionRepositoryImpl.getDatasetVersion:129`:
```java
.where(DATASET_VERSION.ID.eq(datasetVersionId))
```
Single predicate on `version_id` only. NO `data_entity_id` enforcement. The controller passes BOTH ids - the DROP happens one layer down, in the SERVICE: `DatasetVersionServiceImpl.getDatasetVersion(datasetId, datasetVersionId):39-44` calls `repository.getDatasetVersion(datasetVersionId)` and uses `datasetId` ONLY in the not-found message (`:42-43`). The diff path drops it the same way: `getDatasetVersionDiff(datasetId, ...):56-63` calls `repository.getDatasetVersionWithFields(List.of(firstVersionId, secondVersionId))`, whose query (`:147-157`) is scoped solely by `.where(DATASET_VERSION.ID.in(datasetVersionIds))` (`:154`) - no dataset predicate. (Correction 2026-06-10: the original "consumed by the controller and DROPPED ... same predicate doubled" was imprecise - the controller forwards both ids; the service ignores `datasetId`; the diff predicate is a single `.in(versionIds)`, not a doubled one.) ODD has no object-level authorization (permissions are global/role-based per `reference_odd_platform_auth_modes`), so any caller authorized to read ONE dataset's structure reads ANY dataset's full schema (field names + types + descriptions + tags + terms + lookup-table definitions) by enumerating `version_id`. Under `auth.type=DISABLED`, anonymous.

A true 404 still happens for a version-id that exists NOWHERE: `getDatasetVersion` uses `switchIfEmpty(NotFoundException)` (`:41-43`). The leak is specifically for an id that exists under a DIFFERENT dataset - it returns 200 with that dataset's structure.

**Defect 2 - UI URL-paste amplifier (F-191a).** `DatasetStructureCompare.tsx:24-26 + 30-35` reads `firstVersionId` and `secondVersionId` from `useQueryParams` and passes them directly into the fetch hook **WITHOUT** validating they appear in the loaded `datasetVersions` array. Paired with Defect 1, a pasted URL with version-ids from another dataset returns 200 with a structurally-valid but semantically-nonsense diff. The compare viewer is a TRUSTED audit surface; operators reasoning about "what changed between V1 and V2" can be misled by a URL from chat / docs / bookmark.

**Defect 3 - Diff endpoint asymmetric error model (F-045b).** `DatasetVersionServiceImpl.java:69-71`:
```java
throw new RuntimeException("Query returned %s rows for diff request".formatted(versionFields.size()));
```
Bare `RuntimeException` on a missing version-id (the query returns <2 rows) -> falls through to `ControllerAdvice`'s catch-all `@ExceptionHandler(Exception.class)` (`ControllerAdvice.java:61-62`) -> 500. Identical version-ids get a clean `BadUserRequestException` (`DatasetVersionServiceImpl.java:59-60`) -> 400 (`ControllerAdvice.java:24-26`). A caller cannot distinguish "platform broken" from "wrong id" - debugging workflow defeated. (Mappings verified 2026-06-10 against `ControllerAdvice.java`.)

**Defect 4 - UI AppErrorPage swallows 4xx vs 5xx (F-191b).** `DatasetStructureCompare.tsx:46-51`:
```tsx
<AppErrorPage showError={isError} ... error={error as unknown as ErrorState} offsetTop={210} />
```
One-size-fits-all error rendering. Defect 3 backend returns 500 on missing version-ids and 400 on identical version-ids; both bubble through this surface as the same AppErrorPage. A user typing a wrong id sees the same UI as a platform outage.

**Defect 5 - "Latest" means max(version), not max(created_at) (F-045c).** `ReactiveDatasetVersionRepositoryImpl.java:160-217 (getLatestDatasetVersion)` at line 161:
```java
Field<Long> dsvMaxField = max(DATASET_VERSION.VERSION).as("dsv_max")
```
`created_at` is not referenced. Under normal ingestion (version monotonically increases) the two are equivalent. Under manual SQL fixup or collector replay (operator re-ingests an old version, or the platform restores from backup), the two diverge - an operator reading `/api/datasets/{id}/structure` (no version_id) gets the max-VERSION row, which may be older than the actual most-recently-created row.

## User-facing impact

WHO: any user who can open a dataset's Structure tab (or, under `auth.type=DISABLED`, anyone on the network); an API consumer of `/api/datasets/{id}/structure*`.

- **Defect 1 (cross-dataset schema read) - verified by BE trace 2026-06-10, structurally settled.** The service drops the dataset-scoping id (`DatasetVersionServiceImpl:40,62`) and the repository queries by `version_id` alone (`:129`, `:154`); ODD has no per-object authorization, so a caller who can read one dataset's structure can read ANY dataset's full schema by enumerating/pasting a foreign `version_id`. No drive needed - the absence of a dataset predicate is a pure code fact. The user observably gets HTTP 200 + the other dataset's fields (not a 404).
- **Defect 2 (UI amplifier) + Defect 1 - verified by FE/BE trace 2026-06-10.** `DatasetStructureCompare.tsx` passes the URL `firstVersionId`/`secondVersionId` straight into the diff fetch (`:30-35`) with no check against the loaded `datasetVersions` (`:28`). A pasted compare URL carrying another dataset's version-ids therefore renders that dataset's real diff under dataset A's page, while the header dropdowns still show A's versions - a misleading "what changed" surface on a trusted audit screen. Deterministic from the two settled code facts above.
- **Defect 3 + Defect 4 (error-model) - verified by trace 2026-06-10.** A diff request with a non-existent version-id returns 500 (bare `RuntimeException` -> catch-all, `ControllerAdvice:61-62`); identical ids return 400 (`:24-26`). The FE renders both through the same `AppErrorPage` (`:47-51`, no `error.status` branch), so a user who typed a wrong id sees the same screen as a platform outage.
- **Defect 5 (max(version) latest) - static trace consistent; not driven.** The query orders by `max(DATASET_VERSION.VERSION)` (`:161`), not `created_at` - a settled code fact. The user-visible divergence ("latest shows an older row") only manifests when VERSION and CREATED_AT disagree (collector replay / manual SQL / backup restore); confirming that observable needs that data condition set up. Under normal monotonic ingestion the two agree, so no user sees it day-to-day.

## How to reproduce (Defect 1)

1. Take two datasets, A and B, both with schema versions. Get a version-id from B (e.g. via `GET /api/datasets/{B.id}/structure`).
2. As any authenticated user (or anonymous under DISABLED), call `GET /api/datasets/{A.id}/structure/{B.version_id}`.
3. The response returns B's schema, NOT a 404. The path component `A.id` is descriptive only.
4. Reachable via the UI's compare viewer with a hand-pasted URL `/dataentities/{A.id}/datasetStructure?firstVersionId=B.v1&secondVersionId=B.v2` (Defect 2).

## Suggested fix (five threads)

**Thread A - Per-dataset scoping on read paths (Defect 1; the headline).** Add `.and(DATASET_VERSION.DATASET_ODDRN.eq(datasetOddrn))` predicate to the by-id and diff paths in `ReactiveDatasetVersionRepositoryImpl`. The controller resolves `dataEntityId` to `oddrn` via existing repository helpers. Restored: 404 on cross-dataset version-id. The fix is per-line at the WHERE clauses; ~4-6 lines across the by-id and diff paths.

**Thread B - Client-side validation on the compare viewer (Defect 2).** In `DatasetStructureCompare.tsx`, before firing the fetch hook, validate `firstVersionId  in  datasetVersions[]` AND `secondVersionId  in  datasetVersions[]`. Render an inline "Invalid version-id, please re-select" if the check fails - distinct from the AppErrorPage outage treatment. Defence-in-depth even after Thread A lands.

**Thread C - Typed NotFoundException on missing version-id (Defect 3).** Replace the bare `RuntimeException` at `DatasetVersionServiceImpl.java:69-71` with a typed `NotFoundException("Dataset version {} not found")` - `ControllerAdvice` maps to 404. The caller can distinguish "wrong id" (404) from "platform broken" (5xx) from "bad request" (400).

**Thread D - Differentiate 4xx vs 5xx in AppErrorPage (Defect 4).** In `DatasetStructureCompare.tsx`, branch on the error status: 4xx renders a typed inline error ("Invalid version-id" / "Identical version-ids" / "Not authorised"); 5xx escalates to the AppErrorPage outage treatment. The differentiation pattern is reusable across the platform UI - consider lifting into a shared error-renderer hook.

**Thread E - Switch order key to max(CREATED_AT) (Defect 5).** Replace `max(DATASET_VERSION.VERSION)` at line 161 with `max(DATASET_VERSION.CREATED_AT)`. Document the historical behaviour as a doc caveat in the migration window (DOC-192). After the fix, "Latest" matches operator intent - the row created most recently is the one read.

## Operator impact

- Multi-tenant deployments cannot enforce per-team schema visibility - Defect 1.
- The compare viewer can render misleading diffs from forged URLs - Defect 2.
- Debugging workflow defeated - Defect 3 + Defect 4.
- Operators re-ingesting old versions see unexpected "latest" - Defect 5.
