## Description

`test-run-history.md` directs operators to a route that does not exist and conflates two distinct UI surfaces under it.

The page (lines 13-14, 30, 39, 50) repeatedly names **`/test-report`** as the surface that shows "the first 10 runs as a preview." There is no `/test-report` route in the platform. The route token is **`test-reports`** (plural) — `DataEntityDetailsRoutes.TEST_REPORTS = 'test-reports'` — and the per-test report path is built by `dataEntityTestReportsPath(...)` as `/dataentities/{id}/test-reports/{dataQATestId}/{overview|history}`. An operator who "pastes `/test-report`" lands nowhere (or on the SPA 404 fallback).

The two surfaces the page treats as one:

1. **Full history (100/page, infinite-scroll, status filter)** — `TestRunsHistory.tsx`: `pageSize = 100`, `InfiniteScroll`, an `AppSelect` status dropdown. Rendered under the entity's **History** tab. The page describes this correctly as `/dataentities/{id}/history`.
2. **Size-10 preview, no pagination, no status filter** — `TestReportDetailsHistory.tsx`: `fetchDataEntityRuns({ … page: 1, size: 10 })`, a plain `.map` (no `InfiniteScroll`, no status `AppSelect`). This is the per-test-report recent-runs strip, reached at `/dataentities/{id}/test-reports/{testId}/history` (the `history` sub-path of `dataEntityTestReportsPath`), **not** `/test-report`.

An operator following the page builds a deep-link or a runbook step against `/test-report`, gets nothing, and concludes the History feature is broken when in fact the path is wrong. The HTTP-500-while-running caveat (line 50) compounds this by saying "the same 500 affects the `/test-report` first-10-runs preview" — citing the wrong path again.
