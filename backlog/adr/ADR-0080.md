## Description

**Failure shape: cross-audience absence — a dangling reference in public source.** Six merged odd-platform PRs
cite the unified-asset-search decision record **by name** in source comments an upstream contributor reads, and
the record exists only as a workspace draft. Verified on odd-platform `origin/main` (2026-08-30):

- `dto/AssetSearchCursor.java:18` — "the keyset ... depth cap (ADR unified-asset-search D12)"
- `repository/reactive/ReactiveAssetSearchRepository.java:19` — "(ST-5b / #1839, **ADR unified-asset-search D12 + ADR-0021**)"
- `repository/reactive/ReactiveAssetSearchRepositoryImpl.java:89` — "ADR unified-asset-search D12"
- `service/AssetSearchServiceImpl.java:39` — "ADR D12 / SEARCH-CAPABILITIES-DESIGN §2"
- `db/migration/V0_0_99__denormalise_asset_search_sort_columns.sql:14` — "ADR unified-asset-search D2/D12"
- (in PR #1862 / ST-5c) `V0_0_100__snapshot_popularity_score.sql` + `AssetPopularitySnapshotJob` — "ADR unified-asset-search D5 + its rev-3 SRE correction"

`ReactiveAssetSearchRepository.java:19` is the sharpest instance: **one comment cites two ADRs, and a reader can
resolve exactly one of them** — `ADR-0021` is published in the log; `unified-asset-search` is not. The published
log carries 79 ADRs (`ADR-0001`..`ADR-0079`) and none covers the search overhaul
(`git grep -l -i "unified\|asset search" origin/main -- 'docs/developer-guides/architecture-decision-log/*.md'`
returns nothing).

## The wisdom filter (all three pass)

1. **Generates a pattern** — a *second, additive* polymorphic search index beside the per-kind entrypoints (D1/D9);
   the union row as `(asset_kind, asset_id)` reusing the Favorites model (D2); denormalise-a-snapshot-never-the-live-
   counter (D5 + the SRE correction); keyset for seekable sorts / bounded OFFSET for relevance (D12). Five migrations
   and a whole controller→service→resolver→repository chain follow these rules.
2. **Carries a tangible consequence** — operators get a new table, five migrations and an always-on background job;
   maintainers inherit a hard "do NOT add a trigger on `data_entity.view_count`" constraint whose *reason* lives only
   in the draft.
3. **Constrains future work** — #1861 ("Most popular" sort), ST-9 (the numeric-range facet + histogram) and ST-14
   are all specified in terms of these decisions.
