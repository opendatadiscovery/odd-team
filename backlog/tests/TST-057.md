## Description

`search-url-facets.spec.ts:112` — *"a class tab writes the facet to the URL + refilters; the All tab removes
it (round-1 write + round-2 removal)"* (F-017 / ST-1b, part of IT-151) — is a **load-sensitive timing flake**.

- **Observed RED (once):** in the `review-ctrib050` full **feature-complete** run (337 tests, single worker,
  SUT `odd-team-sut-revctrib050` = odd-platform `2c0bfaf3`, digest `sha256:10141b3e…`), this test **failed at
  16.6s** — a timeout on one of its assertions, at position **292/337** (i.e. after ~291 prior tests had
  loaded the single-worker box + the shared stack).
- **GREEN in isolation on the same SUT:** re-running IT-151 (`ODD_STREAM=revctrib050b
  ODD_PLATFORM_IMAGE=odd-platform:odd-team-sut-revctrib050 run-suite.sh IT-151`) → **4/4 passed**, with
  `:112` GREEN in **4.7s** (well under the 15s bound). The implementer's own isolated IT-151 run was likewise
  4/4.
- **Not attributable to the CTRIB-050 / ST-1d change:** that change is a proven **no-op** for a
  class-tab-only selection (no sidebar/enum facet selected ⇒ `resolveFacetNames` returns an empty map ⇒
  `fillResolvedFacetNames` is a no-op; `entityClasses` are skipped in the resolver). The other three
  `search-url-facets` tests (`:143`, `:186`, `:226` incl. the ST-1d assertion) and all `search-url-state`
  (ST-1a) tests passed under the same full-suite load.

**Why it flakes:** `:112` is the most fragile of the four facet tests — it drives a full **round-1 write +
round-2 removal** cycle with **6 separate `{ timeout: 15_000 }` assertions**, each a UI-settle wait. Under
full-suite load (single Playwright worker, shared odd-minimal stack), one settle can exceed 15s. With
`playwright.config` `retries: 0` ("a regression pin must never be masked by a retry"), a single slow settle
becomes a hard RED — so this will **intermittently false-RED `feature-complete`** for every future
contributor/reviewer run, wasting exactly the maintainer/reviewer time the regression harness exists to save.

## Acceptance Criteria
- [ ] Decide the fix shape (prefer the least-invasive that keeps the assertion oracle intact): (a) raise the
  per-assertion timeout for this round-trip test only (e.g. 15s → 30s) to absorb full-suite load; OR (b) split
  the round-1-write and round-2-removal into two focused tests so no single test chains 6 heavy settles; OR
  (c) reduce redundant intermediate settles. Do **NOT** weaken any assertion oracle (`toHaveURL` /
  `toHaveCount(0)` / visibility must stay) and do **NOT** enable retries globally.
- [ ] `:112` passes both in isolation AND at the tail of a full `feature-complete` run (single worker) across
  ≥3 consecutive runs.
- [ ] The ST-1b behaviour it guards (class facet ⇄ URL write + REPLACE-removal) is still genuinely asserted.
