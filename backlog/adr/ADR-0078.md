## Description

The reverse-engineered ADR for the platform's **confirm-before-persist + store-reduce** pattern when
editing a field whose value drives downstream display or semantics (entity lifecycle status; DQ-test
severity). Reconstructed from the existing entity-Status control; the 0.28.0 DQ-severity work
(odd-platform#1750 / CTRIB-015) is the newest adopter and the reason the pattern is written down.

**Numbering note:** ADR-0078 = `max(backlog/adr/) + 1` (the canonical tracker; `ADR-0077` is the
methodology "retire flat index files" ADR). The published platform ADR-log max is `0076`; note the
pre-existing collision where backlog `ADR-0076` (a pending jotai-stores candidate) shares a number with
the *published* `ADR-0076` (info-tooltip, CTRIB-010). `0077` is skipped in the published log (the
methodology ADR is workspace-internal, never published to the platform docs). `0078` collides with
nothing published.
