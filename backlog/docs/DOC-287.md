## Description

`data-quality/test-results-import.md` tells operators to push custom / framework data-quality test results through `POST /api/ingestion/entities/datasets/stats`, mapping them onto a `DataEntityList` carrying `DataQualityTest` objects. Two things are wrong:

1. **Wrong payload for that endpoint.** `/ingestion/entities/datasets/stats` accepts a `DatasetStatisticsList` (per-column profiling statistics), **not** a `DataEntityList`. A `DataEntityList` sent there does not map — results never land (no-op / NPE).
2. **Wrong route for test results.** Framework test results (Great Expectations, dbt, etc.) are pushed as a `DataEntityList` (with the test + test-run entities) to `POST /api/ingestion/entities`. The `/datasets/stats` route is genuinely the profiler's route — but the page presents `/datasets/stats` as the single route for *both* profiling stats and test results, conflating two distinct ingestion contracts.

An operator following the page wires their test-results push to the wrong endpoint with the wrong payload and sees nothing arrive — silently. Critical (incorrect documentation an integrator builds against; the failure is silent data non-arrival).

**Failure shape**: code-doc drift — two ingestion contracts conflated into one; wrong endpoint + wrong payload named for the test-results case.
