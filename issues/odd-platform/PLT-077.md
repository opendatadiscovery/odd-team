## What

`AppInfoController.java:18` reads `@Value("${auth.type}") final String authType` — no `@NotBlank`, no enum constraint, no default. If an operator unsets the key (empty env var) OR typos (`OUATH2`, `LOGINFORM`), every downstream `@ConditionalOnProperty(havingValue=...)` fails to match — `DisabledAuthSecurityConfiguration` (havingValue=`DISABLED`) / `LoginFormSecurityConfiguration` (`LOGIN_FORM`) / `AuthorizationManagerCondition` (`OAUTH2` / `LDAP`) — NONE wire. The platform boots WITHOUT a `SecurityWebFilterChain` bean.

Compounded by `Overview.tsx:25-27` — `appInfo?.authType && appInfo.authType !== 'DISABLED'` evaluates to `false` for empty string AND TRUE for any typo'd non-DISABLED value, silently hiding the OwnerAssociation card or rendering it in a deployment with broken auth.

## Why it matters

Silent boot with no SecurityWebFilterChain means every endpoint is unguarded — operator deploying with `auth.type: OUATH2` (typo'd OAUTH2) ends up with the same anonymously-reachable surface as DISABLED, without the LSN-001-style explicit warning. This is a deployment-time pitfall that no integration test catches because typos are operator-side.

## Suggested fix

**Option A — @Pattern annotation on @Value (recommended, simplest).**

```java
// AppInfoController.java (and other readers if they exist)
@Value("${auth.type}")
@Pattern(regexp = "DISABLED|LOGIN_FORM|OAUTH2|LDAP", message = "auth.type must be one of DISABLED, LOGIN_FORM, OAUTH2, LDAP")
private String authType;
```

Spring's `@Pattern` validator runs at boot if `@Validated` is on the class.

**Option B — Enum-typed @ConfigurationProperties (more idiomatic Spring 3).**

```java
@ConfigurationProperties(prefix = "auth")
public record AuthProperties(AuthType type) {
    public enum AuthType { DISABLED, LOGIN_FORM, OAUTH2, LDAP }
}
```

Spring boot would fail-fast at startup if `auth.type` is unset or unparsable.

**Option C — @PostConstruct startup self-check (defensive).**

```java
@PostConstruct
void validateAuthType() {
    Set<String> validValues = Set.of("DISABLED", "LOGIN_FORM", "OAUTH2", "LDAP");
    if (!validValues.contains(authType)) {
        throw new IllegalStateException("auth.type=" + authType + " is not a valid value. Use one of: " + validValues);
    }
}
```

Recommended Option B — Spring 3 idiomatic; one place owns the contract; type-safe at compile time for downstream readers.

UI defence-in-depth: tighten `Overview.tsx:25-27` to whitelist auth-types:

```tsx
const validAuthType = ['LOGIN_FORM', 'OAUTH2', 'LDAP'].includes(appInfo?.authType);
```
