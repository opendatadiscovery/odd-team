## Description

`PUT /api/tags/{tag_id}` (`updateTag`, `openapi.yaml:381`) responds with the `Tag` schema, which declares `external` and `usedCount` properties (`components.yaml:312,314`). On the update path both come back **null** — the same `Tag` type carries them populated on the read path, so the schema is shape-consistent but the *content* is inconsistent across two operations returning the same type.

Why the two paths differ:

- **Update path (`external`/`usedCount` null).** `TagServiceImpl.update` (`:46-55`) ends with `.flatMap(reactiveTagRepository::update).flatMap(this::updateSearchVectors).map(tagMapper::mapToTag)` (`:54`). The value flowing into that final `mapToTag` is a `TagPojo` (the repository's `update` returns the persisted pojo), so the call binds the **bare-pojo overload** `Tag mapToTag(final TagPojo pojo)` (`TagMapper.java:26`). A `TagPojo` has no `external`/`usedCount` columns — those are derived fields — so the mapper leaves them null.
- **Read path (`external`/`usedCount` populated).** The popular-tags GET (`listMostPopular`) maps through `TagsResponse` → `mapToTag(final TagDto dto)` (`TagMapper.java:24`, the `@Mapping(source = "dto.tagPojo", target = ".")` overload). `TagDto` is `record TagDto(TagPojo tagPojo, Long usedCount, Boolean external)` (`TagDto.java:5`) — it carries the two derived values, so they populate.

**Operator-visible consequence.** A client that calls `PUT /api/tags/{id}` and reads `external` / `usedCount` from the response (e.g. to refresh a UI row in place without re-fetching) sees `null` for both and may conclude the tag has no external relations / zero usage — when in fact the update endpoint simply does not compute them. The correct values require a follow-up read (the popular-tags list / the tag's read DTO). This is a response-shape inconsistency on the same `Tag` type across two endpoints.

There is no dedicated tags api-reference sub-page (the hub defers the tag family to the OpenAPI spec / Swagger UI — `api-reference.md:22`). The operator-facing home for this caveat is the existing "Known limitations and operator caveats" section on `tagging.md`.
