# IngestionController.ingestMetrics — semantic understanding

## understanding

`ingestMetrics` is the metrics-shaped sibling of the data-entity ingestion entry point: collectors `POST /ingestion/metrics` with a `MetricSetList` payload (a list of `MetricSet` each carrying an entity ODDRN + one or more `MetricFamily` records — OpenMetrics-shaped COUNTER / GAUGE / HISTOGRAM / SUMMARY / GAUGE_HISTOGRAM types) and the controller hands the deserialised payload to `IngestionMetricsService.ingestMetrics(...)` returning `201 Created`. The service interface has TWO mirrored implementations gated by `@ConditionalOnProperty(name = "metrics.storage")`: `InternalIngestionMetricsServiceImpl` (writes to ODD's PostgreSQL `metric_series` / `metric_point` tables; `havingValue = "INTERNAL_POSTGRES", matchIfMissing = true` — i.e. **default-on**) versus `ExternalIngestionMetricsServiceImpl` (writes Prometheus-shaped TimeSeries via remote-write `POST /api/v1/write` against `metrics.prometheus-host`, Snappy-compressed; `havingValue = "PROMETHEUS"`). The controller itself carries no authorization annotation; `/ingestion/metrics` is **NOT** covered by `IngestionDataEntitiesFilter` (which exact-matches `/ingestion/entities` POST), is **NOT** covered by `IngestionDataSourceFilter` (which exact-matches `/ingestion/datasources` POST), AND is in `SecurityConstants.WHITELIST_PATHS` (`/ingestion/**`) — so even when every auth toggle is enabled (`auth.type=OAUTH2 | LDAP | LOGIN_FORM`, `auth.s2s.enabled=true`, `auth.ingestion.filter.enabled=true`), this endpoint accepts unauthenticated POSTs from any caller able to reach the platform's HTTP port.

## concepts

- entities: [`MetricSetList` (request body — `items: List<MetricSet>`), `MetricSet` (per-entity: `oddrn` + `metric_families`), `MetricFamily` (Prometheus-shaped: name + type + help + unit + `metrics: List<Metric>`), `Metric` (labels + `metric_points`), `MetricPoint` (timestamp + per-type value: CounterValue / GaugeValue / HistogramValue / SummaryValue), `IngestionMetricsService` (interface — 2 mirrored implementations), `Mono<ResponseEntity<Void>>` (reactive response shape)]
- operations: [accept-metric-set-list, delegate-to-ingestion-metrics-service, dispatch-by-conditional-on-property-to-internal-postgres-or-prometheus-impl, return-201-Created]
- invariants:
  - "Controller has no authorization at the method level — neither `@PreAuthorize` on `ingestMetrics` nor on the `IngestionApi` interface it implements (the interface is generated from the published `org.opendatadiscovery:ingestion-contract-server` Maven artifact and carries no security annotations). The path `/ingestion/metrics` is in `SecurityConstants.WHITELIST_PATHS` (`/ingestion/**`, SecurityConstants.java:96), exempting it from UI auth (LOGIN_FORM / OAUTH2 / LDAP). No `IngestionDataEntitiesFilter`-style path-scoped filter exists for `/ingestion/metrics` — the bundled codebase has TWO ingestion filters (`IngestionDataEntitiesFilter` matching `/ingestion/entities` POST, `IngestionDataSourceFilter` matching `/ingestion/datasources` POST), neither of which extends to the metrics path. The endpoint is unauthenticated in EVERY supported deployment posture."
  - "Service dispatch is BOOT-TIME via mirrored `@ConditionalOnProperty(name = \"metrics.storage\")` on the two `IngestionMetricsService` implementations. `InternalIngestionMetricsServiceImpl.java:66` declares `havingValue = \"INTERNAL_POSTGRES\", matchIfMissing = true` (default-on); `ExternalIngestionMetricsServiceImpl.java:56` declares `havingValue = \"PROMETHEUS\"`. The two beans are mutually exclusive at the Spring-container level; a value outside the enumeration (e.g. `metrics.storage=ELASTICSEARCH`) produces a zero-implementation configuration and the controller's `@Autowired` dependency fails at boot with `NoSuchBeanDefinitionException`."
  - "Response code is `201 Created` (line 94, `HttpStatus.CREATED`). This MATCHES the OpenAPI spec contract (the published `ingestion-contract-server` Maven artifact's spec declares 201 for the operation per the sibling `postDataEntityList.md:concepts.invariants.[2]` evidence chain that contrasts 201 spec vs 200 impl for that method). Sibling `postDataSetStatsList` (line 86, `HttpStatus.CREATED`) also returns 201 — `ingestMetrics` is on the CORRECT side of the openapi-200-vs-201-status-code-drift concept; only `postDataEntityList` (line 44, `ResponseEntity.ok()`, 200) diverges from spec."
  - "Per-tenant scoping is BY-LABEL-CONVENTION at the EXTRACTOR layer, not enforced at the controller. The controller passes `MetricSetList` verbatim; the downstream service splits into per-MetricType extractors (`extractors.stream().filter(canExtract).findFirst()`) which read `odd.tenant-id` at bean construction (`@Value(\"${odd.tenant-id}\")`) and append `tenant_id={value}` as a Prometheus label (PROMETHEUS path) or do nothing tenant-related (INTERNAL_POSTGRES path — there is no `tenant_id` column on `metric_series` / `metric_point` tables). The controller can be POSTed metrics for ANY ODDRN with ANY label set; tenant isolation is brittle by-convention only (see CounterTimeSeriesExtractor sidecar bugs_limitations_corner_cases.[0] HIGH — read/write tenant-id label asymmetry on empty-string)."
  - "Body parsing is REACTIVE — the method signature takes `Mono<MetricSetList>` (line 90), so the WebFlux runtime defers deserialisation until the inner subscriber pulls; in practice `.flatMap(ingestionMetricsService::ingestMetrics)` triggers the parse on the first signal. The full body is buffered to JSON via `spring.codec.max-in-memory-size: 20MB` (application.yml:14-15) — exceeding that cap throws `DataBufferLimitException` → 500 to the caller, not 413. No streaming JSON parser; entire `MetricSetList` materialises before processing."
  - "There is NO empty-payload guard at the controller layer (line 90-95 has no `.filter(...)` or `.switchIfEmpty(...)`). An empty `metricSetList` (`items: []`) reaches `ingestionMetricsService.ingestMetrics(...)`; both implementations short-circuit to `Mono.empty()` on `CollectionUtils.isEmpty(metricSetList.getItems())` (`InternalIngestionMetricsServiceImpl.java:80-82`, `ExternalIngestionMetricsServiceImpl.java:86-88`) — returning 201 Created for a no-op. Contrast with `postDataEntityList` which 400s on empty items via `BadUserRequestException(\"Ingestion payload is empty\")`."
- audiences:
  - "odd-collector / odd-collector-sdk HTTP clients pushing per-entity metric series (the collectors-side push pattern)"
  - "odd-platform UI end users — the per-DataEntity Metrics tab consumes the ingested data via `GET /api/dataentities/{id}/metrics` and `InternalMetricReader` / `ExternalMetricReader`"
  - "the operator's external Prometheus instance (PROMETHEUS mode — Snappy-compressed TimeSeries arrive via `POST /api/v1/write`)"
  - "platform operators picking the storage backend at deploy time"
  - "security reviewers auditing the S2S surface"
