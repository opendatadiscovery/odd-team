## Description

The maintainer retired the workspace's never-auto-file rule on 2026-09-06 (commit `2b20196d`, "issues: FILE them,
don't hand back drafts"), updating `CLAUDE.md`, `.claude/skills/log-issue/SKILL.md` and `issues/README.md`'s lead
text. Three rails still carry the OLD rule and now contradict the authority:

- `playbooks/github-write.md:10` opens by scoping the pillar to "issue comments and DRAFT pull requests … **It never
  creates new issues**", and `:77` repeats it in the case-law list.
- `issues/README.md:127` still states the human-only filing rule.
- `pillars/contributor/gates.md` G-C18 says sub-issues are "paste-ready (the bot is **policy-barred** from creating
  issues — `playbooks/github-write.md`)", and G-C5/G-C14 build on the same premise (hand the maintainer a draft to
  file "as part of approving").

This matters because `github-write.md` is the protocol a `/contribute` run loads to decide what it may do on GitHub.
A session that follows the rails rather than `CLAUDE.md` will hand back a draft and wait — the exact roundtrip the
retirement removed (memory `feedback_agent_files_github_issues`). A session that follows `CLAUDE.md` is right but is
contradicted by its own protocol, which is how a rule quietly becomes folklore.
