## What

The collector token contract has three operator-critical properties the documentation does not surface (it frames regeneration as a benign recovery action and tells operators to copy/use the token without caveat):

1. **Regeneration is an in-place UPDATE with NO grace window.** `regenerateCollectorToken` overwrites the `TOKEN` row in place — there is no old/new token pair and no rotation-grace period. `IngestionDataEntitiesFilter` starts rejecting old-token requests the moment the UPDATE commits, so an already-running collector (the normal state in a Helm/EKS deployment) starts 401-ing on `POST /ingestion/entities` immediately and ingestion stops until the collector is reconfigured with the new token and restarted/redeployed.
2. **Token stored and returned in plaintext.** The token is persisted verbatim in the `TOKEN` table and returned in plaintext in the response body.
3. **Rotation is NOT audit-logged.** No Activity-Feed / audit trail records a token regeneration.

Sources: HARVEST-011, HARVEST-051, HARVEST-057 (doc-understanding harvest, 2026-05-29). Doc caveat tracked at `backlog/docs/DOC-292.md`.

## Why it matters

An operator who follows the docs' "you must regenerate it" recovery advice on a live deployment takes ingestion down without warning: every running collector 401s the instant the UPDATE commits, and ingestion stays broken until each collector is reconfigured and redeployed. There is no overlap window in which both tokens are valid, so a zero-downtime rotation is impossible with the current shape. Compounding it, the token is plaintext at rest and in transit-response and the rotation is unaudited — so a leaked backup exposes live credentials and there is no record of who rotated what. This is the LSN-002 class: the documented operation is a benign-looking action that breaks production.

## Suggested fix

- Introduce a rotation grace window: support a short-lived old/new token pair (accept both for a configurable overlap) so a running collector keeps ingesting while it is reconfigured — making zero-downtime rotation possible. At minimum, document that regeneration breaks active ingestion until redeploy.
- Hash the token at rest (store a hash, compare on the read side) and avoid returning it in plaintext beyond the single creation response; mask it in any actuator/log surface.
- Add an audit-log entry on token regeneration (who/when/which collector).
