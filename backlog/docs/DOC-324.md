## Description

Net-new operator-facing caveats across the Management / admin surfaces (Owners, Data Sources, the Management nav, housekeeping config), each surfaced by the Layer-4b reflections and each `dedup_status: net_new`. Grouped as the operator/admin experience. The security-sensitive owner findings (getOrCreate side-door, soft-deleted-by-id read) are filed as PLTs (PLT-125, PLT-131), not here.

## Acceptance Criteria

- [ ] **Owner rename: OWNER.NAME is safe, OIDC username is hazardous** (F-019 H-010): cross-link, on both the owners page and the user-owner-association page, that renaming an Owner's `name` is FK-safe for user associations (the FK is by the bigserial `owner.id`), but renaming a user's OIDC/SSO username orphans the mapping (no stable-id fallback — see the GitHub-rename hazard). Evidence: `V0_0_4__add_user_owner_mapping.sql:3` (safe) + the F-011 REFACTOR-391 OIDC-username hazard.
- [ ] **Owner name collision returns 400, not 409** (F-019 H-011): document (owners page / API ergonomics) that a duplicate-name create or rename returns HTTP 400 (USR003 `UNIQUE_CONSTRAINT`), not 409 Conflict — a client cannot distinguish "name taken" from "bad input." Evidence: `V0_0_64__remove_is_deleted_field.sql:70` + `ControllerAdvice.handleUniqueConstraint`.
- [ ] **Data source ODDRN is immutable on edit** (F-031 H-004): document that the ODDRN field is disabled on Edit (absent from the update DTO) with no inline help — an operator who mistyped an ODDRN cannot correct it via Edit. Evidence: F-031 H-004 (ui_review note 7).
- [ ] **Data source search is prefix-match, not substring** (F-031 H-010): document that the "Search datasource" box does a name-PREFIX match (not substring), with a header count that freezes during search — so an existing source typed by a mid-name fragment looks unregistered. Evidence: `DataSourcesList.md` doc_drift_findings (REFACTOR-425). Distinct from PLT-090 (the `/api/search` subsystem).
- [ ] **Management tab renders for non-admins** (F-011 H-011): document (auth UI overview / authentication page) that the Management tab (and all top-level tabs) renders unconditionally with no permission gate — a non-admin sees it and, clicking through, gets a permission-denied page rather than a hidden tab. The destination pages are permission-gated; only the tab strip is not. Evidence: `ToolbarTabs.tsx:34-82`. (The reflection recommends an SME consult on hide-vs-show-then-deny convention; documenting current behaviour is the minimum.)
- [ ] **Owner update has no audit + OWNER_UPDATE is global** (F-011 H-013): document that an Owner rename / role-rebind emits no Activity event (no audit trail of who changed it), and that `OWNER_UPDATE` is a global (any-Owner) permission — a holder can rename any Owner regardless of association. Evidence: `OwnerServiceImpl.java:68-85` (no audit) + `SecurityConstants.java:144-145` (NO_CONTEXT global scope). (Owner-lifecycle audit-silence is also tracked at PLT-062 / DOC-246 — cross-link, don't duplicate.)
- [ ] **Housekeeping ShedLock window is razor-thin** (F-010 H-008): document on the config page that the housekeeping orchestrator's `lockAtMostFor=14m` against a `15m` schedule leaves only 60s slack — a cycle running ≥14 minutes can release the lock before it commits and let a second instance run concurrently. Evidence: `HousekeepingJobManager.java:25-26`. (Probe P-011 will confirm reachability; one-line fix is `lockAtMostFor >= 2× fixedRate`.)
