## The defect

`run-regression.sh:32` computes the worktree as:

```bash
WT="${ODD_PLATFORM_DIR:-$(cd "$ROOT/../odd-platform-$ID" 2>/dev/null && pwd)}"
```

The **default** branch is absolutized by `$(cd … && pwd)`. An **explicit override is passed through
verbatim** to `build-sut.sh` (`:84`) and `run-suite.sh` (`:94`), and nothing downstream normalises it —
`run-suite.sh`, `playwright.config.ts` and `global-setup.ts` were all checked.

Playwright runs with cwd `integration-tests/e2e` (`run-suite.sh:237` — `cd "$HERE/e2e"`), while the script
itself runs from the workspace root. So the *same string* means two different directories:

```
resolve('../odd-platform-ctrib063', 'odd-platform-api/src/main/java')
  -> odd-team/integration-tests/odd-platform-ctrib063/...      exists: false
```

`run-regression.sh:33`'s `[ -e "$WT/.git" ]` guard passes anyway, because it is evaluated from the script's
cwd. The run starts, builds the right SUT, and only the specs that read the variable break.

## Blast radius — three consumers, two failure modes

| Consumer | Effect with a relative override |
|---|---|
| `e2e/helpers/demo-stand.ts:28` | `demoCompose()`'s `cwd: PLATFORM_DIR` does not exist → **`Error: spawnSync /bin/sh ENOENT`** inside `beforeAll` — an error that reads as "your shell is missing" |
| `e2e/specs/demo-stand-first-run.spec.ts:47` | `SAMPLE_DIR` / `INJECTOR_DIR` → **`ENOENT: no such file or directory, lstat '../odd-platform-ctrib063/docker/config/injector'`** on cases 7, 8, 9 |
| `e2e/specs/slack-events-webhook-security.spec.ts:73` | `test.skip(!existsSync(PLATFORM_SRC))` fires → **F-098's "ZERO Slack-signature / HMAC verification code exists" characterization silently self-disables.** The suite summary says `1 skipped` and names nothing. |

The skip is the more dangerous half: the demo-stand failure is loud, the security characterization just
stops running and no one can tell from the run-log.

## Measured — A/B, one tree, one commit, one session

| `ODD_PLATFORM_DIR` | `specs/demo-stand-first-run.spec.ts` |
|---|---|
| `../odd-platform-ctrib063` (relative) | **0 passed / 4 failed** |
| `$(realpath ../odd-platform-ctrib063)` (absolute) | **4 passed (2.8 m)** — `up -d odd-platform-enricher` blocked 62 s |

Full `multi-stack` with the relative form: **14 passed / 4 failed**, the four being IT-154's four cases.
With the default (absolute) form the same suite is 18/0.

## Why it matters beyond one item

The relative form is what `run-regression.sh:7` and `:19` themselves document
(`ODD_PLATFORM_DIR=../odd-platform-<id>`), and a **`/review` confirmation run has no alternative**: the
reviewer's stream id never matches the worktree suffix (`revctrib063r3` vs `odd-platform-ctrib063`), so the
default branch that would absolutize the path is unreachable and the override is mandatory. Every future
review of anything touching IT-154 — or reading `ODD_PLATFORM_DIR` at all — starts from a false RED, and the
one that matters most reads as *"the demo-stand fix regressed."*
