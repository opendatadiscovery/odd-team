## Description

The live `/data-discovery/directory` page (WebFetched 2026-05-27, 200 OK) describes the 4-level drill-down + the level-3 `/all` URL convention. It is **silent on the read-collaborative posture's most operator-visible artefact** — the level-2 response reflects every `@PathField`-annotated property of every registered data source's ODDRN to every authenticated user (host, database, port, account, warehouse, cluster, topic), without any owner-scoping or redaction. It is also silent on the level-4 page-vs-count predicate divergence and on the `'all'` magic-string asymmetry in the level-3 URL form. Three operator-visible caveats need a Known Limitations sub-section.

(F-023a's NaN-route-hook observation is a corroboration of DOC-GAP-252 — already written back to `lineage/odd-platform/doc-gaps/detail/DOC-GAP-252.md` by the scan run; not part of this item.)

**Caveat 1 — Level-2 response reflects host / database / port / account / warehouse / cluster / topic to every authenticated caller (F-023d — CRITICAL).** `DirectoryServiceImpl.getOddrnPathProperties` (per F-023 chain hop 2a, cited lines 138-171) reflects every `@PathField`-annotated property of the data-source-type's ODDRN Generator class and emits the resolved string-value map in the level-2 response payload. For PostgreSQL: `host`, `database`. For Snowflake: `account`, `warehouse`. For Kafka: `cluster`. For MySQL: `host`, `database`. For BigQuery: `project`. **There is no owner-scoping** — the call hops `DirectoryController.list → DirectoryServiceImpl.getDataSources → ReactiveDataSourceRepository.list` apply only the default conditions (HOLLOW / STATUS), no `OWNERSHIP` join. An authenticated caller drilling `/api/directory/{type-prefix}` receives the full infrastructure inventory of every data source of that type — operators frequently expose `host` strings that double as DNS targets / firewall rules / VPC names. The live doc page lists "host, port, database, …" as fields shown in the UI but does NOT name the reflection mechanism and does NOT discuss visibility / redaction. Under `auth.type=DISABLED` the endpoint is anonymously reachable (DOC-GAP-252 closure).

**Caveat 2 — Level-4 page count and page list apply different filter predicates; the X-of-Y display silently mismatches whenever EXCLUDE_FROM_SEARCH is in use (F-023c).** Per F-023 chain hops 3a/3b: `ReactiveDataEntityRepositoryImpl.listByDatasourceAndType` (the **page** call) applies HOLLOW + soft-delete only; `countByDatasourceAndType` (the **count** call) applies HOLLOW + soft-delete **plus EXCLUDE_FROM_SEARCH**. In deployments using EXCLUDE_FROM_SEARCH to hide intermediate / transient entities from search but still allow direct browsing (a common collector hygiene pattern), the level-4 page renders `30 entities` but the count badge reads `25` — the X-of-Y display becomes silently wrong. Operators auditing the catalog's per-source completeness see a mismatch between "scroll-through count" and "header count" with no documented explanation. The mismatch direction can also be reversed depending on which page index the user reaches.

**Caveat 3 — Level-3 URL uses the magic string `'all'`, level-4 uses a numeric `{type-id}` — the asymmetry is undocumented (F-023b).** The current page lists the level-3 URL as `/directory/{type-prefix}/{data-source-id}/all` and the level-4 URL as `/directory/{type-prefix}/{data-source-id}/{type-id}`. The `'all'` segment is a load-bearing in-band sentinel — `directoryRoutes.ts:34` (verified this run) coerces it to "no type filter" in the `useDirectoryRouteParams` hook; `DirectoryRoutes.tsx:16` redirects bare level-3 URLs to the `/all` form; `EntitiesTabs.tsx:26` constructs the same sentinel when building tab URLs. Operators bookmarking `/directory/postgresql/123/abc` (typo on the type-id) silently land on a NaN-coerced route that propagates to 6 downstream consumers; operators bookmarking `/directory/postgresql/123/all` get the intended view. No client-side validation; no error page. The 'all' literal is not a number — operators with mental models like "level 4 = numeric type-id, level 3 = `0` or empty" guess wrong.
