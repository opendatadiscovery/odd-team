## Description

Net-new operator-facing caveats across three Active-Platform / discovery feature surfaces (entity Statuses, the Data Quality dashboard, Slack Data Collaboration), each surfaced by the Layer-4b reflections and each `dedup_status: net_new`. The cross-tenant/open-redirect/silent-200 security findings on data-collaboration are filed as PLTs (PLT-119, PLT-129) and deliberately NOT given public doc caveats.

## Acceptance Criteria

- [ ] **Status `propagate` flag is group-only and single-hop** (F-044 H-005): document on the statuses page that the `propagate=true` body flag (a) applies only to group entities and is silently ignored on non-group entities (no error, no signal), and (b) is single-hop — a DEG-of-DEGs propagates to its immediate children only. The page currently does not describe the `propagate` flag at all. Evidence: F-044 H-005 (`updateStatus.md` doc_drift_findings).
- [ ] **No preview of entities scheduled to auto-flip to DELETED** (F-044 H-009): document that there is no operator-facing surface to preview which entities are scheduled to auto-flip to DELETED before the scheduler acts — a mistaken switch-time cannot be caught in advance. Note this becomes materially more dangerous once PLT-027 makes hard-delete actually fire (today the flips persist recoverably as DELETED). Evidence: F-044 H-009.
- [ ] **Scheduled auto-flips are system-attributed** (F-044 H-011): document (statuses page / activity feed) that scheduler-initiated status flips run under the system principal with no human-actor attribution — an auditor cannot link a scheduled delete to the operator who set the switch-time (manual deletes ARE attributed). Evidence: F-044 H-011.
- [ ] **DQ dashboard: Owner + Title in one block is AND-on-one-row** (F-032 H-008): document on the dashboard page that selecting Owner AND Title in a single filter block requires a SINGLE ownership row carrying both (an AND on one row), not two independent filters — producing a surprising (often empty) dashboard. Evidence: F-032 H-008 (new drift class proposed).
- [ ] **DQ dashboard rings count a restricted population** (F-032 H-011): document that the Table Health ring counts ONLY datasets with at least one DQ test (and Monitored Tables only TABLE-type entities) — the rings do not partition all tables, so the dashboard understates untested coverage. Evidence: F-032 H-011 (controller sidecar notes it; no DOC-GAP/PLT tracks the population scope).
- [ ] **Data collaboration: send returns 202 with no final failure feedback** (F-038 H-007): document that `Send` returns `202`/`PENDING_SEND` and never pushes the final `ERROR_SENDING` outcome back to the caller — delivery failures are silent unless the user re-fetches. Document the re-fetch-to-see-status behaviour. Evidence: F-038 H-007 (`postMessageInSlack` sidecar bugs[4]).
- [ ] `Sources:` footer cites the six findings above and the three reflection details (F-044 H-005/H-009/H-011, F-032 H-008/H-011, F-038 H-007).
- [ ] Live-site Gate 8 post-merge: WebFetch the statuses, data-quality/dashboard, and data-collaboration pages and confirm the caveats render.
