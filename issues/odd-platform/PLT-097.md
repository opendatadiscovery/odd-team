## What

Three defects on the entity staleness signal — one **class-1 LSN-001 footgun** (if `odd.data-entity-stale-period` is unset / null in the operator's overlay, the predicate silently returns `false` for every entity in the platform; the stale indicator dies platform-wide; no log, no startup signal, no admin warning surfaces), one semantic-drift defect (entities that have never been ingested report `is_stale: false` — same as fresh, indistinguishable in the UI), and one UI-tier closure of the silent-disable case (the `MetadataStale` widget renders null when `isStale=false`, so a globally-dead signal renders identically to a perfectly-healthy platform).

**Defect 1 — Silent platform-wide indicator death if `stalePeriod` is null (F-208a — CRITICAL, LSN-001 family).** `DataEntityStaleDetector.java:13-17`: `pojo.getLastIngestedAt() != null && stalePeriod != null && DateTimeUtil.generateNow().isAfter(pojo.getLastIngestedAt().plusDays(stalePeriod))`. If the `@Value("${odd.data-entity-stale-period}")`-bound integer is null (config key absent from operator overlay), the predicate short-circuits to `false` for EVERY entity — staleness signal globally dead. Shipped default in `application.yml:211` IS `data-entity-stale-period: 7 # days`, so the footgun materialises only when the operator's Helm values / K8s ConfigMap / Docker `environment:` strips the line. **No `@PostConstruct` validator. No startup INFO log. No admin signal.** Same shape as LSN-001 (attachment-ephemeral default) and LSN-002 (minio-region-unset) — operators following our docs into a stripped overlay get a worse-than-broken state because the UI looks perfectly healthy.

**Defect 2 — Never-ingested entity reports `is_stale: false` (F-208b — MEDIUM).** Same predicate, first conjunct: `pojo.getLastIngestedAt() != null`. An entity with `last_ingested_at` NULL (manually-created in the UI, pending first collector pull, or one the collector skipped) short-circuits to `false`. The UI cannot tell "no stale icon = fresh" from "no stale icon = no metadata at all." Operators using staleness as a freshness signal hit the trap when their dashboards mistake never-ingested for recently-refreshed.

**Defect 3 — UI-tier closure: globally-dead signal renders identically to fresh (F-208c — MEDIUM).** `MetadataStale.tsx:20-31`: `return isStale ? <AppTooltip>...<StaleIcon/></AppTooltip> : null;`. When `isStale=false` the widget renders null. Combined with Defect 1: a deployment with `stalePeriod=null` shows ZERO stale icons across every list / detail / lineage surface; visually indistinguishable from a perfectly-healthy platform. No "staleness disabled" banner, no admin-tab indicator, no per-page sentinel.

## Why it matters

- **Defect 1 is the LSN-001 family fix.** Operators promoting a deployment with a stripped `stalePeriod` (config-templating tool, environment-variable overlay, custom Helm values) lose the staleness signal everywhere. The platform looks perfectly healthy; collectors could be 30 days behind and no signal surfaces. Operators who build their incident response on the staleness signal get a false-negative SLA dashboard.
- **Defect 2 is a mental-model trap.** Manually-created entities and pending-first-ingestion entities look as healthy as recently-refreshed ones. Operators auditing a new ingestion's progress cannot tell "the collector pulled this and it's fresh" from "the collector never pulled this."
- **Defect 3 is the UI-tier compound.** Defect 1's silent-disable becomes a "perfectly-healthy-looking platform" because every list / detail / lineage surface continues to render the same DOM as before. Operators have no surface to inspect.

Severity HIGH — Defect 1 is class-1 (silent-disable with no diagnostic trail meets the LSN-001 / LSN-002 published-mistake threshold).

## Suggested fix

Three coordinated fixes; Defect 1 ships standalone if Defects 2 + 3 need design.

### (a) Defect 1 — Fail-fast on unset stale-period

```java
// DataEntityStaleDetector.java
@Service
public class DataEntityStaleDetector {

  @Value("${odd.data-entity-stale-period:#{null}}")
  private Integer stalePeriod;

  @PostConstruct
  void validate() {
    if (stalePeriod == null || stalePeriod < 1) {
      throw new IllegalStateException(
          "odd.data-entity-stale-period must be set to a positive integer (days). " +
          "Current value: " + stalePeriod + ". " +
          "The platform default is 7 days; check your deployment overlay (Helm values, " +
          "K8s ConfigMap, Docker environment) for a stripped or empty value.");
    }
    log.info("DataEntityStaleDetector configured with stalePeriod={} days", stalePeriod);
  }

  public boolean isStale(final DataEntityPojo pojo) {
    return pojo.getLastIngestedAt() != null
        && DateTimeUtil.generateNow().isAfter(pojo.getLastIngestedAt().plusDays(stalePeriod));
  }
}
```

Spring container fails to start; operator sees the error naming the config key + a remediation hint. Same shape as PLT-089 (advisory-lock fail-fast wrapper) and PLT-005 (housekeeping TTL=0 LSN-001 case).

### (b) Defect 2 — Distinguish never-ingested from fresh

Three-value semantics on the wire + UI:

```java
// DataEntityStaleDetector.java — return an enum rather than a boolean:
public enum FreshnessState { FRESH, STALE, NEVER_INGESTED }

public FreshnessState freshnessOf(final DataEntityPojo pojo) {
  if (pojo.getLastIngestedAt() == null) return FreshnessState.NEVER_INGESTED;
  if (DateTimeUtil.generateNow().isAfter(pojo.getLastIngestedAt().plusDays(stalePeriod))) return FreshnessState.STALE;
  return FreshnessState.FRESH;
}
```

```ts
// MetadataStale.tsx — three icons:
const FreshnessIcon: React.FC<{ state: FreshnessState }> = ({ state, lastIngestedAt }) => {
  switch (state) {
    case 'STALE':           return <AppTooltip title={t('Last updated: {{ts}}', { ts: lastIngestedAt })}><StaleIcon/></AppTooltip>;
    case 'NEVER_INGESTED':  return <AppTooltip title={t('No ingestion recorded yet')}><GreyClockIcon/></AppTooltip>;
    case 'FRESH':           return null;
  }
};
```

The OpenAPI wire contract gains the new enum field on the entity DTO; consumers downgrade gracefully when reading older payloads.

### (c) Defect 3 — Diagnostic surface when signal globally off

Two paths; both supplement the (a) fail-fast above:

**(c1) Admin / actuator-only surface.** Expose `odd_stale_signal_state` Prometheus gauge: 1 if `stalePeriod` resolved to a valid integer at boot, 0 otherwise. Operators monitoring the platform see the gauge in dashboards without inspecting backend config.

**(c2) UI banner on the admin tab.** When `stalePeriod` is null at runtime (only possible if (a) is not yet shipped), the Admin > Health surface displays "Staleness signal disabled — verify `odd.data-entity-stale-period` config" with a docs link.

Recommendation: (a) closes the load-bearing case. (c1) is the operability complement. (c2) becomes obsolete once (a) ships.
