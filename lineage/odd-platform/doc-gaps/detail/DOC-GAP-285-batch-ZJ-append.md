### New operator-impact dimensions surfaced

1. **5-site tabnabbing scope, not 1-site scope**: the original DOC-GAP-285 focused on operator-configured URLs as the broadest attack surface. Batch ZJ confirms the SAME pattern affects all four FIRST-PARTY hardcoded links (Documentation / Slack / GitHub / Product Hunt). Threat model widens: even if the operator NEVER configures `odd.links`, the SPA still leaks `window.opener` to the four hardcoded destinations. A future XSS on any of those domains (docs.opendatadiscovery.org / go.opendatadiscovery.org / github.com / producthunt.com) would have lateral movement into the ODD Platform tab via `window.opener.navigate`. The fix is the same (add `rel='noopener noreferrer'`) but applied at FIVE sites, not one.
2. **Keyboard inaccessibility (NEW class — WCAG 2.1 SC 2.1.1 violation)**: the App Info menu is hover-only. Keyboard-only users (e.g. screen-reader users, motor-impaired users) CANNOT activate it via Tab + Enter / Space. The ARIA attributes falsely claim keyboard accessibility. Touch-device users (iOS Safari, Android Chrome on phone/tablet) ALSO cannot open the menu (no `onTouchStart` or click handler). Accessibility class; compliance-relevant for any operator deploying ODD in regulated environments.
3. **OPERATOR-INVISIBLE CONFIG-IMMUTABILITY (compound)**: the `keepMounted` + `useAppInfo`/`useAppLinks` no-staleTime combination makes the boot-time-bind half of DOC-GAP-285 invisible to operators. An operator editing `odd.links` YAML + restarting the backend STILL sees the old list in any SPA tab opened before the restart. The fix is to invalidate the React-Query cache on app-info / links endpoints OR to drop `keepMounted` + use `staleTime: 0`; either way, the operator-visible immutability has a code-side fix that the original DOC-GAP-285's doc-side note alone does not address.
