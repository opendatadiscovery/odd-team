## What

`POST /ingestion/entities/datasets/stats` (the dataset-field statistics ingestion endpoint the profiler pushes to) is an unauthenticated, unvalidated, and unaudited write surface:

1. **No collector-token auth gate.** `IngestionController.postDataSetStatsList` is a 4-line proxy with no `@PreAuthorize` and no programmatic auth, and the path is NOT covered by `IngestionDataEntitiesFilter` (the filter's `PathPatternParserServerWebExchangeMatcher` binds exact-literal `POST /ingestion/entities` at `IngestionDataEntitiesFilter.java:28`, which does not match the deeper `/ingestion/entities/datasets/stats`). This is **already pinned by a repo test** - `IngestionFilterPathCoverageTest.java:69-70` asserts `gates(filter, POST /ingestion/entities/datasets/stats) == false` (a GREEN `@pins PLT-003` characterization). At the Spring-Security layer the path is anonymous under `DISABLED` (`anyExchange().permitAll()`, `DisabledAuthSecurityConfiguration.java:16`) and whitelisted-anonymous under `OAUTH2`/`LDAP` (the `/ingestion/**` entry in `SecurityConstants.WHITELIST_PATHS`, `:96`, applied by `AuthorizationCustomizer.java:21-23`). **Correction (verified 2026-06-10):** it is NOT anonymous under `LOGIN_FORM` - that config's hand-rolled permit list names only `/ingestion/entities` + `/ingestion/datasources` (`LoginFormSecurityConfiguration.java:50`) and falls everything else through to `.pathMatchers("/**").authenticated()` (`:57`), so the stats path requires a logged-in session there (and LOGIN_FORM applies no per-endpoint RBAC, so any authenticated user still reaches it; the collector-token filter still never gates it). The earlier "reachable under every auth mode" was a backend-only overstatement.
2. **No parent-child validation.** `DatasetFieldServiceImpl.updateStatistics` resolves writes by FIELD ODDRN only (`getLastVersionDatasetFieldsByOddrns(statistics.keySet())`) with no JOIN to the declared parent dataset - so any caller who knows a field's ODDRN can overwrite that field's `dataset_field.stats` JSONB, including a field belonging to a different dataset than the declared parent.
3. **The write is UNAUDITED.** `updateStatistics` carries no `@ActivityLog`, unlike its audited siblings `updateInternalName` (line 99) and `updateDatasetFieldTags` (line 119). An attacker poisoning `dataset_field.stats` leaves NO Activity-Feed trace - forensic invisibility for an operator weighing detection vs. perimeter-only mitigation.

Sources: HARVEST-013, HARVEST-054 (doc-understanding harvest, 2026-05-29). Doc caveat tracked at `backlog/docs/DOC-301.md`.

## User-facing impact

**Verified trace (no dedicated UI surface - this is a write-integrity / forensics finding); all three claims are code-settled, one filter-coverage claim repo-test-pinned.** This endpoint is a server-to-server ingestion sink (the profiler pushes to it); there is no FE component that POSTs it, so the "impact" is on the *data behind* the UI, not a rendered widget:

- **No collector-token gate - CONFIRMED + test-pinned.** The filter exact-path mismatch is verified in source (`IngestionDataEntitiesFilter.java:28`) and pinned by the runnable repo test `IngestionFilterPathCoverageTest.java:69-70` (GREEN `@pins PLT-003`). Per-auth-mode reachability re-derived from the four `*SecurityConfiguration` classes (see corrected claim 1): anonymous under `DISABLED`/`OAUTH2`/`LDAP`, authenticated-session-only under `LOGIN_FORM`.
- **No parent-child validation - CONFIRMED.** `updateStatistics` (`DatasetFieldServiceImpl.java:158-181`) resolves writes via `getLastVersionDatasetFieldsByOddrns(statistics.keySet())` (`:173`) - field ODDRN only, no JOIN to the declared parent dataset. A caller knowing a field's ODDRN writes that field's `dataset_field.stats` JSONB regardless of declared parent. Whatever lands is then rendered with no integrity marker by the Dataset Structure / Quality surfaces that read `dataset_field.stats`.
- **Unaudited write - CONFIRMED (this draft's distinct contribution).** `updateStatistics` carries only `@ReactiveTransactional` (`:158-160`); it has NO `@ActivityLog`, whereas the sibling mutations `updateInternalName` (`:97-100`, `@ActivityLog(DATASET_FIELD_INTERNAL_NAME_UPDATED)`) and `updateDatasetFieldTags` (`:117-120`, `@ActivityLog(DATASET_FIELD_TAGS_UPDATED)`) both emit one. So a stats-poisoning write leaves no Activity-Feed trace - an operator cannot see it in the UI after the fact.

Remaining check (not driven here): a live anonymous `POST /ingestion/entities/datasets/stats` under `DISABLED` returning `201` and mutating a cross-dataset field row + leaving no activity row - the sibling alertmanager path is driven anonymously under `DISABLED` in PLT-003 (IT-115), giving high confidence the whitelist behaves identically for this path; an end-to-end stats-specific run is not yet logged.

## Why it matters

The profiler docs send operators down the stats-push path - "the profiler pushes the resulting statistics into the catalog" - with no mention that the receiving endpoint is unauthenticated and field-ODDRN-scoped with no parent-child check. Downstream consumers (the Quality Dashboard rings, the Dataset Structure tab, BI tools reading `dataset_field.stats`) render whatever lands there with no integrity indicator. Any network-reachable caller can poison any dataset's field statistics, and because the write carries no `@ActivityLog`, the poisoning leaves no audit trace - an operator cannot even detect it after the fact. This is the LSN-001 (forensic invisibility) and LSN-002 (operator-follows-guide-off-cliff) class combined.

## Suggested fix

- Add an auth gate to the stats endpoint: either extend `IngestionDataEntitiesFilter`'s matcher to cover `/ingestion/entities/datasets/stats` (so the collector token authenticates it), or add a dedicated `SecurityRule` / programmatic check. It must not remain anonymous under `DISABLED`.
- Add parent-child validation in `updateStatistics`: filter the field lookup by the declared parent dataset as well as by field ODDRN, and reject fields that do not belong to the declared parent.
- Add `@ActivityLog` to `updateStatistics` so the write is auditable like its siblings.
