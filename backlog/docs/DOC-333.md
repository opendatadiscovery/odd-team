## Description

Two adjacent Owner-identity facets the docs leave implicit (F-019/H-010, F-019/H-011):

1. **Rename safe-vs-dangerous surface.** Renaming `OWNER.NAME` is SAFE for `USER_OWNER_MAPPING` (the mapping is keyed by id, not name). The dangerous half is renaming the **OIDC username** — that silently orphans the user-owner mapping (tracked as PLT-111; the cross-mode bleed is DOC-245). The docs do not cross-link the safe-vs-dangerous rename surface, so an operator cannot tell which rename is harmless and which breaks attribution.
2. **Collision returns the wrong HTTP code.** An Owner name collision (on create or rename) returns `USR003` / HTTP 400, not `409 Conflict` — programmatic clients cannot distinguish "duplicate name" from "malformed input". No API doc states the expected code.
