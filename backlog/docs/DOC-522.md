## Description

**Failure shape: internal contradiction with the artefact the page describes.**

`docs/configuration-and-deployment/deployment.md:37`, in Option 1 (Docker Compose) Prerequisites:

> * Free local ports `8080` (Platform UI / API) and `5432` (sample PostgreSQL)

In `odd-platform:docker/demo.yaml` — the file this option tells the reader to run — the service that
publishes host `5432` is **`database`**, the Platform's own metadata store (`docker/demo.yaml:11-12`,
`ports: - 5432:5432`). The **`sample-postgresql`** service, which is the "sample PostgreSQL" the bullet
names, declares **no `ports` section at all** (`docker/demo.yaml:56-64`) — it is reachable only over the
compose network, by the collector, at `sample-postgresql:5432`.

The neighbouring `trylocally.md` states the same requirement without the wrong attribution ("Ports 5432 and
8080 are free"), so this page is also the odd one out.

**Why it is worth correcting rather than ignoring.** The bullet is the reader's mental model of what the demo
stack binds. An operator who believes 5432 belongs to a throwaway sample database will happily leave it bound
— and then be surprised that the *Platform's own* database is on a well-known port, exposed to anything that
can reach the host. The same page's Option 2/3 (Helm, EKS) rightly treat the Platform's PostgreSQL as the
thing that needs care.
