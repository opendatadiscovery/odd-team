#### Finding F-074a: Live `/permissions` page silent on read-collaborative posture across seven Management read endpoints

#### Finding F-075b: Live `/permissions` description of `DIRECT_OWNER_SYNC` silent on the self-mint composition hazard via `OwnerService.getOrCreate` side-door
- **Verdict**: STATIC-INFERRED · `missing-caveat` · **HIGH** severity · ontology-confirmed
- **Source-of-truth**: `Ontology[F-075:observed_vs_expected.facets[self_mint_then_self_bind_privilege_chain_via_direct_owner_sync]]` → `Repo[odd-platform-api/.../service/OwnerServiceImpl.java:38-42]` (sidecar reference; the mint side-door) + `Repo[odd-platform-api/.../service/OwnerAssociationRequestServiceImpl.java:55-67]` (permission-only check)

- **What the code does**: when a `DIRECT_OWNER_SYNC`-holder POSTs `/api/owner_association_request` with an `ownerName` that does NOT exist in the catalog, `OwnerAssociationRequestServiceImpl` calls `OwnerService.getOrCreate(ownerName)` (no permission check; F-019 root facet `service_tier_get_or_create_permission_bypass_owner_create_side_door`). - **Source-of-truth**: `Ontology[F-076:observed_vs_expected.facets[cascade_check_toctou_race_window_three_management_surfaces_uniform]]` → `Repo[odd-platform-api/.../service/OwnerServiceImpl.java:88-100]` + `Repo[odd-platform-api/.../service/NamespaceServiceImpl.java:73-90]` + `Repo[odd-platform-api/.../service/DataSourceServiceImpl.java:85-96]` (sidecar references; cascade-check chains)

Row Namespaces / Datasources / Collectors — silent on the dependent-row-blocks-delete contract. The `/Roles` page is the only Management cascade-block surface that's explicitly documented; cross-link DOC-GAP-275 (Roles cascade) + DOC-GAP-073 ("Policy is attached to a role" cascade-block).
- **What the code does**: each of Owner/Namespace/DataSource delete paths runs a `Mono.zip` of existence-predicates on referent tables BEFORE issuing the soft-delete UPDATE. - **Operator-visible consequence**: operator clicks Delete on a Namespace with 100 entities under it, gets a ControllerAdvice toast on rejection. - **Suggested fix**: extend the `/features/management` row for Owners / Namespaces / Datasources with a cascade-block caveat. Mirror the existing DOC-GAP-275 (Roles) + DOC-GAP-073 (Policies) treatment: enumerate the referent tables that block the delete; mention the operator must clear the referents first; cross-link the CascadeDeleteException USR004 error code.
- **NEW DOC-GAP candidate**: yes; sibling to DOC-GAP-275 + DOC-GAP-073 — extends the cross-Management cascade-block-undocumented pattern.

#### Finding F-076b: Live `/features/management` silent on TOCTOU race window between cascade-check and soft-delete UPDATE
- **Verdict**: STATIC-INFERRED · `missing-caveat` · LOW severity · ontology-confirmed
- **Source-of-truth**: `Ontology[F-076:observed_vs_expected.facets[cascade_check_toctou_race_window_three_management_surfaces_uniform + namespace_delete_not_reactive_transactional_chain_non_atomic_with_itself]]` → `Repo[odd-platform-api/.../service/NamespaceServiceImpl.java:73-90]` (no `@ReactiveTransactional`) + `Repo[odd-platform-api/.../repository/ReactiveAbstractSoftDeleteCRUDRepository.java:50-59]` (soft-delete UPDATE)
- **What the live doc says**: silent on race-window semantics.

NamespaceServiceImpl.delete is also non-`@ReactiveTransactional` — single-thread partial failures (network blip between EXISTS and UPDATE) leave the namespace as `deleted_at IS NULL` while the operator sees success.
- **Operator-visible consequence**: under sustained admin-delete + ingestion-insert load, orphan referent rows accrete (FK passes at insert but parent is now soft-deleted). The orphan is hidden from list reads (soft-delete filter) but visible via direct by-id read (F-019 visibility-asymmetry facet).
- **Suggested fix**: not a high-leverage doc finding — this is a structural defect (REFACTOR-430 + REFACTOR-427) that should be FIXED in code, not documented as accepted behaviour. Log as PLT-NNN issue draft on the upstream odd-platform repo (see "Upstream issue drafts" at the end of this batch).
- **NEW PLT issue candidate**: yes — PLT-022 (NamespaceServiceImpl.delete non-atomic + cascade-check TOCTOU).
