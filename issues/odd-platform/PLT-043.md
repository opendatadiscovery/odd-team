## What

The live docs at `docs.opendatadiscovery.org/configuration-and-deployment/odd-platform` now warn that `auth.ingestion.filter.enabled` only guards `POST /ingestion/entities` and does not cover sibling ingestion paths. **But the property declaration in `application.yml` has no in-line comment naming the narrow scope.** Operators auditing YAML files in isolation (a common pattern for security audits — offline, in a config-merge tool, in a CI-time review of Helm overrides) cannot reconstruct the narrow scope without leaving the file.

This is a follow-up to DOC-228 (the doc-side fix that ships the 80-cell deployment matrix on `enable-security/README.md`) — operators who don't read the docs but DO read the YAML still need the warning at the YAML surface.

## Where

```
odd-platform-api/src/main/resources/application.yml:46-48
  // current:
  // ingestion:
  //   filter:
  //     enabled: false
```

## Why

Same shape as LSN-001 — the operator-visible knob (the YAML key) and what the system actually does are not the same. Operators reading `auth.ingestion.filter.enabled: false` reasonably interpret it as "the ingestion-auth filter is off"; the actual semantic is "the filter that protects ONE OF FIVE ingestion endpoints is off". Without an in-line comment, the YAML name is the only signal — and the name reads as wider-than-the-implementation.

YAML caveats matter because YAML audits happen at sites where the doc site is not reachable (offline Helm-merge tools, CI pipelines, security-audit terminals on isolated networks). The doc-side warning is necessary; the YAML-side comment is sufficient for the audience that cannot reach the docs.

## How

One-line addition:

```yaml
ingestion:
  filter:
    # auth.ingestion.filter.enabled gates ONLY POST /ingestion/entities; sibling /ingestion/*
    # paths (alert/alertmanager, entities/degs/children, entities/datasets/stats, entities/metrics)
    # are NOT covered by this filter. See docs.opendatadiscovery.org/configuration-and-deployment/enable-security
    # for the per-endpoint authentication matrix.
    enabled: false
```

(Wording can be tightened; the load-bearing pieces are the explicit endpoint-name + the doc URL pointer.)

## Paired doc-side fix

**DOC-228** ships the per-endpoint deployment matrix on `enable-security/README.md` (the 80-cell-or-narrower table that operators auditing the YAML can be pointed at). DOC-228 lands the audience-on-the-doc-side surface; PLT-043 lands the audience-on-the-YAML-side surface.

## Tests

- Build-time check: the application.yml comment renders correctly via Spring Boot's relaxed config-binding (comments are ignored by the binder; this is a doc-string-only addition with no runtime effect).
- Regression check: no behavioural change. The filter still defaults to `false`; the YAML key still maps to `IngestionDataEntitiesFilter`'s `@ConditionalOnProperty`.
