## Description

`IngestionDataEntitiesFilter` gates the ingestion token check on a **hard-coded exact-literal path**:

```java
super(new PathPatternParserServerWebExchangeMatcher("/ingestion/entities", HttpMethod.POST));  // :28
```

Because the matcher is an exact literal (not a `/ingestion/entities/**` subtree, and not a constant derived from the controller's route metadata), any sibling/child ingestion write path added later — e.g. `POST /ingestion/entities/bulk` or `POST /ingestion/entities/{id}/...` — would be served by a controller that does NOT pass through this filter, accepting writes with **no collector-token authentication** even when `auth.ingestion.filter.enabled=true`. The regression is silent: adding the new endpoint compiles and the existing tests stay green, because nothing asserts the matcher's *intended scope*.

This is a **distinct facet** from the already-pinned coverage gap. `IngestionFilterPathCoverageTest.java` (same package) pins **PLT-003** — the *currently-missing* sibling write endpoints (`POST /ingestion/entities/datasets/stats`, `POST /ingestion/metrics`) that no filter matches today. TST-012 is the **forward-looking matcher-scope tripwire**: it does not re-pin which endpoints exist now, it guards the *literal-vs-subtree* shape so that a future widening (or a new child path) trips a test instead of shipping an unauthenticated write. REFACTOR-073 captures the refactor facet (derive the matcher from route metadata / widen to a subtree); this item is its test counterpart, asserting the current narrow literal so the refactor cannot land silently and so a new sibling path cannot slip under the radar.

**Typed gate: characterization-pin (LSN-029).** This pins the CURRENT exact-literal matcher scope. It asserts that the filter gates ONLY `POST /ingestion/entities` and does NOT gate a representative would-be sibling write path (e.g. `POST /ingestion/entities/bulk`) — capturing the present (narrow) behaviour. It goes RED the instant the matcher is widened to a subtree or a sibling becomes gated (the planned fix per REFACTOR-073), at which point the assertion is inverted to assert subtree coverage and re-tagged `@regresses`.
