## Description

Two operator-facing caveats on the per-dataset DQ test reports & SLA flow that don't change the headline behaviour but matter materially for any operator deploying the platform in a multi-team data org.

**Caveat 1 — Four DQ read endpoints unscoped, cross-owner readable (F-022b).** Four GET endpoints (`getDataEntityDataQATests`, `getDatasetTestReport`, `getSLA`, `getDatasetSLAReport`) have NO entry in `SecurityConstants.SECURITY_RULES` (per `odd-platform-api/src/main/java/.../auth/authorization/SecurityConstants.java:243-246`); they fall through to `AuthorizationCustomizer`'s catch-all `.authenticated()`. The repository queries at `ReactiveDataQualityRepositoryImpl.java:46-58, 62-84, 105-126, 130-138` apply only `HOLLOW.isFalse()` + `STATUS.ne(DELETED)` — **no owner JOIN**. Any authenticated caller reads any dataset's DQ tests, test reports, and SLA. The read-collaborative posture (ADR-CANDIDATE-003 / DOC-GAP-082 META) extends silently to P-04. A compliance reviewer at a multi-team data org cannot enforce per-team DQ visibility from configuration alone — every authenticated user sees every dataset's test results.

**Caveat 2 — Default-MAJOR severity silently inflates SLA (F-022c).** The live page states *"Severities are operator-set — the platform does not infer them"*. The mapper at `ReactiveDataQualityRepositoryImpl.java:142-148` (`mapLastRunDto`) returns `DataQualityTestSeverity.MAJOR` for tests with no row in `DATA_QUALITY_TEST_SEVERITY`. The SLA colour an operator sees is computed AS IF every unset test were Major — a dataset with 100 unset tests + 1 actually-critical-failing test renders RED. Operators see RED, investigate, find only one Critical test failing, and are confused why the dashboard is RED. No platform signal distinguishes operator-set MAJOR from default-MAJOR contribution.
