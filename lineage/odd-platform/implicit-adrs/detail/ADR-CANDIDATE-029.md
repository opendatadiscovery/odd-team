- **ADR-CANDIDATE-029** (NEW 2026-05-12C): `auth.type=DISABLED` is the shipped default in `application.yml` — operators opt-OUT of platform security (by setting a different value), not opt-IN. The default is encoded **explicitly and verbatim** rather than via a primitive default, paired with a live-doc page that names it the "default configuration" — a deliberate operator-onboarding stance whose acknowledged cost is silent insecure-by-default deployments on no-override containers
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`DisabledAuthSecurityConfiguration.auth.type@L10`) but the decision is contract-defining for the platform's default deployment posture; cross-validated by the live `disabled-authentication` doc page WebFetched 2026-05-12 (verbatim "This is the default configuration and no additional settings are required") + paired with the explicit `application.yml:32-34` comment enumerating all four documented values (`# DISABLED, LOGIN_FORM, OAUTH2, LDAP`)
  - **Surfaced by**:
    - `odd-platform__java__DisabledAuthSecurityConfiguration__config-key-consumer__auth_type@L10.md:implicit_adrs.[0]` ("DISABLED is the application.yml-shipped default for auth.type and the operator opt-out, not opt-in, of platform security." — intent_anchor: `# DISABLED, LOGIN_FORM, OAUTH2, LDAP\n  type: DISABLED` + live-doc verbatim "This is the default configuration")
  - **Decision statement**: ODD Platform ships with `auth.type=DISABLED` as the verbatim YAML default in `application.yml:32-34`. The choice is **explicit and intentional** — the comment above the line (`# DISABLED, LOGIN_FORM, OAUTH2, LDAP`) enumerates the documented value space, and the live `/configuration-and-deployment/enable-security/authentication/disabled-authentication` page corroborates "This is the default configuration and no additional settings are required" together with "DO NOT use this method in your production environment!". The decision commits the platform to a deployment story where operators inheriting an unmodified container image run a fully permit-all chain (every `/api/**`, every `/actuator/**`, every `/ingestion/**` reachable without authentication) UNLESS they explicitly override `auth.type`. The accepted price is that the same default produces silent insecure deployments when operators forget to override — the LSN-001-class failure mode of "the shipped default IS the danger". The maintainer's mitigation is the live-doc all-caps warning; the absence of (a) a boot-time WARN, (b) a fail-fast on production-profile detection, and (c) any auth-type validation against the documented enum, are the structural consequences captured in REFACTOR-073, REFACTOR-093, REFACTOR-097.
  - **Wisdom test**: PASS. The decision is anchored by (a) the deliberate `application.yml:34` literal `DISABLED` value, (b) the comment enumerating the enum's documented value space, (c) the live-doc page corroborating the stance verbatim, and (d) the four parallel `@ConditionalOnProperty` security-configuration classes whose mutual-exclusion encodes the mode-selection design. The decision IS intent-anchored; the **consequences of the decision** (silent boot, no audit log, actuator unauth, no CORS) are gaps with no defending rationale — they live in `refactoring-scopes.md` as REFACTOR-093/096/097.

    - DisabledAuthSecurityConfiguration.md says: "WebFetch disabled-authentication 2026-05-12 verbatim 'This is the default configuration and no additional settings are required.' + 'DO NOT use this method in your production environment!'"
  - **Existing ADR**: none. Composes with ADR-CANDIDATE-004 (GenAI disabled-by-default) and ADR-CANDIDATE-019 (Data Collaboration disabled-by-default) as the platform's broader "ship-disabled-by-default" stance — but distinct in that GenAI/DataCollab disable the *feature* while DISABLED disables the *security posture*. The maintainer's triage decision is whether DISABLED-as-default for security is the same family as feature-disabled-by-default or a separate operator-onboarding decision.
  - **Co-surfaced gaps** (link from `refactoring-scopes.md`): REFACTOR-073 (no boot-time security-posture validator — STRENGTHENED to 4-sidecar triangulation by DisabledAuthSecurityConfiguration joining AppInfoController + AuthorizationManagerCondition + IngestionDataEntitiesFilter), REFACTOR-093 (no boot-time WARN when DISABLED activates — MEDIUM), REFACTOR-096 (actuator endpoints unauth under DISABLED — MEDIUM), REFACTOR-097 (no audit logging codebase-wide — amplified by DISABLED — MEDIUM), REFACTOR-098 (missing-key fall-through on `auth.type` — MEDIUM).

The maintainer's deliberate choice between "secure-by-default" and "easy-onboarding-by-default" is captured by this ADR; future PRs proposing to flip the default to LOGIN_FORM would be making a structural change against this ADR.
