## Description

Two UI-side behaviour caveats on the per-entity lineage graph that extend the existing DOC-GAP-105 (backend/SQL-layer lineage gaps) with the UI-amplification dimension the original gap does not capture.

**Caveat 1 — UI hardcodes `lineage_depth=1` (F-005a).** The live API-reference doc claims *"Unset returns the platform's default depth"*. The platform UI always sends `lineage_depth=1` across three surfaces — `HierarchyLineage` initial fetch, `LoadMoreButton` incremental, `GroupedEntitiesListModal` (per `odd-platform-ui/src/components/HierarchyLineage/constants.ts:74-84` + `HierarchyLineage.tsx:47` + `useQueryParams.ts:38-44`). The doc's "unset returns default" branch is **unreachable from the UI**. Only direct API callers (curl / SDK / Swagger UI) can omit the parameter — and they hit the NPE-on-null-default already captured in DOC-GAP-105.

**Caveat 2 — Click-through compounds depth (F-005b).** Clicking a graph node title at `odd-platform-ui/src/components/HierarchyLineage/Node.tsx:46-52` navigates to `dataEntityLineagePath(entityId, { ...defaultLineageQuery, d: node.depth || 1 })`. The new view fetches lineage to depth = the clicked node's distance from current root. Drilling 5 hops in + clicking a leaf → new lineage walk to depth=5 around that leaf. Combined with the no-upper-bound class already in DOC-GAP-105 (`?d=999999999` reaches the CTE), casual canvas-clicking can trigger arbitrarily-expensive recursive CTE walks without touching the depth slider — Postgres CPU spikes correlated with user lineage clicks.

## Acceptance Criteria

- [ ] The lineage feature page (or its API-reference companion) documents that **the UI always sends `lineage_depth=1`** — the "unset returns default" branch in the API spec is reachable only from direct API callers. If the API also raises 500 on unset (the NPE class from DOC-GAP-105), state that explicitly so direct API callers don't assume the default-depth branch works.
- [ ] The lineage feature page documents the **click-through depth compounding** behaviour: clicking a node in the canvas opens a new lineage view with `?d` set to that node's distance from the current root. Operators tuning Postgres for the platform should expect deep-walk traffic from casual user clicks, not only from manual depth-slider use.
- [ ] The page cross-links the no-upper-bound caveat (DOC-GAP-105) so the click-through-amplification + bypassable-slider story reads as one operator-facing class.
