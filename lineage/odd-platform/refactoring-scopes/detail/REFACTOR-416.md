- **REFACTOR-416** (NEW 2026-05-19O): Body is parsed TWICE per ingestion request — `IngestionDataEntitiesFilter` parses the payload to `DataEntityList` purely to extract `dataSourceOddrn` (line 40), then re-emits the cached buffers (line 60) for `IngestionController.postDataEntityList` (line 38) to deserialise the SAME payload AGAIN. For a 20MB DataEntityList containing 1000 entities, this is two full Jackson tree-walks per request
  - **Category**: duplicate-parse
  - **Surfaced by**:
    - `IngestionDataEntitiesFilter.md:bugs_limitations_corner_cases.[9]` (MEDIUM)
    - `IngestionDataEntitiesFilter.md:performance.known_performance_gaps.[0]` (MEDIUM)
  - **Statement**: `IngestionDataEntitiesFilter.java:40` Jackson-deserialises the body to `DataEntityList` purely to extract `body.getDataSourceOddrn()`. After the token check, the filter re-emits the cached DataBuffers via `flatMapIterable(ignored -> dataBuffer)` at line 60. `IngestionController.java:38-44` then re-deserialises the same payload through the OpenAPI-generated `IngestionApi.postDataEntityList`'s `@Valid @RequestBody Mono<DataEntityList>` parameter binding. For a 20MB DataEntityList containing 1000 entities, this is two full Jackson tree-walks per request (estimated saving: ~half of per-request parse CPU; meaningful at >100 req/s on 1000-entity payloads).
  - **Evidence**: `IngestionDataEntitiesFilter.java:40` (full deserialise) + `IngestionController.java:38-44` (controller re-deserialises via @RequestBody)
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-138 NEW (body-buffered-before-auth is structural) — the duplicate parse is consequential to the ordering. The fix is a streaming-extraction approach that doesn't require full deserialisation of the body just to read `dataSourceOddrn`.
  - **Proposed remedy**: Use a Jackson streaming `JsonParser` to extract ONLY the `dataSourceOddrn` field from the buffered bytes (token-stream parsing, not tree-walk). Pass the body bytes through to the controller unchanged. Estimated saving: ~50% of per-request parse CPU on large payloads. Alternatively, attach the parsed `dataSourceOddrn` to the request attributes and have the controller read from attributes instead of re-deserialising (requires controller-side changes — more invasive).
  - **Severity rationale**: MEDIUM — performance gap; affects high-throughput ingestion. Not security-critical; operator-observable as slower-than-expected ingestion throughput.
  - **Suggested backlog grouping**: `Ingestion hardening sprint` (performance dimension; paired with REFACTOR-418 no-token-cache — both are per-request-cost optimisations)
