# DOC-504 — Search: the My-data scope filter + retire the Result-class tabs section

## Why

`search.md` documented a **nine-tab result-class strip** that no longer exists. ST-4 (#1838) retired the seven
per-class tabs when class selection moved into the Filters sidebar, and ST-8 (#1842) retires the last one
(`My Objects`) — so the section described a surface a reader cannot find, and the **Type** facet bullet still
told them to "select an entity-class tab at the top of the Catalog".

ST-8 also introduces user-facing behaviour with a real operator hazard: the My-data lineage scope is
**bounded**, so a result can be a strict subset of the true scope. Impact analysis is the reason people reach
for that filter, so a truncated set read as complete is how someone ships a breaking change believing they have
told every downstream consumer. The caveat therefore lives next to the feature, not three sections away.

## Acceptance criteria

- [x] The "Result-class tabs" section is gone; the two sidebar filters that actually scope by kind/class are
      documented in its place, with the class table preserved.
- [x] A "My data" section explains the three additive options, the per-direction depth (1..3, default 1) and why
      it is bounded more tightly than the Lineage view, and which direction is the impact view.
- [x] The partial-result behaviour is a **warning admonition** naming the cause, the remedy, and the rule
      ("never sign off a schema change on a result labelled partial").
- [x] The query-example exclusion and the three availability states (hidden / disabled-with-remedy / empty) are
      stated.
- [x] `catalog-overview.md` renames the two lineage columns to match the filter, documents the View-all
      deep-links, and states the upstream/downstream direction explicitly.
- [ ] **Post-release (the release gate owns this):** live-site verification of the affected URLs.
