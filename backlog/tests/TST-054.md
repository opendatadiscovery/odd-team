## What

The owner-association admin-UI e2e specs flake intermittently under a long single-worker `feature-complete`
run (render/affordance timeouts), and **each passes on an isolated re-run**. Two distinct instances observed
during CTRIB-026 — a *different* test each run, confirming a flaky-neighbourhood, not a reproducible bug:

- **Instance 1 (CTRIB-026 `/review`, ~6.7 min run):** `remove-user-owner-mapping.spec.ts:123 › F-173
  Active-tab Remove › CORNER/UC-003 (PLT-148)` **hard-timed-out at 60s** — `page.waitForResponse` for
  `GET /api/owner_association_request` (the `activeFetch` helper, line 39) never resolved. Passed on the
  clean re-run (✓ 2.0s).
- **Instance 2 (CTRIB-026 rework verification, ~5 min run):** `direct-bind-create.spec.ts:60 › F-172 Admin
  direct-bind › SUCCESS/H-001` failed at 11.0s — `getByRole('button', { name: 'Create association' })`
  element-not-found within the 10s wait. **Re-ran isolated → 3 passed (1.2s).**

Both are **transient flakes**, **entirely unrelated to the #1768 tag/Overview change** (a different feature
surface — owner-association management), and pass deterministically in isolation.

## Why log it (low priority)

A 60s `waitForResponse` hard-timeout is a notable flake signature (the awaited GET either never fired or
the page had not navigated when the wait armed). It surfaced once in a long single-worker run and passed on
re-run. Worth a cheap stabilisation so it does not intermittently RED `feature-complete` for unrelated
changes (a false-alarm cost on every future contributor regression).

## Proposed fix

- `remove-user-owner-mapping`: make `activeFetch` resilient to an already-in-flight / already-completed
  `owner_association_request` GET (arm the `waitForResponse` BEFORE the navigation/action that triggers it,
  or assert the rendered Active-list state directly with a bounded poll instead of gating on the response).
- `direct-bind-create`: give the "Create association" affordance a bounded retry/poll rather than a single
  10s `toBeVisible` (the header affordance can lag first-paint under load).
- Confirm green across a few consecutive `multi-stack`/`feature-complete` runs.
