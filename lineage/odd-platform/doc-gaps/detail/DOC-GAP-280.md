  - **Evidence**:
    - **The constructor and merge function** (per sidecar primary source — `IntegrationRegistryFactory.java:29-40`): the factory constructs a `TreeMap<String, Integration>` with the case-insensitive `Comparator.comparing(String::toLowerCase)`; merge function `(o1, o2) -> o2`. The TreeMap's natural duplicate detection is therefore case-insensitive (two keys with `equalsIgnoreCase` are treated as the same key), and on collision the second-loaded value REPLACES the first-loaded.
    - **The classpath glob** (per sidecar primary source — `IntegrationRegistryFactory.java:26` — `classpath*:META-INF/wizard/*.yaml`): the `classpath*:` prefix scans across ALL jars and resource roots, not just the local jar. The load order is determined by JVM classpath ordering, which depends on filesystem ordering of the lib directory + jar file enumeration semantics. Non-deterministic across deployments — a CI build may load `Snowflake.yaml` before `snowflake.yaml`; a production build may reverse the order; the operator has no compile-time guarantee.
    - **The silent-merge consequence**:
      - **Scenario 1** (vendor + overlay): a vendor jar ships `META-INF/wizard/Snowflake.yaml` with their canonical Snowflake integration. An operator authors `META-INF/wizard/snowflake.yaml` (lowercase) as an overlay in a separate jar with their organisation-specific Snowflake config. Depending on classpath order, EITHER the vendor's Snowflake OR the operator's snowflake wins. The operator's intent (overlay) succeeds half the time; fails the other half; the failure mode is "operator's overlay silently does not take effect; vendor's default reaches the UI" — no error log, no UI signal.
      - **Scenario 2** (two operators in the same organisation): operator A authors `My-Custom-Integration.yaml`; operator B authors `my-custom-integration.yaml` in a separate jar without realising A's exists. Both jars deploy; one silently wins. The losing author has no error to diagnose; the winning author's manifest is what reaches the UI.
      - **Scenario 3** (CI vs prod divergence): same set of jars; different OS / JVM produces different classpath order; the integration that wins in CI is not the one that wins in prod. The same code-base behaves differently across environments.
    - **The case-insensitive intent**: per sidecar `implicit_adrs[plugin-extensible]`, the case-insensitive ordering is deliberate — the TreeMap sorts case-insensitively for UI display purposes (alphabetical wizard list regardless of file naming convention). The COMPOSITION with the merge function is the trap: case-insensitive sort is FINE; case-insensitive uniqueness silently merging is the operator-trap. A strict-uniqueness TreeMap (or a HashMap with case-preserved keys + a separate case-insensitive sort step at display time) would avoid the silent-merge while preserving the UI sort.
    - **The boot-time silence**: `IntegrationRegistryFactory.java` emits NO log warning when two case-collision YAMLs are detected. The factory simply applies the merge function. An operator inspecting the deployment's startup logs has no record of the collision; the operator must manually audit the wizard list against their source YAMLs to detect the merge.
    - **The live doc silence** (per sidecar `inferred_docs[0]` WebFetch 2026-05-25 status 200): the wizard doc page describes the manifest-load-from-classpath mechanism ("manifests on the platform's classpath") but does NOT document: (a) the case-insensitive uniqueness constraint; (b) the last-load-wins merge semantic; (c) the load-order non-determinism with `classpath*:` scanning. Wizard authors composing overlays have NO doc-side guidance on naming conventions to avoid collisions.
    - **The minimum-friction-fix recommendation**: the operator-trap shape is bounded by wizard-author awareness. The fix is a doc-side caveat naming the constraint; an optional code-side fix is to emit a `log.warn` when a case-collision is detected at boot (single-line change in the merge function: `(o1, o2) -> { log.warn("Wizard id collision: '{}' merged from two sources; last-load wins", o2.id()); return o2; }`).
