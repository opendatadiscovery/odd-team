## Description

The set of adapters that emit foreign-key ERD relationships (`ENTITY_RELATIONSHIP`) is stated three different ways across two pages — and one page contradicts itself.

**`relationships.md` (canonical UI-side reference for the Relationships surface)** lists ERD adapters as **PostgreSQL and Snowflake only** (coverage table, lines 58-63), and cross-links `odd-collector.md` as "the per-adapter feature matrix … calls out ERD support explicitly" (Where-to-next, line 113) — i.e. it defers to `odd-collector.md` as the authoritative adapter matrix.

**`odd-collector.md` (the deferred-to authority) drifted and now contradicts itself:**
- Line 1246 (cross-cutting capability matrix): ERD relationships apply to "`postgresql`, `snowflake`, `cockroachdb` (**via PostgreSQL inheritance**)."
- Line 358 (CockroachDB adapter section): "Pulls schemas, tables, columns, **and foreign-key relationships**. Inherits from the PostgreSQL plugin … ERD edges are emitted for cross-schema foreign keys exactly as on PostgreSQL."
- Line 1259 (Known limitations): "**Foreign-key extraction is PostgreSQL/Snowflake only** today. ClickHouse, MySQL, MSSQL, and others extract schemas and columns but not foreign-key relationships."

So within `odd-collector.md`, the matrix and the CockroachDB section claim CockroachDB emits ERD; the known-limitations bullet says only PostgreSQL/Snowflake do. The two pages disagree (relationships.md omits CockroachDB), and the authoritative page disagrees with itself.

An operator deciding "will my CockroachDB source show ERD diagrams?" reads relationships.md and concludes no; reads the odd-collector.md CockroachDB section and concludes yes; reads the same page's limitations bullet and concludes no again. The claim is not file:line-verifiable from the docs because the docs don't agree — it must be resolved against the upstream `odd-collectors` source, which is the canonical owner of what an adapter emits.
