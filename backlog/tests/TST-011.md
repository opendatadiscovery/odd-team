## Description

IT-104 ("Management chrome") characterizes the Management tab strip but runs against the `odd-minimal` stack with **`AUTH_TYPE=DISABLED`**, where the dummy principal resolves `OWNER_ASSOCIATION_MANAGE` as granted, so **all 9 sidebar tabs render — including the conditionally-hidden Associations tab** (IT-104 protocol §2 / §5 CORNER PIN, `integration-tests/protocols/IT-104-management-chrome.md`). That is the wrong posture for verifying the *visibility model*: under DISABLED the `hidden` branch is never exercised, so IT-104 does not pin the case that matters — an LDAP non-admin who lacks `OWNER_ASSOCIATION_MANAGE` and should see the Associations tab HIDDEN (while the other admin tabs remain advertised).

The client-side visibility model is in `ManagementTabs.tsx:14-51`:

```ts
const hideAssociations = useMemo(
  () => !hasAccessTo(Permission.OWNER_ASSOCIATION_MANAGE),   // :14-17
  [hasAccessTo]
);
// ...the 9 tabs; ONLY Associations carries `hidden`:
{ name: t('Associations'),
  link: managementPath('associations'),
  hidden: hideAssociations },                                // :39-43
```

Only the **Associations** tab is conditionally hidden; the other eight (Namespaces, Datasources, Integrations, Collectors, Owners, Tags, Roles, Policies) are always rendered. The backing permission is real and API-enforced: `SecurityConstants.java:148-150` registers `("/api/owner_association_request", GET) → OWNER_ASSOCIATION_MANAGE`. So for a non-admin LDAP user the tab is *hidden in the chrome* but the question of whether the route/API are independently gated is exactly the "hidden-tab-vs-reachable" case IT-104 cannot reach.

**Typed gate: validates-feature.** This validates the F-074/F-105 authorization-visibility promise against the authoritative Management-chrome UI defined in F-161: under a non-admin LDAP posture the Associations tab is hidden while the other admin tabs stay advertised. (It is not a known-bug pin — the hide is intended behaviour; the gap is that no IT runs the posture where the hide actually fires.)
