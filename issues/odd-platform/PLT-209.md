## What

The operator-supplied "Additional links" rendered in the app-info menu are keyed by their URL. When an operator configures two links that point to the **same** URL with **different titles** (a perfectly valid config — e.g. two labels for one internal portal), React sees duplicate keys: it logs a console warning and renders only **one** of the two list items, so one of the configured link labels silently disappears from the menu. The operator gets no error; the link they configured just is not there.

## Where

`odd-platform-ui/src/components/shared/elements/AppToolbar/AppInfoMenu/AppInfoMenu.tsx:61`

```tsx
{links.map(link => (
  <Link key={link.url} to={link.url} target='_blank'>   // line 61: key is the URL, not unique per item
    <S.MenuItem container>
      <Typography variant='h4'>{link.title}</Typography>
    </S.MenuItem>
  </Link>
))}
```

`link.url` is not guaranteed unique across the configured list, so it is not a safe React key.

## Why it matters

Mostly **loud-in-console, silent-in-UI**: every render with a duplicate-URL config emits the React "Encountered two children with the same key" warning, and one of the two links is dropped from the menu. Operators configure these links to point their users at internal docs/dashboards; a silently-missing link is a small but real correctness defect in operator-controlled chrome. Severity **low** — it only triggers on the same-URL-different-title edge and the impact is a missing menu entry, not data loss.

## Suggested fix

Use a stable, unique key — the array index is acceptable here since the list is small, static per render, and not reordered, or a composite `${link.url}-${link.title}-${index}` if a content-based key is preferred (open to alternatives):

```tsx
{links.map((link, index) => (
  <Link key={`${link.url}-${index}`} to={link.url} target='_blank'>
    ...
  </Link>
))}
```

This is a one-line render fix and should be folded into the **PLT-088** UI PR, which already touches this exact `.map`/`<Link>` block (PLT-088 modifies line 61 to add `rel='noopener noreferrer'`).
