## Description

DOC-287 corrected `data-quality/test-results-import.md` to route custom-framework **test results** to `POST /ingestion/entities` (a `DataEntityList` of `DataQualityTest` / `DataQualityTestRun` entities), with an explicit warning against `POST /ingestion/entities/datasets/stats` (which accepts a `DatasetStatisticsList` — per-column profiler statistics, not test results). The fix landed on the canonical page only. Three **secondary surfaces** still carry the original (wrong) endpoint for custom frameworks — all confirmed live on `docs.opendatadiscovery.org` 2026-05-29:

- `data-quality.md:15` (Subsections → Test Results Import bullet): "…and the `POST /ingestion/entities/datasets/stats` endpoint for custom frameworks."
- `Features.md:78`: "Custom frameworks can push their own test results through the `POST /ingestion/entities/datasets/stats` endpoint…"
- `use-cases/dq-visibility.md:11`: "Teams with a custom DQ framework can push results through the `POST /ingestion/entities/datasets/stats` endpoint…"
- `use-cases/dq-visibility.md:22`: "…push its results through the `POST /ingestion/entities/datasets/stats` endpoint so the custom KPIs show up…" — **AMBIGUOUS, see note**.

Same Critical failure mode as DOC-287: an integrator following any of these wires their client to the wrong endpoint with the wrong payload and sees **silent data non-arrival** (a `DataEntityList` sent to the `DatasetStatisticsList` route does not land). The canonical page is now correct but **contradicts** these surfaces, and the hub + `Features.md` are higher-traffic landing pages than the deep canonical page.

**Failure shape**: parallel surfaces with drift / internal contradiction — the same critical code-doc-drift error DOC-287 fixed, un-propagated to the pages that summarise it.

**Note on `dq-visibility.md:22` — do NOT blindly rewrite.** That sentence describes "custom KPIs / profiles compared across datasets" pushed via a scheduled SQL script. If those outputs are **per-column statistical profiles**, `/ingestion/entities/datasets/stats` (`DatasetStatisticsList`) is the **correct** endpoint there and the line should stay. If they are **pass/fail DQ test outcomes**, it is wrong and must move to `/ingestion/entities`. The implementer must read the surrounding intent and disambiguate before editing line 22. Lines 11, `Features.md:78`, and `data-quality.md:15` are unambiguously about "test results" and are wrong.
