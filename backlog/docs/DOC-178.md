## Description

The live Business Glossary page frames the **Dictionary tab** as "the catalog-wide list of all terms in the platform" — a flat list. The implementation is a **server-side faceted-search session UI** (`TermSearch.tsx`). On first visit (no URL parameter) the platform `POST /api/termsearch`-es an empty query, redirects to `/termsearch/{uuid}`, and renders an **empty results table** until the user types or applies a facet. A new operator clicking "Dictionary" expecting a list sees an empty results table and concludes the catalog is empty.

Three caveats follow from the faceted-search session shape:

**Caveat 1 — Empty-first-view UX surprise (F-024a).** Documented as a flat list; behaves as a session-scoped search whose default state is empty. The doc copy actively misleads.

**Caveat 2 — Facet debouncer recreated per render — 1500ms rate-limit is broken (F-024b).** `TermSearch.tsx:50-64` wraps `useDebouncedCallback(..., 1500, {leading: true})` in `useCallback` with `[termSearchId, termSearchFacetParams]` as deps. `termSearchFacetParams` changes on every facet click → a NEW debouncer is constructed each click → the prior debouncer's trailing timer is GCed before it fires. Effective behaviour: every facet click dispatches `updateTermSearch` IMMEDIATELY; the 1500ms rate-limit applies to nothing. A user rapidly clicking five facets in two seconds dispatches five PUTs instead of the intended one. (Same defect pattern at a second site within the same component tree: `MultipleFilterItemAutocomplete.tsx:97-116`.) Operator-visible: more API requests than the doc/UI implies; potential server-side cost amplification on busy term catalogs.

**Caveat 3 — Search-session UUID URL share = session-state share (F-024c).** Sharing `/termsearch/{uuid}` via Slack/Confluence inadvertently shares the session's full state (filters, query, pagination, paging cursor). Recipients can mutate the session. No per-caller ownership check on six search-state endpoints at `TermController.java:166-216`. Operator-visible consequence is bounded (Term catalog is platform-wide-readable anyway; the marginal info-disclosure is the recipient's ability to mutate the sharer's session view, not to see otherwise-restricted data).
