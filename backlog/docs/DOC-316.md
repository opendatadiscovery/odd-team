## Description

The Architectural Decision Log index (`README.md` "Records" list) and the SUMMARY.md nav block list the 27 ADRs in **the order they were authored**, which is neither numeric nor by visible theme. Observed order:

`0001, 0002, 0004, 0007, 0008, 0012, 0018, 0019, 0020, 0040, 0041, 0042, 0043, 0044, 0021, 0022, 0028, 0045, 0046, 0073, 0071, 0070, 0072, 0003, 0058, 0074, 0075`

Notifications (0040-0044) precede activity (0021-0022); the platform-backbone block runs `0073, 0071, 0070, 0072` (scrambled); `0003` (read-collaborative authz) sits 25th despite being a low number a reader scans for near the top. SUMMARY.md mirrors the identical order, so the nav rail gives the same disorientation. There are no thematic group headings, so nothing signals an organizing principle — it reads as random.

**Failure shape:** index-ordering / placement defect.

## Acceptance Criteria

- [ ] The README Records list is re-ordered to a predictable scheme — either strict numeric, OR thematic subgroup headings (e.g. HTTP/API & contract layer; Security & auth; Feature-gating posture; Notifications & delivery; Activity feed; Storage & partitioning; Identity & ingestion; Platform stack & dependencies) with ADRs numeric-sorted *within* each group
- [ ] `docs/SUMMARY.md` nav block is re-ordered to match the README scheme (the two surfaces stay in lock-step)
- [ ] (folded in) The `SUMMARY.md` entry for ADR-0028 is aligned to the full H1/README title ("…at boot and nightly") — currently the SUMMARY label is shorter than the page H1

## Context

- Surfaced by the mandatory doc-product editorial audit (`playbooks/doc-product-editorial-read.md`) during the `/review` of the 26-ADR backbone batch on 2026-05-31.
- Verbatim (README.md:32-39): `* [ADR-0073 …]` then `* [ADR-0071 …]` then `* [ADR-0070 …]` then `* [ADR-0072 …]` — the backbone block out of sequence.
- Editorial verdict: this is a real reader-facing defect, not acceptable thematic grouping (no group headings exist to signal intent).
- Recommended-fix direction: thematic subgroups read better than flat numeric for a 27-entry log, but flat numeric is the cheaper, predictable minimum. Fix both surfaces in one commit (Gate 7 keeps README + SUMMARY in sync).
