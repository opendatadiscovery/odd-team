## Context

The 2026-09-03 pre-push scan of odd-team `main` (a public repository) found the maintainer's absolute home
path in **53 committed files**: 4 new that day (two run-logs' hand-written `evidence/notes:` lines, the
CTRIB-063 record, TST-066) and 49 older ontology/state artefacts (test-map details, probe-run stderr tails,
meta-review raw notes, DOC-435, a review-sweep). All were rewritten in commit `5fd0dcb0`. The rule ("never
commit `/home/<user>/...`") has existed as memory `feedback_no_hardcoded_absolute_paths` since 2026-05 and
was violated 53 times anyway, because nothing enforces it — the same *knowing != preventing* shape as
LSN-036 and LSN-042. Sessions re-leak it every time they paste a shell command or a tool result into a
record.

The harness is not the source: `integration-tests/run-suite.sh:252-270` writes a short SHA, the image tag
and the digest into a run-log entry and never a path. The absolute forms came from sessions filling the
`evidence/notes:` line by hand (and from the reducers' "verified via Glob over /home/..." evidence strings
in 2026-05). So the fix is a deterministic guard at commit/push time, not a writer change.

## Acceptance criteria

1. **The enforced check leads.** `scripts/check-no-home-paths.sh` exists, is executable, greps the staged
   diff (`git diff --cached -U0`) by default and the whole tracked tree with `--all`, matches
   `/home/[A-Za-z0-9_-]+/` (and `/Users/[A-Za-z0-9_-]+/` for macOS), prints `file:line` for every hit and
   exits non-zero on any. Verified by running it: `--all` on the current tree exits 0; a staged file with a
   planted `/home/someone/x` path makes it exit 1 (then unstage the plant).
2. `CLAUDE.md` "Git Hygiene" carries one line: run the check before committing; absolute home paths are a
   commit-blocker. The `/implement` skill's step 6.5 mechanical sweeps and `playbooks/github-write.md` step 5's
   pre-push block both name it, so every commit path in the workspace (implement, contribute, review
   bookkeeping) runs the same guard.
3. The replacement convention is stated once, next to the rule: repo-relative (`./`) inside odd-team,
   sibling-relative (`../odd-platform/...`) for the other checkouts, and `$(realpath ../<worktree>)` when the
   text must convey "an absolute path was passed" (the TST-066 / IT-154 A/B rows).
4. No new session guidance is needed beyond the pointer — the memory already exists; the item closes when the
   guard, not the memory, is what stops the next leak.

## Notes

- Keep it a shell script (git + grep only): the workspace has no budget and the guard must run in every
  session without a toolchain (memory `project_no_budget_self_hosted_guardrails`).
- A `.git/hooks/pre-commit` is local and uncommitted, so it cannot be the deliverable; the committed script +
  the three pointers are. If the maintainer wants the hook too, the script is what the hook calls.
- Case-law: `retrospectives/LSN-042` (the session that ran the scan), commit `5fd0dcb0` (the 53-file cleanup),
  `retrospectives/LSN-036` (a catalogued invariant must be promoted to an enforced check).
