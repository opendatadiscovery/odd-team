## Description

Adjacent finding from CTRIB-028 (out of #1754's scope). `DatasetFieldTermsDtoMapper.mapRecordToDto`
(`repository/mapper/DatasetFieldTermsDtoMapper.java:51-52`) dereferences `dataEntityPojo` **unconditionally**:

```java
.dataEntityName(dataEntityPojo.getExternalName())
.dataEntityId(dataEntityPojo.getId())
```

`ReactiveDatasetFieldRepositoryImpl.listByTerm` resolves the data entity via a **LEFT** join
(`DATA_ENTITY.ODDRN = <field's max dataset_version dataset_oddrn>`). If a `dataset_field` is linked to a term
(`dataset_field_to_term`) but has **no resolvable `data_entity`** (orphaned column — no `dataset_structure`/
`dataset_version`, or its dataset row is gone), `dataEntityPojo` is null and the mapper NPEs → the **entire**
Linked-columns page 500s (`SYS001`). LSN-024/LSN-001 silent-failure class.

Observed live during CTRIB-028 seeding: 60 `dataset_field_to_term` rows whose fields had no `dataset_structure`
→ `GET /api/terms/{id}/linked_columns` returned HTTP 500 with
`NullPointerException ... DataEntityPojo.getExternalName() ... DatasetFieldTermsDtoMapper.java:51`.

## Reachability (to confirm when worked)

Depends on whether deleting a dataset cascades its `dataset_field` / `dataset_field_to_term` rows. If orphan
columns with surviving term links can exist (data-source deletion, partial re-ingest), this is reachable in
production and breaks the whole tab. Confirm the cascade behaviour, then fix accordingly.

## Suggested fix

Null-guard the data entity in the mapper (emit `dataEntityName`/`dataEntityId` as null when absent) AND/OR
exclude orphan columns at the query level. A null data entity must degrade one row gracefully, never 500 the page.

## Acceptance

- A term linked to an orphan column renders the linked-columns list (the orphan row degraded, not a page 500).
- A repository/Testcontainers test seeds the orphan condition and asserts a 200 + graceful row.
