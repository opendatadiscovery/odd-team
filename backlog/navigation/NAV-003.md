## Description
`navigation/domains/lookup-tables.md` lists the lookup-table repositories, mappers, DTOs, and UI component, and references the `/api/referencedata/` surface conceptually — but it does **not** list the two core backend files of that surface as explicit file pointers:
- `odd-platform-api/.../controller/ReferenceDataController.java`
- `odd-platform-api/.../service/ReferenceDataServiceImpl.java` (+ the `ReferenceDataService` interface)

The workspace bar (CLAUDE.md Token Budget / navigation guidance) is that navigation domains list the controller/service/repository chain so consumer-read audits find them without grepping. These two are the owners of the lookup-table write contract — the subject of CTRIB-033 / odd-platform#1769.

## Acceptance Criteria
- [ ] `navigation/domains/lookup-tables.md` lists `ReferenceDataController.java` and `ReferenceDataServiceImpl.java` (+ the `ReferenceDataService` interface) under the backend file pointers.
- [ ] The entry notes the column-belongs-to-table invariant locus: the read guard `getLookupTableField` and the write-path guards on `updateLookupTableField` / `deleteLookupTableField` (added by #1769), plus `createLookupTable`'s `existsByTableName` collision pre-check.

Discovered during `/review` of CTRIB-033 (odd-platform#1769). The fix touched `ReferenceDataController` + `ReferenceDataServiceImpl` + `ReferenceDataService` + `ReactiveLookupTableRepository[Impl]`; only the repository was already in the nav domain. Pre-existing gap (not introduced by CTRIB-033). Low priority — the domain covers the surface conceptually; this adds the missing file pointers.
