## What

Six operator-visible gaps on the GenAI Assistant feature surface, grouped as two related defects. The platform-to-EXTERNAL posture (toward the LLM provider) is already documented (per DOC-045 / live page WebFetched 2026-05-27). The **platform-to-USER posture** is undocumented and undefended.

**Defect 1 — Platform-to-user posture is unrestricted.** `GenAIController.java:13-24` carries no `@PreAuthorize`, does not reference `ServerWebExchange` for security checks, and `SecurityConstants.java:98-355` has **no `/api/genai/**` entry**. The endpoint falls through to global `.authenticated()` under LOGIN_FORM / OAUTH2 / LDAP, and to **anonymous** under `auth.type=DISABLED`. Five sub-gaps:

- **(a) Any authenticated user can drive cost** on the operator's external LLM account — no rate-limit, no throttle, no per-user quota
- **(b) No audit** — no in-platform record of who asked what (and the activity-feed schema-rooted constraint per F-021a means this can't be added without a schema migration)
- **(c) No PII redaction** — entity owner names, lineage entity names, free-form chat content flow verbatim to the external LLM
- **(d) No request-body size cap** — large free-form prompts pass through unbounded
- **(e) Under `auth.type=DISABLED`** — no per-user attribution at all; anonymous callers drive cost

**Defect 2 — `genai.url` is operator-config SSRF surface.** `GenAIProperties.java:10` declares `String url` with no `@URL` constraint, no `@Pattern` scheme/host allowlist. Operator (or attacker with config-write access) can point outbound POST at any reachable URL **including the platform's own internal network** — private subnets, internal services, cloud-metadata endpoints (e.g., `http://169.254.169.254/latest/meta-data/iam/security-credentials/`). The WebClient runs in the platform's JVM — requests originate from the platform's egress identity.

## Why it matters

GenAI is a **cost-amplification surface**. The operator pays per token on the external LLM bill. The platform proxies user prompts through their account with no upper bound on per-user activity.

The compound failure mode: operator enables GenAI; user discovers the endpoint (UI button or `/api/genai/ask`); user (or compromised user-credential-holder) loops requests; LLM bill explodes; operator has no audit trail to identify the culprit.

Severity is HIGH because:
- Cost-injection is a financial impact (real money, not just compute time)
- The compound with `auth.type=DISABLED` (used in dev / evaluation deployments) is **fully unauthenticated** cost injection
- SSRF via `genai.url` enables credentials-exfiltration on cloud deployments (instance-metadata access)
- The fix is multiple small changes, but each is well-bounded

## Suggested fix

### PR-1 — Authentication + authorization (Defect 1a + 1e)

```java
// SecurityConstants.java — add /api/genai/** to the SECURITY_RULES list
new PathPatternParserServerWebExchangeMatcher("/api/genai/**", POST)
    .requires(GENAI_USE),

// new permission: GENAI_USE — operator grants this to roles allowed to invoke GenAI
// pair with a new GENAI_ADMIN permission for any future config / model selection endpoints
```

Default: deny under `auth.type=DISABLED` unless explicit `genai.allow-disabled-mode: true` opt-in. Document the new permission in `permissions.md`.

### PR-2 — Rate limiting (Defect 1a)

```java
// new config: genai.rate-limit.per-user-per-minute (default: 10)
// new config: genai.rate-limit.platform-per-minute (default: 100)
// implementation: Bucket4j or Redis-backed token bucket keyed by username + global

// GenAIController.java
@PostMapping("/api/genai/ask")
public Mono<GenAIResponse> ask(@RequestBody GenAIRequest req, ServerWebExchange exchange) {
    return rateLimitService.tryAcquire(currentUser(exchange))
        .flatMap(allowed -> allowed
            ? genaiService.ask(req)
            : Mono.error(new RateLimitedException("rate limit exceeded"))
        );
}
```

### PR-3 — Audit (Defect 1b)

Two options given the activity-feed schema-rooted constraint:

- **Option A** — emit a non-activity-feed audit event to a new `genai_request_log` table. Operator can query this for cost-attribution.
- **Option B** — extend the activity-feed schema (relates to F-021a) to support nullable `data_entity_id`. Larger architectural change; not in scope of this PLT.

Recommend Option A for this PLT; revisit Option B at the F-021a resolution.

### PR-4 — PII redaction + body-size cap (Defect 1c + 1d)

```java
// new config: genai.pii-redaction.enabled (default: true — opinionated default for safety)
// new config: genai.max-request-body-size-bytes (default: 16384 = 16KB)

// GenAIController.java — body-size enforcement
@PostMapping("/api/genai/ask")
public Mono<GenAIResponse> ask(@RequestBody @Size(max = 16384) GenAIRequest req) { ... }

// GenAIService — PII redaction
//   - identify owner-email patterns, owner-name patterns (configurable allow-list of known-safe identifiers)
//   - replace with [REDACTED-EMAIL], [REDACTED-OWNER] tokens
//   - log the redaction count for operator observability
```

### PR-5 — SSRF allowlist (Defect 2)

```java
// GenAIProperties.java
public class GenAIProperties {

    @NotBlank
    @Pattern(regexp = "^https?://[^/]+(/.*)?$")
    private String url;
}

// new config: genai.url-allow-list (default: empty — accepts any URL matching the @Pattern)
// operators with stricter posture configure: genai.url-allow-list: ["api.openai.com", "internal-llm.corp.example"]
// implementation: validate parsed URL host against the allow-list before instantiating WebClient
```
