## Description

The "cap to N + `View All (N)` collapse" pattern is **hand-rolled in ~7 places** in `odd-platform-ui`,
each re-implementing the slice/sort/map + the `<Collapse>` + the toggle button:

- `DataEntityDetails/Overview/OverviewTags/OverviewTags.tsx`
- `DataEntityDetails/Overview/OverviewTerms/OverviewTerms.tsx`
- `DataEntityDetails/Overview/OverviewGroups/OverviewGroups.tsx`
- `Terms/TermDetails/Overview/OverviewTags/OverviewTags.tsx`
- `DataEntityDetails/.../DatasetFieldOverview/DatasetFieldTags/DatasetFieldTags.tsx`
- `DataEntityDetails/Overview/OverviewMetrics/OverviewMetrics.tsx`
- `DataEntityDetails/Overview/OverviewAttachments/AttachmentsList/AttachmentsList.tsx`

**Why it matters (the class behind #1768).** The duplication is exactly why the #1768 defects existed
and recurred:
- the slice-then-sort importance bug appeared **independently in 3 of the tag lists** (fixed one-by-one
  in #1768 / PLT-096);
- the new `Showing N of M` truncation hint (#1768 Defect 3) was applied to only **3 of the 5+
  truncatable lists** (entity Overview Tags/Terms/Groups) to keep that PR bounded — the term-detail and
  dataset-field lists still lack it, an inconsistency the duplication forces;
- the `view_all_collapse_unmountonexit_loses_user_scroll_position` facet (F-179) is still open in every
  instance.

A single `<TruncatedList items=... visibleLimit=... comparator?=... renderItem=...>` would carry
sort-before-slice, the hint, and the View-All toggle **once**, so a future change can't regress one copy
and miss the others.

## Proposed scope

- Add a shared `components/shared/elements/TruncatedList` (or similar) encapsulating: optional comparator
  (applied to the WHOLE list before slicing), the `Showing {{visible}} of {{total}}` hint, the
  `View All (N)` / `Hide` toggle, and (optionally) scroll-position retention on collapse.
- Migrate the 7 call sites to it; delete the per-component slice/sort/View-All code.
- Carry the i18n key already added in #1768.
