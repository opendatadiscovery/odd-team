## Description

A signed-in user who has not been associated with an `Owner` is silently "not bound" to any data-entity ownership. Every personalised "My-*" surface in the platform — My Objects, the **My** mode of the Activity feed, My Alerts, and the Overview page's my/popular split — resolves its data through the same association lookup, and each independently renders a **generic empty state** when that lookup comes back empty. There is no single platform-wide signal telling the user "you are not associated with an Owner yet; request an association" — each surface looks identically empty to a user who simply owns nothing, which is misleading: a brand-new authenticated user cannot tell the difference between "I have no objects" and "I am not bound to an Owner so the platform cannot attribute anything to me."

The mechanism: every personalised surface ultimately depends on `AuthIdentityProvider.fetchAssociatedOwner()`, which is `getCurrentUser().flatMap(user -> userOwnerMappingRepository.getAssociatedOwner(...))` (`AuthIdentityProviderImpl.java:49-53`). When the user→owner mapping row does not exist, `getAssociatedOwner(...)` emits empty, the Mono completes empty, and the downstream "My-*" query yields nothing — so the surface falls back to its ordinary empty state with no association-specific affordance.

The harvest's `REFACTOR-224` covers only the DataEntity `/my` locus. This item documents the **platform-wide** absence so an operator (and the docs) frame it once, for every My-* surface, rather than per-locus. The user-owner-association page is the natural home: it already explains *how* a user gets bound; it should also explain *what the UI looks like before that happens* and that the empty state is expected, not a bug.

## Context

Source feature: F-064 (My objects / personalised activity). Known ref: `REFACTOR-224` (DataEntity `/my` locus only) — this item generalises the same absence across every My-* surface so the doc fix closes the whole class in one pass.

Canonical code truth (verified 2026-06-08):
- `odd-platform-api/.../auth/AuthIdentityProviderImpl.java:49-53` — `fetchAssociatedOwner()` = `getCurrentUser().flatMap(user -> userOwnerMappingRepository.getAssociatedOwner(user.username(), user.provider()))`; emits empty when no mapping row exists.
- `odd-platform-api/.../service/IdentityServiceImpl.java:36-51` — `whoami()` defaults the associated owner to `new OwnerPojo()` and maps `owner.getId() != null ? owner : null`, i.e. an unbound user's `AssociatedOwner.owner` is `null` — the platform's own model for "not bound", surfaced with no distinct affordance.

The proposed shared `<EmptyStateAffordance>` component in the harvest is a UI code enhancement (highest cross-feature leverage) — an upstream follow-up, not part of this doc item. This item documents the current behaviour and expectation for operators.
