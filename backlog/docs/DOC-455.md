## Description

The platform fix for odd-platform#1741 (CTRIB-013) ships at **0.28.0**: `MinioConfig` now accepts an optional
`attachment.remote.region` and passes it to the MinIO builder, so AWS S3 buckets outside `us-east-1` work once
the region is set. The doc page must (a) document the new config key and (b) retire the now-obsolete
"AWS S3 region pinned to `us-east-1`" known-limitation.

**Authored on `release/0.28.0`** (the train; publishes at the 0.28.0 release gate, never to docs `main` before
the code ships). The agent could NOT push to the shared `release/0.28.0` branch (correctly gated — the
maintainer controls release-branch pushes); the change is committed locally in a worktree and recorded below
for the maintainer to apply + push.

### The change (apply to `docs/configuration-and-deployment/odd-platform.md` on `release/0.28.0`)

1. **Config-key list** — reword the `attachment.remote.url` bullet to point at the new key, and ADD:
   > * `attachment.remote.region`: AWS S3 region used for request signing (for example `eu-central-1`).
   >   **Optional** — when left unset, the MinIO Java SDK's default (`us-east-1`) is used. Set it to your
   >   bucket's region when using **AWS S3 outside `us-east-1`**, otherwise uploads fail signature validation
   >   with `AuthorizationHeaderMalformed` or `PermanentRedirect`. Self-hosted MinIO and most other
   >   S3-compatible services ignore the region and can leave it unset.
2. **YAML config example tab** — add `    region: {aws_region} # optional; e.g. eu-central-1 for AWS S3 outside us-east-1` under `remote:`.
3. **Environment-variable tab** — add `ATTACHMENT_REMOTE_REGION={aws_region}`.
4. **Known limitations (REMOTE mode)** — REMOVE the `{% hint style="warning" %}` "AWS S3 region pinned to
   `us-east-1`" block (no longer a limitation; it's now a config key). Leave the HTTP-timeout, chunked-staging,
   no-retry, and IAM-role caveats UNCHANGED (those facets of PLT-086 are out of scope of #1741).
