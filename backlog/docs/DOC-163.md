## Description

After DOC-162 ships (5-axis scanner Method), re-run `/enumerate scanners/docs/coverage/undocumented-features.md` against `odd-platform` `origin/main` to:

1. Refresh the existing 4-axis enumeration (commit drift since 2026-04-21 / `279fe8ee`).
2. Generate the new `ui_shell` axis items: every `<AppToolbar>` widget directory; `locales/i18n.ts` + `locales/translations/*.json`; theme provider; error-page family; auth-flow UI (login form, OIDC entry, LDAP entry, S2S entry); any TS file imported by `index.tsx` not already in axes 1-3; any component mounted inside `<AppToolbar>` render.
3. Generate the new `config_prefixes` axis items: every top-level `application.yml` key → `@ConfigurationProperties` consumer class.
4. Cross-reference each new item against the documentation repo's SUMMARY.md to identify undocumented gaps.
5. Write findings to `findings/docs-coverage-undocumented-features/2026-05-NN.md` (use the date the scan executes).
6. Update `state/coverage/docs-coverage-undocumented-features.yaml` with the new items + bumped `*_repo_commit_at_enumeration` SHAs.

## Acceptance Criteria

- [ ] Coverage manifest YAML's `last_enumerated` updated; `*_repo_commit_at_enumeration` reflects current `origin/main` of `odd-platform`.
- [ ] `ui_shell` axis section in the manifest enumerates ≥6 items (i18n bootstrap, ≥3 toolbar widgets, theme, error pages, auth flow). Each item carries `axis: ui_shell` annotation.
- [ ] `config_prefixes` axis section enumerates every top-level prefix in `application.yml` with its consumer class.
- [ ] Findings file lists each undocumented item with: feature name, evidence (file path + symbol), whether completely undocumented or partially, estimated documentation effort.
- [ ] i18n appears in the findings file (validation that the original probe lands).
- [ ] `navigation/features.yaml` updated for any newly discovered features that warrant feature-level pointer.

## Context

Sequel to DOC-162 (the cheap patch). Authorised under the same ADR Q2 ("Ship today (Recommended)") — DOC-162 is the patch; DOC-163 is the work the patch enables.

Note: this is `/enumerate` + finding-write, NOT triage into per-feature backlog items. Triaging the findings into individual DOC-NNN items happens in a follow-up `/triage` session per `playbooks/follow-up-on-disk.md`. Each finding becomes its own DOC item (one i18n doc page, one theme doc page, etc.) — this item is bookkeeping for the surfacing pass only.
