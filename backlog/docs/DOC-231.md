## Description

DOC-182 already covers four operator caveats on the Lookup Tables page (NO_CONTEXT RBAC, cascade orphan, ALTER TABLE rename break, XSS surface). This item adds two NET-NEW caveats surfaced in the F-058 + F-059 mode-B clue reads — both operator-load-bearing and not addressed by DOC-182's existing scope.

**Caveat 5 — Lookup Tables list silently truncates at 30 rows; pillar P-03's SOLE user-facing surface is broken for any tenant with >30 lookup tables (F-058a).** `LookupTablesList.tsx:51` declares `<ScrollableContainer id='lookup-tables-list'>`. Line 53 declares `<InfiniteScroll scrollableTarget='directory-entities-list'>` — the `scrollableTarget` references the Directory feature's DOM id (copy-paste from the Directory infinite-scroll site), NOT the local container id. The `react-infinite-scroll-component` library cannot find `directory-entities-list` on this page; falls back to window scroll. The container has `overflow: auto`, so window scroll never fires within it. Net effect: the 31st row is never requested. The list APPEARS complete (no skeleton at the bottom, no "Load more" button, no pagination indicator), but stops at 30 rows for any tenant with >30 lookup tables. The H1 counter at `LookupTables.tsx:60-62` shows the REAL total ("250 lookup tables overall") while the list shows 30 — the discrepancy IS the only operator-visible signal, and most won't notice. Per `system-mission.md:125-141`, pillar P-03 is intentionally narrow (one child surface — Lookup Tables); the listing bug means **100% of P-03's user-facing UX is degraded** for any tenant exceeding 30 tables.

**Caveat 6 — Lookup Table rename emits no ActivityEvent; post-mortem investigations cannot answer "who renamed which table when" (F-059b).** `ReferenceDataServiceImpl.updateLookupTable` (lines 107-124) has no `@ActivityLog` annotation; no `last_modified_by` column update; no version increment; no `LOOKUP_TABLE_RENAMED` event type (the `ActivityEventTypeDto` enum has no slot for it — would be a 28th value if added). Combined with DOC-182 Caveat 3 (ALTER TABLE rename silently breaks downstream BI/ETL pipelines), the audit silence amplifies the blast radius: operators investigating "why did the revenue dashboard break last Tuesday" cannot answer "who renamed which lookup table when" from platform logs. Cross-pillar audit-asymmetry pattern: same shape as F-057 (DQ severity audit silence) and F-025a.4 (Query Examples audit silence — already in DOC-183 Caveat 4) — this is the third operator-mutating surface with no audit emission.
