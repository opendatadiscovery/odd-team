## Description

The live `/configuration-and-deployment/odd-platform#additional-navigation-links-odd-links` section (WebFetched 2026-05-27, 200 OK) documents global visibility verbatim ("links are exposed to the UI through the authenticated `GET /api/links` endpoint and are visible to every user signed in to the platform") and warns against embedding credentials/tokens in URLs. It is **silent on three operator-visible behaviours**.

**Caveat 1 — `AdditionalLinkProperties` has no validation; title and url accept null / empty / malformed / `javascript:` / `data:` / `file:` (F-035a).** `AdditionalLinkProperties.java:6-10` is a record-of-record (`record AdditionalLinkProperties(List<Link> links) { record Link(String title, String url) {} }`) with NO validation annotations (`@NotBlank` / `@URL` / `@Pattern` / `@Validated` / `@PostConstruct validate()`). The record accepts: missing `title` (renders as invisible-but-clickable menu item — phishing-vector enabler); missing `url` (`<a href=null>` non-clickable but visible); `javascript:alert(1)` (React 17+ neutralises but warns in console); `data:text/html,<script>...</script>` (browser sandboxes but surprising); `file:///etc/passwd` (modern browsers refuse but no failure-mode signal); `wiki.internal` (browser interprets as relative path — broken link). **None fail at config-load time** — bad operator-supplied data ships silently into the UI.

**Caveat 2 — `AppInfoMenu` reverse-tabnabbing: 5 link sites render `target='_blank'` without `rel='noopener noreferrer'` (F-035b — security).** `AppInfoMenu.tsx:41,61,95,103,112` — 5 link sites (operator-configured links at line 61, project-version GitHub link at 41, Documentation link at 95, Slack link at 103, Feedback link at 112). React Router `<Link target='_blank'>` renders an underlying `<a>` without `rel`. An attacker controlling any destination (compromised internal wiki, future XSS on first-party domain, operator-supplied bad link from Caveat 1) can `window.opener.location = "phishing.example.com"` from JS — replacing the parent ODD tab with an attacker-controlled login page. The Caveat 1 + Caveat 2 compound is operator-amplified: an unvalidated operator-configured link (Caveat 1) becomes a workspace-wide reverse-tabnab vector (Caveat 2).

**Caveat 3 — `AppInfoMenu` is keyboard-inaccessible despite declaring ARIA support (F-035c — WCAG 2.1 SC 2.1.1 violation).** The icon button declares `aria-haspopup='true'` (`AppInfoMenu.tsx:80`) + `aria-controls={menuId}` (line 79) — **claiming keyboard accessibility** — but wires ONLY `onMouseEnter` (line 81). NO `onClick`, NO `onKeyDown`, NO `onFocus`. Touch-device users (iOS Safari, Android Chrome) generate no `mouseenter`; assistive-technology users (screen-reader + keyboard) cannot open the menu. The Documentation / Slack / Feedback / Version / operator-links surface is inaccessible to keyboard and touch users.
