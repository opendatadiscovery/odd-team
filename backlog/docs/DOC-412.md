## Description

The metadata-stale page tells operators that "hovering the icon reveals the **last refresh timestamp**" (`metadata-stale.md:11`) and that the entity detail header shows "the stale icon and the relative-time tooltip" (`metadata-stale.md:90`). What neither the page nor any other surface says is that the tooltip string itself **never names staleness and never names the threshold** — it is a single bare relative timestamp.

The UI widget (`MetadataStale.tsx:15-18`) builds its tooltip text as:

```ts
const text =
  lastIngestedAt !== undefined
    ? `Ingested at ${formatDistanceToNow(lastIngestedAt, { addSuffix: true })}`
    : ``;
```

So the operator hovering an orange icon sees only e.g. `Ingested at 9 days ago`. The word "stale" never appears in the tooltip, and the `odd.data-entity-stale-period` threshold that caused the icon to appear (default 7 days) is never shown. An operator who has not read this page cannot tell from the tooltip alone *why* the icon is orange, *what* the cutoff is, or that "9 days ago" crossed a configured boundary rather than just being a neutral fact. The freshness signal's meaning is invisible at the exact point of interaction.

This misleads by omission: the page's "How the indicator surfaces" section describes the tooltip as if it conveys the staleness verdict, when in fact it conveys only a relative timestamp and leaves the reader to infer the rest. DOC-264 and DOC-263 (the entity-staleness documentation work) cover the predicate, the threshold, and the operator caveats, but neither covers the **tooltip wording** — that the on-hover string is purely relative-time with no staleness label and no threshold.
