## What

Eight UX defects on the per-entity detail page (Overview tab composition + class/type badges) that share a single load-bearing observation - the `DataEntityClassNameEnum` enum drives 7+ rendering decisions across the page but the per-class UX, the per-class affordance hints, and the permission map are inconsistent, undocumented, or silently absent. Operators landing on the detail page cannot answer "what does my class set unlock?" without trial-and-error.

**Defect 1 - Class badge has no tooltip (F-177a - MEDIUM).** `DataEntityDetailsHeader.tsx:79-85` renders `<EntityClassItem entityClassName={entityClass.name}/>` with `key + sx` only. `EntityClassItem.tsx:24` sets the `title` to the `.normal` form of the label (the enum name humanised - "SET" -> "Dataset"); the label is NOT a description. Operators have no signal of "SET unlocks the Structure tab + DQ panel" or "QUALITY_TEST unlocks the test-execution history."

**Defect 2 - DCT type hardcoded outside OpenAPI enum (F-177b - LOW).** `EntityTypeItem.tsx:9`: `entityTypeName: DataEntityTypeNameEnum | 'DCT'`. The string `'DCT'` is hardcoded as a special case alongside the generated enum, with no comment explaining the divergence.

**Defect 3 - Multi-class entity badge overflow (F-177c - LOW).** `DataEntityDetailsHeader.tsx:74-75`: `<Grid container alignItems='center' flexWrap='nowrap'>`. Line 79-85's `entityClasses?.map` is unbounded. An entity with 4+ classes overflows the `lg={7}` allocation without wrap and without a "+N more" affordance.

**Defect 4 - EntityClassItem empty render when entityClassName undefined (F-206a - LOW).** `EntityClassItem.tsx:13-29`: both the title prop and the inner text render only when `entityClassName` is defined. Undefined -> empty chip - visual whitespace in dense lists, no signal that the entity is unclassified.

**Defect 5 - EntityTypeItem no colour coding; asymmetric with class badge (F-206b - LOW).** `EntityTypeItem.tsx:13-19` uses a uniform `S.Content` background; class badge uses `theme.palette.entityClass[$entityClassName]` per-class. Scanning the badge row, operators cannot visually distinguish types at a glance.

**Defect 6 - DQ-zero vs DQ-loading indistinguishable (F-176b - MEDIUM).** `Overview.tsx:105`: `{isDataset && datasetQualityTestReport?.total ? <SectionContainer>...</SectionContainer> : null}`. Zero tests AND loading state produce the same DOM absence.

**Defect 7 - Unknown class renders no stats panel silently (F-176c - LOW).** `OverviewStats.tsx:23-83` switches over `entityClass.name` with `default: return null`. Entities with `entityClasses === undefined`, `[]`, or an unknown enum value render no stats panel; no "unclassified" placeholder.

**Defect 8 - Seven `WithPermissionsProvider` wraps, no single composer-level provider (F-176d - LOW).** `Overview.tsx:67-147` has 7 separate `<WithPermissionsProvider>` blocks each with a different `allowedPermissions` array - Description / Attachments / Metadata / General / Groups / Tags / Terms. Reviewers cannot derive the full permission map from one grep.

## User-facing impact

Re-verified 2026-06-10 by reading all five cited components. **Every one of the 8 defects HOLDS at the cited file:line** - this draft is accurate. Notes per defect:

- **Defect 1 (class badge no descriptive tooltip) - HOLDS.** `EntityClassItem.tsx:24` sets `title` to the humanised label (`DataEntityClassLabelMap.get(name)?.normal`, e.g. "Dataset"), not an affordance description. There IS a native browser tooltip, but it only restates the class name - it does not tell the operator what the class unlocks. Accurate as written.
- **Defect 2 (DCT hardcoded) - HOLDS.** `EntityTypeItem.tsx:9` `entityTypeName: DataEntityTypeNameEnum | 'DCT'`, no comment.
- **Defect 3 (multi-class overflow) - HOLDS.** `DataEntityDetailsHeader.tsx:74` `flexWrap='nowrap'` + unbounded `entityClasses?.map` at `:79-85`.
- **Defect 4 (empty render on undefined class) - HOLDS.** `EntityClassItem.tsx:26-27` renders the label only when `entityClassName` is defined -> empty `<S.Content>` otherwise.
- **Defect 5 (type badge no colour, asymmetric with class badge) - HOLDS.** `EntityTypeItem.tsx:13-17` uses a uniform `S.Content` background (it does set a `title`, but no per-type colour), vs the class badge's per-class `theme.palette.entityClass[...]`.
- **Defect 6 (DQ-zero vs DQ-loading) - HOLDS, highest user impact.** `Overview.tsx:105` `{isDataset && datasetQualityTestReport?.total ? (...) : null}` - zero tests and not-yet-loaded both collapse to the same DOM absence; an operator cannot tell "no tests configured" from "still loading."
- **Defect 7 (unknown class no stats panel) - HOLDS.** `OverviewStats.tsx:81-82` `default: return null` over the class switch.
- **Defect 8 (7 separate WithPermissionsProvider) - HOLDS.** Counted 7 `WithPermissionsProvider` blocks in `Overview.tsx` (Description `:67`, Attachments `:74`, Metadata `:81`, General/Ownership `:95`, Groups `:112`, Tags `:127`, Terms `:134`); no composer-level provider.

All defects are UX paper-cuts (LOW individually, MEDIUM as a cluster); none is a security or data-integrity issue. The cluster's value is the consolidated DOC-263 doc page + the per-defect polish.

## Why it matters

Each defect on its own is a minor UX paper-cut. Together they make the entity detail page **opaque** to operators learning the platform - they cannot derive "what unlocks where" from the UI, the badges, or the absence of panels. The cluster is the right consolidation surface for DOC-263's new umbrella page (Entity detail page composition + class-driven affordances).

- **Defect 6 is the highest user-impact** - operators watching a dataset Overview load see no DQ section and cannot tell "tests are still loading" from "this dataset has no tests configured." Both invite different next actions.
- **Defect 1 is the second-highest** - the class badge is the page's primary class-affordance signal; no tooltip means operators have to navigate-and-discover. A reference doc (DOC-263) is the load-bearing complement.
- **Defects 4 / 7** (silent empty renders) compound for entities mid-ingestion or with unknown / new classes that the UI does not yet recognise.

Severity MEDIUM as a cluster; individual defects vary LOW -> MEDIUM.

## Suggested fix

### (a) Defect 1 - Class badge tooltip with per-class affordance summary

```tsx
// EntityClassItem.tsx
const tooltipFor = (cn: DataEntityClassNameEnum): string => {
  switch (cn) {
    case 'SET':           return 'Dataset - unlocks Structure tab + Data Quality panel + Lineage.';
    case 'TRANSFORMER':   return 'Transformer - surfaces consumer/producer chains on Lineage.';
    case 'CONSUMER':      return 'Data Consumer - surfaces upstream lineage + consumer metadata.';
    case 'INPUT':         return 'Data Input - entry point for collected metadata pipelines.';
    case 'QUALITY_TEST':  return 'Quality Test - unlocks the Test Execution History tab.';
    case 'ENTITY_GROUP':  return 'Group - surfaces Members tab; group-level status apply choice.';
    case 'RELATIONSHIP':  return 'Relationship (ERD) - surfaces the ERD diagram tab.';
    default:              return cn;
  }
};
// <AppTooltip title={tooltipFor(entityClassName)}><S.Content>...</S.Content></AppTooltip>
```

### (b) Defect 2 - Reconcile DCT in OpenAPI spec OR documenting comment

Either flip `DCT` into the OpenAPI `DataEntityTypeNameEnum` (preferred - single source of truth), OR add a comment explaining the union: `// 'DCT' is a transient client-side type for Data Catalog Templates; absent from OpenAPI by design - see DOC-XXX.`

### (c) Defect 3 - Multi-class overflow collapse

```tsx
// DataEntityDetailsHeader.tsx
<Grid container alignItems="center" flexWrap="wrap" gap={0.5}>
  {entityClasses?.slice(0, 3).map(...)}
  {entityClasses && entityClasses.length > 3 && (
    <AppTooltip title={entityClasses.slice(3).map(c => DataEntityClassLabelMap.get(c.name)?.normal).join(', ')}>
      <S.Content>+{entityClasses.length - 3}</S.Content>
    </AppTooltip>
  )}
</Grid>
```

### (d) Defect 4 - Explicit unclassified placeholder OR require entityClassName

```tsx
// EntityClassItem.tsx
if (!entityClassName) return <S.Content title="Unclassified" $entityClassName={undefined}>-</S.Content>;
```

### (e) Defect 5 - Symmetric per-type colour coding (or document the deliberate asymmetry)

If type categories are stable (DATABASE / WAREHOUSE / STREAMING / FILESYSTEM / BI / ML), assign per-category colours in `theme.palette.entityType`. If the asymmetry is deliberate (types are too many / too volatile to colour-code consistently), add a code comment naming the design choice + cross-link **DOC-263**.

### (f) Defect 6 - Distinguish DQ-loading from DQ-empty

```tsx
// Overview.tsx:105 - three states instead of two:
{isDataset && (
  datasetQualityTestReportLoading
    ? <SectionContainer><Skeleton variant="rectangular" height={120}/></SectionContainer>
    : datasetQualityTestReport?.total
      ? <SectionContainer>... DQ contents ...</SectionContainer>
      : <SectionContainer><EmptyState message="No quality tests configured"/></SectionContainer>
)}
```

### (g) Defect 7 - Explicit "unclassified" stats panel

```tsx
// OverviewStats.tsx
switch (entityClass?.name) {
  case 'SET':         return <DatasetStats .../>;
  // ...
  default:            return <UnclassifiedStats entityClass={entityClass}/>;   // <- visible placeholder
}
```

### (h) Defect 8 - Consolidate panel-permission map at composer level

```tsx
// Overview.tsx
const PANEL_PERMISSIONS = {
  Description: ['DATA_ENTITY_DESCRIPTION_UPDATE'],
  Attachments: ['DATA_ENTITY_ATTACHMENT_CREATE', 'DATA_ENTITY_ATTACHMENT_DELETE'],
  // ... full map ...
};
// Single <WithPermissionsProvider allowedPermissions={Object.values(PANEL_PERMISSIONS).flat()}>
// wrap; per-panel gates derive from PANEL_PERMISSIONS[panelName] via the context.
```

The export of `PANEL_PERMISSIONS` itself is the documented single-source.
