## What

When an administrator **accepts** a single owner-association request, the platform does not only approve that one request — inside the same transaction it **auto-declines every other request that is currently approved for the same owner (or the same username)**. This cascade is entirely silent: there is no confirmation dialog, no UI affordance, and no on-screen indication that approving this row will revoke other approvals. The collided requests are flipped to `DECLINED` and logged only as a "manually declined" activity, even though the administrator never declined them — they merely accepted a different one.

## Where

The accept/decline handler runs the collision-cancel step as a side-effect of approval —
`service/OwnerAssociationRequestServiceImpl.java:184-203` (invoked at line 102 from `updateOwnerAssociationRequest`):

```java
.flatMap(this::createMappingForApprovedRequest)
.flatMap(item -> createActivity(item, false, item.getStatusUpdatedBy()))
.flatMap(this::cancelCollisionAssociationByIdForApprovedRequest)   // :102 — silent cascade on Accept
```

```java
private Mono<OwnerAssociationRequestPojo> cancelCollisionAssociationByIdForApprovedRequest(
    final OwnerAssociationRequestPojo pojo) {
    if (!pojo.getStatus().equals(OwnerAssociationRequestStatus.APPROVED.getValue())) {
        return Mono.just(pojo);
    }
    return ownerAssociationRequestRepository.cancelCollisionAssociationById(pojo)
        .flatMap(item -> activityService.createOwnerAssociationRequestActivity(item, item.getStatusUpdatedBy(),
            REQUEST_MANUALLY_DECLINED))      // :199-200 — collided rows logged as "manually declined"
        .collectList()
        .thenReturn(pojo);
}
```

The cascade scope is the SQL `UPDATE ... SET status = DECLINED` —
`repository/reactive/ReactiveOwnerAssociationRequestRepositoryImpl.java:190-202`:

```java
final var query = DSL.update(OWNER_ASSOCIATION_REQUEST)
    .set(Map.of(OWNER_ASSOCIATION_REQUEST.STATUS, OwnerAssociationRequestStatus.DECLINED.getValue(), ...))
    .where(OWNER_ASSOCIATION_REQUEST.OWNER_ID.eq(pojo.getOwnerId())
        .or(OWNER_ASSOCIATION_REQUEST.USERNAME.eq(pojo.getUsername())))   // same owner OR same username
    .and(OWNER_ASSOCIATION_REQUEST.STATUS.eq(OwnerAssociationRequestStatus.APPROVED.getValue()))  // currently APPROVED
    .and(OWNER_ASSOCIATION_REQUEST.ID.ne(pojo.getId()))                  // every OTHER row
    .returning();
```

So: the just-approved row is set to `APPROVED`; then every *other* row matching `owner_id = X OR username = Y`, currently `APPROVED`, is flipped to `DECLINED`.

## Why it matters

Silent and destructive-to-state. An administrator triaging owner-association requests has no way to know, from the Accept button, that the click will revoke other already-approved associations for that owner/username. The revoked requests are recorded as `REQUEST_MANUALLY_DECLINED`, so the activity log misattributes the decline to a manual action that never happened — making the audit trail misleading for exactly the people who would investigate "why did this owner lose their association?". No data is destroyed (request rows are status-flipped, not deleted), which keeps it medium — but on an access/ownership surface, a silent revoke-by-side-effect with a misleading audit entry is precisely the behaviour an operator must be warned about before they click.

## Suggested fix

Disclose the cascade at the point of action. Before committing the approval, surface a confirmation dialog that names the other approved request(s) for the same owner/username that will be declined as a result (the same set the SQL `WHERE` selects), and require explicit confirmation. Secondarily, consider logging the cascaded declines with an activity event type that reflects "auto-declined as a side-effect of approving request N" rather than `REQUEST_MANUALLY_DECLINED`, so the audit trail is accurate. Open to alternatives on the exact dialog copy and on whether a distinct activity event type is introduced — the load-bearing change is that the cascade is disclosed before it happens and not attributed to a manual decline after the fact.
