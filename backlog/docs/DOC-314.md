## Description

The Policies **list** path filters soft-deleted rows (`WHERE deleted_at IS NULL`, soft-delete base class), so a deleted policy disappears from the Policies tab. But the **grant** path `getRolesPolicies` (`ReactivePolicyRepositoryImpl`, verified @ ede5d277) joins `POLICY` with **no `deleted_at` filter** — so a role still bound to a soft-deleted policy **keeps being granted that policy's permissions** on every authorized request. An operator who "deletes" a policy through the UI sees it gone and reasonably believes access is revoked — but it is not. This is a security-relevant catalogue-vs-grant asymmetry (a silent no-op of the operator's intent).

**Failure shape**: security exposure / actively-misleading absence — the operator believes a delete revoked access when it did not.
