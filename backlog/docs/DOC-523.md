## Description

**Failure shape: reader-flow defect / dead cross-reference — and specifically the `LSN-004` GitHub-fallback
shape the live-site gate exists to catch.**

`docs/developer-guides/build-and-run/custom-collectors.md` carries three relative links whose targets do not
exist relative to the page's own directory (`docs/developer-guides/build-and-run/`):

| Line | Written as | Resolves to | Correct target |
|---|---|---|---|
| 386 | `build-and-run/build-and-run-odd-collectors.md#full-configuration-reference` | `.../build-and-run/**build-and-run/**build-and-run-odd-collectors.md` — the segment is doubled | `build-and-run-odd-collectors.md#full-configuration-reference` |
| 465 | `how-to-contribute.md` | `.../build-and-run/how-to-contribute.md` | `../how-to-contribute.md` |
| 471 | `github-organization-overview.md` | `.../build-and-run/github-organization-overview.md` | `../github-organization-overview.md` |

**This is not a source-only defect — it is broken on the published site right now.** GitBook cannot resolve an
unresolvable relative target to an internal page, so it falls back to a raw GitHub blob URL. Measured on
`https://docs.opendatadiscovery.org/developer-guides/build-and-run/custom-collectors` (HTTP 200):

```
href="https://github.com/opendatadiscovery/documentation/blob/main/docs/developer-guides/build-and-run/build-and-run/build-and-run-odd-collectors.md#full-configuration-reference"   -> 404
href="https://github.com/opendatadiscovery/documentation/blob/main/docs/developer-guides/build-and-run/how-to-contribute.md"                                                          -> 404
href="https://github.com/opendatadiscovery/documentation/blob/main/docs/developer-guides/build-and-run/github-organization-overview.md"
```

All three GitHub URLs return **HTTP 404** — the files are not at those paths in the repo either. So a reader
following "How to contribute" from the custom-collector guide is thrown out of the manual onto a GitHub 404.

The same page proves the correct form works: its *other* links to the same two pages render as
`href="/developer-guides/how-to-contribute"` and `href="/developer-guides/github-organization-overview"`
(both HTTP 200). The three above are the only ones missing their `../`.

**Why this page in particular matters.** `custom-collectors.md` is the developer guide for people writing a
new adapter — the exact readers the project most wants to convert into contributors — and two of the three
dead links are the "now go contribute it upstream" call to action at the end of that journey.
