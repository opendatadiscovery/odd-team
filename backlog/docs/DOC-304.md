## Description

`multilingual-ui.md` frames the missing-translation behaviour as "missing translations fall through to English" affecting "a small number of strings" for **non-English** users. The code situation is materially worse and the blast radius includes English users:

- **14+ keys are absent from ALL six locales** (not just the non-English ones). When a key is missing from every locale file, there is **no English value to fall through to** — the UI renders the **raw key string** (e.g. the i18n key itself) to the user.
- Among the missing keys are **all three top-level navigation tabs** — **Data Quality**, **Data Modelling**, and **Master Data** — which therefore render as their raw keys in the primary navigation **for every user, including English**.

So the page's "graceful fall-through to English, minor, non-English-only" framing is wrong on three counts: it is not graceful (raw keys shown), it is not minor (top-level nav tabs), and it is not non-English-only (English users see it too).

High — a primary-navigation rendering defect that the page actively downplays; an operator/user reading the page would not expect to see raw keys in their own (English) nav.

**Failure shape**: code-doc drift — the page understates the scope and the affected audience of a known i18n gap.
