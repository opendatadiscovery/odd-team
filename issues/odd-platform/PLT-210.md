## What

`AppInfoMenu` consumes the app-info and app-links queries by destructuring **only** their `data`. It never inspects `isError` or `isLoading`. When the `/api/links` request **fails** (network error, 5xx, auth expiry), the hook returns `data === undefined`, and the component's render guard (`if (!links || links.length === 0) return null;`) treats that failure **identically** to a correctly-empty configuration: it renders nothing. There is no error indicator and no loading state, so an operator who has configured links but whose request is failing sees an empty menu and cannot tell a broken fetch from "no links configured". The same blindness applies to the app-info (version) query.

## Where

`odd-platform-ui/src/components/shared/elements/AppToolbar/AppInfoMenu/AppInfoMenu.tsx:17-18`

```tsx
const { data: appInfo } = useAppInfo();   // line 17: no isError / isLoading
const { data: links } = useAppLinks();    // line 18: no isError / isLoading
```

and the conflated empty/error guard downstream (`:55-56`):

```tsx
const projectLinks = React.useMemo(() => {
  if (!links || links.length === 0) return null;   // failure (undefined) == empty config
  ...
}, [links]);
```

## Why it matters

**Silent.** A failed links/app-info fetch is indistinguishable from a healthy-but-empty state, so a real backend problem is masked as "nothing to show". Operators relying on the configured links (or the version badge) get a silently-degraded menu with no signal that something is wrong, which makes the failure hard to notice and hard to diagnose. Severity **low** — the menu is auxiliary chrome and the failure is non-destructive — but the conflation of error and empty is a genuine UX defect worth a small fix.

## Suggested fix

Read `isError` / `isLoading` from both hooks and render distinct states (open to alternatives):

```tsx
const { data: appInfo, isError: appInfoError } = useAppInfo();
const { data: links, isError: linksError, isLoading: linksLoading } = useAppLinks();
// in projectLinks: distinguish loading (spinner/skeleton) and error (small inline error)
// from the legitimately-empty case before returning null.
```

Keep it lightweight — a brief loading affordance and a small inline error suffice for an auxiliary menu; the key change is that an errored fetch no longer renders as "empty".
