# DOC-506 — one relationship, two names, depending on which page you are on

## Why

CTRIB-062 (#1842 ST-8) corrected the two Recommended-panel captions from **"Upstream dependents" /
"Downstream dependents"** to **"Upstream of my data" / "Downstream of my data"**, and named the new search
filter's options the same way. The correction was right: a *dependent* depends on you — i.e. is
**downstream** — so the old upstream caption asserted the inverse of what the endpoint returns.

The Activity Feed's tabs were deliberately left out of that slice (a cross-surface rename is its own change).
The result is that ODD now presents **the same lineage relationship under two different names**, and the
manual documents both without saying they are the same thing:

- `data-discovery/catalog-overview.md` + `data-discovery/search.md` (on the `release/1.0.0` train) —
  *"Upstream of my data"* / *"Downstream of my data"*, with an explicit hint that earlier releases used the
  other wording.
- `configuration-and-deployment/enable-security/authorization/owners.md:111` — *"The **Activity Feed**'s
  `My Objects` / `Upstream Dependents` / `Downstream Dependents` tabs"*.

A reader who learns the corrected vocabulary on the catalog pages and then meets "Upstream Dependents" on the
Activity Feed has no way to know whether it is the same axis or a different one — and the old label still
reads the wrong way round for the upstream side, which is the defect the rename existed to fix.

## What to decide, then do

1. **Decide** whether the Activity Feed tabs get renamed too. That is a product call and it changes shipped
   UI strings in all 7 locales, so it belongs on an odd-platform issue, not in a doc edit.
2. **If renamed** — the doc updates follow the platform change and ride the same milestone.
3. **If kept** — the manual must disambiguate: one sentence on the Activity Feed page and on `owners.md`
   saying the tabs are the same axis as the catalog's *Upstream/Downstream of my data*, and that
   "dependents" there means the same direction the catalog now names explicitly.

Either way, the split must not ship undocumented: two names for one relationship, with one of them
semantically backwards, is exactly the drift the caption correction was made to remove.

## Acceptance criteria

- [ ] The decision (rename vs disambiguate) is recorded, with the odd-platform issue link if renaming.
- [ ] Every page that names the lineage-neighbour relationship uses one vocabulary, or explicitly states the
      equivalence where it does not.
- [ ] No page still asserts "Upstream dependents" as the entities the owned set depends on without a
      correction or a cross-reference.
