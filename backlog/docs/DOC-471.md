## Description

The published Test Run History page (created by DOC-185) documents two behaviours that the
odd-platform #1757 fix (CTRIB-024, milestone 0.29.0) **resolves**, so the page becomes incorrect for
0.29.0+ once that release ships:

- **Caveat 1 (danger) — "HTTP 500 while a test is currently running."** FIXED: `RUNNING` is now a
  first-class wire status; the endpoint loads in-flight runs (200).
- **Caveat 3 (info) — in-flight runs appear "undated-looking" at the top.** REVISED: in-flight runs
  stay at the top (the freshest activity — product decision, not the issue's suggested bottom-sort)
  but now render a clear **`running`** status badge; ordering is a deterministic total order.

The change rides the **`release/0.29.0`** documentation train and publishes at the 0.29.0 release gate
(the live manual describes the latest published release — `adrs/drafts/release-train-doc-gating.md`).

**Caveat 2 (warning) — cross-owner `status_reason` read** is UNCHANGED (a platform-wide RBAC posture,
REFACTOR-024 family; not in #1757's scope) and stays documented.

## Edits made on `release/0.29.0`

- Sort section: in-flight runs first, then completed end-time DESC; deterministic (id tiebreaker);
  the `running` badge.
- Status param table + the status-filter list: add `RUNNING`.
- Remove the HTTP-500 danger hint (no longer true in 0.29.0).
- Revise the in-flight info hint: top placement + `running` badge + "both old problems fixed in 0.29.0".
