## Description

IT-073 (F-206 search-row class/type badge) runs its encoding-distinctness corner on a
DATA_SET row only, because while PLT-147 was open a raw-seeded (NULL `specific_attributes`)
entity of any other detail-bearing class 500d the results list — DATA_SET was "the only
NPE-safe class for the raw-seed path" (IT-073 protocol + the F-206 flow note + #1755 body).

The #1755 null-guard fix (CTRIB-009, `contrib/CTRIB-009-mapper-null-details-guard`) removes
that constraint: every class branch in `DataEntityMapperImpl.mapPojo`/`mapDtoDetails` now
tolerates a null details DTO, so raw-seeded TRANSFORMER / QUALITY_TEST / CONSUMER / INPUT
rows render. IT-073's corner can now assert badge encoding distinctness across TWO classes
(e.g. a DATA_SET vs a DATA_TRANSFORMER row) as originally intended.
