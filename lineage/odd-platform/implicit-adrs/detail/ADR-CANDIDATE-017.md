- **ADR-CANDIDATE-017** (NEW 2026-05-10A; STRENGTHENED 2026-05-10B): Collector tokens are rotated **in-place** (UPDATE-not-INSERT), returned plaintext on rotation, masked on read, and authenticated via plaintext String-equals against the in-DB value (no hashing layer)
  - **Category**: promote
  - **Support**: surfaced by 2 sidecars (`regenerateCollectorToken` from the rotate side + STRENGTHENED 2026-05-10B by `IngestionDataEntitiesFilter` from the verify side at `IngestionDataEntitiesFilter.java:56` — two-independent-sidecar corroboration of the plaintext-equality model; the rotate side establishes the storage shape, the verify side confirms the comparison shape, together they compose the full shared-secret S2S model)
  - **Surfaced by**:
    - `odd-platform__java__CollectorController__controller-method__regenerateCollectorToken.md:implicit_adrs.[1]` ("Token rotation is an in-place UPDATE of the existing row, not an append-new-then-revoke-old transition" — intent_anchor: "the method is named `regenerateToken` (not `rotateToken` or `issueNewToken`), and the repository method is `updateToken` (not `replaceToken` or `revokeAndIssue`) — the vocabulary encodes the in-place semantic.")
    - `odd-platform__java__CollectorController__controller-method__regenerateCollectorToken.md:implicit_adrs.[2]` ("Token is returned in plaintext on rotation; masked on read" — intent_anchor: "the `TokenDto` record has both a 1-arg constructor defaulting `showToken=false` AND a static `visibleToken(token)` factory, indicating the design treats visibility as a deliberate per-call-site choice. Returning plaintext on regenerate is intentional because the user has no other way to learn the new secret.")
    - `odd-platform__java__CollectorController__controller-method__regenerateCollectorToken.md:implicit_adrs.[3]` ("Token authentication is plaintext-equality against an in-DB string; no hashing layer" — intent_anchor: "the comparison is a direct `String.equals(...)`, NOT `BCrypt.matches(...)` / `MessageDigest.isEqual(...)` / a HMAC verification — the model is 'shared secret stored as-is'. This is consistent with the token being a long-random opaque string (40 alphanumeric ≈ 238 bits of entropy) used over TLS-protected transport, but it does mean a DB read or backup carries plaintext credentials.")
    - **STRENGTHENED 2026-05-10B** — `odd-platform__java__IngestionDataEntitiesFilter__config-key-consumer__auth_ingestion_filter_enabled@L20.md:implicit_adrs.[2]` ("Token authentication is plaintext-equality against the in-DB shared secret — no hashing layer, no constant-time comparison" — intent_anchor: "the comparison at IngestionDataEntitiesFilter.java:56 is `String.equals(...)`, NOT `BCrypt.matches(...)`, NOT `MessageDigest.isEqual(...)`, NOT HMAC verification. This is consistent with the rest of the token model — the sibling `CollectorController.regenerateCollectorToken` sidecar already established that tokens are stored as raw `RandomStringUtils.randomAlphanumeric(40)` plaintext in the TOKEN table. The implementation choice carries across the rotate-side AND the verify-side: shared-secret semantics, not hashed-credential semantics.")
  - **Decision statement**: ODD's Collector token model is a **40-character alphanumeric shared secret**, persisted in the `TOKEN` table as plaintext, authenticated by `IngestionDataEntitiesFilter` via direct `String.equals(...)` against the in-DB value. Token rotation is an **in-place UPDATE** of the existing TOKEN row (not an INSERT-new + REVOKE-old transition), keyed 1:1 to the Collector via `CollectorPojo.tokenId`. The new value is returned in plaintext in the rotation response (`TokenDto.showToken=true`); list/get reads mask via `mapValue` to `******{last6}` (`TokenDto.showToken=false` default). The composition is deliberate: a single mutable shared-secret with TLS as the only confidentiality boundary.
  - **Wisdom test**: PASS. The four sub-decisions are all anchored in **vocabulary** (method names, repository method names, factory method names, constructor defaults) and **structure** (1:1 schema relationship, no hashing column, single-value equality). The rationale "long-random opaque string over TLS" is implicit but consistent. The trade-offs are real and structural: rotating one token requires a coordinated client-side restart (no grace window); a DB backup carries credentials; an SQL-injection at the TOKEN table escalates to platform-wide ingestion compromise.
  - **Evidence**:
    - regenerateCollectorToken.md says: "TokenGeneratorImpl.java:44-52 (`regenerate(...)` mutates the passed-in TokenPojo via `setValue(...).setUpdatedAt(...).setUpdatedBy(...)`) + ReactiveTokenRepositoryImpl.java:30-39 (`updateToken` issues `DSL.update(TOKEN).set(tokenRecord).where(TOKEN.ID.eq(tokenPojo.getId()))`)"
    - regenerateCollectorToken.md says: "TokenMapper.java:15-18 (`return dto.showToken() ? dto.tokenPojo().getValue() : \"******\" + dto.tokenPojo().getValue().substring(dto.tokenPojo().getValue().length() - 6);`) + ReactiveTokenRepositoryImpl.java:37-38 (`updateToken` returns `new TokenDto(r.into(TokenPojo.class), true)`)"
    - regenerateCollectorToken.md says: "IngestionDataEntitiesFilter.java:55-58 (`if (!dto.tokenPojo().getValue().equals(token)) { throw new AccessDeniedException(\"Token is not correct\"); }`) + TokenGeneratorImpl.java:39,49 (token value is the raw `RandomStringUtils.randomAlphanumeric(40)` — no hashing prior to persistence)"
  - **Existing ADR**: none.
  - **Co-surfaced gaps** (link from `refactoring-scopes.md`): REFACTOR-045 (non-SecureRandom RNG — direct contradiction of the "long-random opaque string" implicit rationale; the actual implementation uses ThreadLocalRandom not SecureRandom), REFACTOR-046 (no rotation audit log — `updated_by` is overwritten on each rotation, single-state forensic trail), REFACTOR-047 (no rotation grace period — in-flight ingestion 401s the moment the UPDATE commits), REFACTOR-048 (token plaintext-at-rest — DB backup carries credentials), REFACTOR-049 (DISABLED-mode bypass — anonymously rotatable).
  - **Proposed action**: Promote to `adrs/drafts/collector-token-rotation-semantics.md` (new ADR). Document the four invariants as a coherent model; explicitly call out that the rationale (TLS + long-random) is implicit and that the listed gaps (NEW REFACTOR-045..049) are the price of the design — operators choosing an ODD deployment with REMOTE collectors over untrusted networks must understand the full set. Doc-side: a new "Token Rotation" section under `/configuration-and-deployment/enable-security` is the canonical home (currently neither the Authentication page nor the Permissions page covers operational rotation).
  - **Severity rationale**: HIGH — security-architecture decision underlying every S2S ingestion request in the platform. A future maintainer who proposes "let's hash tokens at rest" or "let's add a grace window" is making a structural change against this ADR; the ADR forces the conversation to happen.
