## Description

The live `developer-guides/api-reference` page says "Swagger UI can be accessed on your deployed ODD platform at `{platform-base-url}/api/v3/api-docs`" — silent on which auth modes gate it. Verified at primary source this run:
- `/api/v3/api-docs` is under `/api/**`, NOT `/ingestion/**` — so the `SecurityConstants.WHITELIST_PATHS` does NOT cover it. The path is gated by the `SecurityWebFilterChain` wiring per auth mode.
- `DisabledAuthSecurityConfiguration` permits everything; the LOGIN_FORM / OAUTH2 / LDAP configurations may or may not gate it depending on `SecurityRule` entries — the 4-cell matrix is not enumerated in-repo (verified via grep against `SECURITY_RULES`).

**Operator-visible consequence**: a separation-of-duties-conscious organisation expecting "Swagger UI is admin-only" cannot verify the assumption against the docs. An open-by-default operational deployment exposes the full 194-operation API surface to unauthenticated network callers (the "reconnaissance-via-spec" risk class). Operators need to know per-auth-mode reachability to decide whether to gate `/api/v3/api-docs` separately at a reverse-proxy layer.
