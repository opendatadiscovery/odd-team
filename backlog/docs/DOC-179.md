## Description

The live Alerting page (WebFetched 2026-05-27) already discloses the **auth posture** of the AlertManager webhook — *"The AlertManager webhook endpoint is not authenticated. ODD Platform whitelists the entire `/ingestion/**` namespace in Spring Security ... it does not cover `/ingestion/alert/alertmanager`."* That partial disclosure is correct but incomplete. Three additional operator-visible behaviours remain undocumented, each load-bearing:

**Caveat 1 — Forge-and-display compound (F-007a).** `AlertServiceImpl.java:178` maps `labels.entity_oddrn` from the webhook payload directly to `AlertPojo.dataEntityOddrn` with no validation that the oddrn refers to a real DataEntity and no check that the caller has permission to alert that entity. The webhook endpoint itself is unauthenticated (already documented). Combined with the cross-owner-read posture on the platform-wide "All" alerts tab (`REFACTOR-024`), any caller with network reach (anonymous under `auth.type=DISABLED`; any authenticated user otherwise) can POST `entity_oddrn=<any-target>` and inject a **false-positive Distribution Anomaly alert** on that target. The forged alert surfaces on the "All" tab readable by every authenticated user. A reviewer triaging the All tab cannot distinguish forged from real. Compliance-driven multi-tenant deployments see arbitrary cross-team alert injection.

**Caveat 2 — Generator URL stored-XSS / open-redirect surface (F-007b).** `AlertServiceImpl.java:168` parses the generator URL via `UriComponentsBuilder.fromUri(...)` — which does NOT block `javascript:` scheme — and embeds it into the alert description at line 185 via `String.format("Distribution Anomaly. URL: %s", queryUrl)`. Combined with the unauthenticated endpoint (Caveat 1), any caller can plant `javascript:alert(1)` or attacker-controlled URLs that render in the UI's alert description. Stored XSS in the alerts UI.

**Caveat 3 — Missing idempotency causes Prometheus retry duplication (F-007c).** `ReactiveAlertRepositoryImpl.java:324-343` `createAlerts` issues `INSERT ... RETURNING` with no `ON CONFLICT (...) DO NOTHING` clause. Prometheus's standard retry policy duplicates rows on retry. The application-level `AlertActionResolver` de-duplication used by the in-platform path is intentionally skipped on the AlertManager path. Operators see N-times-duplicated alerts in the UI for every transient network blip between AlertManager and the platform.
