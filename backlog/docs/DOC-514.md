## Description

`docs/developer-guides/build-and-run/custom-collectors.md` is published today at
`https://docs.opendatadiscovery.org/developer-guides/build-and-run/custom-collectors` (HTTP 200). Three of its
relative links are written as if the page sat one directory higher than it does. GitBook cannot resolve them,
so it falls back to a raw `github.com/.../blob/main/...` URL built from the same wrong path — and every one of
those URLs 404s. This is the `retrospectives/LSN-004` failure shape: a broken relative link does not render as
a broken link, it renders as a plausible-looking GitHub URL that goes nowhere.

| Line | Written as | Resolves to | Should be |
|---|---|---|---|
| `:386` | `build-and-run/build-and-run-odd-collectors.md#full-configuration-reference` | `developer-guides/build-and-run/**build-and-run/**build-and-run-odd-collectors.md` — the directory is doubled | `build-and-run-odd-collectors.md#full-configuration-reference` (same directory) |
| `:465` | `how-to-contribute.md` | `developer-guides/build-and-run/how-to-contribute.md` | `../how-to-contribute.md` |
| `:471` | `github-organization-overview.md` | `developer-guides/build-and-run/github-organization-overview.md` | `../github-organization-overview.md` |

The three intended targets all exist and are reachable:

`docs/developer-guides/how-to-contribute.md`, `docs/developer-guides/github-organization-overview.md`.

## A fourth instance, same class, different page

`docs/Architecture.md` links `configuration-and-deployment/odd-platform.md#attachment-storage`. The heading is
`## Attachment Storage Configuration`, so the live id is `attachment-storage-configuration`; fetching the page
and grepping for `id="attachment-storage"` returns **0** and for `id="attachment-storage-configuration"`
returns **1**. The link therefore lands on the top of a ~1200-line configuration reference rather than on the
attachment section — silently, the way a truncated anchor always does.

Found by the same sweep, while checking the cross-links on the pages CTRIB-060 changed. It was deliberately
**not** folded into that change: CTRIB-060 rides the `release/1.0.0` train and this is released truth, so
fixing it there would leave the live page broken until 1.0.0 ships.

*(Verified non-finding from the same sweep, recorded so it is not re-derived: `Features.md` →
`odd-platform.md#additional-navigation-links-odd.links` **is valid** — GitBook keeps the dot in the id.)*

## Why it matters

All three sit at the end of the custom-adapter guide, exactly where a developer who has just written an adapter
is sent next: the full `collector_config.yaml` reference (the page's own "runtime-config source of truth"), the
contribution flow, and the repo map. A reader who follows any of them lands on a GitHub 404 and has no way to
tell whether the page moved, the repo moved, or the doc is wrong.
