## Description

`POST /ingestion/entities/datasets/stats` triggers a full-text-search structure-vector recompute on the **declared parent** dataset oddrns **unconditionally — even when not a single field in the payload resolves to a real row**. There is no early exit on an empty resolution:

- `DatasetFieldServiceImpl.java:160-181` (`updateStatistics`): `datasetOddrns` is built from `datasetStatisticsList.getItems()` (the **payload's declared** `datasetOddrn`s, lines 168-170), independently of whether any field ODDRN matches an existing row.
- `DatasetFieldServiceImpl.java:179`: the chain ends with `.then(reactiveSearchEntrypointRepository.updateStructureVectorForDataEntitiesByOddrns(datasetOddrns))`. This `.then(...)` fires for the declared parents regardless of the upstream outcome.
- `DatasetFieldServiceImpl.java:233-251` (`updateFieldsStatistics`): when `existingFields` is empty, `fieldsToUpdate` is empty and `bulkUpdate([]).then()` completes normally — it does **not** short-circuit the chain. The FTS recompute at `:179` still runs.

Operator-facing consequence: because the endpoint is unauthenticated and unscoped under every `auth.type` (already documented), any caller on the network can POST a stats payload that names arbitrary dataset oddrns with **junk (non-existent) field ODDRNs** and force the platform to recompute full-text-search vectors for those datasets on every request — with zero legitimate write happening. This is a **standalone DoS amplifier**: the attacker does not even need a valid field ODDRN (which the cross-dataset-write hazard in DOC-194/PLT-044 does require). Repeated calls naming the platform's heaviest datasets turn a cheap unauthenticated request into a repeated expensive FTS recompute.

DOC-194 (done) and the profiler page already mention FTS-recompute-on-the-declared-parent, but **only as a side-effect of the cross-dataset write** ("...writes to dataset B and recomputes FTS on dataset A"). Neither captures the no-early-exit amplifier: the recompute fires even when nothing resolves. This item documents the amplifier explicitly and routes the code fix (an early exit when nothing resolves) into PLT-044.
