## Description

The Apache Hive adapter table on the odd-collector page documents the HiveServer2 port default as (`integrations/collectors/odd-collector.md` line 866):

> `connection_params.port` ... Defaults to `10000` when `scheme` is unset, **`1000`** when `scheme: http` / `https` (per the upstream HS2 client convention).

`1000` is almost certainly wrong. The HiveServer2 / `pyhive` convention is `10000` for the default **binary** (Thrift) transport and **`10001`** for the **HTTP** transport — `1000` is not an HS2 port convention anywhere, and the missing-trailing-digit shape (`1000` vs `10001`/`10000`) reads like a transcription typo. An operator who configures `scheme: http` and trusts the documented default would point the adapter at port `1000` and get a connection refused / wrong-service error against a real HiveServer2 HTTP endpoint, with the doc actively steering them to the wrong port.

This is a low-severity accuracy fix, but it is the "incorrect documentation" class (actively misleading), not merely "missing" — so it outranks a pure omission.

**Cannot be resolved from this workspace alone:** the `odd-collectors` repo is **not checked out locally** (`/home/raman/work/odd/odd-collectors` is absent — only `documentation`, `odd-platform`, and `odd-team` are present). The canonical default lives in `HiveConnectionParams` in `odd_collector/domain/plugin.py` (the field default / validator that picks the port from `scheme`). The implementer MUST read that model — and the underlying `pyhive`/HS2 client default it mirrors — before writing the corrected number; do not "fix" `1000 -> 10001` from inference alone. The value `10001` is the strong hypothesis, not yet a verified fact in this session.
