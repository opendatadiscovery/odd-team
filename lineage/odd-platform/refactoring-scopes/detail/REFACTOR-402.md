- **REFACTOR-402** (NEW 2026-05-19O): Cognito `/logout` endpoint does NOT sign user out of UPSTREAM federated IdPs (Google / Facebook / SAML brokers). An ODD deployment that federates Cognito → Google sees a user "logged out" of ODD + Cognito but the user's Google session remains active; the next login attempt skips the Google password prompt. AWS docs explicitly call this out; ODD docs do not

  - **Statement**: AWS Cognito's `/logout` endpoint signs the user out of the Cognito User Pool session ONLY — it does NOT sign the user out of federated upstream IdPs (Google, Facebook, SAML providers) that the user may have authenticated via. Per AWS docs (WebFetched 2026-05-19 status 200): "The logout endpoint doesn't sign users out of OIDC or social identity providers (IdPs). To sign users out from their session with an external IdP, direct them to the sign-out page for that provider." ODD's `CognitoLogoutSuccessHandler.java:40-46` calls Cognito's `/logout` only; no upstream-IdP-signout step exists. An ODD deployment that federates Cognito → Google (Cognito as OIDC broker) sees a user "logged out" of ODD AND Cognito but the user's Google session remains active — the next login attempt skips the Google password prompt. The ODD docs do not warn about this; operators with compliance requirements (immediate cross-IdP logout) need to know.
  - **Evidence**: `CognitoLogoutSuccessHandler.java:40-46` (only calls Cognito's `/logout`, no upstream-IdP step) + WebFetch AWS docs `https://docs.aws.amazon.com/cognito/latest/developerguide/logout-endpoint.html` 2026-05-19 status 200 (verbatim: "The logout endpoint doesn't sign users out of OIDC or social identity providers")
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-132 NEW (per-provider revocation strategy) — Cognito's end-session-only stance is part of the broader per-provider asymmetry. The upstream-IdP signout is an EXTRA layer the platform could add but doesn't. The maintainer's intent is consistent with the "operator inherits the IdP contract" stance; the gap is doc-completeness.
  - **Proposed remedy**: Either (a) add a doc warning to the live OAuth2/OIDC page about Cognito's federated-IdP-signout limitation; (b) provide operator guidance on the federated-logout pattern (sequential redirects through each upstream IdP's signout endpoint); (c) implement an upstream-IdP-signout step in the handler (requires querying Cognito for the user's federation IdP, then redirecting through that IdP's signout — complex). The doc fix is fastest; the code fix is structural enough to require an ADR-level discussion.
  - **Severity rationale**: MEDIUM — operator-mental-model violation; compliance-shaping (stringent immediate-revocation requirements not met). Symptom is subtle (next login skips the upstream password prompt — operator may not notice until an audit).
  - **Suggested backlog grouping**: `OAuth2 hardening sprint` (paired with REFACTOR-404 Cognito no token revocation + DOC-NNN on the live OAuth2/OIDC page for Cognito federated-IdP semantic)
