- **REFACTOR-392** (NEW 2026-05-19O): GitHub `/user/teams` pagination is silently truncated at the first page (30 teams default) — a user in 31+ teams across all their GitHub orgs may have their ADMIN-eligible team beyond page 1, silently demoting them to USER role. No `?page=N` parameter, no `Link` header handling, no recursion over pages
  - **Category**: missing-pagination
  - **Surfaced by**:
    - `GithubUserHandler.md:bugs_limitations_corner_cases.[3]` (LOW)
  - **Statement**: `GithubUserHandler.java:104-113` fetches `/user/teams` with no `?page=N`, no `Link: ...rel="next"` header handling, no recursion over pages. GitHub's `/user/teams` returns ALL teams across ALL orgs the user belongs to (not scoped by `?org`); the default page size is 30. A user in 31+ teams whose ADMIN-eligible team (matching `adminGroups`) happens to be on page 2+ is silently demoted to USER role on every login. The truncation has no operator-visible signal — no log warning, no audit trail. Edge case but reproducible.
  - **Evidence**: `GithubUserHandler.java:104-113` (`webClient.get().uri("/user/teams").retrieve().bodyToMono(new ParameterizedTypeReference<>() {})` — no pagination handling) + GitHub REST API docs (paginated at 30 per page default, `Link: ...rel="next"` for navigation)
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-135 NEW (GitHub OAuth2 + two-pass HTTP) — the two-pass architecture is the parent pattern; this gap is a missing-pagination refinement that doesn't change the architectural commitment. Adding pagination is refactoring within the existing structure.
  - **Proposed remedy**: Add multi-page recursion: parse `Link` response header, follow `rel="next"` until exhausted, accumulate teams across pages. Alternatively, scope the query to the configured org: `/orgs/{org}/teams` is org-scoped and avoids the all-orgs response shape (but loses the cross-org admin-group scenario). The maintainer should pick based on the expected operator deployment shape.
  - **Severity rationale**: LOW — affects users with >30 teams across all GitHub orgs (uncommon; mostly large enterprise users with many participations). Not security-critical; a silent demotion to USER is fail-safe (the user keeps access to their own resources; they lose ADMIN they thought they had). Operator-debug-hostile (the user complains they should be ADMIN but aren't, with no log to explain why).
  - **Suggested backlog grouping**: `OAuth2 hardening sprint` (paired with REFACTOR-390/391/393/394)
