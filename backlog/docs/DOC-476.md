## Description

Editorial coherence finding from the CTRIB-026 `/review` doc-product audit (failure shape:
**parallel-surfaces-with-drift**). The #1768 fix (CTRIB-026, milestone 0.29.0) revises
`entity-detail-page.md` Section 5 so the Groups/Terms ordering note is downgraded from a `warning`
caveat (the old "ordering is undefined / stringification defect") to an `info` note ("the Groups and
Terms panels show the server's order"). But the cross-link on the sibling page still frames it as a
caveat:

- `data-discovery/groups-domains.md:98` — "[Data entity detail page](entity-detail-page.md) — the
  per-entity surface where the sidebar Groups panel lives, plus the **visible-window truncation caveat**
  on Groups membership."

After the fix, "caveat" mildly overstates the post-0.29.0 framing (it is now an informational
server-order note; the only residual caveat is "do not rely on this order being alphabetical"). Both
pages ride the **same `release/0.29.0` train**, so they publish together — the drift would otherwise ship
to the live manual on the 0.29.0 gate.

**Secondary (sub-threshold) note**: on `entity-detail-page.md`, the truncation-hint intro paragraph uses
"Showing 20 of N" as the generic example, but the Groups panel caps at 10 (the second info hint correctly
states "10 for Groups, 20 for Terms"). The exact caps are co-located, so this is a representative-example
nit, not a contradiction — fold a one-word generalisation in only if touching the page anyway.

## Proposed fix

- `groups-domains.md:98`: reword "the visible-window truncation caveat on Groups membership" → e.g. "how
  the Groups panel truncates and orders the visible window" (or "…the visible-window truncation behaviour"),
  matching the now-informational entity-detail framing.
- Optionally generalise the entity-detail hint-intro example to be panel-agnostic.
