## Description

The Compact / Full view-mode toggle is a user-visible control on the lineage canvas — present on both DEG-lineage and per-entity (Hierarchy) lineage. Every lineage doc page is silent on its existence (verified WebFetch 2026-05-27, all three pages 200 OK; ZERO mentions of "Compact" / "Full" / "view mode" on any of `features/data-lineage.md`, `features/data-lineage/data-objects.md`, `features/data-lineage/microservices.md`).

**Facet 1 — One user-visible label, two subsystem behaviours (F-186a, HIGH).** Verified per F-186 substrate (UI files at `DEGLineageControls.tsx:21-27,42-48`, `LineageControls.tsx:50-54,96-102`, `DEGLineageLayouter.tsx:39-56`, etc.):
- The DEG-side `DEGLineageControls.handleViewChange` triggers `setIsLayouted(false)` forcing the elkjs/dagre layout to re-run — visible as a loading spinner + node-shift animation.
- The Hierarchy-side `LineageControls.handleViewChange` ONLY sets the `full` query param — d3-hierarchy + visx Tree re-renders but does NOT re-layout. Visible as an instant shape change with no layout migration.

Same control, two observable behaviours. An operator who learns the toggle on a DEG canvas builds the wrong mental model for the Hierarchy canvas; switching modes on a dense Hierarchy graph may produce visual overlap because node positions stay static while nodeSize changes.

**Facet 2 — Compact mode hides DEG-membership entry point in the Hierarchy canvas (F-186b, HIGH).** The DEG-Items button (the `GroupedEntitiesListModal` opener for the Hierarchy-side rendering of a DEG-typed node, per `Info.tsx:120-141`) is gated by `full && externalName && nodesRelatedWithDEG?.length > 0`. Compact mode → button HIDDEN → user cannot click into a DEG node to see its members. The trade-off is invisible until the user wants to drill in; the navigational affordance is silently lost.
