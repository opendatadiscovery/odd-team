# DOC-495 — the search URL is a shareable, bookmarkable `/search?q=` link (#1825 ST-1a / CTRIB-048)

ST-1a (the first slice of the #1825 search overhaul) moves the search **query** into the URL as `?q=`. The
Catalog page's address bar becomes **`/search?q=<query>`** instead of the opaque `/search/{uuid}` session id,
so a search is a **stable, shareable, bookmarkable, back/forward-correct link**. This **changes** the existing
documented behaviour, so the `data-discovery/search.md` "Known limitations and operator caveats" section had a
caveat that is now outdated for 1.0.0.

**Routing (G-C11):** unreleased behaviour (1.0.0). Authored + committed on the `release/1.0.0`-based branch
`docs/CTRIB-048-search-url-state` @ `61cd0a8`. The push to the shared train is the maintainer's action (see
`routing:` above). It publishes when the train merges to documentation `main` at the 1.0.0 release gate; the
live manual is unchanged until 1.0.0 ships.

## What was authored (on docs/CTRIB-048-search-url-state @ 61cd0a8)

Rewrote the caveat **"The `/search/{id}` URL is a server-side session, not a frozen query"** →
**"The search URL is a shareable, bookmarkable `/search?q=` link"**:

- The address bar is `/search?q=<query>` — the query encoded in the URL, not an opaque session id; the search
  is a stable, shareable, bookmarkable link and back/forward step through prior queries.
- Sharing a `/search?q=…` URL re-runs the same query **as the recipient** (under *their* permissions — the link
  carries the query, not results), and it does not expire.
- Bookmarking is now durable (no server-side session to evict).
- **Honest scope note:** this release puts the *query* in the URL; the sidebar **facets are not yet in the
  URL** (they move there as the overhaul lands — ST-1b), so for now a shared link reproduces the query but not
  the facet selections.
- Legacy `/search/{uuid}` links still load (the session is kept server-side as an internal detail; an evicted
  one shows the graceful "This search has expired" + "Start new search").

The `housekeeping.ttl.search_facets_days` reference + the "Where to next" link are preserved (legacy sessions
still exist + are evicted).

## Follow-up when the facet-URL slice ships (#1825 ST-1b)

When ST-1b puts the facets in the URL, drop the "facets are not yet in the URL" bullet and document the full
shareable filtered-search URL — an additive edit on the same train, no rewrite.
