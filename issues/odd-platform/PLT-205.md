## What

On a data entity's **Discussions** tab, when there are no messages the empty-state placeholder reads "No messages" - and that string is **hardcoded English**, not passed through the i18n translation function. Every other user-facing string in the surrounding Data Collaboration UI is translated; this one is not, so under a non-English locale the empty Discussions panel shows untranslated English while the rest of the page is localised.

## Where

`odd-platform-ui/src/components/DataEntityDetails/DataCollaboration/MessagesList/MessagesList.tsx:70`

```tsx
{isMessagesLoaded && !messagesLength && (
  <EmptyContentPlaceholder text='No messages' />   // <-- literal string, no t() wrap
)}
```

`MessagesList.tsx` does not import `useTranslation` at all, so the literal is the only option as written. Contrast the sibling component in the same `DataEntityDetails` tree, `LinkedItemsList/LinkedItemsList.tsx`, which DOES wrap its empty-state:

```tsx
// LinkedItemsList.tsx:4   import { useTranslation } from 'react-i18next';
// LinkedItemsList.tsx:19  const { t } = useTranslation();
// LinkedItemsList.tsx:86  <EmptyContentPlaceholder text={t('No linked entities')} />
```

The two empty-states are structurally identical (`EmptyContentPlaceholder text=...`); one is translated, one is not - a localisation drift between siblings.

## Why it matters

Silent (no error; visible only to non-English users, and only in the empty state). Affects operators running the platform under a non-default locale: the Discussions panel leaks an untranslated English string, breaking the localisation contract that the rest of the collaboration UI honours. Low functional impact but a real consistency/i18n defect; medium per the triage given it is a user-visible inconsistency on a shipped surface and the fix is trivial.

## Suggested fix

Import `useTranslation` in `MessagesList.tsx`, pull `const { t } = useTranslation();`, and wrap the literal: `<EmptyContentPlaceholder text={t('No messages')} />` - mirroring `LinkedItemsList.tsx:86`. Add the corresponding key to the translation catalogues.

## How discovered

Surfaced in the 2026-06-08 feature-reflection contradiction harvest - `lineage/odd-platform/harvest/2026-06-08-contradiction-harvest.md`, sourced from the F-197 feature reflection (`lineage/odd-platform/feature-reflections/detail/F-197.yaml`). The sibling-component comparison (`LinkedItemsList.tsx` wrapping the same placeholder in `t()`) confirmed this is unintended drift, not a deliberate non-translatable string.
