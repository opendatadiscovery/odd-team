## Description

The Architectural Decision Log is a **one-way navigation leaf**: the ADRs link richly *outward* (to feature pages, `main-concepts.md#oddrn`, `Architecture.md`, operator config) but **no page outside the subtree links into it.** The reader who most needs the "why" — the one already reading the architecture overview or the ODDRN concept — has no path to discover the decision log.

The asymmetry is sharpest where an ADR explicitly *claims* the relationship: `ADR-0070:41` says of Architecture.md *"This ADR is the decision behind that structure; the page is the operator's view of it"* — yet `Architecture.md` (which has its own "Pull vs Push", "ODDRN", "Cross-cutting concerns", and "Where to read the code" sections) contains zero ADR references. Same for `main-concepts.md#oddrn` ↔ ADR-0073.

**Failure shape:** cross-audience absence (one-way leaf). This is the editorial audit's **highest-priority** finding — it makes a complete, high-quality decision log undiscoverable from the pages a contributor actually starts on.

## Acceptance Criteria

- [ ] `docs/Architecture.md` gains a discoverable pointer into the decision log — ideally from the "Where to read the code" section (the exact audience for an ADR log) and/or the "Pull vs Push" / "ODDRN" sections, into ADR-0070/0071/0072/0073
- [ ] `docs/main-concepts.md` ODDRN section links to ADR-0073; the architecture-chain section links to ADR-0072/0070
- [ ] The added links reciprocate relationships the ADRs already assert in prose (e.g. ADR-0070:41's claim about Architecture.md) — verify each ADR→parent link now has a parent→ADR counterpart
- [ ] Live-site Gate 8: anchors resolve on `docs.opendatadiscovery.org` post-merge
