## Description

CTRIB-020 (PLT-018 / GHSA-mf43-2636-9289) adds `rehype-sanitize` (in the correct `rehypeRaw` → `rehypeSanitize`
order) to the shared `Markdown.tsx` wrapper and routes the `DataEntityDetailsPreview` direct-render through it —
closing the stored-XSS hole on the **Markdown render surfaces** (entity description, dataset-field description,
term definition, Query Examples definition/query, and the data-entity preview). Post-fix, the published "fix is on
the roadmap / until it ships, operator-trust is the only defence" framing is no longer accurate for those surfaces.

Graduate the caveats when the fix ships:
- `data-modelling/query-examples.md` — the `{% hint style="danger" %}` stored-XSS caveat (~lines 102-108): the
  definition/query render is now sanitized; revise to a "resolved limitation" note (the create-dialog
  "no client-side validation" caveat at ~lines 110-114 can stay as a UX note, but drop the "stored-XSS chain" framing).
- `data-discovery/entity-description.md` (DOC-187) — the "stored-XSS family across six Markdown surfaces" section
  (~lines 53-74): record that the `rehype-sanitize` render-time fix shipped for the Markdown-render surfaces, and
  narrow the remaining-risk language to the surfaces NOT closed by this fix (Lookup Tables → PLT-019; Slack mrkdwn
  → PLT-016) if those are still open at release.

This is a post-fix **accuracy/graduation** update (NOT a pre-fix caveat): it must publish **with** the fix.
