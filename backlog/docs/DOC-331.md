## Description

Two rigidity defects in the notification delivery path silently drop alerts or disable transport security; both are operator-correctable once documented:

- **Generic-webhook delivery accepts ONLY HTTP 200 (F-009/H-005)** — `201`/`202`/`204` from async-accept receivers are treated as failures and the alert is dropped. Operators pointing ODD at a receiver that returns `202 Accepted` (a common async-ingest convention) lose alerts with no obvious cause. Not covered by PLT-016 (webhook-channel-specific).
- **SMTP protocol match is case-sensitive lowercase `smtp` (F-009/H-009)** — uppercase `SMTP` silently hits the ELSE branch, so STARTTLS + SMTP AUTH never engage (credentials may go plaintext), with no boot warning. The code fix is filed as PLT-107; this surfaces the operator caveat alongside the webhook one.
