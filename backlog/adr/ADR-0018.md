## Description

Promote `ADR-CANDIDATE-018` (5-sidecar cross-feature, wisdom-test PASS) into a published ADR.

The decision: configuration required for an outbound integration is validated **fail-fast at
boot** — e.g. the Slack OAuth token is checked non-empty in the bean factory and raises
`IllegalArgumentException` on empty/missing, rather than degrading silently to a runtime
failure when the first message is sent. The pattern recurs across the `@ConfigurationProperties`
surface (Data Collaboration, Notifications, Email sender, LDAP), framing config-binding
failures as deployment errors surfaced at startup, not in production traffic.

## Context

Surfaced as `ADR-CANDIDATE-018` (HIGH, `promote`, wisdom-test PASS) and strengthened across
five batches into a cross-feature convention. A clean, operator-relevant decision: it tells
an operator that a misconfigured integration fails at startup, not silently at runtime — the
inverse of the LSN-002 / LSN-001 silent-degradation failure mode.

## Implementation Notes

Descriptive voice. Pin down which integrations are fail-fast vs which degrade silently —
the candidate names Slack OAuth + the config-properties validators; verify the boundary so
the ADR does not over-claim "all outbound config is fail-fast" if a channel (e.g. a webhook
with no key) is silently no-op by design (cf. ADR-CANDIDATE-041).
