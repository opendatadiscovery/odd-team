## What

**Defect 1 - Cognito revocation not called (F-086a).** AWS documents Cognito's `/oauth2/revoke` endpoint as available on every User Pool. `CognitoLogoutSuccessHandler.java:33-50` issues session-only invalidation. Contrast `GoogleLogoutSuccessHandler.java:43-54` which POSTs to `oauth2.googleapis.com/revoke`. One-line code addition closes the gap. Operator logging out from a shared workstation expects token revocation; the access token (1h TTL) + refresh token (up to 90 days on Cognito) remain valid.

**Defect 2 - UI no feedback on revocation outcome (F-086c).** `AppToolbar.tsx:35-37` issues `window.location.href = '/logout'` without surfacing any feedback distinguishing "successful local logout, no IdP revocation" (Azure / Cognito / ODD_IAM) from "successful logout + IdP token revoked" (Google / GitHub). Operators on shared workstations may believe they've fully logged out when the IdP-issued tokens still work.

## Why it matters

Cognito is an enterprise-tier OAuth2 provider; operators deploying ODD with Cognito expect the same revocation guarantees as GitHub or Google. The session-only invalidation creates a residual-token-exposure window (1h access + up to 90d refresh) that operators using shared/public workstations are unaware of.

Combined with Defect 2, even an operator who reads the doc and goes through the Cognito web console for full logout has no in-platform confirmation of which IdP-tokens were actually revoked.

## Suggested fix

**Thread A - Add Cognito /oauth2/revoke call.**

```java
// CognitoLogoutSuccessHandler.java
public Mono<Void> onLogoutSuccess(WebFilterExchange exchange, Authentication authentication) {
    OAuth2AuthenticationToken token = (OAuth2AuthenticationToken) authentication;
    String accessToken = oauth2AuthorizedClientService.loadAuthorizedClient(...).getAccessToken().getTokenValue();
    String revokeUri = "https://" + cognitoDomain + "/oauth2/revoke";
    return webClient.post()
        .uri(revokeUri)
        .body(BodyInserters.fromFormData("token", accessToken)
            .with("client_id", clientRegistration.getClientId()))
        .retrieve()
        .bodyToMono(Void.class)
        .then(super.onLogoutSuccess(exchange, authentication));   // session invalidation
}
```

Pattern-mirror GoogleLogoutSuccessHandler.java:43-54. The Cognito domain is operator-configured; verify the lookup path.

**Thread B - UI feedback on revocation outcome.**

Modify the SPA logout flow to surface a brief message:

```tsx
// AppToolbar.tsx
const handleLogout = async () => {
    const response = await fetch('/logout', { redirect: 'manual' });
    // response.headers carries an X-ODD-IdP-Revoked: true|false header set by the handler chain
    const idpRevoked = response.headers.get('X-ODD-IdP-Revoked') === 'true';
    if (idpRevoked) {
        showToast('Logged out. IdP token revoked.');
    } else {
        showToast('Logged out. IdP-issued tokens may remain valid until they expire - for shared/public terminals, sign out from the IdP web console as well.');
    }
    window.location.href = '/';
};
```

Backend side: each `*LogoutSuccessHandler` sets the `X-ODD-IdP-Revoked` response header. The SPA reads it; no per-provider client-side knowledge needed.
