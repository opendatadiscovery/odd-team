## Description

The Data Entity Detail Overview composer paints its whole body the moment the top-level details fetch resolves, but several child panels own their own independent async. `DataEntityDetails/Overview/Overview.tsx` renders the body behind a single condition — `dataEntityDetails && !isDataEntityDetailsFetching` (`Overview.tsx:52`) — and the only skeleton is the one gated on that same `isDataEntityDetailsFetching` (`Overview.tsx:151`). But inside that body, `OverviewAttachments` (`Overview.tsx:73-78`) and the DQ panels `OverviewDQSLAReport` + `OverviewDQTestReport` (`Overview.tsx:105-110`) are self-fetching children driven by their own queries, not by `getDataEntityDetailsFetchingStatuses`.

So between "details resolved" and "attachments / DQ resolved", the page paints a structurally complete Overview while those panels are still spinning — or have errored — with no top-level skeleton or boundary covering them. On a slow link this is a visible half-loaded frame: stats/description/tags present, attachments and DQ/SLA blank-or-spinning-or-broken. The report flags this as a transient-state hypothesis to measure under throttling (PENDING-F-176-1, slow-3G), since it only manifests under latency.

**Typed gate: validates-feature (loading-state behaviour), probe-gated.** This is not a known-bug pin — there is no asserted-wrong value yet; it characterises a transient UX state. The deliverable is the throttled observation (PENDING-F-176-1): does a usable-looking Overview render while child panels are unresolved, and do those panels degrade gracefully (their own skeleton) or paint a broken/empty frame? The e2e test then locks the observed behaviour so a regression (e.g. a child panel that throws into the painted body, or a panel that paints empty instead of its own skeleton) is caught. If the probe shows each child already renders its own skeleton/empty-state cleanly, the finding is recorded as acceptable progressive loading and the test pins that contract.

## Acceptance Criteria
- [ ] PENDING-F-176-1 runs the Overview under network throttling (slow-3G / Playwright route latency) for a dataset that has attachments and DQ/SLA data, and records the intermediate frame: which sections are painted while `OverviewAttachments` and the DQ panels are still loading, and how each unresolved panel presents (own skeleton vs empty vs error).
- [ ] A Playwright IT drives the real UI→backend→DB flow with the attachments and DQ responses delayed relative to the details response, and asserts the OBSERVED contract: the top-level skeleton clears when details resolve, the body paints, and each independent panel shows its own loading affordance (not a broken/empty box and not an unhandled error) until its data arrives.
- [ ] If the probe reveals a panel that paints empty (indistinguishable from "no data") or throws into the painted body during the gap, that is logged as a follow-up DOC-/PLT- defect (with the panel + file:line) and the IT pins the current degraded behaviour as a characterization until the fix lands.
- [ ] The IT carries the PENDING-F-176-1 reference and a note on what regression flips it (a child panel newly throwing into the body, or the top-level skeleton being widened/narrowed).
