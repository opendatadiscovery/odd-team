## What

`GoogleUserHandler.java` (74 lines, full re-read this run) does NOT extend `AbstractOIDCUserHandler` and NEVER calls `provider.getAdminGroups()`. Admin detection consults only `adminPrincipals` (full-string equality against `email` claim via `GOOGLE_EMAIL = "email"` at line 31, unless overridden by `adminAttribute`). The field binds successfully - `ODDOAuth2Properties.java:49` has `adminGroups` as a unified field across providers - no boot warning, no error.

An operator configuring `auth.oauth2.client.google.admin-groups: [workspace-admins]` sees ZERO behaviour change. The user expected to be admin remains USER. Operator hostile silent-no-op.

## Where

| File | Lines | Role |
|------|-------|------|
| `odd-platform-api/src/main/java/.../auth/handler/impl/GoogleUserHandler.java` | 1-74 | Full file: no `getAdminGroups` call anywhere |
| same | 31 | `GOOGLE_EMAIL = "email"` literal constant |
| `odd-platform-api/src/main/java/.../auth/ODDOAuth2Properties.java` | 49 | `adminGroups` field defined on shared properties POJO |

## Why it matters

This is a silent operator hazard. The Google administrator IS configuring the field with intent - the silent no-op is operator-hostile. Compounds with the unified-POJO design: same field name across providers, semantically different per-provider, no doc warning.

## Suggested fix

**Option A - boot-time cross-field validation (recommended).**

Add `@PostConstruct` on `ODDOAuth2Properties` that fails-fast or warns when `provider == GOOGLE` AND `adminGroups` is non-empty:

```java
@PostConstruct
void validateProviderConfig() {
    for (var provider : client.values()) {
        if (Provider.GOOGLE.name().equalsIgnoreCase(provider.getProvider())
            && provider.getAdminGroups() != null
            && !provider.getAdminGroups().isEmpty()) {
            log.warn("auth.oauth2.client.{}.admin-groups is set but GoogleUserHandler does NOT consult admin-groups. Use admin-principals (email) or admin-attribute (custom claim) instead.",
                provider);
            // OR: throw new IllegalStateException(...) for fail-fast
        }
    }
}
```

Recommended warn-first; promote to fail-fast in a later release after the warn-period reveals zero accidental config.

**Option B - implement admin-groups support for Google (feature, larger scope).**

Google's OAuth2 access token does NOT carry group membership; admin-groups for Google requires a separate Workspace Admin SDK call with elevated scopes. Substantially larger code change; track as a separate feature request if there's operator demand.

Recommended Option A as the immediate closure; Option B is gated on actual operator demand.
