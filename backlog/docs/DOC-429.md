## Description

The **top-level Data Lineage landing page** (`data-lineage.md`) carries a full deep-dive on the "my-objects triplet" — `GET /api/dataentities/my`, `…/my/upstream`, `…/my/downstream` — at lines 24-67. That deep-dive includes three API-contract / performance / debugging caveats that are far below the altitude of a section-landing page:

- **Wrong-shape OpenAPI `danger`** (lines 36-40) — the spec summary for `getMyObjectsWithUpstream` / `getMyObjectsWithDownstream` describes the response as "your owned set" when it is the non-owned adjacent set.
- **Anchor-fetch single-site `warning`** (lines 46-50) — owner-scoping is enforced at exactly one site (`fetchAssociatedOwner`) with no defence-in-depth in the lineage projection.
- **O(anchor) pagination `warning`** (lines 52-56) — the triplet fetches the full owned set before pagination; admin / CI-bot owners trigger O(anchor) DB cost on every call regardless of `size`.
- **4-way-ambiguous empty-response `info`** (lines 58-67) — an `HTTP 200 []` is indistinguishable across four root causes.

This is the same content-altitude drift class as LSN-006 (deep content homed on a landing page) and LSN-007 (sub-feature placed at a primary-pillar altitude): a section-landing page should orient and route; deep API-contract + per-endpoint performance caveats belong on the sub-page or the API reference. Meanwhile the natural deep home — `data-objects.md`'s **Access model** (lines 92-103) — covers only the per-entity upstream/downstream and group-lineage endpoints' read posture and **omits the my/upstream/downstream triplet entirely**. So a reader who opens the Data Objects Lineage sub-page (the page they'd land on from "trace upstream/downstream") never sees the triplet's owner-scoping, pagination, or empty-response semantics; and a reader scanning the landing page for "what is this section" is dropped into anchor-architecture detail.

This misleads an operator: the API contract + performance caveats they most need are on the wrong altitude (the landing they skim) instead of the deep page they read when integrating, and the deep page they read omits them.
