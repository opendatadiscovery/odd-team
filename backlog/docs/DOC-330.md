## Description

Several SPA surfaces do not invalidate (or never re-fetch) their cache after a mutation, so the screen shows stale data after a successful write — the success toast contradicts what the user sees. Confirmed across features:

- **Query Examples (F-131/H-006, F-131/H-007)** — `useCreateQueryExample` invalidates no React-Query cache, so a newly-authored snippet is absent from the catalog list / per-dataset tab / per-term tab until manual refetch; `useUpdateQueryExample` invalidates only the details key, so an edited snippet shows stale definition/query on the list, search, and per-dataset/per-term tabs.
- **Alert tab badges (F-007/H-008)** — fetch once on mount (`useEffect([])`) and never refresh after a Resolve / new alert; the count stays stale until a full reload (and re-pays a 3-COUNT + recursive-lineage-CTE fetch).
- **Directory level-1 grid (F-023/H-007)** — a stale-while-revalidate singleton (static queryKey, no staleTime, no invalidation); a datasource registered in Management does not refresh an already-open Directory until hard reload or 5-min gcTime eviction.
- **Auth-mode-derived UI (F-119/H-011)** — OwnerAssociation gate + version can lag a live `auth.type` change within one SPA session (keepMounted + no invalidateQueries + no staleTime); correct only across a full reload.

Per the no-code-change-now posture, this documents the behaviour as a known limitation; the cache-invalidation code fix is a follow-up upstream PLT (PLT-059 already covers one instance — queryClient invalidate by undefined termId in CREATE mode).
