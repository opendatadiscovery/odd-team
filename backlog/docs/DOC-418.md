## Description

The data-entity **Overview tab** renders its two-column grid with a hard 9/3 ratio that never changes with viewport width. In `DataEntityDetails/Overview/Overview.tsx` the layout is `<Grid container spacing={2} ...>` (`Overview.tsx:53`) with a main column `<Grid item xs={9}>` (`Overview.tsx:54`) and a sidebar `<Grid item xs={3}>` (`Overview.tsx:93`). `xs` is the smallest MUI breakpoint and there are **no `sm`/`md`/`lg` overrides**, so the sidebar is pinned at 25% of the row at every width. On a narrow viewport the sidebar (General identity, Owners, DQ panels, Groups, Tags, Terms — per `docs/data-discovery/entity-detail-page.md:16`) is crushed into a quarter-width strip instead of stacking below the main column, which is the responsive behaviour an operator would expect and which differs from other catalog surfaces.

The doc's "Overview tab composition" section already describes the two-column grid (`docs/data-discovery/entity-detail-page.md:13-16`) but does not state that the split is fixed and non-responsive. An operator opening a catalogued entity on a tablet has no documented expectation that the sidebar will not reflow. This is a layout caveat on the existing entity-detail page.

A platform-side responsive refactor is a candidate but is **probe-pending (PENDING-F-176-2)** — confirm the rendered narrow-viewport behaviour before any code change; this backlog item is the documentation-side caveat only.
