# ReactiveMetadataFieldRepositoryImpl — semantic understanding

## understanding

`ReactiveMetadataFieldRepositoryImpl` is the jOOQ/Reactor persistence surface for the `metadata_field` table — the GLOBAL (no tenant / project / owner column) registry of custom-metadata field DEFINITIONS keyed by `(name, type, origin)`. It extends `ReactiveAbstractSoftDeleteCRUDRepository<MetadataFieldRecord, MetadataFieldPojo>` so all base CRUD reads through a `metadata_field.deleted_at IS NULL` filter applied via `addSoftDeleteFilter`. Beyond CRUD it implements four feature primitives: (a) `listInternalMetadata(query)` — the UI dropdown source for the per-entity "add metadata" panel, restricted to `origin=INTERNAL` and free-text-substring-filtered case-INSENSITIVELY by `nameField.containsIgnoreCase(query)`; (b) `listByKey(Collection<MetadataKey>)` — partition-batched OR-chain existence-lookup on `(name, type)` keys driving the auto-create-on-miss UX in `MetadataFieldServiceImpl.getOrCreateMetadataFields` and `MetadataFieldServiceImpl.ingestMetadataFields`; (c) `ingestData(List<MetadataFieldPojo>)` — the bulk-upsert that the COLLECTOR INGESTION path uses, pinning to the partial unique index `IX_UNIQUE_EXTERNAL_NAME_TYPE` and adding a runtime `.where(ORIGIN.ne(INTERNAL))` to match the partial-index predicate; (d) `getDtosByDataEntityId(long)` — joins `metadata_field_value` ↔ `metadata_field` to produce the per-entity metadata panel populated on the data-entity detail page. The class is the SQL primary source for several cross-batch invariants: a **soft-delete + partial-unique-index mismatch** (the `metadata_field` partial indexes do NOT include `WHERE deleted_at IS NULL` whereas the sibling `tag_name_unique` does — Tag-side fix in `V0_0_64`, metadata-side not migrated); the **case-sensitive name semantics** for `(name, type)` exact lookup paired with case-INSENSITIVE UI substring search (same shape as the Tag asymmetry); and the **TWO distinct partial unique indexes** by origin (`IX_UNIQUE_INTERNAL_NAME (name) WHERE origin='INTERNAL'` for UI-curated; `IX_UNIQUE_EXTERNAL_NAME_TYPE (type, name) WHERE origin <> 'INTERNAL'` for collector-ingested) — a deliberate asymmetry where INTERNAL forbids name reuse across types but EXTERNAL allows `cost_centre:STRING` and `cost_centre:INTEGER` as distinct fields. The class has 96 lines; the `ingestData` upsert (`:74-109`) is 36 of them.
