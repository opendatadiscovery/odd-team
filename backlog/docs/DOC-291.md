## Description

Both the Alerting feature page and the api-reference/alerts page tell readers the global alert listings show **open and resolved** alerts:

- `alerting.md` describes the **All** tab (and by extension My / Dependents) as showing "open and resolved" alerts.
- `api-reference/alerts.md` calls the global listing "every alert across the platform" with no status qualifier.

The code hard-filters **`STATUS = OPEN`** in all three global listing queries (the `listAll…WithStatusOpen` family). **Resolved alerts never appear on any global tab.** An operator looking for a resolved alert on the All tab will not find it and may conclude it was deleted or that resolution failed, when in fact the tab simply never shows resolved alerts.

High priority — actively misleading about what a primary UI surface and its API show.

**Failure shape**: code-doc drift (the harvest's "Category B" — a listing documented as broader than the query actually returns), restated on two parallel surfaces.
