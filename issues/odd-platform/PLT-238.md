## Description

Same bug class as #1766's redux-thunk arm (PLT-233), but on a **form submit**, not a `ConfirmationDialog`,
so it is **out of CTRIB-031's scope** (CTRIB-031 fixes only the `ConfirmationDialog` thunk consumers).

`DataEntityDetails/Overview/OverviewMetadata/MetadataItem/MetadataItem.tsx:47-56` — the custom-metadata
**edit** form submit:

```tsx
const handleUpdate = (data: MetadataFieldValueUpdateFormData) =>
  dispatch(
    updateDataEntityCustomMetadata({
      dataEntityId,
      metadataFieldId: metadataItem.field.id,
      metadataFieldValueUpdateFormData: data,
    })
  ).then(() => {
    setEditMode(false);   // <- runs even when the update FAILED
  });
```

A redux-toolkit dispatch promise **resolves even on failure** (`handleResponseThunk.ts:41` →
`rejectWithValue`), so `.then(() => setEditMode(false))` runs unconditionally. When
`PUT /api/dataentities/{id}/metadata/{fieldId}` is refused (validation 400, RBAC 403, 500), the editor
**closes as if the edit was saved** — the operator sees their edit form dismissed and assumes success, while
the stored value is unchanged. An error toast does appear (post-#1771), but the edit-mode-exit contradicts it
(the same false-success shape as #1766's silent-close).

Note: the sibling `handleDelete` in the same file IS fixed by CTRIB-031 (it is a `ConfirmationDialog`
`onConfirm`); `handleUpdate` is the form-submit path and was deliberately left untouched to keep CTRIB-031
bounded to the `ConfirmationDialog` arm (G-C5).

Static trace only (not driven; `user_facing_verified: false`) — confirm live when worked.

## Suggested fix

Gate the edit-mode exit on actual success — `.unwrap()` the dispatch so `setEditMode(false)` only runs when
the update resolved (and the rejection surfaces via the toast / inline form error):

```tsx
const handleUpdate = (data) =>
  dispatch(updateDataEntityCustomMetadata({ ... }))
    .unwrap()
    .then(() => setEditMode(false));
```

(The same `.unwrap()` idiom PLT-233 / CTRIB-031 apply to the `ConfirmationDialog` consumers; this is the
form-submit instance.) Audit sibling form submits for the same pattern (e.g. any `dispatch(thunk).then(close)`
on an edit form) while here.

## Acceptance

- A failed custom-metadata update keeps the editor open (does not silently exit edit mode); a successful update
  still closes it.
