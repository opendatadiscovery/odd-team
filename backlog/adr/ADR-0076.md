## Description

The SPA applies TWO state-management paradigms: per-feature **jotai** stores scoped to the component mount lifetime (Data Quality dashboard, Data Lineage, Dataset Structure, and at least one term tab), and a session-persistent **Redux** store for the majority. The reflection pass found this is a *consistently-applied* implicit architecture decision (F-104/H-007) — not random drift — with NO CONTRIBUTING / ARCHITECTURE / ADR documenting WHEN to use which. The contributor-facing absence produces future operator-facing inconsistency: the jotai areas reset their filters/cursor on navigate-away while the Redux majority persists for the session (the operator-facing half is documented as a caveat in DOC-332). F-152/H-008 corroborates: three sibling term tabs (LinkedTerms = tanstack-query, LinkedEntities = redux thunks, LinkedColumns = tanstack-query) use two patterns in one parent.

This item drafts the ADR that NAMES the decision (per-feature ephemeral stores are deliberate, scoped to mount lifetime; the URL is the persistence mechanism where cross-navigation persistence is wanted) so contributors know the rule and new features inherit it consistently. Follows the implicit-adrs → backlog ADR → published ADR-log flow (the ADR pillar).
