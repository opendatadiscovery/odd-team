- **REFACTOR-408** (NEW 2026-05-19O): Azure logout has NO server-side token revocation — the handler invalidates only the local WebSession. The OAuth2 access token, refresh token, and id_token issued by Azure remain valid at Azure until their natural TTL expires (typical Azure access token TTL: 60-90 minutes; refresh token: up to 90 days for confidential clients). Azure AD v2.0 does NOT expose RFC 7009 token revocation; the gap is platform-side documentation, not implementation

  - **Statement**: `AzureLogoutSuccessHandler.java:31-48` invalidates only the platform-side `WebSession`. The OAuth2 access token, refresh token, and id_token issued by Azure remain valid at Azure until their natural TTL expires. If the token was previously exfiltrated (via XSS, a non-HttpOnly storage tier, a browser-extension compromise), logging the user out of the platform does NOT invalidate the token at Azure or revoke its access to other resources the user had consented for. Azure AD v2.0 does NOT expose RFC 7009 token revocation, so even attempting revocation would fail — but the platform-side caveat is undocumented. Operators with stringent immediate-revocation requirements need to know. Compare: `GoogleLogoutSuccessHandler.java:43-54` actively revokes via `oauth2.googleapis.com/revoke`; `GithubLogoutSuccessHandler.java:51-63` revokes via `DELETE /applications/{client_id}/grant`.
  - **Evidence**: `AzureLogoutSuccessHandler.java:31-48` (no outbound revocation HTTP) + `GoogleLogoutSuccessHandler.java:43-54` (contrast) + `GithubLogoutSuccessHandler.java:51-63` (contrast) + Microsoft documentation (Azure AD v2.0 lacks RFC 7009 revocation endpoint)
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-132 NEW (per-provider revocation strategy) — Azure's end-session-only stance is structurally forced by Azure AD's protocol. The maintainer's intent is consistent with the IdP contract. The gap is doc-completeness: operators choosing Azure as their OAuth2 provider should know their tokens persist after logout.
  - **Proposed remedy**: Doc-only fix — update the live OAuth2/OIDC page's Azure section to explicitly state: "Azure logout invalidates the local platform session; access/refresh/id_token issued by Azure remain valid at Azure AD until their natural TTL expires (Azure AD v2.0 does not expose token revocation). Operators with stringent immediate-revocation compliance requirements should configure short Azure-side token TTLs or pair with conditional access policies." No code change is feasible (Azure AD doesn't support revocation).
  - **Severity rationale**: MEDIUM — compliance-shaping; affects operators with stringent immediate-revocation requirements. Symptom is invisible (tokens persist; no operator-visible signal); compliance audit may surface the gap.
