## What

Four defects on the Term Detail page's Query Examples tab and Overview right-rail (tags + owners panel). Two are React-correctness bugs (key on free-text + slice-then-sort); one is a silent-failure UX pattern (mutateAsync no catch); one is an RBAC bypass on tag-create (sibling pattern to the namespace-create bypass on PLT-059).

**Defect 1 — TermQueryExamples React key on `qe.definition` (free-text SQL) — duplicate definitions collide; React silently drops the duplicate row (F-155a).** `TermQueryExamples.tsx:48-55` uses `key={qe.definition}` for the React key. Query Example definition is free-text — two query examples with identical definitions (e.g., commonly-pasted snippets) collide. React renders only the first match. Usual pattern is `key={qe.id}`.

**Defect 2 — AssignTermQueryExampleForm `mutateAsync` has no `.catch` handler — silent failure on backend reject (F-155b).** `AssignTermQueryExampleForm.tsx:32-41` — `mutateAsync(...)` with NO `.catch(...)`. Same shape as F-154b (TermsForm — closed by PLT-059 PR-2 Defect 4). Operator sees no error message on backend reject; dialog stays open with form filled.

**Defect 3 — OverviewTags slice-then-sort ordering bug; important tags silently hidden beneath "View All" collapse (F-156a).** `OverviewTags.tsx:47-49` — `tags.slice(0, visibleLimit).sort(tagsCompare)`. The slice is applied BEFORE the sort. `tagsCompare` sorts by `important` first then alphabetic — the INTENT is "show the most important 20 tags". But `.slice(0, 20)` takes the FIRST 20 tags by insertion-order (i.e., `id`-order from the backend payload), THEN sorts those 20. If a Term has 50 tags with the 25th-inserted tag marked `important`, that important tag is silently hidden beneath the "View All" collapse. Same bug in the second slice path at line 63 (`?.slice(visibleLimit).sort(tagsCompare)`).

**Defect 4 — TagsEditForm tag-create bypass — TERM_TAGS_UPDATE bypasses TAG_CREATE (F-156b).** `TagsEditForm` is the AUTHORING entry point for the F-002 batch K facet `tag_create_bypass_via_upsert_tags`. An operator with `TERM_TAGS_UPDATE` (but without `TAG_CREATE`) types a novel tag name; backend `tagService.getOrCreateTagsByName` silently creates a tag. UI provides no signal. Same architectural class as PLT-059 Defect 2 (namespace bypass).

## Why it matters

- **Defect 1**: subtle but real — pasted SQL snippets are common; the duplicate row vanishes silently. Operators auditing "what query examples are linked to term X" see an incomplete list.
- **Defect 3**: prioritisation contract violated — operators trust the Overview right-rail to surface important tags. The bug means important tags are silently hidden until the operator clicks "View All". For a heavily-tagged Term (50+ tags), this is the typical case.
- **Defect 4**: separation-of-duties bypass; multi-team deployments expecting `TAG_CREATE` to gate tag creation leak via TermsForm. Same architectural pattern as namespace-create bypass on PLT-059 Defect 2 — both are "soft-create on read-binding" patterns from the F-002 batch K family.

Severity is HIGH (Defect 4 is the RBAC bypass — security-relevant on multi-team deployments; Defect 3 is the visible prioritisation bug that operators encounter every day on heavily-tagged Terms).

## Suggested fix

### PR-1 — React correctness (Defects 1 + 3)

**Defect 1 — one-line key change:**

```tsx
// TermQueryExamples.tsx:48-55
- {queryExamples.map((qe) => <TermQueryExampleRow key={qe.definition} ... />)}
+ {queryExamples.map((qe) => <TermQueryExampleRow key={qe.id} ... />)}
```

**Defect 3 — sort then slice (both paths):**

```tsx
// OverviewTags.tsx:47-49
- tags.slice(0, visibleLimit).sort(tagsCompare)
+ [...tags].sort(tagsCompare).slice(0, visibleLimit)

// OverviewTags.tsx:62-64
- tags?.slice(visibleLimit).sort(tagsCompare)
+ [...(tags ?? [])].sort(tagsCompare).slice(visibleLimit)
```

The spread copy is needed because `Array.prototype.sort` mutates in place; otherwise the React state could be mutated.

### PR-2 — Silent-failure handler (Defect 2)

**Defect 2 — add `.catch`:**

```tsx
// AssignTermQueryExampleForm.tsx:32-41
mutateAsync(...)
  .then(...)
+ .catch((err) => {
+   setError(serializeBackendError(err));
+   // render in dialog's existing Alert slot
+ });
```

Coordinate with PLT-059 Defect 4 — same shape; both can share a `useFormErrorHandler()` hook for cross-form consistency.

### PR-3 — Tag-create RBAC (Defect 4)

**Defect 4 — split TERM_TAGS_UPDATE from TAG_CREATE:**

Mirror the PLT-059 Defect 2 fix for namespace-create:

```tsx
// TagsEditForm.tsx
<TagsAutocomplete
  restrictToExisting={!hasPermission(TAG_CREATE)}
  onNovelInput={(name) => setShowCreateTagPrompt(true)}
/>
{showCreateTagPrompt && (
  <CreateTagDialog
    permission={TAG_CREATE}
    onCreated={(tag) => addTag(tag)}
  />
)}
```

Backend hardening: `tagService.getOrCreateTagsByName(names)` consults `TAG_CREATE` per novel name; throws `ForbiddenException` if absent.
