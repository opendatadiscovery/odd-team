- **REFACTOR-414** (NEW 2026-05-19O; CONSOLIDATES REFACTOR-079 from batch B): IngestionDataEntitiesFilter token comparison uses `String.equals` — NOT constant-time. The 40-character alphanumeric token has 238 bits of entropy (~2.4e71 search space) so brute-force is infeasible, but the principle is violated; the token is also stored at-rest as plaintext in PostgreSQL (REFACTOR-048)

  - **Statement**: `IngestionDataEntitiesFilter.java:56` uses `dto.tokenPojo().getValue().equals(token)` — plaintext `String.equals`, NOT `MessageDigest.isEqual` (not constant-time) and NOT a hash comparison. Timing-based token discovery on a low-latency network is theoretically feasible: an attacker measures response time difference between "incorrect first byte" (fast rejection) and "correct first byte, incorrect second byte" (slower rejection due to string traversal). For a 40-char alphanumeric token the search space is large (62^40 ≈ 2.4e71), but the principle is violated. The token is also stored at-rest as plaintext in PostgreSQL via `RandomStringUtils.randomAlphanumeric(40)` (REFACTOR-048) — a DB-read attack (read-only SQL injection elsewhere in the platform) would yield live ingestion tokens.
  - **Evidence**: `IngestionDataEntitiesFilter.java:56` (`String.equals` — not constant-time) + REFACTOR-048 (plaintext-at-rest companion)
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-017 (collector token rotation semantics + plaintext-equality stance) — the maintainer's stance is "shared secret + TLS + long-random = sufficient". The constant-time gap is the documented cost of that stance; the fix is to use `MessageDigest.isEqual` or a hash-then-compare model.
  - **Proposed remedy**: Replace `String.equals` with `MessageDigest.isEqual(expected.getBytes(UTF_8), actual.getBytes(UTF_8))` — constant-time comparison. Optionally hash tokens at rest (move from `String.equals` to BCrypt.matches) — but this requires schema migration + breaks current rotate-and-return-plaintext semantics. The constant-time fix is one-line; the at-rest hash is structural.
  - **Severity rationale**: MEDIUM — theoretical attack vector; bounded by entropy + TLS. Defensive code hygiene rather than active threat.
  - **Suggested backlog grouping**: `Ingestion hardening sprint` (paired with REFACTOR-048 plaintext-at-rest + REFACTOR-079 timing-side-channel — consolidate into one shared-secret-stance review batch)
