## Description

The Layer-4b reflection over the AlertManager Integration + global Alerts read surface (F-007) surfaced three net-new operator-facing caveats the live alerting docs do not name. The security spine of F-007 (unauthenticated webhook, forge-and-display, XSS, idempotency) is already covered by PLT-014 + DOC-179; the "All"-tab name-drift is filed as PLT-121. This item covers only the three **net_new** operator caveats below.

## Acceptance Criteria

- [ ] **AlertManager `status=resolved` is silently dropped** (F-007 H-005): document that the platform's hand-rolled inbound DTO carries only `labels` / `generatorURL` / `startsAt` — the AlertManager v2 fields `status` (firing|resolved), `endsAt`, `annotations`, `fingerprint` are dropped by Jackson. Every inbound alert is created OPEN and there is no path that consumes the resolve signal, so an operator who sets Prometheus `send_resolved: true` finds ODD never auto-closes the alert. Recommend `send_resolved: false` (the resolve must be manual or via the in-platform auto-resolve). Evidence: `AlertManagerController.java:28-32` + `ExternalAlert.java:9-15`; `AlertServiceImpl.java:177, 179`.
- [ ] **The webhook ingress is unaudited** (F-007 H-009): document that only the alert STATE transitions are audited (an `OPEN_ALERT_RECEIVED` Activity event) — the ingress POST itself records no request-level log, no `@Timed` counter, no correlation-id of WHO POSTed. After a forged-alert incident an operator cannot reconstruct the source from ODD telemetry and must correlate with reverse-proxy/ingress logs. Evidence: `AlertManagerController.java:21-26`; `AlertServiceImpl.java:309-325` (the audited state-transition half). Cross-link the F-006 audit-silence family.
- [ ] **Orphan alerts (no `entity_oddrn`) inflate the open-alert total** (F-007 H-010): extend the existing config-page orphan note — an alert POSTed without `entity_oddrn` is accepted with 204 and persisted with a NULL FK, invisible on every UI surface YET counted in the platform-wide open-alert total (`countAlertsWithStatusOpen` has no entity-FK predicate), so the badge can read higher than the sum of visible alerts. Evidence: `AlertServiceImpl.java:178` + `AlertManagerController.java:25`.
- [ ] `Sources:` footer cites each `file:line @ ede5d277` above and the F-007 reflection (`lineage/odd-platform/feature-reflections/detail/F-007.yaml` H-005/H-009/H-010).
- [ ] Live-site Gate 8 post-merge: WebFetch `docs.opendatadiscovery.org/features/active-platform-features/alerting` and `.../configuration-and-deployment/odd-platform` and confirm the caveats render.
