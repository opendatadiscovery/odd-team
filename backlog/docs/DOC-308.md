## Description

The actuator/env exposure caveat on `odd-platform.md` (in the "Management endpoint exposure and credential hygiene" section, ~`:106`) states that the platform configures `management.endpoint.env.show-values: WHEN_AUTHORIZED`. The same attribution is replicated in the workspace backlog framing of **DOC-242** (`:30` — "enables `endpoint.env.enabled=true` with `show-values=WHEN_AUTHORIZED`") and **DOC-239** (`:27` — "`application.yml:226-242` enables ... `show-values=WHEN_AUTHORIZED`").

Verified against `odd-platform/odd-platform-api/src/main/resources/application.yml` @ `ede5d277`: the `management.endpoints` block enables `endpoint.env.enabled: true` (`:237-238`) but sets **no `show-values` key at all**. Spring Boot's default for `management.endpoint.env.show-values` is `NEVER`. So the explicit `WHEN_AUTHORIZED` attribution is not in the configuration, and the exact value-exposure behaviour described downstream (e.g. "returns the JDBC URL verbatim") depends on the resolved default, not on a `WHEN_AUTHORIZED` setting.

This is a factual-provenance (Gate 9) inaccuracy on a **security-posture** claim, replicated across one published page and two backlog items — the parallel-surface-drift-of-a-wrong-fact pattern.

**Failure shape**: factual inaccuracy (phantom config value) on a security caveat, replicated across surfaces.
