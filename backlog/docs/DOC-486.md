## Description

On `docs/active-platform-features/alerting.md`, the **## Known UX limitations** section opens (line ~202) by
framing every item as a *current* gotcha:

> "A handful of behaviours on the Alerts UI surface that operators encounter in normal use … Each item below
> states what an operator might assume and **what the UI actually does today**."

But the `{% hint style="info" %}` at lines ~206-208 now describes behaviour that **works correctly** (after
odd-platform#1803 / CTRIB-034 + the PLT-005 retention-caveat correction):

> "**Resolving or reopening an alert asks for confirmation, and the per-entity tab reflects the change without
> a refresh.** … The change is also recoverable: a resolved alert is retained for the full `resolved_alerts_days`
> window …, so you can **Reopen** it before the window elapses."

A positive feature note describing a *working* safeguard reads incongruously inside a section whose stated
purpose is current limitations/gotchas. This is a side-effect of how the fix was documented: the pre-#1803
warning (a real limitation — "no confirmation dialog") was **converted in place** (`warning`→`info`) rather than
relocated or removed, and the PLT-005 follow-up then refined the text in place.

Per Cornerstone 5 (one canonical home per content type) a *working feature* belongs in the feature narrative,
not in a limitations section.

## Recommended fix direction (pick one)

- **(a) Remove the info-hint.** The limitation is resolved; a *new* operator reading the published manual does
  not need the history that the platform once lacked a confirmation dialog. The recoverable-via-Reopen fact is
  already carried by the [Auto-cleanup of resolved alerts](#auto-cleanup-of-resolved-alerts) section it links to.
- **(b) Relocate the safeguard description** into the main **## Alert lifecycle: statuses, resolution, cleanup**
  narrative (near line ~101, the `RESOLVED` row / the Resolve action), framed as a feature: "Resolve/Reopen open
  a confirmation dialog; the per-entity tab reflects the change in place."

Either way the **## Known UX limitations** section is left holding only genuine current limitations (the
user-owner-association tab-visibility note and the Notification-Settings optimistic-concurrency note).
