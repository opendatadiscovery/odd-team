## Description

The read-posture caveat on `sla-statuses.md` (~`:48`) enumerates several per-dataset DQ endpoints, two of which have wrong path strings (verified against the platform OpenAPI spec @ `ede5d277`):

1. `GET /api/dataentities/{data_entity_id}/datasetstests` — does not exist. The DQ-tests endpoint is `GET /api/datasets/{data_entity_id}/dataqatests` (`openapi.yaml:1932`, `operationId getDataEntityDataQATests`; served by `DataQualityController.getDataEntityDataQATests`). The caveat has the wrong resource root (`dataentities` vs `datasets`) **and** wrong segment (`datasetstests` vs `dataqatests`).
2. `GET /api/datasets/{data_entity_id}/test_reports` — mis-pluralised. The spec path is singular `test_report` (`openapi.yaml:1915`, `getDatasetTestReport`).

(The other two paths in that caveat — `/sla` `openapi.yaml:1880` and `/sla_report` `:1898` — are correct, and were the in-scope subject of DOC-307.)

**Failure shape**: factual inaccuracy (wrong API path strings) on a caveat — an integrator copying these hits 404s.
