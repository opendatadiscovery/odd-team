## Description

`Overview.tsx` is the SPA home shell — the operator's first surface after login (F-141). Its `return` block (`Overview.tsx:44-60`) composes six independent widgets in a fixed vertical sequence — `MainSearch` (line 47), `TopTagsList` (line 49), `Domains` (line 50), `DataEntitiesUsageInfo` (line 51), `Directory` (line 52), and the conditional `OwnerAssociation` (lines 53-59) — directly under a single `<S.Container>` with **no intermediate IA wrapper**: each band carries its own heading/typography (F-141 facet `domains_widget_renders_under_full_owner_association_subtree_visually_competes_with_recommended_panel`). The page lifts its skeleton after only `isIdentityFetching || isTagsFetching` resolve (`Overview.tsx:29-32`), so the other four widgets self-load.

The behaviour to guard: **the home shell composes its full six-band set in the fixed sequence, with no IA wrapper collapsing or re-ordering them**, and the skeleton path is taken while identity/tags load. A refactor that drops a band, re-orders the composition, or wraps the bands in a conditional container would silently change the operator's first impression with the build still green at the unit tier.

TYPED GATE: **validates-feature** (F-141-UC-01, the composition promise). NB this is NOT a duplicate of the existing e2e smoke — `integration-tests/e2e/specs/catalog-overview-home.spec.ts` (IT-071) already asserts that three of the six surfaces (MainSearch hero box + DataEntitiesUsageInfo "Total entities" card + Directory strip + a top tag) compose on the live `/` route. This item is the **unit/RTL-tier** complement: a fast, deterministic mount that asserts all six bands (the three IT-071 omits — `TopTagsList`, `Domains`, `OwnerAssociation` — plus the three it covers) render in the documented order with no IA wrapper, and the loading-skeleton branch. F-141's `test_matrix.unit` is `state: GAP` with zero covered cells; this fills the composition cell.
