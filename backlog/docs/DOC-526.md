## What

**Failure shape: cross-audience absence.** `docs/developer-guides/api-reference.md` lists ten per-feature pages
under `## Per-feature endpoints` — Alerts, Data Collaboration, Directory, GenAI, Glossary, Integrations, Lineage,
Query Examples, Reference Data, Relationships (`api-reference.md:11-20` on `origin/release/1.0.0`). There is **no
Search page**, and `git ls-tree origin/release/1.0.0 docs/developer-guides/` confirms no
`api-reference/search.md` exists.

The asymmetry is stark: the *Glossary* page documents term faceted search, the *Reference Data* page documents
Lookup-Table search — but the catalog search, the platform's headline feature and the one every operator meets
first, has no developer-audience page at all. The operator-facing page (`data-discovery/search.md`) is the only
surface, and by Gate 10 / Cornerstone 5 it must **not** grow endpoint tables to compensate.

## Why now (what changed)

The absence is old — the legacy session search (`POST /api/search`, `GET /api/search/{id}/results`) was never
documented in the API reference either. **1.0.0 widens it materially**: the `#1825` overhaul ships an entirely
new, direct-API-callable surface that no page describes.

* `POST /api/search/assets` — the unified cross-kind request. Body `AssetSearchFormData`: `query` (with the
  operator grammar documented on `search.md`), `filters` (eight facet dimensions), `sort`, the My-data scope
  group (`my_data` + `upstream_depth` / `downstream_depth`, plus the deprecated `my_objects`), `asset_kinds`
  and `favorites`. Cursor pagination (`next_cursor`) plus `scope_truncated` / `scope_truncation_reason` on the
  response — an operator consuming this API needs to know that a truncated scope is a *partial* result set.
* `GET/POST/PUT/DELETE /api/saved_searches` — the ST-3 saved-search CRUD. From `odd-platform#1878`
  (CTRIB-065) the stored `spec` is the **full `AssetSearchFormData`**, so a client can save exactly the request
  it runs; an absent `favorites` / `asset_kinds` stays absent and must never be defaulted to `false` / `[]` by a
  client. Nothing on the site says any of this.
* The facet/count endpoints the Filters panel drives.

Direct API callers are a real audience for this surface (the api-reference exists precisely for them, and every
smaller feature area is served). Today they have the Swagger UI and nothing else — and Swagger UI itself is
currently broken on the platform (`issues/odd-platform/PLT-141`), so the fallback does not hold.

## Acceptance Criteria

- [ ] `docs/developer-guides/api-reference/search.md` created **on the `release/1.0.0` train**, matching the
      shape of its ten siblings (a lead paragraph naming the audience + the endpoint table with method / path /
      operationId / one-line purpose, then the request-schema detail and the caveats).
- [ ] The unified request documented: `POST /api/search/assets`, the full `AssetSearchFormData` field list, and
      the three degrade-gracefully contracts the spec deliberately encodes — an unknown `sort` falls back rather
      than 400s, an unknown `my_data` token is dropped, an out-of-range depth is CLAMPED into [1,3] (a
      wrong-JSON-type value is still rejected). These are documented in the spec descriptions and nowhere on the
      site.
- [ ] `scope_truncated` / `scope_truncation_reason` documented as a **completeness** signal, not a warning:
      `NODE_CAP` returns a deterministic prefix (a shareable URL re-runs identically), `TIMEOUT` means **no**
      scope was applied. An API client that presents a truncated set as complete makes a false governance claim.
- [ ] Saved searches documented: the four CRUD endpoints, per-user scoping (the row is keyed on the
      authenticated identity, and under `auth.type=DISABLED` all callers share one bucket), the unique-name-per-user
      constraint (a duplicate is a clean 4xx, never a 500), and the `spec` contract **as widened by #1878** — the
      full `AssetSearchFormData`; an unset `favorites` reads back `null` and must never be sent as `false`
      (`false` is a real filter: only un-starred assets).
- [ ] The lenient stored-spec read stated as a contract, not an accident: a stored `asset_kinds` token that no
      longer exists is dropped from that one field on read; a structurally unreadable spec degrades to the empty
      spec rather than 500-ing the list.
- [ ] The legacy session search (`POST /api/search` + `GET /api/search/{search_id}/results`) documented as
      **deprecated-but-live**, with the one-line statement of what it does NOT honour (`my_data`, `asset_kinds`,
      `favorites` — unified-path-only by design, ADR `unified-asset-search` D9), so a caller reading only this
      page cannot pick the wrong endpoint.
- [ ] `api-reference.md`'s `## Per-feature endpoints` list gains one alphabetically-placed bullet, and
      `SUMMARY.md` gains the matching child entry in the same order (Gate 7).
- [ ] `data-discovery/search.md` gains a one-line pointer to the new page (and grows **no** endpoint table —
      Gate 10).
- [ ] Frontmatter `description` <= 200 chars with no `: ` hazard (PyYAML-checked before commit).
- [ ] Live-verified at the 1.0.0 release gate against the URL above.
