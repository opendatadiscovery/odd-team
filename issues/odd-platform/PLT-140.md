## What

Two backend defects break the Term Detail page's **Linked Terms** reverse-lookup tab:

1. **`GET /api/terms/{term_id}/term` returns HTTP 500/405 at runtime and the tab hangs (F-152/H-002).** The `/term` path stem is overloaded with the link/unlink **write** verbs, so the reverse-lookup **read** does not resolve to a working handler - the Linked-Terms tab issues the request and hangs.
2. **`TermServiceImpl.listByTerm` hardcodes `hasNext=false` / `total=items.size()` (F-152/H-006).** Pagination is faked: the response always claims there is no next page and that the total equals the current page size. A term with 51+ linked terms silently truncates at the first page - terms #51+ are **unreachable** through the UI's infinite scroll. This is the LSN-024 silent-truncation class.

These are **backend** defects. The Term-Detail **UI** epic PLT-058 covers the UI side of the reverse-lookup tabs (LinkedColumnsList `next={() => {}}` no-op pagination at Defect 4; LinkedTermsList synthesised `status:500` at Defect 5). The two defects here are the server-side root: even a correct UI cannot page past 50 linked terms because the backend never reports `hasNext=true`, and the reverse read endpoint itself errors.

## Why it matters

The Linked Terms tab is a primary navigation surface of the Business Glossary. A term that participates in a rich term-to-term graph (the exact case the feature is built for) silently shows only its first 50 links and the reverse-lookup tab can hang outright - operators conclude the links do not exist (LSN-024 silent-truncation: the UI promises more but the backend refuses to deliver). Severity HIGH: it is reachable in any deployment with >50 term-to-term links and on every reverse-lookup tab open; the truncation is invisible (no error, no "showing 50 of N" affordance).

## Suggested fix

1. **Real pagination in `listByTerm`** - compute `total` from a COUNT and `hasNext` from `offset + items.size() < total`, mirroring the working `useInfiniteQuery` pattern the sibling endpoints use. (Pairs with PLT-058 Defect 4 on the UI side.)
2. **Disambiguate the `/term` path stem** - give the reverse-lookup read a non-overloaded route (e.g., `GET /api/terms/{term_id}/linked-terms`) distinct from the link/unlink write verbs, or fix the routing so the read resolves to a working handler returning 200.
3. Add an integration test (contract / WebTestClient) asserting page 2 is reachable when >50 links exist (LSN-024 regression anchor).
