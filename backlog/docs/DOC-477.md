## Description

Editorial coherence finding from the CTRIB-026 `/review` doc-product audit (failure shape: **code-doc
drift** — a published doc claim contradicted by a shipped UI relabel on the same surface).

`data-quality/dashboard.md:48` enumerates the Quality Dashboard's filter dimensions as:

> Filter the dashboard by five dimensions: **Namespace**, **Datasource**, **Owner**, **Title**, and **Tag**.

But the dashboard's "Title" filter was **deliberately relabeled to "Owner title"** in odd-platform
(`#1767` / CTRIB-011). The fix's own test states the rationale verbatim
(`odd-platform-ui/src/components/DataQuality/DataQualityFilters/FilterItem/__tests__/TitleFilter.test.tsx:9-10`):

> The bare label `t('Title')` reads as the dataset title and silently misleads operators. The filter
> must be labelled "Owner title".

So the doc now reproduces the exact ambiguity the UI fix removed — an operator reading the manual still
sees "Title" and infers the dataset title, while the running UI says "Owner title" (the owner's role /
title). VERIFIED via the UI source (the relabel + its test) cross-checked against `dashboard.md:48`.

## Proposed fix

- `dashboard.md:48`: change the dimension name "Title" → "Owner title" (matching the shipped UI label),
  e.g. "Namespace, Datasource, Owner, Owner title, and Tag." Confirm against the live filter chips when
  driving the page for live-site verification.
