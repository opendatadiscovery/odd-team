## Description

`docs/active-platform-features.md` L41 currently reads:

> For the API surface behind the six subsystems → see [API Reference](developer-guides/api-reference.md). Per-subsystem sub-pages: [Alerts](developer-guides/api-reference/alerts.md), [Data Collaboration](developer-guides/api-reference/data-collaboration.md). The Activity Feed, GenAI, Metrics Ingestion, and notifications dispatch APIs are documented inline on each active-platform-features sub-page where they apply.

The classification of **GenAI** as inline-only is incorrect:

1. **`docs/developer-guides/api-reference/genai.md` exists** as a dedicated per-subsystem sub-page (10 files in `developer-guides/api-reference/`: alerts, data-collaboration, directory, **genai**, glossary, integrations, lineage, query-examples, reference-data, relationships).
2. **`docs/SUMMARY.md` L109** lists `* [GenAI](developer-guides/api-reference/genai.md)` as a peer sub-page under API Reference (between Data Collaboration and Glossary).
3. **`docs/developer-guides/api-reference.md` L14** explicitly enumerates GenAI on its "Per-feature endpoints" index: `* [**GenAI**](api-reference/genai.md) — the single POST /api/genai/ask endpoint…`.

The correct enumeration of per-subsystem API-reference sub-pages for the six active-platform subsystems is **three**, not two:

| # | Subsystem | Dedicated api-reference sub-page | Inline API on subsystem feature page |
|---|---|---|---|
| 1 | Alerting | ✅ `developer-guides/api-reference/alerts.md` | — |
| 2 | Notifications | — | ✅ `active-platform-features/notifications.md` (POST `/ingestion/alert/alertmanager`) |
| 3 | Activity Feed | — | ✅ `active-platform-features/activity-feed.md` (DEG-membership endpoints) |
| 4 | Data Collaboration | ✅ `developer-guides/api-reference/data-collaboration.md` | — |
| 5 | GenAI | ✅ `developer-guides/api-reference/genai.md` | ✅ `active-platform-features/genai.md` H2 `## Platform endpoint` (parallel surface) |
| 6 | Metrics Ingestion | — | ✅ `active-platform-features/metrics-ingestion.md` (POST `/ingestion/metrics`, GET `/api/dataentities/{id}/metrics`) |

GenAI is the special case: its API surface appears on **both** a dedicated sub-page AND inline on its subsystem feature page (the feature page's `## Platform endpoint` H2 carries the same operation table). The L41 reframe must acknowledge both surfaces — moving GenAI into the "Per-subsystem sub-pages" list while keeping the inline-pointer accurate.

**Failure shape**: parallel-surfaces drift / cross-page reference incompleteness (axis A4 — Reference integrity). The pre-existing classification was authored on 2026-05-06 (DOC-131 created the page) when `developer-guides/api-reference/genai.md` did not yet exist. Commit `0eb0ed1` (DOC-161 + DOC-184 + DOC-204, 2026-05-07) added the dedicated GenAI api-reference sub-page but did not back-update L41 of `active-platform-features.md`. DOC-282 (2026-05-28) extended L41's inline-API enumeration to include Metrics Ingestion but did not catch the stale GenAI classification.

This is the same drift shape as DOC-282 itself (a separate feature shipped — the api-reference subtree's GenAI sub-page — without back-updating the per-pillar landing narrative).
