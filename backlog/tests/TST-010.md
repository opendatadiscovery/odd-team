## Description

When a user posts a message to a data-entity's Discussions/Collaboration thread, the list re-fetch that should surface the new message is keyed on the *message-creating* loading flag flipping, not on the new message landing in the redux store — so the refetch can race AHEAD of the new row and the just-sent message is missing until the next render.

In `DataCollaboration.tsx`:

```ts
const { isLoading: isMessageCreating } = useAppSelector(           // :31-33
  getMessageToSlackCreatingStatuses
);

React.useEffect(() => {
  dispatch(
    fetchDataEntityMessages({ dataEntityId, channelId, size, lastMessageId: lastId })   // :37
  );
  return () => { dispatch(clearCollaborationState()); };
}, [dataEntityId, channelId, isMessageCreating]);                  // :43 — dep on the CREATING flag
```

The effect re-runs whenever `isMessageCreating` changes — i.e. when the create-message request *starts and finishes*. But the refetch reads `lastMessageId: lastId` (a paging cursor from `getDataEntityMessagesPageInfo`, `:27`) and `lastId` is NOT in the dependency array, while the redux slice that actually holds the created message is not chained to this fetch's completion. The reload can therefore fire on the `isMessageCreating: true → false` transition before/independently of the created message being merged into `getDataEntityMessages`, producing an off-by-one where the just-sent message is absent from the rendered list.

**Typed gate: characterization-pin (LSN-029).** This pins the CURRENT effect-dependency wiring (refetch keyed on `isMessageCreating`, `lastId` absent from the dep chain, slice-completion not awaited). The end-to-end "message visible after send" reproduction is probe-gated (PENDING-F-038-1 — Playwright against local docker-compose). The unit pin asserts the observable wiring fact — the effect's dependency list and that the dispatched fetch carries the stale-cursor arguments rather than a slice-keyed trigger — and goes RED when the fix lands (refetch keyed on the created-message slice / cursor, not on the creating flag).
