# ODDOAuth2Properties (prefix `auth.oauth2`) — semantic understanding

## understanding

`ODDOAuth2Properties` is the typed POJO that Spring binds the `auth.oauth2.*`
configuration namespace into when ODD Platform runs in OAuth2 authentication
mode. The class itself holds a single field — `Map<String, OAuth2Provider> client`
— so operators register one logical OAuth2/OIDC client per map key (e.g.
`auth.oauth2.client.azure.*`, `auth.oauth2.client.google.*`); the nested static
`OAuth2Provider` class is the per-client schema with 21 fields covering Spring
OAuth2 client-registration plumbing (`clientId`, `clientSecret`, `scope`,
`issuerUri`, …) and ODD-specific extensions (`adminPrincipals`, `adminGroups`,
`adminAttribute`, `adminUserInfoFlag`, `allowedDomain`, `organizationName`,
`logoutUri`, `pkce`). The class also runs a minimal `@PostConstruct` validator
that fails boot if any client is missing `clientId` or `provider` — but no
other field (including provider-required ones like Azure `logoutUri`) is
validated, and there is no enum-typed constraint on `provider` so any string
flows through.
