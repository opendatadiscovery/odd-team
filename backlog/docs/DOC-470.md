## What

The published Lookup Tables page carried two "until the upstream fix lands" caveats that #1753 /
CTRIB-023 fixes in 0.29.0:

1. **List truncation at 30 rows** (the `scrollableTarget` DOM-id bug) - fixed by D1.
2. **Rename emits no Activity Feed event** (the audit silence) - fixed by D2 (`LOOKUP_TABLE_RENAMED`).

Both caveats become factually wrong the moment 0.29.0 ships. They have been retired on the
documentation `release/0.29.0` train branch (commit fb03ce3 - "docs(lookup-tables): retire the
list-truncation + rename-audit-silence caveats"); they publish to docs main + go live when 0.29.0
releases, per the release-train gating (the live manual describes the latest RELEASED version, so the
caveats correctly stay live until then).

## Explicitly KEPT (not retired)

The **rename-break caveat** ("Renaming a Lookup Table silently breaks every downstream BI / ETL
pipeline" - the destructive `ALTER TABLE ... RENAME TO` on the public schema) is NOT fixed by #1753 and
REMAINS a live operator caveat. The audit-silence caveat referenced it ("amplifies the blast radius");
removing the audit-silence block leaves the rename-break block intact and self-contained.
