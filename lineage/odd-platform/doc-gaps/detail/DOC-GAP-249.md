       > "**Query syntax**. The search bar accepts free-text input that the platform converts into a PostgreSQL `to_tsquery` prefix-match expression. The conversion splits the input on whitespace, appends `:*` to each token, and joins with `&`. Example: typing `customer order` produces the tsquery `customer:* & order:*`.
       >
       > **Reserved characters**: the tsquery language treats `!`, `(`, `)`, `:`, `&`, `|`, `<->`, `'`, `\\` as metacharacters. Including any of these in your search query may produce unexpected results or break the session:
       > - `!`, `&`, `|` — interpreted as tsquery logical operators (NOT / AND / OR)
       > - `(`, `)` — interpreted as tsquery grouping
       > - `:`, `:*`, `<->` — interpreted as tsquery weight / prefix / phrase operators
       > - `'`, `\\` — interpreted as SQL literal delimiters
       >
       > **Avoid these characters** until [a future release](https://github.com/opendatadiscovery/odd-platform/issues/REFACTOR-229) introduces query-text escaping. A query containing reserved characters may poison the session: the session URL `/search/{uuid}` returns broken facet reads permanently until the session expires (default 30-day TTL).
       >
       > **Operator workaround**: if a shared session URL stops working unexpectedly, the recipient should navigate to `/search` (without the UUID) to create a fresh session. **Operator security note**: do not click `/search/{uuid}` links from untrusted sources — a malicious sender can poison a session and use the URL as a denial-of-service vector against the recipient's catalog browsing."
