## What

Five UX defects on the alerting surface that together make alerts impractical at scale. Each is small in isolation; together they push operators to direct API calls. Doc-side mitigation (DOC-200 + DOC-201) names these as known limitations today.

**Defect 1 — Per-entity Alerts tab hardcoded `size=30`, no filter UI, no export.** `DataEntityAlerts.tsx:31` hardcodes `size = 30`; lines 78-80 render with no filter / sort / status selector. The audit-export workaround documented at the API has no UI affordance.

**Defect 2 — Bare-`/alerts` auto-redirect lands users on cross-owner All tab.** `AlertsRoutes.tsx:18` declares `<Route path='/' element={<Navigate to='all' replace />} />`. Every user — including unprivileged users — lands on `/alerts/all` (cross-owner). Combined with hidden My/Dependents tabs, the All tab is the ONLY visible tab.

**Defect 3 — AlertsTabs `hidden` hides UI tabs but backend routes remain navigable.** `AlertsTabs.tsx:30, :36` — `hidden: !showMyAndDepends` on My/Dependents tabs. Routes `/alerts/my` and `/alerts/dependents` REMAIN mounted in `AlertsRoutes.tsx:10-21`. URL-known users reach them; page renders empty (no user_owner_mapping) — visually indistinguishable from "no alerts."

**Defect 4 — Global Alerts list has no filter UI.** `AlertsList.tsx:37-108, :72` — no status / type / date / entity-name filter; hardcoded size=30. Sibling Activity page has 7-facet filter panel; Alerts has nothing.

**Defect 5 — Global Alerts list has no bulk-resolve, no export, no search-by-entity-name.** `AlertsList.tsx:83-107` — no bulk-select scaffolding; `AlertItem.tsx` is a single-row Resolve.

## Why it matters

Alerts are an operator's primary diagnostic surface. The five defects compound: doc-recommended audit-export workaround cannot be exercised through the UI; unprivileged users land on the cross-owner feed; shared links to `/alerts/my` reach empty pages with no diagnostic; teams with hundreds of open alerts cannot scan by status / type / entity / time.

## Suggested fix

**Defect 1** — status filter on per-entity tab + page-size selector + Export button on the API workaround.

**Defect 2** — `AlertsDefaultRedirect` component reading `getOwnership`:
```tsx
- <Route path='/' element={<Navigate to='all' replace />} />
+ <Route path='/' element={<AlertsDefaultRedirect />} />
// ownership present → 'my'; otherwise 'all'; /alerts/my surface gets empty-state CTA
```

**Defect 3** — guard `/my` and `/dependents` with a render-block when ownership absent.

**Defect 4** — Filters component analogous to Activity (minimum: status + type).

**Defect 5** — bulk-select + bulk-resolve UI (backend already supports per-alert PUT; per-row permission re-check).
