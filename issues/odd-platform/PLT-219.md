## What

`ReactiveRelationshipsRepository.getRelationshipByDataEntityIds(List<Long>)` (interface +
implementation in `ReactiveRelationshipsRepositoryImpl`) has zero callers in main code: a
grep over `odd-platform-api/src/main/java` for the method name matches only the interface
declaration and the implementation. No controller, service, or other repository invokes it.

## Where

```
odd-platform-api/src/main/java/org/opendatadiscovery/oddplatform/repository/reactive/ReactiveRelationshipsRepository.java:12
odd-platform-api/src/main/java/org/opendatadiscovery/oddplatform/repository/reactive/ReactiveRelationshipsRepositoryImpl.java:76-83
```

## User-facing impact

None (dead code). Maintenance cost only: the method reads as a live query surface during
audits (it was individually verified during the #1752 visibility-predicate work) and would
silently miss future predicate alignments since no behaviour depends on it.

## Suggested fix

Delete the method from the interface and the implementation. If a future bulk-fetch need
arrives, it can be reintroduced with the then-current visibility semantics.

## How discovered

CTRIB-006 (the #1752 Relationships-hardening contribution) enumerated every read path of
the relationships repositories to scope the default-visibility fix; this method came back
caller-less. Deliberately excluded from that PR (G-C5 bounded diff).
