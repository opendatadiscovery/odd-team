## Description

The business-glossary page documents (`business-glossary.md:185`) that on the Term-side reverse panels, auto-linked (description-mention) rows are visually distinct and that "the platform's read-time de-duplication prefers the auto-linked variant" when a (term, entity) pair has both a manual link and a description-mention link. That de-duplication is **Term-side only**. The dataset-field-by-term path that backs the Term **Linked Columns** tab skips it.

`DatasetFieldServiceImpl.listByTerm` (`DatasetFieldServiceImpl.java:183-188`) maps results straight through with no dedup collapse:

```java
public Mono<DatasetFieldList> listByTerm(final Long termId, final String query,
                                         final Integer page, final Integer size) {
    return reactiveDatasetFieldRepository.listByTerm(termId, query, page, size)
        .collectList()
        .map(datasetFieldListMapper::mapPojos);
}
```

The collapse the doc describes lives in `TermServiceImpl.removeDuplicateNonDescriptionTerms` (`TermServiceImpl.java:444`) and is applied only on the term-side reverse lookups (`TermServiceImpl.java:269` for entity-terms, `:275` for dataset-field-terms) — i.e. the data flowing into the **Term**'s Terms/Linked-Entities surfaces, not the column list rendered by `listByTerm`. Consequently, on the Linked Columns tab: (a) there is no description-mention vs direct-link distinction on the rows, and (b) a dataset field linked to the term both via a `[[namespace:term]]` description mention and via a direct link can surface as a **duplicate row** rather than a single collapsed row.

This misleads because the page's existing dedup note (`:185`) reads as a platform-wide behaviour, when in fact the column tab does neither the dedup nor the badge that the Term-side panels do. An operator reconciling "which columns reference this term" can over-count, and cannot tell a description-driven link from a manual one on this tab. DOC-230 / DOC-231 cover the **Term-side** linked tab; this dataset-field path is untracked. The duplicate-row outcome is a probe-pending observation (`PENDING-F-153-2`) — the code skips the collapse for certain, the exact dual-link UI row count is to be confirmed by probe.
