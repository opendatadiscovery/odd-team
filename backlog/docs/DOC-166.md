## Description

The live page at `docs.opendatadiscovery.org/features/data-discovery/catalog-overview` carries two factual claims that directly contradict the platform's code. Both were verified at primary source during the Mode B scan.

**Contradiction 1 — DISABLED-mode visibility (F-001a).** The page (line 43) states *"on auth-disabled deployments the panel is visible but the per-user filtering does not apply"*. The code at `odd-platform-ui/src/components/Overview/Overview.tsx:25-27` gates the entire `OwnerAssociation` wrapper (which contains the Popular column) on `authType !== 'DISABLED'`. Under DISABLED the Popular column is **hidden from the home page**, not "visible but unfiltered". An operator following the doc to debug "where's my Popular column under DISABLED?" will not find it.

**Contradiction 2 — click-target (F-001b).** The page states *"Clicking a tile opens that entity's Structure page"*. The code at `odd-platform-ui/src/components/Discovery/Result/DataEntityList.tsx:38` + `odd-platform-ui/src/routes/dataEntitiesRoutes.ts:66-73` routes to `/dataentities/{id}/overview` (the **Overview** tab), not `/structure`. BI / analytics tooling simulating user clicks from the documented path will hit the wrong URL.

Both contradictions are operator-misleading by the strongest definition: the published doc describes platform behaviour that the platform does not exhibit.
