- **ADR-CANDIDATE-046** (NEW 2026-05-12D): Housekeeping is intentionally **opt-OUT** — ships `housekeeping.enabled: true` as the verbatim YAML default paired with `@ConditionalOnProperty(havingValue="true")` strict-no-`matchIfMissing` on the `HousekeepingJobManager` bean. The combination produces opt-out semantics for shipped deployments (housekeeping runs by default) AND strict-opt-in semantics when `application.yml` is replaced (no shipped key = no bean = no housekeeping). The deliberate divergence from the ship-disabled-by-default family (ADR-CANDIDATE-004 GenAI / -019 DataCollab / -029 DISABLED / -040 Notifications) codifies "bounded DB growth is the platform's default operational posture; operators must explicitly choose unbounded growth"
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`HousekeepingTTLProperties`) — single occurrence but contract-defining for the platform's default data-retention posture; the maintainer's choice diverges from the cross-feature ship-disabled-by-default convention DELIBERATELY, signalling that DB-growth-bounding is a platform-operational concern (not a feature opt-in)
  - **Surfaced by**:
    - `odd-platform__java__org_opendatadiscovery_oddplatform_housekeeping_config__config-properties-class__HousekeepingTTLProperties.md:implicit_adrs.[2]` ("Subsystem is OPT-OUT (`housekeeping.enabled: true` ships as default in application.yml) — the platform deletes data BY DEFAULT in shipped deployments. The decision favours bounded DB growth over data preservation; an operator must explicitly set `housekeeping.enabled: false` to retain all RESOLVED alerts / soft-deleted entities indefinitely. The opt-out stance is reinforced by the `@ConditionalOnProperty(havingValue = \"true\")` with no `matchIfMissing` — strict opt-in if the key is missing from the YAML, which combined with the shipped application.yml's `enabled: true` produces opt-out semantics for shipped deployments." — intent_anchor: "the `havingValue = \"true\"` literal with NO `matchIfMissing` attribute — explicit strict-opt-in coupled with the shipped YAML default of `true` — the combination is the architectural decision")
  - **Decision statement**: ODD ships with `housekeeping.enabled: true` as the verbatim YAML default in `application.yml:165-166`, paired with `@ConditionalOnProperty(value="housekeeping.enabled", havingValue="true")` (no `matchIfMissing`) on `HousekeepingJobManager.java:18`. The combination is deliberate: (a) shipped deployments inherit opt-out semantics — operators receive automatic 30-day retention on RESOLVED alerts / search-facets / soft-deleted entities WITHOUT configuration; (b) when `application.yml` is replaced (e.g. by `--spring.config.location=` or Spring Cloud Config) WITHOUT re-supplying `housekeeping.enabled`, the strict-no-`matchIfMissing` falls through to no-bean-no-housekeeping — silent disabling that the integration-test profile DELIBERATELY exploits (`application-integration-test.yml:7-8` flips to `false`). The decision codifies a CROSS-FEATURE DIVERGENCE from the ship-disabled-by-default family: heavyweight outbound-integration features (GenAI, DataCollab, Notifications, Auth security) ship off because they require external configuration to function; housekeeping ships ON because bounded DB growth is the platform's default operational posture. The accepted price is REFACTOR-141 (Java-side primitive defaults = 0 if YAML keys are absent — production-class data loss) — the divergence makes housekeeping's "ships ON" stance sharper but also makes the YAML-default-floor more load-bearing for safety.
  - **Wisdom test**: PASS. The verbatim `housekeeping.enabled: true` in `application.yml:166` (not relying on a Java primitive default) PAIRED with the strict `@ConditionalOnProperty(havingValue="true")` (no `matchIfMissing`) is the dual intent anchor — the maintainer wrote BOTH the default ON AND the strict no-`matchIfMissing` guard. The integration-test profile flip to `false` confirms the toggle is structurally exposed. Structural for every future schedule-driven cleanup subsystem decision.
