## Description

The Dataset Quality Statuses (SLA) page describes the `DataSetSLAReport` JSON returned by `GET /api/datasets/{data_entity_id}/sla_report` as carrying "a `sla_ref` **self-link**" (`data-quality/sla-statuses.md` line 25). That label is wrong.

`SLACalculator.getSLAReport(...)` sets the field at `SLACalculator.java:64`:

```java
result.setSlaRef("/api/datasets/%s/sla".formatted(datasetId));
```

`/api/datasets/{id}/sla` is the **PNG-badge sibling endpoint** — the very row above in the same doc table (`sla-statuses.md` line 24) documents `GET /api/datasets/{data_entity_id}/sla` as returning `image/png`. So `sla_ref` is a **cross-link to the PNG badge**, not a self-link back to the `/sla_report` JSON resource. An operator parsing the JSON who reads "self-link" expects to be able to re-fetch the same JSON document from `sla_ref`; following it instead returns a binary PNG, which silently breaks any client that treats the link as a JSON re-fetch / HATEOAS self relation.

This is a precision fix on a single live published surface — low severity, but actively misleading about what the link resolves to.
