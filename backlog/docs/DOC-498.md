## Description

An outside contributor (PR #1864) built manual term-to-term links into a genuinely bi-directional
relation, and cited **our published manual as the specification** for doing so:

> `business-glossary.md:74` — "The link is bi-directionally visible: it appears on both terms' pages and
> can be removed from either side."

Verified against `odd-platform` at the time of review: the second half of that sentence was **not true**
of any released version. A manual link is stored as one directed row (`assigned -> target`); the Overview
TERMS panel reads `target = X` while the Linked-terms tab and badge read `assigned = X`. So the link did
appear on both terms' pages, but in *different* surfaces — and only the Overview carries a delete
affordance (PLT-235), so it was removable **only from the side it was created on**.

This is a Gate 9 / Gate 4 miss on our side, not the contributor's: we published a behavioural claim that
no consumer-read supported, and it stood on the live site through 0.27.x, 0.28.0 and 0.29.0. It is the
`LSN-002` shape — a claim written from intent rather than from the code that enforces it.

The claim is **not** being edited, because #1864 (merged 2026-08-30, `00b03129`) makes it true from 1.0.0. Editing the
live text to describe the 0.29.0 behaviour and then editing it back at 1.0.0 would be two changes to land
in the same state. The residual exposure is the window until 1.0.0 ships, on a low-severity UX claim that
has already been live and wrong for three releases.

## Acceptance

- [ ] At the 1.0.0 release gate (`playbooks/release-review.md` check 4), fetch both live URLs above and
      confirm the bidirectional sentences now describe shipped behaviour — a manual term link created from
      either term's page is visible **and removable** from both.
- [ ] Confirm on the released 1.0.0 instance, not from source: create a term link from term A, then remove
      it from term B's page.
- [ ] Confirm the description-link wording still reads correctly — #1864 deliberately keeps description
      links directional ("references" vs "referenced-by"), so any prose implying description links are
      also symmetric would now be the wrong claim.
- [ ] If PLT-253 (the duplicate-render follow-up) is still open at the gate, check that the page does not
      promise a de-duplicated list.

## Fallback — if #1864 does NOT ship in 1.0.0

Correct both pages instead: state that a manual link appears on both terms' pages but is removable only
from the term it was created on, and drop "can be removed from either side". Route the correction on the
documentation `release/{version}` train for whichever release is then current.
