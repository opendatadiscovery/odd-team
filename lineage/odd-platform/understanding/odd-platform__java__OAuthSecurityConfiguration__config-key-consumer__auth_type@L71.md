# auth.type=OAUTH2 gate on OAuthSecurityConfiguration.java:71 — semantic understanding

## understanding

This `@ConditionalOnProperty(value="auth.type", havingValue="OAUTH2")` annotation gates the entire `OAuthSecurityConfiguration` class (the production-oriented authentication wiring for ODD Platform) so that all six of its `@Bean` methods materialize only when an operator sets `auth.type=OAUTH2`. When active, it wires a single `SecurityWebFilterChain` covering `/**` that (a) disables CSRF, (b) enables CORS with Spring defaults, (c) applies the full Policies/Permissions/Roles/Owners authorization framework via `new AuthorizationCustomizer(permissionService, extractors)` at line 98, (d) enables `.oauth2Login(withDefaults())` for Spring Security's standard OAuth2/OIDC code-flow handling, (e) wires a custom `OAuthLogoutSuccessHandler` for provider-specific logout, and (f) conditionally composes the S2S API-key filter when `auth.s2s.enabled=true` (line 108-110). The class also constructs the in-memory `ReactiveClientRegistrationRepository` from `ODDOAuth2Properties` (the `auth.oauth2.client.*` POJO at line 11 of `ODDOAuth2Properties.java`) and applies a Google-only `allowedDomain` URL augmentation by appending `?hd={domain}` to the authorization URI (line 168-175). When more than one OAuth2 client is configured, a Thymeleaf-rendered `LoginPageFilter` (lines 203-268) intercepts `GET /login` and shows a chooser page rendered from `templates/oauth2_login.html`.

- **hot_paths**:
  - `"OAuth2 login flow at /oauth2/authorization/{regId} → /login/oauth2/code/{regId} is two-roundtrip per-login (redirect + callback + provider user-info fetch via DefaultReactiveOAuth2UserService / OidcReactiveOAuth2UserService); each callback invokes the registered OAuthUserHandler.enrichUserWithProviderInformation chain (lines 124, 137) which may issue additional provider API calls (e.g. GitHub org/team lookup in GithubUserHandler).
