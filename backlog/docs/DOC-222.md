## Description

Live `/user-owner-association` user-side section's closing line (22): "After all these steps user will have an associated owner which can be used across the platform." Nothing about removal. The operator-side paragraph does not mention the Active tab or Remove.

Code reality (verified this session, `ActiveAssociationRequest.tsx:32-94` + `SecurityConstants.java:159-162`): Management → Associations → Active tab lists every APPROVED binding (one per `user_owner_mapping` row). Per-row Remove button opens ConfirmationDialog "User X will stop being associated with owner Y." On confirm, DELETE `/api/owners/mapping/{ownerId}` → backend deletes the binding row. Backend gate is `OWNER_RELATION_MANAGE`. The UI gate today is `OWNER_ASSOCIATION_MANAGE` (a mismatch tracked separately as PLT-040).

Operator-visible consequence: a user who picked the wrong Owner cannot self-recover (per DOC-216); admins cannot discover from the docs how to help them. The Active-tab UI is the answer, but operators must trial-and-error to find it.
