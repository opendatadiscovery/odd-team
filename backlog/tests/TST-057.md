## Description

`search-url-facets.spec.ts:112` — *"a class tab writes the facet to the URL + refilters; the All tab removes
it (round-1 write + round-2 removal)"* (F-017 / ST-1b, part of IT-151) — is a **load-sensitive timing flake**.

- **Observed RED (once):** in the `review-ctrib050` full **feature-complete** run (337 tests, single worker,
  SUT `odd-team-sut-revctrib050` = odd-platform `2c0bfaf3`, digest `sha256:10141b3e…`), this test **failed at
  16.6s** — a timeout on one of its assertions, at position **292/337** (i.e. after ~291 prior tests had
  loaded the single-worker box + the shared stack).
- **GREEN in isolation on the same SUT:** re-running IT-151 (`ODD_STREAM=revctrib050b
  ODD_PLATFORM_IMAGE=odd-platform:odd-team-sut-revctrib050 run-suite.sh IT-151`) → **4/4 passed**, with
  `:112` GREEN in **4.7s** (well under the 15s bound). The implementer's own isolated IT-151 run was likewise
  4/4.
- **Not attributable to the CTRIB-050 / ST-1d change:** that change is a proven **no-op** for a
  class-tab-only selection (no sidebar/enum facet selected ⇒ `resolveFacetNames` returns an empty map ⇒
  `fillResolvedFacetNames` is a no-op; `entityClasses` are skipped in the resolver). The other three
  `search-url-facets` tests (`:143`, `:186`, `:226` incl. the ST-1d assertion) and all `search-url-state`
  (ST-1a) tests passed under the same full-suite load.

### Second instance (review-ctrib051, 2026-07-03) — same class, different spec

In the `review-ctrib051` full **feature-complete** run (335 pass / 2 fail, single worker, SUT
`odd-team-sut-revctrib051` = odd-platform `f3c71338`), `:112` was **GREEN (3.5s)** — but
`owner-association-history.spec.ts:129` (IT-109 / F-174 H-005, "free-text search filters History server-side")
**timed out (1.0m)** at position ~231. Re-run in isolation (`ODD_STREAM=rc051iso
ODD_PLATFORM_IMAGE=odd-platform:odd-team-sut-revctrib051 run-suite.sh IT-109`) → `:129` **GREEN in 2.7s**, while
a *sibling* test in the same spec, `:93` (H-004), then timed out (1.0m) instead. So the flake **moves between
tests/specs run-to-run** — it is the *tail-of-a-long-single-worker-feature-complete-run* load pattern, not a
property of any one test. This is the class the fix must address (see below), which is why the title/scope are
generalised beyond `:112`. IT-109's waits are `activityFetch` network-settle promises — the same settle-under-load
failure mode as `:112`'s UI-settle awaits. Not attributable to CTRIB-051 (a pure FE facet-chip render; zero
coupling to owner-association or the activity endpoint).

### Third instance (ctrib059, 2026-08-30) — same class, DIFFERENT BUCKET (odd-platform CI unit test)

The class is **not confined to the odd-team Playwright harness**. In the `ctrib059` full
`:odd-platform-api:build` (the CI replica, 4 Gradle test workers + ~10 concurrent Testcontainers Postgres
instances), **`OpenApiDocsContractTest.platformApiGroupDocumentLoads()`** failed with
`IllegalStateException: Timeout on blocking read for 60000000000 NANOSECONDS` — **747 tests completed, 1
failed**, build RED in 23m46s.

- **GREEN in isolation on the SAME tree, idle box:** `run-platform-tests.sh --tests "*OpenApiDocsContractTest*"`
  → **3/3 PASS**, with `platformApiGroupDocumentLoads` at **17.79s** — against a **60s** bound
  (`@AutoConfigureWebTestClient(timeout = "60000")`). A ~3.4x margin, consumed by full-suite contention.
- **The document generator is healthy:** 17.79s matches the **17.3s** healthy baseline recorded by the session
  that authored this test on the fixed springdoc 2.8.17 (`contributor/CTRIB-008.md:443`).
- **NOT the PLT-141 bug re-appearing:** that bug hangs **both** group documents (`CTRIB-008.md:274` /
  `state/PROGRESS.md`: "60s `Timeout on blocking read` **x2 groups** captured verbatim"). Here the sibling
  `ingestionApiGroupDocumentLoads` and `swaggerConfigListsBothGroups` both PASSED in the same class — only the
  large `platform-api` document (191 operations) exceeded the bound.
- **Not attributable to CTRIB-059** (snapshotted `popularity_score`, #1839 ST-5c): the change adds no
  controller, no `@ControllerAdvice`, and no request mapping, so it cannot alter the OpenAPI document; and the
  test passes with the change present.

**Why this instance raises the priority of a suite-level remedy:** the two earlier instances false-RED a *local*
regression run (costing reviewer time). This one false-REDs **odd-platform CI**, where a RED build blocks a PR
and is visible to upstream maintainers — the cost lands on the public project, not just on us. The remedy shape
also differs by bucket: the unit instance is a **fixed 60s client bound on a genuinely slow (~18s) operation**
under worker contention, not a chain of UI settles.

**Why it flakes:** `:112` is the most fragile of the four facet tests — it drives a full **round-1 write +
round-2 removal** cycle with **6 separate `{ timeout: 15_000 }` assertions**, each a UI-settle wait. Under
full-suite load (single Playwright worker, shared odd-minimal stack), one settle can exceed 15s. With
`playwright.config` `retries: 0` ("a regression pin must never be masked by a retry"), a single slow settle
becomes a hard RED — so this will **intermittently false-RED `feature-complete`** for every future
contributor/reviewer run, wasting exactly the maintainer/reviewer time the regression harness exists to save.

## Acceptance Criteria
- [ ] Because the flake now spans ≥2 unrelated specs (search-url-facets, owner-association-history) and moves
  run-to-run, weigh a **suite-level** remedy alongside the per-spec ones: a per-project default `expect` timeout
  bump for the `feature-complete` single-worker profile, and/or sharding the 135-protocol suite across a small
  worker pool so no single test runs after ~290 prior tests on one box. Keep `retries: 0` (a regression pin must
  never be masked by a retry); the goal is to remove the load, not to hide the RED.
- [ ] Decide the fix shape (prefer the least-invasive that keeps the assertion oracle intact): (a) raise the
  per-assertion timeout for this round-trip test only (e.g. 15s → 30s) to absorb full-suite load; OR (b) split
  the round-1-write and round-2-removal into two focused tests so no single test chains 6 heavy settles; OR
  (c) reduce redundant intermediate settles. Do **NOT** weaken any assertion oracle (`toHaveURL` /
  `toHaveCount(0)` / visibility must stay) and do **NOT** enable retries globally.
- [ ] `:112` passes both in isolation AND at the tail of a full `feature-complete` run (single worker) across
  ≥3 consecutive runs.
- [ ] The ST-1b behaviour it guards (class facet ⇄ URL write + REPLACE-removal) is still genuinely asserted.
- [ ] **Unit bucket (odd-platform CI):** decide the remedy for `OpenApiDocsContractTest` — raise the
  `@AutoConfigureWebTestClient` bound for this class (60s is thin for an operation that legitimately costs ~18s
  idle and runs alongside 3 sibling workers), and/or stop the `platform-api` document build from racing the
  other workers. Do NOT weaken the oracle: the test must still fail if the document does not load (that is the
  whole PLT-141 regression guard), and the `@regresses #1759` intent must survive the change.
- [ ] The class is measured across BOTH buckets before closing: no load-induced false-RED in 3 consecutive full
  `:odd-platform-api:build` runs AND 3 consecutive full `feature-complete` runs.
