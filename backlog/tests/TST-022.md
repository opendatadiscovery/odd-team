## Description

On the Revision Compare viewer the **empty state and the error state are selected independently**, and a version-id that *resolves to an empty/partial diff without throwing* falls into the empty branch — so the user is shown "no changes" when in fact a revision id failed to resolve, concluding the schema is unchanged when really their input was wrong.

Confirmed against source (`DatasetStructureCompare.tsx`):
- The diff list renders only when `isSuccess && data?.structureDiffList.length > 0` (line 40).
- The error page is gated solely on `isError`: `<AppErrorPage showError={isError} .../>` (lines 47-51).
- The empty placeholder is gated on success + empty: `<EmptyContentPlaceholder isContentLoaded={isSuccess} isContentEmpty={!data?.structureDiffList.length} .../>` (lines 52-56).

So the branch a bad-input pair takes depends entirely on whether the backend throws (→ `isError` → AppErrorPage) or returns a structurally-valid-but-empty `structureDiffList` (→ `isSuccess` + empty → "no changes"). Per F-191 H-011 + the F-045 backend evidence (`DatasetVersionServiceImpl.java:69-71` — `size != 2` throws → 500), a *fully*-missing version-id routes to the error path, but a *cross-dataset or partially-resolving* pair can produce an empty success that fires `EmptyContentPlaceholder` — indistinguishable from a genuine no-op diff. The reflection deferred the verdict to a probe (PENDING-F-191-1) precisely because which branch fires for a partially-resolving pair is not traceable from source without running the pair. This overlaps F-045 (the backend diff endpoint that anchors the empty-vs-throw decision).

**Typed gate: characterization-pin (per LSN-029).** The probe PENDING-F-191-1 runs the bad-input pairs against the local stack and observes which branch renders today. The IT then pins that outcome: if a partially-resolving / cross-dataset pair renders `EmptyContentPlaceholder` ("no changes"), the IT asserts that CURRENT misleading behaviour — GREEN now, RED the instant the viewer is fixed to surface an actionable "this revision isn't part of this dataset" error (PLT-028 Thread B/D, the F-191 H-004/H-005 fix family). Not `@Disabled` / `test.fixme` — a live tripwire.
