## Description

On the Management → Policies list, the caption reads "**N** policies overall", where **N is the deployment-wide unfiltered total** and stays frozen while the operator searches. When a non-admin (or any user) types into the Policy search box, the row list correctly narrows to matching policies, but the "N policies overall" number does **not** change — it keeps showing the pre-search total. The result is a confusing surface: a small filtered list of rows sitting beside a much larger count, with no caption text distinguishing "overall" from "matching".

The **narrowing itself is correct** — this is not a search bug. The defect is purely the count caption: it says "overall" but reads as if it should reflect what is on screen, and there is no companion "X of N matching" copy to disambiguate. An operator auditing RBAC ("how many policies match `s3`?") cannot read the answer off the screen; they have to count the rows.

This is a UI-copy / documentation caveat. The actionable fix is a caption that distinguishes overall-vs-matching (e.g. keep "N policies overall" but make explicit it is the deployment total, independent of the active search), surfaced in whatever doc page covers Policy/RBAC management. There is no published policies-management page carrying this today, so the caveat needs a canonical home under `enable-security/authorization/`.

## Context

Canonical code truth (verified 2026-06-08, `odd-platform/odd-platform-ui/src/components/Management/PolicyList/PolicyList.tsx`):
- `:33` — `const { page, hasNext, total } = useAppSelector(getPoliciesListPageInfo);` — `total` is the server-reported page-info total.
- `:37` — `const [totalPolicies, setTotalPolicies] = React.useState(total);` — a separate piece of local state holds the displayed count.
- `:43-45` — `React.useEffect(() => { if (!query) setTotalPolicies(total); }, [total]);` — `totalPolicies` is updated from `total` **only when `query` is empty**. Once the operator types a query, `total` from the filtered fetch is deliberately *not* copied into `totalPolicies`, so the caption stays frozen at the last unfiltered value.
- `:47-50` — `fetchNextPage` and `:52-57` `handleSearch` both `dispatch(fetchPolicyList({ ..., query }))`, so the **row list** does reflect the search (narrowing is correct).
- `:78` — `<NumberFormatted value={totalPolicies} /> {t('policies overall')}` — the caption renders the frozen `totalPolicies`, not the matching count.

The `:43-45` guard is what produces the "overall, not matching" behaviour by design; line 78 is the surfacing. Together they confirm the harvest one-liner: "'N policies overall' beside fewer rows, no caption distinguishing overall-vs-matching; narrowing itself is correct."
