  - **Proposed doc action**: Two-part fix on `configuration-and-deployment/enable-security/authentication/oauth2-oidc.md`. (1) Doc-side stop-gap: in the GitHub provider section, add a "**Known limitation**" admonition: "**GitHub Enterprise Server (GHES) is not supported.** The platform's GitHub OAuth2 handler hard-codes outbound API calls to `https://api.github.com` (public GitHub.com only). GHES deployments with API at `https://github.example.com/api/v3` will fail at first user login with a network or certificate error. The platform does not currently expose a configuration knob for the GitHub API base URL. If you operate GHES and need OAuth2 user authentication, use a generic OIDC provider configuration (`provider: custom`, `issuer-uri: <ghes-oidc-issuer>`) — note that this loses GitHub-specific `organization-name` and `admin-groups` enforcement (the platform's GitHub-specific handler is bypassed in this configuration). To request first-class GHES support, file an upstream issue."
