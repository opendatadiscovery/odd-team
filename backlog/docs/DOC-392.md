## Description

The Dictionary tab is a server-side faceted-search session. When an operator clicks a facet and then types a query and presses Enter (or the reverse, depending on which form last submits), the just-applied facet can silently disappear from the active filter set.

The server side is **not** the loss point: `TermSearchServiceImpl.updateFacets` (`TermSearchServiceImpl.java:84-86`) maps the incoming form to a delta and merges it onto the persisted session state via `FacetStateDto.merge(currentState, delta)` — a server-side merge that preserves prior facets. The loss is a **client round-trip artefact**: the text-submit path posts a form whose `filters` payload is effectively empty (`filters:{}`) for the facet dimensions the client did not re-send, and the client's local slice applies last-write-wins, so the user observes the freshly-clicked facet vanish even though the previous merged session still held it server-side.

For an operator narrowing the Dictionary by a facet and then refining with a search term, this reads as "my filter got ignored" — they cannot tell whether the platform dropped the facet or never registered the click, and there is no UI signal that a round-trip reset the local view.

- [ ] The caveat states accurately that the server merges facet deltas (`FacetStateDto.merge`) so the loss is a client-side round-trip, not a server-side overwrite — i.e. it does not misattribute the cause.

Canonical code truth — server-side merge, so the loss is a client round-trip:
- `odd-platform-api/src/main/java/org/opendatadiscovery/oddplatform/service/term/TermSearchServiceImpl.java:84-86` — `updateFacets` does `fetchFacetState(searchId).map(facetStateMapper::pojoToState).map(currentState -> FacetStateDto.merge(currentState, delta))`. The persisted session state is preserved and the incoming delta is merged onto it; the server does not blank prior facets on a text submit.

Canonical home: `business-glossary.md` already documents the Dictionary tab as a server-side faceted-search session (`## The Dictionary tab`, ~line 26) and the session-share semantics (~line 38); the facet-loss-on-text-submit round-trip is an additional, currently-undocumented operator caveat for the same surface. No other doc surface carries this claim (grep of `documentation/docs` for the Dictionary search / facet behaviour returns only `business-glossary.md`).

This is a low-severity behaviour caveat (no data loss, no security exposure). The cleaner long-term fix is on the platform side (the text-submit should re-send the active facet payload so the local slice does not reset) — if that ships upstream, this caveat is retracted; until then the doc caveat is the operator-side guidance.
