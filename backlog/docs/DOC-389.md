## Description

`data-lineage.md` documents the my-objects upstream/downstream **triplet** with a cluster of operator caveats under `### Anchor architecture and operator caveats` (`data-lineage.md:42`). Four are present today: (1) the wrong-OpenAPI-shape danger hint (`:36`), (2) owner-scoping enforced at exactly one site (`:46`), (3) the full owned set is fetched before pagination (`:52`), and (4) an empty `200 OK []` is indistinguishable across four root causes (`:58`).

A **fifth** behaviour of the same triplet is undocumented: the final projection silently drops **hollow** entities and **soft-deleted** entities from the neighbour set, with no tombstone or count signal in the response.

Tracing it:

- `DataEntityServiceImpl.java:223` builds the triplet's neighbour list with `reactiveDataEntityRepository.listByOddrns(oddrns, false, false, page, size)` — the two boolean arguments are `includeHollow=false` and `includeDeleted=false`.
- `ReactiveDataEntityRepositoryImpl.java:237-245` implements those flags: when `includeDeleted` is false it adds `addSoftDeleteFilter(...)`, and when `includeHollow` is false it adds `conditions.add(DATA_ENTITY.HOLLOW.eq(false))`. Both filters drop rows from the result; the method returns only the surviving pojos.

**Operator-visible consequence.** A neighbour that exists in the lineage graph but is a hollow stub (an entity referenced by an ingested ODDRN but never fully ingested — a placeholder) or has been soft-deleted is omitted from the upstream/downstream list. The response carries no marker that a neighbour was elided, so an operator sees a *smaller* dependency set than the lineage edges imply and cannot tell that the gap exists. This is distinct from the four-root-causes empty-response hint (which is about an empty anchor or empty neighbourhood) — here the neighbourhood is non-empty but some members are filtered away invisibly. Documenting it completes the triplet's caveat set so operators reconciling lineage against the raw edge graph know why a referenced neighbour may be missing.
