## Description

odd-platform #1764 (CTRIB-004, `contrib/CTRIB-004-view-count-double-fetch`) fixes the
LSN-017 front-end double-fetch: from release 0.28.0 one detail-page open registers
exactly **+1** view (e2e-verified: IT-002 RED on pre-fix main with `view_count==2`,
GREEN on the fixed tree). Three published pages carry the now-version-bound "+2" claim
(the full-tree sweep found all three; DOC-297 shipped the first two, DOC-260 the third):

1. `entity-detail-page.md` — the "+2, not +1" warning hint.
2. `catalog-overview.md` — the "+2" clause inside the Popular-column hint.
3. `search.md` — the "Clicking a result row inflates the entity's view count by +2"
   section (which also contained factually false advice that direct navigation to
   `/dataentities/{id}` avoids the count — the detail mount fires the same fetch
   however you arrive; dropped in the rewrite).

The "view count is the sole Popular ranking signal and is trivially inflatable"
warnings are NOT retired — they stay true until the hardening lands (PLT-217 /
deferred facets of #1764).

**Authored on documentation branch `release/0.28.0`** (commit `a0199ae`) per the
release-train rule: the live manual describes the latest published release; these
notes publish when 0.28.0 ships. The train branch was created from `origin/main`
(@ `5d92250`) and pushed same-name; docs `main` untouched.
