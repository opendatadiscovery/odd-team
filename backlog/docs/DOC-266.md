## Description

`entity-detail-page.md`'s **Per-class panel matrix** rows for `TRANSFORMER_RUN` and `QUALITY_TEST_RUN` say (lines 47, 51):

> | `TRANSFORMER_RUN` (Job run) | Inherits its parent transformer's run-specific surface; per-run details live in History. | Lineage, History (own row), Linked entities, Discussions, Activity. |
> | `QUALITY_TEST_RUN` | Inherits the parent quality test; per-run reports live in History. | History, Linked entities, Discussions, Activity. |

The **Inherits its parent ... surface** wording implies the run-class entity's main-column stats panel renders something (the parent's panel). Verified against `OverviewStats.tsx:23-83` on 2026-05-27 — the switch has cases for `SET`, `TRANSFORMER`, `CONSUMER`, `QUALITY_TEST`, `INPUT`, `RELATIONSHIP`, `ENTITY_GROUP` (seven cases), plus `default: return null` at line 81-82. **There is no case for `TRANSFORMER_RUN` or `QUALITY_TEST_RUN`** — both fall through to the default branch and render no main-column stats panel.

This contradicts the admonition immediately below the table (lines 57-59):

> **An entity with an unrecognised or empty class set renders no main-column stats panel — silently.** The class-driven stats panel switches over the entity's class list; an entity whose class array is empty, undefined, or contains a value the UI does not recognise renders no stats panel at all.

The admonition's "value the UI does not recognise" framing is also imprecise — `TRANSFORMER_RUN` and `QUALITY_TEST_RUN` are **declared** enum values (verified at `lib/constants.ts:69, 73`); the UI recognises them as enum members but the switch does not handle them. The defect is "recognised class without a switch case", not "unrecognised class".

Operator impact: an operator landing on a TRANSFORMER_RUN detail page sees no main-column stats panel; reads the matrix; expects "Inherits parent transformer's run-specific surface" to be visible somewhere; concludes the UI is broken or their data is incomplete. The matrix sets a false expectation.
