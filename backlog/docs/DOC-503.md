## What

`documentation@release/1.0.0 docs/data-discovery/favorites.md:33` promises that the Favorites surface lists
assets **"most-recently-favorited first"**. CTRIB-061 (#1841, ST-7) retires the tab that delivered that
ordering and replaces it with a search filter, which orders by the standard search ordering. The ordering is
restored by ST-7b (`issues/odd-platform/PLT-257`, a paste-ready sub-issue awaiting the maintainer's filing).

So the page's claim is true if and only if **both** slices ship in 1.0.0. This item exists so the 1.0.0
release gate is forced to decide which, rather than publishing whichever sentence happens to be on the branch.

## Why it needs a tracked item rather than a note

The seam is invisible to every other mechanism. The release gate derives its manifest by grepping
`backlog/` + `contributor/` for `milestone: "1.0.0"` (`playbooks/release-train-merge.md`), so a note in a
CTRIB record that has already flipped to `pending-release` would not surface it. This item's `milestone:`
line is the only thing that makes the gate look.

## Resolution — decide at the gate, from what actually merged

| If, at the 1.0.0 gate… | Then |
|---|---|
| **ST-7b has merged** | Keep the ordering claim. Rewrite `:31-33` from "the Favorites tab" to the Favorites filter, retaining "most-recently-favorited first" as the default ordering when the filter is on. |
| **ST-7b has NOT merged** | **Drop the ordering claim** from the rewritten prose — do not publish it. Say the filter narrows the catalog to starred assets, and say nothing about order. Re-open this item against the next milestone so the claim returns with ST-7b. |

Either way `:2` (the frontmatter `description:` — this is the published `<meta name="description">` and the
og:description, so it is reader-visible SEO text, not an internal comment), `:7` (the intro) and `:29` (the
panel paragraph's "View all link to the Favorites tab"), plus `catalog-overview.md:43`, must stop asserting a
top-level Favorites tab, because ST-7 removes it regardless.

## Acceptance

- No page on the 1.0.0 train asserts a top-level **Favorites tab**.
- The ordering sentence is present if and only if ST-7b shipped in 1.0.0.
- `favorites.md`'s frontmatter `description:` is accurate and stays within the 200-character GitBook meta
  limit (it is silently truncated mid-word beyond that).
- Both live URLs verified after the 1.0.0 release.
