## Description

The live Query Examples page (`documentation/docs/data-modelling/query-examples.md`, published at `https://docs.opendatadiscovery.org/data-modelling/query-examples`) has a **"## Known operator caveats"** section (shipped by DOC-183) whose first two caveats frame **by-design ODD behaviour as defects**. The maintainer withdrew both as non-issues on 2026-06-17 (PLT-018 review). A published manual that cries "security gotcha" over normal, documented behaviour misleads operators into distrusting a correct design — `incorrect documentation has higher priority than missing` (CLAUDE.md).

**Caveat to REMOVE — "permissions split across three controllers → miss four of seven gates"** (live page ~line 85). This is a fabricated operator problem. ODD policies grant permissions **by name** (the 7 `QUERY_EXAMPLE_*` values are `PolicyPermissionDto` constants, all selectable in the policy editor); *which controller hosts each endpoint* is an invisible implementation detail the operator never configures against. The complete permission→operation map is already in the page's **"## Permissions (RBAC)"** table. A feature whose mutations are gated by more than one permission is normal policy composition, not a trap. Remove the caveat (the table already informs the operator).

**Caveat to REFRAME — "all reads open to every authenticated user" framed as un-enforceable** (live page ~line 97). The *content* is accurate and useful and must stay (treat Query Example bodies as read-collaborative; do not author secrets — production credentials, restricted column references — in `definition`/`query`). But the *framing* presents it as a defect: "Multi-team deployments expecting per-team query-example visibility **cannot enforce it through the RBAC layer today**" implies a missing feature with a "today" that will change. It will not — ODD is **read-collaborative by design** (`lineage/odd-platform/implicit-adrs.md:140`: `SECURITY_RULES` holds only mutation matchers; GET endpoints fall through to `.authenticated()` platform-wide). Reframe from "cannot enforce (yet)" to "by design: the catalog is read-collaborative; only mutations are permission-gated", drop "today", and cross-link the platform posture (the [Audit trail scope](../configuration-and-deployment/enable-security/audit-trail-scope.md) page already frames the read-collaborative model). Keep the actionable do-not-author-secrets guidance verbatim.

**Caveats that STAY unchanged:** the XSS caveat (real — removed when the PLT-018 / GHSA fix ships in 0.28.0, on its own release-train DOC) and the audit-silence caveat (real — tracked by PLT-227).
