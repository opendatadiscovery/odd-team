    - Operator threat-model: an operator who configures `organization-name: my-cool-org` reasonably believes this acts as a global gate (only users in `my-cool-org` can authenticate). An operator additionally configuring `admin-principals: [trusted-consultant]` to elevate a specific user does NOT expect that user to bypass the org gate. The actual behaviour: `trusted-consultant` does NOT need to be in `my-cool-org` to authenticate as ADMIN — the admin-principals branch fires first, returns ADMIN, and never reaches the org-membership check.

The design choice is defensible; the documentation gap is the problem.
  - **Proposed doc action**: One-part doc-side fix on `configuration-and-deployment/enable-security/authentication/oauth2-oidc.md`. In the GitHub provider section, immediately after the `admin-principals` description, add a "**Precedence**" admonition: "**`admin-principals` BYPASSES `organization-name`.** A user listed in `admin-principals` authenticates as ADMIN regardless of whether they are a member of `organization-name`. The admin-principals allowlist is evaluated FIRST; users matched here skip the organization membership check entirely. This is intentional — operators can grant ADMIN to specific users outside the organization (e.g. an external consultant, a contracted administrator) — but operators should be aware of the precedence when designing access control. If you want `organization-name` to act as a hard gate (only users in the organization can authenticate at all), do NOT use `admin-principals` to add out-of-org users; instead, add them to the organization and use `admin-groups` (team-based ADMIN within the organization) or `admin-attribute`-based assignment scoped to org members." (Future code-side enhancement: file `/log-issue odd-platform` upstream to optionally reverse the precedence under a configuration flag like `auth.oauth2.client.{id}.admin-principals-require-org-membership: true`, which would enforce that admin-principals users ALSO satisfy the org membership check — defence-in-depth for operators who want strict org-gating.)
