## Description

`docs/data-quality.md` line 15 (the **Test Results Import** subsection bullet) contains three inline cross-links to integration pages:

```markdown
* [**Test Results Import**](data-quality/test-results-import.md) — how test results land in the catalog: push-client integrations with [Great Expectations](../integrations/push-adapters/odd-great-expectations.md) and [dbt](../integrations/push-adapters/odd-dbt.md), statistical profiles via [`odd-collector-profiler`](../integrations/collectors/odd-collector-profiler.md), and the `POST /ingestion/entities/datasets/stats` endpoint for custom frameworks.
```

The three `../integrations/...` paths are **wrong**:
- `data-quality.md` sits at `docs/data-quality.md` — already at the `docs/` root.
- `../` resolves up to the repo root (`documentation/`), not back into `docs/`.
- The target dirs are at `docs/integrations/` (no `integrations/` exists at the repo root).
- GitBook's published-site WebFetch shows the rendered hrefs falling back to GitHub raw URLs at `documentation/blob/main/integrations/push-adapters/odd-great-expectations.md` — a path that does **not** exist on the repo (the real path is `documentation/blob/main/docs/integrations/push-adapters/odd-great-expectations.md`).

Operators clicking any of the three links from the Data Quality landing page (https://docs.opendatadiscovery.org/features/data-quality) hit a GitHub 404, breaking the discovery flow into the per-integration pages.

## Context

Found during the Phase 2 editorial audit of the `data-quality/` subtree (iter 40). The bug is a classic relative-path scope error: the parent landing file sits at the same depth as its sibling `integrations/`, but the cross-link was written as if the parent landing lived one level deeper (alongside its children in `data-quality/`).

This is a **Gate 7 (layout)** + **Gate 8 (live-site verification)** + **Axis A4 (cross-page reference consistency)** finding. The bug is invisible to a code reviewer reading the file in isolation — relative paths look reasonable until you compute the resolution from the file's actual location.

Related: similar broken-link patterns may exist on other top-level landing pages (`data-discovery.md`, `data-lineage.md`, `data-modelling.md`, `master-data-management.md`, `data-glossary.md`) — they all sit at `docs/` root and any `../` in their cross-link list is suspect.
