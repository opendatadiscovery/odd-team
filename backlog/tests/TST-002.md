## Description

There is **no test that walks the live platform against the OpenAPI spec** (F-029/H-012). This is the structural root that lets every status-code (201-vs-200), inverse-semantic, missing-field, and operationId drift class accumulate undefended — SPC-001/002/003 each fix instances, but nothing prevents the next drift from shipping.

This item adds a spec-driven contract test: spin a local docker-compose mirror (platform + Postgres), and use `WebTestClient` to walk every operation declared in `openapi.yaml`, asserting the declared status and response shape. Per the pin-known-bugs idiom (LSN-029), where the platform CURRENTLY diverges from the spec (the known 201-vs-200 pairs, the `getMyObjectsWithUpstream` inversion, etc.), the test asserts the **current actual** behaviour as a GREEN characterization tripwire — it goes RED the instant either the spec or the platform changes, forcing a deliberate spec/platform reconciliation rather than silent drift. It is NOT a build-breaking RED aspiration and is NOT `@Disabled`.

## Acceptance Criteria
- [ ] A contract test boots the platform against a local ephemeral Postgres (Testcontainers or the existing docker-compose test harness — match the repo's integration-test convention) and drives `WebTestClient`.
- [ ] The test parses `openapi.yaml` (the vendored copy) and, for each operation, issues a representative request and asserts the response status against the spec's declared status.
- [ ] Where the platform currently diverges from the spec (e.g., the SPC-001 201-vs-200 pairs at `openapi.yaml:372,400,454,482,558,586`; the SPC-002 summary inversions), the assertion characterizes the CURRENT platform behaviour with an in-source comment naming the divergence + the SPC item that tracks the reconciliation (`@pins SPC-001` style), so the test is GREEN today and RED on any change.
- [ ] The in-source flip protocol is documented: on RED, decide intentional reconciliation (invert the assertion to the spec's value, move the pin to a regression guard, close the SPC facet) vs unplanned change (stop and investigate).
- [ ] A JUnit `@Tag("known-bug")` (or the repo's equivalent) marks the characterization assertions so the known-drift register is runner-filterable.
- [ ] The test runs in CI; failure blocks the merge.
