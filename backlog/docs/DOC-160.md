## Description

Editorial-audit / spot-check finding from DOC-156 implementation 2026-05-07. DOC-156's AC line ran a tree-wide grep for `github.com/opendatadiscovery/odd-` minus the canonical-home repos and surfaced two additional sites that were not in DOC-156's scope (DOC-156 covered use-case pages only):

### Site 1 — `configuration-and-deployment/trylocally.md` L72-75 + L80

Five GitHub-direct references to per-collector READMEs:

```
docs/configuration-and-deployment/trylocally.md:72:  * [supported data sources by odd-collector](https://github.com/opendatadiscovery/odd-collectors/blob/main/odd-collector/README.md)
docs/configuration-and-deployment/trylocally.md:73:  * [supported data sources by odd-collector-aws](https://github.com/opendatadiscovery/odd-collectors/blob/main/odd-collector-aws/README.md)
docs/configuration-and-deployment/trylocally.md:74:  * [supported data sources by odd-collector-gcp](https://github.com/opendatadiscovery/odd-collectors/blob/main/odd-collector-gcp/README.md)
docs/configuration-and-deployment/trylocally.md:75:  * [supported data sources by odd-collector-azure](https://github.com/opendatadiscovery/odd-collectors/blob/main/odd-collector-azure/README.md)
docs/configuration-and-deployment/trylocally.md:80:   See the [`odd-collector` README's plugin examples](https://github.com/opendatadiscovery/odd-collectors/blob/main/odd-collector/README.md) for per-source-type configuration shapes.
```

Per `pillars/documentation/canonical-homes.md` Integrations row, the canonical homes are `docs/integrations/collectors/{odd-collector,odd-collector-aws,odd-collector-gcp,odd-collector-azure}.md` — all of which now exist post-DOC-042 (integrations hub). Same shape as DOC-156: a use-case-style page bypasses the doc-product canonical home and points at GitHub.

The fix is mechanical — retarget L72-75 to `../integrations/collectors/{name}.md` and L80 to `../integrations/collectors/odd-collector.md` (or to a more specific anchor like `#per-adapter-configuration-reference` if the prose is asking about plugin examples specifically).

The L41 `git clone https://github.com/opendatadiscovery/odd-platform.git` reference is the legitimate operator-facing repo-clone instruction; that link should stay GitHub-direct (clone instructions need the repo URL).

### Site 2 — `data-modelling/relationships.md` L29 + L58

Two references to the odd-collectors monorepo's "Relationships section":

```
docs/data-modelling/relationships.md:29:These mirror the cardinality vocabulary defined in the `odd-collectors` monorepo's [Relationships section](https://github.com/opendatadiscovery/odd-collectors#relationships).
docs/data-modelling/relationships.md:58:Adapter coverage as of the time of writing (per the upstream [`odd-collectors` Relationships matrix](https://github.com/opendatadiscovery/odd-collectors#relationships)):
```

Same shape as DOC-159's L86 site (per-adapter capability matrix lives on contributor README, no doc-product canonical home today). DOC-159's recommended Option 1 is "accept the gap; log the deferral on canonical-homes.md" — applying the same call here would mean the L29 + L58 GitHub references stay as-is until a per-adapter capability matrix gets a doc-product home.

If DOC-159 lands as Option 2 or Option 3 (a new matrix page in the integrations hub), this item retargets these two references to that new home in the same change. If DOC-159 lands as Option 1 (the recommended call), this item is **subsumed** by DOC-159 — the L29 + L58 references survive as another concrete use-site of the `canonical-homes.md` "No canonical home today" deferral.
