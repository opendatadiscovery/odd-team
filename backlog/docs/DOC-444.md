## Description

odd-platform #1760 (CTRIB-005, `contrib/CTRIB-005-search-session-not-found`) ships three
0.28.0 behaviour changes the published manual must reflect at the release gate:

1. **Deep links load the session again.** Since the Dec-2023 router refactoring (#1551) the
   SPA mounted `/search/*` as a splat, so `params.searchId` was always undefined and every
   cold `/search/{uuid}` (and `/termsearch/{uuid}`) silently created a fresh empty session.
   Fixed in 0.28.0 — sharing and reloading now reach the server-side session row, which is
   what `search.md`'s session bullets always described as the intent.
2. **Evicted/dead links get a graceful state.** "This search has expired" + a
   **Start new search** action, replacing the silent reset (and the residue-dependent
   "Unknown Error" of the pre-fix UI). search.md bullet 4 updated, version-anchored.
3. **Framework error statuses pass through the advice.** An unmatched `/api` route stays
   404 and invalid request input stays 400 (USR-coded bodies) instead of 500 SYS001
   (#1760 + #1761). The published ADR-0007 page's handler enumeration (Decision + Evidence)
   updated to include the `ResponseStatusException` pass-through.

Authored directly on the documentation train branch `release/0.28.0` (commit recorded in
CTRIB-005; pushed same-name). Docs `main` untouched — the live manual keeps describing
0.27.x until the release gate.
