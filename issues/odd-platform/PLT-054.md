## What

Four defects on the Slack data-collaboration integration. Doc-side mitigation ships as DOC-204; structural fixes are this PLT.

**Defect 1 — `/api/slack/events` accepts forged POSTs from any internet caller (HIGH).** `EventApiController.java:22-27` deserializes raw body from `@RequestBody Mono<String>` and never reads any header. Grep for `X-Slack-Signature`, `signing.secret`, `verifySignature`, `HMAC.SHA256` returns ZERO matches. Slack's protocol mandates HMAC-SHA256 over `v0:{timestamp}:{body}` — ODD does NONE of this. Any internet caller forges events into the message stream (inject child messages, manipulate thread state, plant `javascript:` URLs).

**Defect 2 — At-least-once delivery materialises N child message rows per duplicate (MEDIUM).** `V0_0_59__data_collaboration.sql:25-39` — `message_provider_event` has NO unique on (provider, event_id); `ReactiveMessageRepositoryImpl.java:136-155` INSERT is plain — no ON CONFLICT. Duplicated Slack delivery inserts N rows; processor materialises N child messages. `getUUIDByProviderInfo` lacks LIMIT 1 — order-undefined return on multi-result.

**Defect 3 — Slack channels autocomplete uses startsWith filter (LOW).** `SlackMessageProviderClient.java:52` — `slackChannel.name().startsWith(nameLike)`. Typing the middle of a channel name returns nothing.

**Defect 4 — 1-minute Caffeine cache on Slack channels (LOW).** `SlackMessageProviderClient.java:36-44` — `expireAfterWrite(1, MINUTES)`. Freshly-invited bot-channel membership invisible for up to 60s.

## Why it matters

Defect 1 is most operator-load-bearing: any internet caller forges events into the platform's message stream. The open-redirect/XSS class means forged events with `javascript:` URLs plant live JS in the UI on render. Security-conscious deployments need reverse-proxy HMAC verification today (per DOC-204 caveat). Defect 2 is a data-integrity hazard. Defects 3+4 are UX surprises operators work around.

Severity HIGH: Defect 1 is anonymous remote write into the message stream.

## Suggested fix

**Defect 1 — HMAC-SHA256 signature verification:**
```java
public boolean verify(String body, String timestamp, String signature) {
  if (!isFreshTimestamp(timestamp)) return false;   // reject replay > 5 min
  final var basestring = "v0:" + timestamp + ":" + body;
  final var computed = "v0=" + HmacUtils.hmacSha256Hex(signingSecret, basestring);
  return MessageDigest.isEqual(computed.getBytes(UTF_8), signature.getBytes(UTF_8));
}

@PostMapping("/api/slack/events")
public Mono<ResponseEntity<Void>> postSlackEvent(
    @RequestBody Mono<String> body,
    @RequestHeader("X-Slack-Request-Timestamp") String timestamp,
    @RequestHeader("X-Slack-Signature") String signature) {
  return body.flatMap(raw -> verifier.verify(raw, timestamp, signature)
      ? slackEventService.handle(raw).thenReturn(ResponseEntity.ok().build())
      : Mono.just(ResponseEntity.status(401).build()));
}
```
Config: `datacollaboration.slack-signing-secret`; Spring Sanitizer masks `secret`-suffixed names.

**Defect 2 — unique + ON CONFLICT:**
```sql
CREATE UNIQUE INDEX uq_message_provider_event_provider_event_id ON message_provider_event(provider, event_id);
```
```java
dslContext.insertInto(MESSAGE_PROVIDER_EVENT).values(...)
  .onConflict(MESSAGE_PROVIDER_EVENT.PROVIDER, MESSAGE_PROVIDER_EVENT.EVENT_ID).doNothing();
```
Plus `LIMIT 1` on `getUUIDByProviderInfo`.

**Defect 3 — contains filter:**
```java
- .filter(slackChannel -> slackChannel.name().startsWith(nameLike))
+ .filter(slackChannel -> StringUtils.containsIgnoreCase(slackChannel.name(), nameLike))
```

**Defect 4 — configurable TTL + cache-bust on `member_joined_channel` events:**
```java
- .expireAfterWrite(Duration.ofMinutes(1))
+ .expireAfterWrite(Duration.ofMinutes(channelCacheTtlMinutes))   // datacollaboration.channels-cache-ttl-minutes
```
