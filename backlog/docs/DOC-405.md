## Description

This CORRECTS content already shipped live by **DOC-239** (status `done`, critical — the disabled-authentication.md "what's anonymously reachable" expansion). It is a **reopen/retract** of the whoami payload-shape portion of DOC-239's output: that page renders the `GET /api/identity/whoami` synthetic-admin response as a **flattened** object, which is wrong.

The actual response shape is the `AssociatedOwner` wrapper. `IdentityController.whoami` (`IdentityController.java:23-33`) returns `Mono<ResponseEntity<AssociatedOwner>>`; its `dummyOwner()` builds `new AssociatedOwner().identity(new Identity().username("admin").permissions(Arrays.asList(Permission.values())))` (`IdentityController.java:30-32`). The `AssociatedOwner` model carries three top-level fields — `identity` (an `Identity` with `username` + `permissions`), `owner`, and `associationRequest` (`AssociatedOwner` generated model fields). So `username` and `permissions` are **nested under `identity`**, never top-level.

`disabled-authentication.md` renders the payload flattened in two places:

- Line ~34: "...returns a synthetic admin identity: `{ "username": "admin", "permissions": [ … ] }`".
- Line ~45 (the fingerprint matrix `DISABLED` row): "`200 OK` + `{ "username": "admin", "permissions": [ ... ] }`".

**How it misleads an operator / SDK author.** A client coding against the documented flattened shape reads `response.username` / `response.permissions` and gets `undefined` — the real keys are `response.identity.username` / `response.identity.permissions`. The doc-driven client silently fails to resolve identity. This is an accuracy defect (actively misleading), the highest-priority documentation class.

**Scope correction vs. the harvest line.** The harvest item asserted the flattened shape was shipped on BOTH disabled-authentication.md (DOC-239) AND api-reference.md (DOC-240). On verification, **api-reference.md is already correct** — DOC-240 authored the wrapper shape there: the success example is `{ "identity": { "username", "permissions" }, "owner": {…} }` (`api-reference.md` lines ~36-41) and the DISABLED note is `{"identity": {"username": "admin", "permissions": […]}}` (`api-reference.md` line ~44). So api-reference.md needs **no change**; it is the canonical reference whose shape disabled-authentication.md must be brought into line with. This item therefore carries the whole remaining class: the two flattened renderings on disabled-authentication.md.
