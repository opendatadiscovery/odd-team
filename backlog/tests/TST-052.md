## Description

While redacting the GHSA-mf43-2636-9289 (markdown stored-XSS) precise vectors during `/review CTRIB-020`
(maintainer-authorized), a repo-wide grep showed the same **literal working-PoC-payload** pattern recurs across
**other, separate** security findings — committed into the **public** odd-team workspace for vulnerabilities that
are **still unfixed** (or fixed only on an unreleased train). The genuine weapons (as opposed to the inert
textbook pins) are a **cookie-exfiltration** payload and a working **`javascript:`/`data:`-URI execution**
payload. The GHSA-mf43 family (CTRIB-020 surfaces 1-4) was redacted in commit `2567bd1`; the occurrences
below are **out of that advisory's scope** and were deliberately NOT touched there because each belongs to a
different finding with its own disclosure decision (some are intentionally public — e.g. the CTRIB-019 G-C14b call
kept the PLT-160 *tracking item* public):

- `TEST-GAP-738` — a link-attachment cookie-exfil `javascript:` URL. This is **GHSA-vw2p /
  CTRIB-019**, which is itself `pending-release` (unfixed until 0.28.0) — same risk profile as the one just redacted.
- `TEST-GAP-783` — a login-form-redirect cookie-exfil `javascript:` URL.
- `TEST-GAP-733` — a Lookup-Table row-value img-onerror exfil payload (surface 5 = PLT-019; no advisory filed yet,
  so it is openly tracked, but it is still a working payload for an unfixed XSS).
- `P-177.yaml` — an additional-links data-URI script payload.

(Textbook *inert* pins — a bare script-alert tag, or a `javascript:`-alert Markdown link — are the **accepted**
public posture, matching the deliberately-public PLT-018 framing, and are NOT in scope here. The concern is only
the genuine copy-paste weapons: real exfil callbacks + working `javascript:`/`data:` execution.)

This is the same failure CLASS as [[TST-051]] (the probe-runner host-absolute-path leak): a methodology that
persists **machine/PoC content verbatim** into public artefacts without a scrub step. Here the content is an
attacker-usable payload rather than a host path.

## Acceptance Criteria

- [ ] **Per-finding disclosure decision (maintainer).** For each occurrence above, decide redact-vs-keep against
      its own advisory/finding state (GHSA-vw2p link is pending-release → likely redact, matching the GHSA-mf43
      call; PLT-019 lookup has no advisory → maintainer's call). Redact the genuine weapon to textbook level
      (keep vector SHAPE + structural `file:line` + a held/parent-item pointer), exactly as `2567bd1` did for the
      markdown family. HEAD-redaction only — note that git history retains the pre-redaction blobs.
- [ ] **Authoring guard (the class fix).** Add a methodology guard so future probe (`/probe-define`) and test-gap
      authoring defaults PoC payloads to **neutered placeholders** — keep the vector shape needed for the test
      (`<img onerror>`, `<iframe src=javascript:>`, `[x](javascript:…)`) but never a working exfil callback or a
      real cookie send. A `git grep` lint over committed probe/test-map artefacts (matching exfil-fetch-to-remote
      + cookie-read patterns), runnable in CI, is the cheapest enforcement — the implementer pins the exact regex.
- [ ] After the per-finding sweep, re-run the lint and record the residual (intentionally-public textbook pins are
      allowed; genuine cookie-exfil/exec weapons for unfixed findings are not).

## Context

Found during `/review CTRIB-020` (2026-06-17), the same way [[TST-051]] was found during `/review CTRIB-019`: a
systemic, pre-existing public-workspace hygiene leak surfaced while handling one advisory's redaction. The affected
files are **already public (already pushed)**, so the sweep removes no *new* exposure — the value is (a) not
shipping copy-paste weapons for vulnerabilities operators have not yet been able to patch, and (b) an authoring
guard so the methodology stops regenerating the pattern. Non-urgent but it should not sit indefinitely: a working
cookie-exfil payload for a `pending-release` advisory (TEST-GAP-738 / GHSA-vw2p) is the sharpest case. The
CTRIB-020 review's held record (`contributor/CTRIB-020.md` § G-C14b finding) carries the full provenance.
