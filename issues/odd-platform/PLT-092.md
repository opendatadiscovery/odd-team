## What

Two adjustments on the Catalog page's 9-tab class-strip surface - one i18n class miss (6 of 9 tab names hardcode English; LSN-013 i18n-class incident repeat), and one architectural-clarification (the My-Objects tab dispatch encoding is correct at HEAD but the contract is split across 3 files with no single-truth comment / unit test).

**Adjustment 1 - i18n: SearchResultsTabs hardcodes English on a load-bearing UI surface (F-148c).** `SearchResultsTabs.tsx:1-95` (verified this run): NO `useTranslation` import; the 9 tabs at lines 26-62 use literal English strings - `'All'`, `'My Objects'`, `'Datasets'`, `'Transformers'`, `'Data Consumers'`, `'Data Inputs'`, `'Quality Tests'`, `'Groups'`, `'Relationships'`. Cross-link **LSN-013** (i18n class incident) - this is the latest miss on a load-bearing surface. The tab strip ALWAYS renders on the catalog page, so the i18n gap is operator-visible from the first page-load in every non-English deployment.

**Adjustment 2 - My-Objects sentinel encoding contract split across 3 files; correct at HEAD but no single-truth (F-148b - ontology-extended).** F-148's sidecar originally flagged facets 1 + 2 as `ui_unverified` pending a reducer read - the worry was that the string sentinels `'my'` and `'all'` reach the backend and corrupt the typed `entityClasses: number[]` payload. **Verified this run at `dataEntitySearch.slice.ts:173-174`**: `const myObjects = facetName === 'entityClasses' ? facetOptionId === 'my' : state.myObjects;` - clicking the My Objects tab DOES flip `FacetStateDto.myObjects` to true. **`dataEntitySearch.slice.ts:187`**: `...(facetOptionId && typeof facetOptionId === 'number' && { ... })` - the string sentinels `'all'` and `'my'` are filtered OUT of the `entityClasses` facetState payload before PUT. The bug the sidecar predicted is **NOT present at HEAD**; the encoding contract is correct. The architectural concern is that the contract has THREE coupled invariants split across `Results.tsx:83-99` (dispatch encoding), `dataEntitySearch.slice.ts:173-174, :187` (reducer normalisation), and `EntityClasses.ts` (type narrowing) - a future refactor that moves any one of them can silently break the others.

## Why it matters

**i18n (Adjustment 1)** is straightforward - non-English deployments see the entire result-class navigation in English regardless of `i18n.language`. Operators running ODD for Russian / Spanish / German / French teams hit the gap on the first page. LSN-013 is the canonical case-law for this class.

**Encoding-contract clarity (Adjustment 2)** is purely architectural - the bug the sidecar predicted is not present today, but the three-file invariant means a future refactor (e.g., consolidating the slice or replacing redux-toolkit) can silently violate it. The cheapest defence is either a unit test that pins the contract or a refactor that moves the My Objects tab onto its own dispatch action (so the type system enforces the boundary).

## Suggested fix

### (a) Adjustment 1 - Wrap tab names in `t(...)`

```tsx
// SearchResultsTabs.tsx
import { useTranslation } from 'react-i18next';

const SearchResultsTabs: React.FC<...> = ({ ... }) => {
  const { t } = useTranslation();
  const tabsItems = useMemo(() => [
    { name: t('All'),            value: 'all' },
    { name: t('My Objects'),     value: 'my' },
    { name: t('Datasets'),       value: DataEntityClassNameEnum.SET },
    { name: t('Transformers'),   value: DataEntityClassNameEnum.TRANSFORMER },
    { name: t('Data Consumers'), value: DataEntityClassNameEnum.CONSUMER },
    { name: t('Data Inputs'),    value: DataEntityClassNameEnum.INPUT },
    { name: t('Quality Tests'),  value: DataEntityClassNameEnum.QUALITY_TEST },
    { name: t('Groups'),         value: DataEntityClassNameEnum.ENTITY_GROUP },
    { name: t('Relationships'),  value: DataEntityClassNameEnum.RELATIONSHIP },
  ], [t]);
  ...
};
```

Update `public/locales/{lang}/translation.json` for each existing target language with the 9 new keys.

### (b) Adjustment 2 - Pin the encoding contract

Two options, pick one:

**(b1) Add a unit test (lowest cost, preserves shape).**

```ts
// dataEntitySearch.slice.test.ts
it('string sentinels never reach the entityClasses backend payload', () => {
  const state = baseState();
  const after = reducer(state, changeDataEntitySearchFacet({ facetName: 'entityClasses', facetOptionId: 'my' }));
  expect(after.myObjects).toBe(true);
  expect(after.facets.entityClasses).toEqual([]);     // no 'my' appended
  expect(typeof after.facets.entityClasses[0]).not.toBe('string');
});
```

**(b2) Refactor My Objects onto a dedicated action (cleanest, larger blast).**

Add `toggleMyObjects` action on the slice; the tab strip dispatches `toggleMyObjects` when the My-Objects tab is clicked and `changeDataEntitySearchFacet` only when a class tab is clicked. The slice no longer needs the string-sentinel intercept; the type system enforces the boundary statically.

Recommendation: ship (b1) now (test pins the invariant immediately), open a separate epic for (b2) if a broader slice refactor lands later.
