## Description

The live Business Glossary page (WebFetched 2026-05-27) claims "Searches and term-to-entity link operations resolve within the namespace by default" and implies term-linking is permission-gated by `DATA_ENTITY_ADD_TERM`. Both implications are contradicted by three independent code defects that operators currently have no way to discover from documentation.

**Caveat 1 — Silent term-link authorization bypass (F-002a, REFACTOR-217).** `SecurityConstants.java:238` registers the path-matcher rule as `/api/dataentities/{data_entity_id}/term` (SINGULAR `term`) but the actual endpoint exposed via OpenAPI (`openapi.yaml:973`) is `/api/dataentities/{data_entity_id}/terms` (PLURAL `terms`). The `PathPatternParserServerWebExchangeMatcher` never matches the live request path; the `DATA_ENTITY_ADD_TERM` gate falls through to the global `.authenticated()` rule. The symmetric DELETE half (`SecurityConstants.java:241` vs `openapi.yaml:1042`) is identically broken — `DATA_ENTITY_DELETE_TERM` also silently inert. **Result: any authenticated user under LOGIN_FORM/OAUTH2/LDAP can link OR unlink any term to any data entity regardless of Policy grants the operator made for these two permissions.**

**Caveat 2 — Description-edit auto-link side-channel (F-002b).** `TermAssignmentActivityHandler.java` auto-creates Term-to-Entity link rows when an entity description is edited with `[[term-namespace:term-name]]` syntax. The auto-link path bypasses `DATA_ENTITY_ADD_TERM` entirely. **Operators granting only `DATA_ENTITY_DESCRIPTION_UPDATE` implicitly grant term-link capability** — a separation-of-duties policy expecting these to be distinct grants leaks. Even if Caveat 1 above is fixed by PLT-012, this side channel remains until PLT-013 lands.

**Caveat 3 — Cross-namespace term enumeration (F-002c).** The page's "resolve within the namespace by default" sentence is false at the SQL layer. `ReactiveTermRepositoryImpl` has zero per-namespace filter on any read site; namespace is a payload field, not a query predicate. Multi-namespace deployments see every term from every namespace in every read response. Single-namespace deployments are unaffected.
