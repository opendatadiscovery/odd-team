## Summary

The Activity actor/asset-filter rework (#1657) added eight new user-facing strings - the three
filter labels/hints (Owner / Made by (owner) / Made by (user)), their "(i)" help text, and the action
row's "current owner" note. They were added to `en.json` only. The platform ships seven locales
(`en, es, br, fr, ch, ua, hy`), and the other six - which are otherwise near-complete (~420 of ~434
keys) - carry none of these. react-i18next falls back to `en`, so a user on a non-English UI sees these
eight strings in English while the rest of the page is localized. Same class as PLT-190 (#1748), here for
the Activity surface.

## Where

`odd-platform-ui/src/locales/translations/en.json` (keys, ~lines 426-435):

```
"Made by (owner)"
"Made by (user)"
"current owner"
"Filters to changes on data entities that the selected owner owns - the owner of the affected asset, not the person who made the change."
"Filters to changes made by users currently associated with the selected owner. ODD maps each user to an owner, and this filter uses that current association - re-associating an owner changes which past changes match."
"Filters to changes made by the selected user, identified by their external username. This is stable over time and works even for users who have no owner association."
"The owner shown is the user's current association (as of now) - it may differ from the user's owner at the time the change was made."
"The editor's current owner"
```

These keys are absent from `es.json`, `br.json`, `fr.json`, `ch.json`, `ua.json`, `hy.json`.

## User-facing impact

A non-English operator filtering the Activity feed sees the filter labels and the "(i)" hint text in
English. The feature is fully functional (graceful English fallback - nothing breaks, nothing is
misleading), but the localization is incomplete on a surface the rest of which is translated. Low
severity: cosmetic-localization, not a correctness or data issue.

## Proposed fix

Add the eight keys to all six non-English locale catalogs with proper native translations (the locale
maintainers / native speakers, as the catalogs were originally authored - not machine translation for a
published product). No code change; locale JSON only.

## Why this is a separate item (not folded into the #1657 PR)

The #1657 PR adds the English source strings and is verifiable end-to-end by its author. Translating into
six languages (incl. Ukrainian, Chinese, Armenian) cannot be verified by the same author to publishing
standard, so per the design-before-build impact checklist (i18n dimension) it is tracked here rather than
machine-translated blind into the PR. The PR notes this follow-up in its scope-exclusions.
