## Description

`OpenApiDocsContractTest.platformApiGroupDocumentLoads()` fails with
`IllegalStateException: Timeout on blocking read for 60000000000 NANOSECONDS` when it runs inside the full
`:odd-platform-api:build`, and passes when run alone. Measured both directions on the same machine, same day:

| Run | Result |
|---|---|
| pure `origin/main` @ `b5d9f150`, test alone (`--tests "*OpenApiDocsContractTest*"`) | 3/3 **pass** (build 7m33s) |
| branch `contrib/CTRIB-060-…` @ `6281a9df`, test alone | 3/3 **pass** (build 3m51s) |
| branch `contrib/CTRIB-060-…` @ `6281a9df`, inside the full build (810 tests) | **1 failure** — the 60s timeout |

So it is **not** attributable to a code change on either side; it is the springdoc document build being slow
enough that a 60 s blocking read is a real ceiling once the JVM is sharing the box with the rest of the suite
(Testcontainers included). Note that even *alone* the base run took 7m33s — document generation is not cheap.

The test itself is load-bearing and should stay: it was introduced by `3f02dd63` ("springdoc-openapi 2.2.0 ->
2.8.17 — revive the OpenAPI/Swagger surface dead since the Spring 6.2 upgrade") precisely because this surface
had silently died once, and a **hang** is its documented failure mode (PLT-141). The problem is the wait
strategy, not the assertion.

## Why it matters beyond a flake

A timeout here is indistinguishable from the real PLT-141 regression it exists to catch. That makes it worse
than an ordinary flake: it trains the reader to dismiss exactly the signal the test was written for. It also
cost this slice a full same-conditions A/B (three extra builds) to establish that a `description` added to
`SearchFormData.query` had **not** broken document generation.

## Acceptance criteria

- [ ] The exchange gets an explicit, generous `responseTimeout` (or the test is given a warm-up/retry) so a slow
      document build under load does not read as a hang.
- [ ] The failure message distinguishes "document generation exceeded the budget" from "the document did not
      load", so a future timeout is triageable without an A/B.
- [ ] Re-verified inside a full `:odd-platform-api:build`, not just standalone.
