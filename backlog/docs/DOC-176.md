## Description

The `WithPermissions` HOC at `odd-platform-ui/src/components/shared/contexts/Permission/WithPermissions.tsx:11-34` is the dominant RBAC affordance pattern in the platform UI. Its default branch is `return hasAccessTo(permissionTo) ? <>{children}</> : null` — it unconditionally **hides** the affordance for users without the named permission. There is no `disabledWithTooltip` mode, no admin-contact CTA, no first-time-hint, no platform-wide signal that the UI is filtered by permission.

Operator-visible consequence: a new user encountering a permission-gated page sees a seemingly read-only UI with no signal that affordances are hidden. They cannot self-diagnose ("am I missing a permission?") without admin help. The hide-not-disable convention is platform-wide and undocumented at the operator surface.

The live `/configuration-and-deployment/enable-security/authorization` page (WebFetched 2026-05-27) covers Policies, Permissions, Roles, Owners, and User-owner association at the architectural level but says nothing about how the UI manifests the absence of permissions to a user.

## Acceptance Criteria

Frame it operator-facing: *"Affordances the signed-in user does not have permission to use are hidden — no greyed-out button, no tooltip, no message. A user who expects to see an action but doesn't should ask their admin which permission is missing."*
