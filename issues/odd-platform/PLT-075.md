## What

All 5 logout handlers derive the redirect target from `exchange.getRequest().getURI()` via `UriUtils.getBaseUri` (`AzureLogoutSuccessHandler.java:38-44`, `CognitoLogoutSuccessHandler.java:43`, `GoogleLogoutSuccessHandler.java:40`, `GithubLogoutSuccessHandler.java:45`, `ODDIAMLogoutSuccessHandler.java:38`). NO platform.base-url allowlist; NO Host validation; NO scheme enforcement.

Grep across the repo for `platform.base-url` / `odd.platform-url` / `allowed.redirect` returns ZERO matches. A reverse proxy that trusts and forwards user-controlled `Host` or `X-Forwarded-Host` headers propagates that value into the IdP's logout redirect chain.

**Attack scenario**: Multi-env Azure tenant with one App Registration serving dev/staging/prod with logout URLs `https://*.example.com/`. Attacker crafts request with `X-Forwarded-Host: attacker.example.com`. User clicks logout. Platform 302s to IdP end-session endpoint with `post_logout_redirect_uri=https://attacker.example.com/`. IdP allowlist permits any `*.example.com` host. User lands on attacker domain after successful authenticated logout.

## Why it matters

Compounds with F-086 (token-revocation gaps - PLT-073): even if the open-redirect lands the user on attacker domain post-logout, the IdP-issued OAuth2 tokens (if previously captured) remain valid against IdP-protected resources for the rest of TTL. Cluster severity is HIGH.

## Suggested fix

Add a config property + boot-time validation:

```yaml
# application.yml
odd:
  platform-base-url: "https://your.odd.platform"
```

```java
@Value("${odd.platform-base-url:}")
private String platformBaseUrl;

@PostConstruct
void requirePlatformBaseUrl() {
    if (platformBaseUrl.isBlank() && authType != AuthType.DISABLED) {
        log.warn("odd.platform-base-url is unset. Post-logout redirect derives target from inbound Host header - at risk of X-Forwarded-Host hijack. Set odd.platform-base-url to your platform's canonical URL.");
        // Optionally fail-fast for OAUTH2 mode where logout-redirect is most operator-load-bearing
    }
}

// In each *LogoutSuccessHandler, replace:
//   String redirectTo = UriUtils.getBaseUri(exchange.getRequest().getURI());
// with:
//   String redirectTo = platformBaseUrl;   // configured at deployment time, not derived
```

Migration note: operators with multi-env deployments using the same App Registration need to deploy the same `odd.platform-base-url` ALONGSIDE the auth-mode config. Doc-side cross-link from DOC-236 explains this.

Alternative - keep Host derivation but validate against allowlist:

```java
@Value("${odd.platform-base-url.allowlist:}")
private List<String> baseUrlAllowlist;   // host:port entries

private String safeRedirectTarget(URI requestUri) {
    String inbound = UriUtils.getBaseUri(requestUri);
    if (baseUrlAllowlist.isEmpty() || baseUrlAllowlist.contains(URI.create(inbound).getHost())) {
        return inbound;
    }
    throw new IllegalStateException("Host " + URI.create(inbound).getHost() + " not in odd.platform-base-url.allowlist");
}
```

Recommended single-value `odd.platform-base-url` first - simpler operator story; allowlist is a follow-up for multi-host deployments.
