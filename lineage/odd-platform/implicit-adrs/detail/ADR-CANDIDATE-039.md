- **ADR-CANDIDATE-039** (NEW 2026-05-12C): LDAP directory query posture is "fail-loud on directory inconsistencies, silently tolerate size-limit overruns" — `LdapTemplate.setIgnorePartialResultException(false)` + `setIgnoreNameNotFoundException(false)` + `setIgnoreSizeLimitExceededException(true)`. The combination is a deliberate availability trade-off: directories with millions of users would otherwise crash group-membership queries on every login
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`LDAPSecurityConfiguration.auth.type@L51`) — single occurrence but a substantive operational-architecture decision; the deliberate (false, false, true) combination cannot occur by accident
  - **Surfaced by**:
    - `odd-platform__java__LDAPSecurityConfiguration__config-key-consumer__auth_type@L51.md:implicit_adrs.[5]` ("`LdapTemplate` is configured to fail loudly on directory inconsistencies (`setIgnorePartialResultException(false)`, `setIgnoreNameNotFoundException(false)` — lines 129-130) but to silently tolerate size-limit overruns (`setIgnoreSizeLimitExceededException(true)` — line 131). This is a deliberate availability trade-off: directories with millions of users would otherwise crash group-membership queries on every login." — intent_anchor: the three explicit `set*` calls in sequence)
  - **Decision statement**: The platform's LDAP query posture commits to TWO inconsistency-tolerance stances simultaneously: (a) FAIL-LOUD on directory inconsistencies — `setIgnorePartialResultException(false)` (a partial referral causes an exception) + `setIgnoreNameNotFoundException(false)` (a missing DN causes an exception); operators see the failure rather than silent wrong data; (b) SILENTLY TOLERATE size-limit overruns — `setIgnoreSizeLimitExceededException(true)` allows the directory's per-query size limit to truncate the result set without raising. The trade-off: a query for "all members of an admin group with 100k members" would either crash or silently truncate; the platform chooses silent truncation under the operator's assumption that group sizes are manageable. The consequence is REFACTOR-121 — an admin user whose group-membership row falls past the directory's per-query cutoff is silently demoted to USER. The choice IS deliberate (the third `set*` call is alphabetically distinct and IDE auto-complete would have surfaced the other two as adjacent options) and operational (Microsoft AD / OpenLDAP / 389 Directory all have per-query size limits, typically 1000-5000 entries).
  - **Wisdom test**: PASS. The three explicit `set*(boolean)` calls in sequence (false, false, true) constitute the intent anchor — the operator could have left all three at their defaults (Spring LDAP's default behaviour varies but typically would not have produced this combination). The trade-off is acknowledged: fail-loud where data integrity matters, fail-quiet where availability matters more than completeness. Structural for every future LDAP-query path (the template is shared across user lookup + group enumeration).
