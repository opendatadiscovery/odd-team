## Description

Brazilian-Portuguese (`odd-platform-ui/src/locales/translations/br.json`) renders the two
ODD concepts **Label** (dataset-field level) and **Tag** (entity level) inconsistently, and
overloads one term for both:

| key | line | current br value |
|---|---|---|
| `Label` | 184 | `Etiqueta` |
| `Label Name` | 185 | `Nome da Etiqueta` |
| `Labels` | 186 | `Etiquetas` |
| `Tag` | 326 | `Etiqueta` |
| `Tag Name` | 327 | `Nome da Etiqueta` |
| `Tags` | 328 | `Etiquetas` |
| `Create Label` | 72 | `Criar **Rótulo**` |
| `Delete Label` | 104 | `Excluir **Rótulo**` |
| `Edit Label` | 130 | `Editar **Rótulo**` |
| `Delete Tag` | 110 | `Excluir Etiqueta` |
| `Edit Tags` | 535 | `Editar Etiquetas` |

So **`Etiqueta` is used for both Label and Tag** (a concept collision on screens that show
both), while **Label** itself flips between `Etiqueta` (`Label`/`Label Name`/`Labels`) and
`Rótulo` (`Create`/`Delete`/`Edit Label`). ODD treats labels and tags as **distinct**
concepts, so a single rendering for both is wrong.

## Why deferred from #1776 / CTRIB-036

#1776's GATE-1-approved scope (RamanDamayeu, 2026-06-25) fixes the 6 `main search placeholder`
values + the three unambiguous pt-BR typos. This terminology split is a **semantic decision
across ~10 keys that requires a native Brazilian-Portuguese speaker** — the #1776 issue itself
names **@fredguth** (the PR #1564 author) as the natural reviewer. Deciding it inside the
contributor PR would risk shipping a wrong call into a public UI, so it is split out here.

## Suggested resolution (for the native-speaker decision)

The #1776 author's suggestion: render **Label → `Rótulo`** and **Tag → `Etiqueta`**
consistently (so the two concepts stay visually distinct). Needs @fredguth's confirmation
before any catalog edit. Affects only `br.json` (the other locales should be checked for the
same collision class as a parity follow-up).
