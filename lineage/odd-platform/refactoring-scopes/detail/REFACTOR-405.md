- **REFACTOR-405** (NEW 2026-05-19O): Cognito + Azure logout requests carry NO `state` / `nonce` CSRF parameter — the logout flow is GET-based per IdP contracts; ODD does not add CSRF protection. An attacker who tricks a victim's browser into hitting ODD's `/logout` forces the victim to log out. AWS docs strongly recommend `state`; OIDC RP-Initiated Logout 1.0 §5 RECOMMENDS `state`
  - **Category**: missing-csrf
  - **Surfaced by**:
    - `CognitoLogoutSuccessHandler.md:bugs_limitations_corner_cases.[5]` (LOW)
    - `CognitoLogoutSuccessHandler.md:security.known_security_gaps.[3]` (LOW)
    - `AzureLogoutSuccessHandler.md:security.known_security_gaps.[3]` (LOW)
  - **Statement**: ODD's OAuth2 logout flows (Cognito, Azure, Google, GitHub, ODD_IAM — all 5 siblings) issue the logout redirect with ONLY `client_id` and `post_logout_redirect_uri` (or `logout_uri`) query parameters. NO `state`, NO `nonce`. AWS docs (WebFetched 2026-05-19 status 200): "[state is] Strongly recommended if you use a redirect_uri parameter." OIDC RP-Initiated Logout 1.0 §5: "state — RECOMMENDED" to bind the logout request to the user session and prevent CSRF on the post-logout redirect. Risk: an attacker who induces a victim's browser to hit ODD's `/logout` endpoint forces the victim out (no auth bypass; the worst an attacker achieves is forcing a user to log out). LOW severity but the absence is project-wide across 5 handlers.
  - **Evidence**: `CognitoLogoutSuccessHandler.java:40-46` (no `state` / `nonce` query params) + `AzureLogoutSuccessHandler.java:38-44` (same) + sibling handlers (Google, GitHub, ODDIAM all similarly omit) + WebFetch AWS Cognito logout docs 2026-05-19 status 200 + OIDC RP-Initiated Logout 1.0 spec
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-132 NEW (per-provider revocation strategy) and ADR-CANDIDATE-133 NEW (post-logout redirect URI) — the broader logout-flow ADRs do not address CSRF. The omission is project-wide; no comment defends it.
  - **Proposed remedy**: Add a generated `state` parameter to each logout handler's query-param construction: `String state = UUID.randomUUID().toString();` then `.queryParam("state", state)` on the URI builder. Store the state in the session BEFORE the redirect, validate on return. The fix is small per-handler + requires session round-trip. Alternatively, document the trade-off explicitly (CSRF on logout is acceptable because the user is already authenticated and the worst outcome is a logout-forcing).
  - **Severity rationale**: LOW — low-severity attack vector (worst outcome is forcing a logout, no auth bypass). Project-wide absence; if the maintainer judges this acceptable, document the choice.
  - **Suggested backlog grouping**: `OAuth2 hardening sprint` (composed with REFACTOR-401/404/408 — broader logout-handler hygiene)
