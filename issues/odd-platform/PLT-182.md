> **Largely FALSIFIED on the mechanism (verified 2026-06-10, group G22); downgraded medium -> low, near REJECT-CANDIDATE.** The draft's load-bearing claims - that the disabled `namespaceName` "is still part of the submitted payload" and is "silently discarded **by the server**" - are **false**. The generated TS client strips `namespace_name` at serialization: `LookupTableUpdateFormDataToJSON` (`odd-platform-ui/src/generated-sources/models/LookupTableUpdateFormData.ts`) hard-whitelists only `{ name, description }`, and `updateLookupTableRaw` sends exactly `body: LookupTableUpdateFormDataToJSON(...)` (`generated-sources/apis/ReferenceDataApi.ts:608`, `PUT /api/referencedata/table/{lookup_table_id}`). So `namespace_name` **never reaches the wire** and the server never sees or discards it - the UPDATE contract is enforced at the FE client boundary by the generated serializer, not silently dropped server-side. The only residue is a cosmetic FE nit: the edit form is *typed* with the create shape (`LookupTableFormData`) and the namespace control is disabled in edit mode. There is no wire mismatch, no user-facing defect, and no server discard. Body retained for audit trail; the corrected facts are below.

## What

The lookup-table **edit** form reuses the **create**-shaped form data type `LookupTableFormData` (which carries `namespaceName`), and the namespace control is **disabled** in edit mode (greyed out, pre-filled with the current namespace). The original draft claimed this leaks a `namespace_name` value onto the wire that the server then silently discards. **That does not happen.** The generated client serializer for the UPDATE body (`LookupTableUpdateFormDataToJSON`) emits only `name` and `description`, so whatever `data` carries, the PUT body contains no `namespace_name` - the field is stripped client-side before the request is sent. The end behaviour (namespace immutable on edit) is honest at every layer, including the wire. The residual is purely a readability/typing nit (the edit path is typed as the create shape), with no observable consequence in code execution or for the user.

## Where

The edit form is typed with the **create** shape `LookupTableFormData` and passes the whole `data` object to `editLookupTable`:

`odd-platform-ui/src/components/MasterData/LookupTableForm.tsx:49,60-66`
```tsx
const { handleSubmit, control, reset, formState } = useForm<LookupTableFormData>({  // line 49 - CREATE shape, has namespaceName
  ...
});
...
const onSubmit = useCallback(
  (data: LookupTableFormData) => {
    const mutation$ = lookupTable
      ? editLookupTable({
          lookupTableUpdateFormData: data,        // line 63 - create-shaped data passed in
          lookupTableId: lookupTable.tableId,
        })
      : addLookupTable({ lookupTableFormData: data });
```

The namespace control is disabled (and un-required) precisely in edit mode (`LookupTableForm.tsx:119-121`: `disabled={!!lookupTable}` / `rules={{ required: !lookupTable }}`), confirming it is non-editable on update.

**But `namespaceName` does not reach the wire.** The generated client serializer for the UPDATE body whitelists only `name` and `description`, so the PUT body never contains `namespace_name` regardless of what `data` holds:

`odd-platform-ui/src/generated-sources/models/LookupTableUpdateFormData.ts`
```ts
export function LookupTableUpdateFormDataToJSON(value?: LookupTableUpdateFormData | null): any {
    ...
    return {
        'name': value.name,
        'description': value.description,   // no namespace_name emitted
    };
}
```
`odd-platform-ui/src/generated-sources/apis/ReferenceDataApi.ts:608` sends exactly that: `body: LookupTableUpdateFormDataToJSON(requestParameters.lookupTableUpdateFormData)` to `PUT /api/referencedata/table/{lookup_table_id}`.

The UPDATE contract has no `namespace_name`, and that is enforced by the serializer above (client-side), so the server is never sent the field:

`odd-platform-specification/components.yaml:3853-3862`
```yaml
LookupTableUpdateFormData:
  type: object
  properties:
    name:
      type: string
    description:
      type: string
  required:
    - name
```

(Contrast the CREATE shape immediately above it, `LookupTableFormData` at `components.yaml:3840-3851`, which declares `name`, `description`, **and** `namespace_name`, with `name` + `namespace_name` required.)

## User-facing impact

**None (verified 2026-06-10, group G22).** Namespace is immutable on lookup-table edit at every layer: the control is disabled in the UI (`LookupTableForm.tsx:120`), the field is stripped from the request body by the generated serializer (`LookupTableUpdateFormDataToJSON`), and the server-side contract has no `namespace_name` to begin with. There is no wire payload carrying a discarded field, so the "I changed the namespace and it didn't save, with no error" scenario the original draft posited cannot occur via the UI - the operator cannot change it (disabled) and nothing about a namespace edit is ever transmitted. No user-facing symptom; `user_facing_verified` stays `false` (nothing to drive - there is no defect to observe).

## Why it matters

Down-scoped from "contract/UI honesty defect" to a **cosmetic FE typing nit**. The substantive claim - a wire payload carrying a field the server silently drops - is falsified: the generated client serializer enforces the UPDATE contract before the request leaves the browser. What remains is only that the edit path is typed with the create shape (`LookupTableFormData`) rather than the update shape (`LookupTableUpdateFormData`); a careful reader still has to follow the generated serializer to confirm `namespaceName` is dropped, so the type-reuse is mildly misleading in code review. That is a low-value readability tidy-up, not a defect with any runtime or user-facing consequence. Severity low; arguably a REJECT-CANDIDATE since the described mechanism does not exist.

## Suggested fix

Optional FE tidy-up only (no contract or server change is warranted):

- Type the edit path to the UPDATE shape (`LookupTableUpdateFormData`) instead of reusing `LookupTableFormData` for both create and update (`LookupTableForm.tsx:49,60-66`), so the code reads honestly and a reviewer does not have to consult the generated serializer to confirm `namespaceName` is not sent.

No server-side "reject unexpected `namespace_name`" change is needed: the field never reaches the server. The earlier "discard-vs-reject" framing is moot - there is no server-side discard to make explicit.
