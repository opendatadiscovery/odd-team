## Description

When S2S is enabled alongside `LOGIN_FORM`, a single request that presents BOTH an authenticated session cookie AND a valid `X-API-Key` does not run as the logged-in user — it resolves to the built-in `ADMIN`. The API key wins. The s2s page documents the fall-through case ("if a request has no `X-API-Key` header — or the value doesn't match — the filter falls through and the normal auth chain handles the request", `s2s.md` line ~14) but is silent on the both-present case, leaving the precedence undocumented.

Mechanism:

- Under `LOGIN_FORM` with `auth.s2s.enabled: true`, the S2S filter is inserted into the chain at the HTTP-Basic position: `sec.addFilterAt(s2sAuthenticationFilter, SecurityWebFiltersOrder.HTTP_BASIC)` (`LoginFormSecurityConfiguration.java:61-63`).
- `S2sAuthenticationFilter.filter(...)` checks the `X-API-Key` token first; if it is valid it builds an `ADMIN` principal (`User.withUsername("ADMIN")...roles("ADMIN")`) and writes that authentication into the reactive security context via `.contextWrite(ReactiveSecurityContextHolder.withAuthentication(...))` (`S2sAuthenticationFilter.java:31-39`). Only when the token is invalid/absent does it fall through untouched (`S2sAuthenticationFilter.java:27-29`).
- So when a valid key is present, the request carries the S2S-supplied ADMIN authentication regardless of any session cookie also on the request — the key-derived ADMIN context takes effect.

**How it misleads an operator.** An operator reasoning "S2S only matters for non-human callers that don't have a session" can be surprised when a browser/automation context that happens to carry both a logged-in cookie and the shared key has its mutations attributed to the built-in `ADMIN` (with full ADMIN role), not to the signed-in user. For activity-feed attribution and least-privilege expectations this matters: a request a least-privileged user thought ran under their own permissions actually ran as ADMIN because the key was also attached. The behaviour is intended (S2S is a global ADMIN grant); the gap is purely that the precedence is undocumented.

DOC-172 (the s2s caveats item, status `done`) **explicitly listed this facet as NOT folded in** ("api-key-at-HTTP-Basic overrides session cookie under LOGIN_FORM", DOC-172 Context, "Not folded in from F-088"). This item picks up that deferred facet.
