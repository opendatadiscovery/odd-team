## Description

DOC-308 corrected `configuration-and-deployment/odd-platform.md` (§ Management endpoint exposure and credential hygiene) to state the verified `/actuator/env` posture at odd-platform `@ ede5d277`: **no `show-values` key is set anywhere**, so Spring Boot 3.4.10's default (`NEVER`) applies and `/actuator/env` masks **every** property *value* (`******`) — including `spring.datasource.url` — for **all** callers, authenticated or not. What an unauthenticated caller actually learns is the **configuration-key schema** (which keys / property sources exist), not the values.

That correction landed on the canonical page only. Four other published surfaces still carry the pre-correction model — the same phantom-`WHEN_AUTHORIZED` / "URL leaks in clear text" framing DOC-308 was created to retire — and now **contradict** the corrected `odd-platform.md`:

1. **`deployment.md:206`** (verbatim): *"…`/actuator/env` is exposed and not behind auth, so it returns `spring.datasource.url` (your PostgreSQL host/port/db-name) **in clear text** (the password value itself is masked)."* — FALSE under default `NEVER`: the URL *value* is masked like every other value. (HIGH)
2. **`deployment.md:245`** (verbatim): *"The endpoint **masks values whose key looks like a secret** (so the DB *password* is redacted), but it returns `spring.datasource.url` … and any configured Slack / webhook URLs **verbatim**."* — FALSE: masking is not key-pattern-selective under `NEVER`; all values are masked. (HIGH)
3. **`quick_launch_on_amazon_elastic_kubernetes_service.md:159`** (verbatim): *"…the **password is the only part that gets masked**. The endpoint still returns `spring.datasource.url` … **in clear text**."* — FALSE, same as above. (HIGH)
4. **`disabled-authentication.md:36`** (verbatim): *"Property *values* are redacted (`show-values: WHEN_AUTHORIZED`), but the **keys themselves** are still informative…"* — the *conclusion* (values redacted, keys informative) is correct, but the **`show-values: WHEN_AUTHORIZED` attribution is the phantom value** — no such key is set; the default is `NEVER`. (MEDIUM)
5. **`data-collaboration.md:52`** (verbatim): *"Spring's default property-source sanitiser **masks `token`-suffixed property names** in `/actuator/env` output…"* — implies selective (key-pattern) masking; under default `NEVER` **all** values are masked. The Slack-token "only-protection" point still stands; only the masking characterisation needs a light touch. (LOW)

The operator harm gradient: surfaces 1-3 are *actively wrong* on a security-posture claim (they tell operators the JDBC URL host:port:db is readable by anonymous callers, when it is masked) and contradict the corrected canonical page — the "ODD docs lie" trust risk. The direction is conservative (overstates the leak → operators lock down harder), which is why this is HIGH, not critical (no data-loss / no security *hole* is introduced by the wrong text).

**Failure shape**: parallel surfaces with drift / internal contradiction — the same wrong-fact-replicated-across-surfaces pattern as DOC-287→DOC-305, here created by DOC-308 correcting one of five surfaces. DOC-308's bi-directional duplication sweep (Gate 1) reconciled the two *backlog* items (DOC-242, DOC-239 context blocks) but under-counted the *published* surfaces.
