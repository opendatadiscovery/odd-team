- **ADR-CANDIDATE-060** (NEW 2026-05-12F): Bulk mutations that don't fit the single-resource shape of `@ActivityLog` AOP use **programmatic activity-event emission** at the service layer — `DataEntityInternalStateServiceImpl.logStatusChangeEvents(oldStates, ids)` is the canonical pattern, emitting per-affected-entity activity events with `oldState` captured before the bulk mutation. The decision codifies "AOP for single-resource writes; programmatic emission for bulk writes that need per-resource events"
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`updateStatus`) but anchored against the contrast with `@ActivityLog` AOP usage in `OwnershipServiceImpl.create` (batch-F createOwnership sidecar's implicit_adrs[1]). The two-side contrast within the same batch makes the decision explicit
  - **Surfaced by**:
    - `odd-platform__java__DataEntityController__controller-method__updateStatus.md:implicit_adrs.[4]` ("Status transitions are recorded as `DATA_ENTITY_STATUS_UPDATED` activity events with explicit `oldState` and `newState` payloads, captured at the service layer (not via a `@ActivityLog` AOP intercept, unlike most other mutation paths in this service). The handler emits the (status, status_switch_time) tuple JSON-serialised for both states." — intent_anchor: "Programmatic event emission (vs. AOP) is required here because the mutation is bulk (`bulkUpdate(pojos)`) and the `oldState` must be captured per-pojo before the in-place mutation; the AOP intercept's single-resource shape (`@ActivityParameter(...)` on a method arg) does not fit.")
  - **Decision statement**: ODD's activity-feed emission uses TWO patterns depending on the mutation shape: (a) **AOP via `@ActivityLog`** for single-resource writes — the annotation on the service method (e.g., `OwnershipServiceImpl.create` at line 48 with `@ActivityLog(event = OWNERSHIP_CREATED)`) intercepts at the method boundary; the handler captures the resource ID from `@ActivityParameter(...)` on a method arg and reads BEFORE/AFTER state via repository calls; (b) **programmatic emission** for bulk mutations — `DataEntityInternalStateServiceImpl.logStatusChangeEvents(oldStates, ids)` at lines 164-169 is the canonical pattern: the service captures `oldState` per-pojo BEFORE the in-place bulk mutation, then emits one activity event per affected entity after the write commits. The decision codifies: (i) the AOP shape's single-resource constraint (`@ActivityParameter` binds to a single method arg) cannot handle N-entity bulk writes where each entity needs its own oldState capture; (ii) the programmatic emission shape preserves the per-resource granularity in the audit log while supporting bulk operations. Trade-off: a future refactor that calls `dataEntityRepository.bulkUpdate(updatedPojos)` directly (bypassing the internal-state service) would silently lose the audit row — the activity-emission is a service-method invariant the maintainer must preserve, not an AOP-protected contract.
  - **Wisdom test**: PASS. The two-pattern split (AOP for single-resource, programmatic for bulk) is the intent anchor; the maintainer could have refactored `@ActivityLog` to accept a list arg (more complex AOP) or skipped the per-entity audit for bulk writes (worse audit fidelity). Choosing programmatic emission for bulk + AOP for single-resource is the deliberate boundary. Structural for every future bulk-write endpoint on the platform.
  - **Evidence**:
    - updateStatus.md says: "DataEntityInternalStateServiceImpl.java:155-182 (programmatic activity-event construction with `oldState` captured before the mutation and `newState` resolved after) + DataEntityStatusUpdatedActivityHandler.java:39-63 (the handler's `getState(pojo)` JSON-serialises the tuple)"
    - createOwnership.md says (contrast): "OwnershipServiceImpl.java:48 (`@ActivityLog(event = OWNERSHIP_CREATED)`) + OwnershipCreatedActivityHandler.java:11-37 (the AOP-driven single-resource pattern)"
  - **Existing ADR**: none. Composes with ADR-CANDIDATE-059 (service-layer transactional boundary — the activity-emission lives inside the transaction, so a rollback also rolls back the audit event for AOP; programmatic emission is similarly transaction-scoped).
