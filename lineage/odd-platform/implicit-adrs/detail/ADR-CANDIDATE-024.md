- **ADR-CANDIDATE-024** (NEW 2026-05-10B): `AppInfo` response intentionally publishes the active authentication mode (and project version) to clients so the frontend SPA can render the appropriate login flow without a prior authentication round-trip — the consumer is **reporter-not-reactor** (`@Value("${auth.type}")` reading the raw string for reporting, vs `@ConditionalOnProperty(havingValue="...")` for behaviour-gating)
  - **Category**: promote
  - **Support**: surfaced by 1 sidecar (`AppInfoController.auth.type@L18`) — single occurrence but contract-defining; the published `AppInfo.authType` field is part of the OpenAPI spec, not an accidental leak
  - **Surfaced by**:
    - `odd-platform__java__AppInfoController__config-key-consumer__auth_type@L18.md:implicit_adrs.[0]` ("AppInfo response intentionally exposes the active auth mode to clients so the frontend SPA can render the appropriate login flow without a prior authentication round-trip." — intent_anchor: "the OpenAPI contract `AppInfoApi.java:43` documents the endpoint as `GET /api/appInfo : Get application info` and the model `AppInfo.java:48-66` exposes `authType` as a first-class field with `@JsonProperty(\"authType\")` — the field is part of the published contract, not an accidental leak.")
    - `odd-platform__java__AppInfoController__config-key-consumer__auth_type@L18.md:implicit_adrs.[1]` ("The auth-mode switch is a global runtime switch consumed by mutually-exclusive `@ConditionalOnProperty(value=\"auth.type\", havingValue=...)` configurations; `AppInfoController` deliberately bypasses that pattern and reads the raw string so it can report the mode rather than react to it." — intent_anchor: "the parallel structure across four `*SecurityConfiguration` classes consistently uses `@ConditionalOnProperty`; this controller's single deviation to `@Value` is the reporter-not-reactor pattern.")
  - **Decision statement**: `AppInfoController` is the single consumer of `auth.type` in the codebase that reads the property as a raw `String` via `@Value("${auth.type}")` rather than reacting to it via `@ConditionalOnProperty(havingValue=...)`. The decision is deliberate: every other `auth.type` consumer (`DisabledAuthSecurityConfiguration.java:10`, `LoginFormSecurityConfiguration.java:31`, `OAuthSecurityConfiguration.java:71`, `LDAPSecurityConfiguration.java:51`, `AuthorizationManagerCondition.java:11,15`) is a *reactor* — its bean is wired only when the property matches a specific value. `AppInfoController` is the *reporter* — it reads the value verbatim and round-trips it into the OpenAPI-published `AppInfo.authType` field so the React SPA can render the appropriate login flow before any authentication round-trip. The decision commits the platform to "active auth mode is a deployment-introspection contract" — operators cannot disable this disclosure without breaking the SPA.
  - **Wisdom test**: PASS. The `@Value` vs `@ConditionalOnProperty` parallel-structure across five files is the intent anchor; the OpenAPI contract publication of `AppInfo.authType` confirms it is a deliberate first-class field, not an accidental leak; structural (the published `AppInfo` model carries this field across every API consumer).
  - **Evidence**:
    - AppInfoController.md says: "AppInfoController.java:18 (`@Value(\"${auth.type}\") final String authType`) vs DisabledAuthSecurityConfiguration.java:10 / LoginFormSecurityConfiguration.java:31 / OAuthSecurityConfiguration.java:71 / LDAPSecurityConfiguration.java:51 (all `@ConditionalOnProperty(value=\"auth.type\", havingValue=...)` constructions). The parallel structure across four `*SecurityConfiguration` classes consistently uses `@ConditionalOnProperty`; this controller's single deviation to `@Value` is the reporter-not-reactor pattern."
    - AppInfoController.md says: "AppInfo.java:48-66 — `authType` is a first-class published field with `@JsonProperty(\"authType\")`; the OpenAPI-generated `AppInfoApi.java:43` documents the endpoint as `Get application info`."
  - **Existing ADR**: none.

Cross-link with ADR-CANDIDATE-002 (centralised SECURITY_RULES) — `/api/appInfo` should arguably be added to `SecurityConstants.WHITELIST_PATHS` so it is reachable BEFORE authentication completes under LOGIN_FORM/OAUTH2/LDAP (the current configuration likely relies on some other mechanism for pre-auth reachability under LOGIN_FORM; verify and document).
