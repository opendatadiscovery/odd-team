## Description

The DOC-312 + DOC-314 re-review (2026-05-30) corrected two factually-wrong claims on the **published docs** (now live and verified). But the cross-tree residue sweep found both claims still alive across the **ontology substrate** (`lineage/`), where they originated. The published-doc deliverables are correct; this item closes the substrate so the next `/doc-gap-check` refresh does not regenerate the same wrong findings.

Two claim families:

**(A) Policy-delete "keeps granting" — operator-inference-false.** The substrate asserts an operator who deletes a policy through the UI leaves bound roles still granting. The code makes that **unreachable**: `PolicyServiceImpl.delete` cascade-blocks with `CascadeDeleteException("Policy is attached to a role")` while any `ROLE_TO_POLICY` row references the policy (verified @ ede5d277; see DOC-314). The **query-level** fact is true (`getRolesPolicies` omits `deleted_at IS NULL`) but the **operator-facing inference** is wrong; the genuine residual is the narrow raw-API ghost-grant tracked by **PLT-110** (re-scoped).
- `lineage/odd-platform/doc-gaps.md:707-708` — DOC-GAP-165 evidence ("operator … sees it gone but it keeps granting") + `proposed_doc_action` proposes the **wrong** danger admonition (now superseded by the shipped code-true note).
- `lineage/odd-platform/understanding/…PolicyList.md:165` — **HIGH-severity** finding asserting "an operator using this UI to 'remove' a policy … cannot tell that the role-binding survives and the policy keeps granting." Re-frame: the UI **blocks** deleting a bound policy; the residual is non-UI (raw API).
- `concepts/…rbac-soft-delete-persistence…yaml:96` + `feature-flows/index.yaml:7447` — "keeps granting" framing; re-scope to query-level + the non-UI residual.

**(B) GitHub `user-name-attribute: login` "default" — false default.** The substrate asserts `login` is the default `user-name-attribute`. There is **no code default**: `GithubUserHandler.java:53` reads `provider.getUserNameAttribute()` with no fallback; `ODDOAuth2Properties.java:44` is a bare field; an unset value throws at `DefaultOAuth2User` construction (verified @ ede5d277; see DOC-312). `login` is what the example configures. The query-level identity-keying facts are correct; only the "default" framing is false.
- `understanding/…GithubUserHandler.md:66` — false "default `login`" **and a fabricated live-doc quote**: claims live docs WebFetched 2026-05-19 say *"Defines the username token claim (default: login)"*. The live page (`oauth2-oidc.md:52`) says only *"Defines which token claim should be picked as username"* — **no default**. This is a fabricated-citation substrate error; correct it and audit the sidecar's other quotes.
- `understanding/…GithubUserHandler.md:163`, `doc-gaps/detail/DOC-GAP-177.md:1`, `refactoring-scopes/detail/REFACTOR-391.md:1`, `shoebox/…SHB-104…:12`, `feature-flows/detail/F-011.yaml:201`, `concepts/…user-owner-mapping.yaml:442` — all repeat "default `user-name-attribute: login`". ## The class, not the instance (methodology root-cause — the higher-value finding)

Both families share one root: **a reducer asserted an operator-facing consequence from a single query/constant without tracing the guarding code path.** The doc-gap-finder read `getRolesPolicies` (omits `deleted_at`) and inferred "operator deletes → keeps granting" — never reading `PolicyServiceImpl.delete`'s cascade guard. A sidecar read `USER_LOGIN = "login"` and inferred "default `login`" — never reading that the handler has no fallback. This is **Gate 4 (consumer-read) incompleteness at the reducer/sidecar layer** — the same class that ships backwards caveats (it produced DOC-314's first, 180°-wrong implementation).

**Proposed methodology guard:** a `/doc-gap-check` (and per-node enrichment) finding that asserts an *operator-facing consequence* ("operator does X → Y happens") must cite the **full operator path** — the entry-point/controller, the service guard, AND the repository query — not the single query that surfaced it. A finding citing only one query may state the query-level fact but must **not** state an operator inference. Candidate retrospective: "reducer-asserted operator consequences must pass guard-path consumer-read before triage." Maintainer owns the LSN decision.
