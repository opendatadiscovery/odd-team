## What

The Recently Viewed foundation (#1816) shipped a 5-item **Recently Viewed** panel in the main-page Recommended
block, but with no "View all" affordance: the original design's standalone Recently Viewed *tab* was
deliberately dropped in favour of the unified faceted Search (#1825), which gains a recently-viewed filter.

Close that loop: the panel's header (and/or a "View all" link) should **deep-link into the unified Search with
the recently-viewed filter applied** — i.e. Search scoped to the current user's assets whose `last_viewed_at`
is not null, most-recent-first. That gives the user the full, filterable history the dropped tab would have
provided, reusing the new Search surface instead of a parallel one.

## Where

- **Panel** — `odd-platform-ui/.../Overview/OwnerAssociation/OwnerEntitiesList/RecentlyViewedColumn/`
  (the column ships today **without** a "View all" — see #1827 and the foundation PR). Add the link/target here.
- **Filter foundation** — the read API already supports recency bounds: `GET /api/recently-viewed/list` accepts
  `viewed_after` / `viewed_before` (shipped with #1816). The Search-side recently-viewed filter is **#1825**'s
  to build; this issue only wires the panel entry-point to it.
- **Target URL/state** — whatever query-param / filter-state shape #1825 settles on for "recently viewed != null"
  (e.g. `/search?recently_viewed=true` or the facet equivalent). This issue must conform to #1825's final shape.

## User-facing impact

A user opens the main page, sees their 5 most-recent assets in the Recommended → Recently Viewed panel, clicks
"View all", and lands in Search pre-filtered to their recently-viewed assets (most-recent-first), where they can
refine with the other facets. No separate, parallel "Recently Viewed" list surface to maintain.

## Why it matters

It is the last piece of the #1816 vision (the panel was always meant to lead somewhere) and it keeps the
catalog to a **single** search/list surface rather than a panel that dead-ends. Strictly blocked on #1825
delivering the recently-viewed Search filter + its URL/filter-state contract.

## Dependencies / sequencing

- **Blocked by #1825** (the recently-viewed Search filter + its filter-state contract).
- Trivial once #1825 lands: a link + the correct target state + a small e2e asserting the panel → filtered
  Search round-trip (assert the user-observable result, not a forced navigation — per the test-integrity lesson
  from #1816's list-reachability fix).

## How discovered

Surfaced while closing #1816 (Recently Viewed). The foundation shipped (record-on-open, per-user history, the
main-page panel, cross-surface recency, per-row remove, retention); the standalone tab + "View all" target were
deferred to the #1825 Search overhaul. This issue tracks the remaining hand-off so it is not lost when #1816
closes.
