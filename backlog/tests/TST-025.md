## Description

On the per-entity **Alerts** tab, each alert row (`DataEntityAlertItem`) holds its expand/collapse "show history" state in a **component-local** hook: `const [showHistory, setShowHistory] = React.useState(false);` (`DataEntityAlertItem.tsx:36`). The parent `DataEntityAlerts` renders the list under `react-infinite-scroll-component` and re-fetches on a redux thunk (`fetchDataEntityAlerts({ dataEntityId, page, size })`, page-resetting `useEffect` keyed on `dataEntityId` at `DataEntityAlerts.tsx:31-35`; `fetchNextPage` paging at lines 46-49). Because `showHistory` lives in the row, not in redux or a stable list key, an operator who expands an alert's history and then triggers a remount — InfiniteScroll appending the next page, the alert list re-fetching, or the OPEN↔RESOLVED status mutation re-rendering the list — may have that expansion silently collapse. The harvest tracks this as the F-198 facet `alert_item_show_history_button_loses_state_on_remount`; survival across remount is **asserted by reading the source, not by a test**.

**Typed gate: characterization-pin (LSN-029).** The behaviour is a suspected UX defect (state loss on remount), not a confirmed-correct feature, and there is no upstream code fix in flight. The test therefore PINS the **current** observed behaviour: it drives the real Alerts tab, expands a row's history, forces a list remount, and asserts what actually happens. If the run confirms the loss, the pin asserts the loss (the panel stays/collapses as observed) and goes RED the instant a fix (lifting `showHistory` to redux or a stable keyed list) preserves it — at which point the assertion inverts to `@regresses` per the LSN-029 flip protocol. Never `@Disabled` — a disabled test pins nothing. The probe `PENDING-F-198-1` is the obligation to MEASURE the survival behaviour before the assertion direction is frozen; this item folds into the PLT-050 Alerts-UX cluster.
