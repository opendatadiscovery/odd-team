## Description

`documentation/docs/master-data-management/lookup-tables.md:164` opens the "Known operator caveats"
section with:

> Six behaviours of the Lookup Tables surface are non-obvious from the UI alone. Each item below states
> what an operator might assume, what the platform actually does, and what to do today.

On the `release/0.29.0` train the section renders **five** `{% hint %}` blocks, not six:

1. (danger) `LOOKUP_TABLE_*` permissions are global — no per-table RBAC
2. (info) Deleting a Lookup Table removes both halves
3. (danger) Renaming silently breaks downstream BI / ETL
4. (warning) Values stored/rendered without escaping — trusted-input surface
5. (info) Where a Lookup Table's description appears  ← the CTRIB-032 / #1781 info-note

This is an **internal-contradiction** (count drift) a reader hits on the published page.

### Why the train shows five

`docs/main` carries two additional caveats that were added **after** `release/0.29.0` forked — the
"list silently truncates at 30 rows" and the "rename emits no Activity Feed event" hints (visible in
`git diff origin/main..origin/release/0.29.0 -- docs/master-data-management/lookup-tables.md` as
train-side deletions). They are **base-skew**, not removed by any train commit: CTRIB-032's only doc
commit (`9e35fcb`) *converted* the description caveat (warning→info), it did not remove a block. A
normal 3-way merge at the 0.29.0 release gate restores main's two caveats onto the train.
