## Description

The live `/user-owner-association` page describes only TWO flows — an "admin" path (which the doc claims is "Select owner...press Associate") and a user path ("Select owner...press Send request → admin approves"). The page is silent on a third existing branch — the `DIRECT_OWNER_SYNC` auto-approve short-circuit at `OwnerAssociationRequestServiceImpl.createOwnerAssociationRequest` (sidecar references `OwnerAssociationRequestServiceImpl.java:55-67,184-190`). When the requester holds `Permission.DIRECT_OWNER_SYNC`, the service immediately fires `userOwnerMappingService.createRelation` AND emits `OwnerAssociationRequest.status=APPROVED`, bypassing the admin-approval roundtrip the doc describes.

Operator-visible consequence: a deployment that grants `DIRECT_OWNER_SYNC` to a custom Policy (intending to fast-path OIDC-group-mapped users) cannot discover from the doc that the auto-approve branch exists. Operators tick the `DIRECT_OWNER_SYNC` box trusting the bare permission description without realizing they are bypassing the entire admin-approval workflow.
