## Description

The live `odd.links` section of `odd-platform.md` documents global visibility — "The links are exposed to the UI through the authenticated `GET /api/links` endpoint and are visible to every user signed in to the platform" (`odd-platform.md:989`, shipped by DOC-257) — and warns against embedding secrets in link URLs. It is **silent on two further access angles** that an operator reasoning about "who can read my operator links" needs:

**Angle 1 — under `auth.type=DISABLED`, `/api/links` is reachable anonymously, not just by signed-in users.** The current sentence says "every user signed in," which is accurate for `LOGIN_FORM`/`OAUTH2`/`LDAP` but understates `DISABLED`. `/api/links` is **not** in the security whitelist (`LoginFormSecurityConfiguration.java:49-51` whitelists only `/actuator/health`, `/favicon.ico`, `/ingestion/entities`, `/ingestion/datasources`, `/api/slack/events`), so it falls to `pathMatchers("/**").authenticated()` (`:57`). Under `DISABLED` the entire chain short-circuits to `anyExchange().permitAll()` (`DisabledAuthSecurityConfiguration.java:16`) — there is no "signed in" at all, and the links (including anything an operator put in their titles/URLs) are served to **any unauthenticated caller** who can reach the platform.

**Angle 2 — there is no per-role visibility scope on operator links — it is all-or-nothing.** `/api/links` carries no method-level authorization (no `@PreAuthorize`/`@Secured`), and the platform exposes no mechanism to show a given link only to a given role/owner/team. Every link in `odd.links` is visible to **every** reader at once; an operator cannot publish, e.g., an "admin runbook" link to admins only. The visibility is the chain-level posture (authenticated-everyone, or anonymous-everyone under DISABLED), full stop.

How it misleads an operator: the "visible to every user signed in" framing implies a logged-in audience and implies links are a per-user-but-uniform surface. An operator running `DISABLED` (a common single-tenant / behind-VPN posture) may not realise the link set — and any internal URL or hint encoded in it — is served with no authentication at all; and an operator wanting role-scoped links has no signal that the feature does not exist.
