## Description

The live `configuration-and-deployment/odd-platform` page is **silent on three operator-facing defaults** that together turn a default ODD deployment into a one-line-away-from-full-PG-compromise system. The `enable-security/*` pages cover auth-mode-specific posture; this page is the operator's REFERENCE for environmental defaults — and it does not warn about three shipped-default classes that bypass auth-mode posture entirely.

**Facet 1 — `/actuator/**` whitelisted — unauthenticated credential-schema enumeration on EVERY auth mode (F-122a, HIGH→CRITICAL).** `SecurityConstants.java:95-96` `WHITELIST_PATHS` contains `/actuator/**`. Reachable BEFORE auth in every mode (not just DISABLED). `application.yml:226-242` enables `management.endpoint.env.enabled=true` + `show-values=WHEN_AUTHORIZED`. An attacker scraping `/actuator/env` learns the SCHEMA of configured credentials: which OAuth2 providers are wired (Google/Azure/Cognito key prefixes), whether LDAP is configured, whether REMOTE attachment storage is set up, the JDBC URL `host:port:dbname`. Network-level mitigation (firewall / separate management port) is required; platform default does NOT provide it.

**Facet 2 — Lombok `@Data` includes credentials in `toString()` unfiltered (F-122b, MEDIUM→HIGH).** `ODDLDAPProperties.java:10, 14` carries `@Data` + a `password` field. `ODDOAuth2Properties.java:30, 34` carries `@Data` + a `clientSecret` field on `OAuth2Provider`. Lombok's `@Data` generates `toString()` including the credential verbatim. NO `@ToString.Exclude` on any password / secret / key / token field. A future `log.info("loaded properties: {}", properties)` line — or an exception-handler emitting properties on boot failure — emits LDAP password / OAuth secrets cleartext into log infrastructure.

**Facet 3 — `spring.datasource.password=odd-platform-password` shipped default (F-122c, MEDIUM→HIGH).** `application.yml:7` ships `odd-platform-password` as the default DB password. An operator forgetting to override deploys with a public well-known credential. Combined with Facet 1 leaking the JDBC URL via `/actuator/env`, deployments are one operator-override-skip away from full PG compromise. **LSN-001-pattern**: silent insecure default, doc-only warning absent, no programmatic guardrail.

## Acceptance Criteria

- [ ] A new "## Management endpoint exposure & credential hygiene" H2 section is added (positioning: near the existing logging/metrics block, before the auth-mode-pointer section). Structure:
  - **`/actuator/**` is anonymously reachable in every auth mode** — the `WHITELIST_PATHS` array in `SecurityConstants` bypasses auth for `/actuator/**`. `application.yml` enables `endpoint.env.enabled=true` with `show-values=WHEN_AUTHORIZED`; an unauthenticated caller learns the SCHEMA of configured credentials (which OAuth2 providers, LDAP wiring presence, JDBC URL host:port:dbname). Operator-side mitigations (recommendation table):

    | Mitigation | How | Recommended for |
    |---|---|---|
    | Separate management port | `management.server.port: 8081` (route `:8081` to internal-only network) | All production deployments |
    | Firewall the actuator path | nginx/proxy rule rejecting `/actuator/**` from public CIDR | Single-port deployments |
    | Restrict default exposure | `management.endpoints.web.exposure.include: health,prometheus` (drop env, info) | All production deployments |

    Until PLT-078 restricts the platform default, operators MUST take one of these mitigations.

  - **Lombok `@Data` includes credentials in `toString()`** — properties classes (ODDLDAPProperties, ODDOAuth2Properties.OAuth2Provider) carry `@Data` with password/clientSecret fields. There is NO `@ToString.Exclude`. A future `log.info("loaded: {}", properties)` line or an exception that emits properties on boot failure would leak credentials into log infrastructure. Until PLT-079 ships, operators should treat application logs as credential-sensitive.

  - **`spring.datasource.password` ships a well-known default** — `application.yml` ships `odd-platform-password` as the database password. An operator forgetting to override deploys with a public credential. Combined with the `/actuator/env` JDBC-URL leak above, this is a one-line-away-from-compromise default. Operators MUST override `spring.datasource.password` AND `spring.custom-datasource.password` (when set) before production. Track PLT-080 for dropping the shipped default.

## Platform-side follow-up filed

- **PLT-078** — Restrict default `management.endpoints.web.exposure.include` to `health, prometheus`; require explicit opt-in for `env, info`. Add doc admonition that actuator runs on the main port (platform-side guidance to set `management.server.port`).
- **PLT-079** — `@ToString.Exclude` on every credential field in ODDLDAPProperties + ODDOAuth2Properties + any other `*Properties.java` carrying `@Data` + credential fields.
- **PLT-080** — Drop `spring.datasource.password` default from `application.yml`; require explicit operator config; add startup self-check that the default has been overridden.
