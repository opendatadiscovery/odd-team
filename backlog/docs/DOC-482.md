## Description

`documentation/docs/management.md:85` describes the cascade-block delete UX for the
Owner / Namespace / Datasource trio:

> Both errors render through the same `ControllerAdvice` chain as a toast on the UI; the operator
> sees a brief "cannot be deleted" message and **the dialog stays open with the cancel option highlighted.**

The "**cancel option highlighted**" clause is a **doc-claim-vs-code drift**. The dialog behind these
deletes is the shared `ConfirmationDialog` (→ `DialogWrapper`). On a failed/refused confirm it renders:
the title + an **X close icon** (top-right), the "Are you sure…" content, an **inline error line**
(`errorText`), and the **single action button** (e.g. "Delete"). There is **no distinct "Cancel" button**
to highlight. The only "Cancel" button in `DialogWrapper` lives in its `confirmOnClose` "Are you sure you
want to close this form?" sub-dialog — and `ConfirmationDialog` never sets `confirmOnClose`, so that
sub-dialog never appears here.

The accurate behaviour (true for BOTH dialog arms — the TanStack `mutateAsync` arm shipped in #1797 and the
redux-thunk arm completing in 0.29.0 / CTRIB-031): the dialog **stays open with the failure surfaced
inline**; the operator dismisses it via the X close icon or retries the action. There is no highlighted
cancel affordance.
