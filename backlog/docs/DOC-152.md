## Description

Editorial-audit finding from `/review batch:feature/state-doc141-ia-refactor-2026-05-07` 2026-05-07.

`docs/Architecture.md` L38 (Cross-cutting concerns → Search) reads:

> *"**Search.** Free-text plus seven facets (entity class, data source, namespace, owner, tag, type, group). Complemented by the Directory's hierarchy-driven browse. See [Data Discovery](data-discovery.md)."*

The new canonical home for Search — `docs/data-discovery/search.md` (DOC-142, this batch) L19-27 — enumerates the **seven** facets correctly:

1. **Datasource** — single-select.
2. **Type** — multi-select; only shown after an entity-class tab is selected at the top of the Catalog.
3. **Namespace** — single-select.
4. **Owner** — multi-select.
5. **Tag** — multi-select.
6. **Groups** — multi-select.
7. **Statuses** — multi-select; e.g. `STABLE`, `DEPRECATED`.

The Architecture.md list says "seven facets" but enumerates **(entity class, data source, namespace, owner, tag, type, group)** — which mismatches in two ways:

- **`entity class` is not a facet.** It is the **top-level tab strip** at the top of the Catalog page (Datasets / Transformers / Data Consumers / Data Inputs / Quality Tests / Groups / Relationships) — selecting a tab is what *unlocks* the `Type` facet. Listing it as a facet conflates the tab and the facet.
- **`Statuses` is missing.** It is one of the seven facets per the new search.md (and confirmed against the live UI screenshot at `data-discovery.md:13`'s `search-facets.png`).

Net effect: Architecture.md L38 lists 7 items but they are 6 actual facets (data source, namespace, owner, tag, type, group) plus 1 mislabelled non-facet (entity class), and is missing 1 actual facet (Statuses).

This wasn't introduced by the IA refactor batch — the old text predates the carve-out — but the batch updated Architecture.md L37 (the Lineage line, redirected from `Features.md#end-to-end-data-objects-lineage` to `data-lineage/data-objects.md`) without aligning the adjacent L38 Search line. The reviewer caught it on cross-reference between Architecture.md and the new search.md.

## Acceptance Criteria

See [Data Discovery](data-discovery.md) and the dedicated [Search and Filtering](data-discovery/search.md) page for the per-facet semantics and the per-result transparency icons."*

## Context

- **Why low priority.** Architecture.md is the structural mental model — operators reading it form a high-level picture before diving into the detail pages. The defect is mild (the count is right, the list is partial) and Search has its own canonical home now where the correct list lives. Operators landing on `data-discovery/search.md` get the accurate enumeration. The Architecture.md text only causes confusion if read as a standalone reference rather than as a pointer-to-detail.
- **Why this is worth filing.** It is exactly the sort of "old framing not updated when the canonical home moved" drift the Gate 7 IA-coherence check should catch on `/review`. The reviewer caught it; logging it on disk per `playbooks/follow-up-on-disk.md` is how the system stays honest.
