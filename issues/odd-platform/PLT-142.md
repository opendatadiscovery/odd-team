## What

`POST /ingestion/entities/datasets/stats` (the dataset-statistics ingestion endpoint) performs no input
validation. Three facets, all confirmed live against the `:latest` image (odd-minimal):

1. **Malformed/empty body -> 500, not 4xx.** An empty body or a JSON `null` body returns **HTTP 500**
   (server error) instead of a clean `400`. (`{}` returns 201.)
2. **Unknown/typo'd field ODDRN -> silent 201.** Stats keyed by a field ODDRN that does not exist on the
   dataset are **silently accepted (201)** and dropped - no `4xx`, no logged warning. A collector author
   who typos a field ODDRN gets a success response and no data.
3. **Out-of-range stats stored verbatim.** Negative counts and inverted min/max are accepted (201) and
   **persisted as-is** - verified by read-back: `low_value=100, high_value=1, nulls_count=-5,
   unique_count=-9` round-trips onto the field's `number_stats` unchanged. No rejection, no normalisation.

## Where

(Code path verified against current HEAD `3049b9af`.)

- Endpoint: `POST /ingestion/entities/datasets/stats` -> `IngestionController.postDataSetStatsList`
  (`IngestionController.java:81-87`): `datasetStatisticsList.flatMap(ingestionService::ingestStats)
  .thenReturn(ResponseEntity.status(CREATED))`. No `@Valid`, no `switchIfEmpty`, no required-body guard - an
  empty/`null` body has no clean 4xx path (confirmed live: 500).
- `IngestionServiceImpl.ingestStats` (`:76-79`) -> `DatasetFieldServiceImpl.updateStatistics`
  (`:158-181`).
- `DatasetFieldServiceImpl.updateFieldsStatistics` (`:233-251`): iterates **existing** fields fetched by
  oddrn (`getLastVersionDatasetFieldsByOddrns:173`); a stat keyed by an oddrn with no matching existing field
  is simply never applied - no error, no 4xx (facet 2, silent-accept of unknown field ODDRN). For each
  matched field it does `field.setStats(JSONB.jsonb(serializeJson(stat)))` (`:246`) - the stat object is
  persisted verbatim with **no** value validation (facet 3, out-of-range stored as-is).

## User-facing impact

The endpoint is a Collector/SDK ingestion surface (no interactive UI form), so the affected actor is the
**collector author / ingestion client**, and the downstream victim is the **operator reading the catalog**:

- A collector author who typos a field ODDRN gets a `201` success and no logged warning, yet the stat lands
  nowhere - a silent no-op they have no signal to debug (facet 2).
- Out-of-range stats (negative counts, inverted min/max) are persisted verbatim and **render on the Dataset
  Structure tab** of the UI (`GET /api/datasets/{id}/structure`), so operators see garbage column statistics
  presented as truth (facet 3) - the one facet with a visible UI surface.
- A malformed/empty body returns `500` (an alarming server error) for what is a client-side mistake (facet 1).

No data loss of existing records and no security exposure; the harm is silently degraded catalog data quality
plus a hidden collector-author failure. All three facets were confirmed live against the `:latest` image
(odd-minimal) during the IT-045 integration-test grind and are pinned by three characterization tests that
flip RED when validation lands.

## Reproduce

```
S={base}/ingestion/entities/datasets/stats
curl -s -o /dev/null -w '%{http_code}\n' -X POST $S -H 'content-type: application/json' -d ''       # -> 500
curl -s -o /dev/null -w '%{http_code}\n' -X POST $S -H 'content-type: application/json' -d 'null'   # -> 500
# unknown field ODDRN under a real dataset -> 201 (silently accepted)
# out-of-range {low_value:100,high_value:1,nulls_count:-5,unique_count:-9} -> 201, read back verbatim on GET /api/datasets/{id}/structure
```

## Impact

- **Data quality:** garbage column statistics (negative counts, inverted ranges) enter the catalog and
  render on the Dataset Structure tab, misleading operators.
- **Silent collector errors:** a typo'd field ODDRN is a no-op with a 200/201 - the collector author has
  no signal their stats didn't land.
- **Robustness:** a malformed body 500s (an alarming server error for what is a client mistake).

## Fix

On the stats ingestion path: (a) validate the request body and return `400` (not 500) for empty/null/
malformed input; (b) reject or log-and-skip stats for field ODDRNs not present on the target dataset
(signal the collector); (c) validate stat invariants (counts >= 0, `low_value <= high_value`) and reject or
clamp/normalise. Pinned by odd-team `IT-045` (three characterization pins - they flip RED when validation lands).

## Severity rationale

Medium (held): no data loss or security exposure, but it silently degrades catalog data quality and hides
collector-author mistakes; the 500 is a robustness defect.
