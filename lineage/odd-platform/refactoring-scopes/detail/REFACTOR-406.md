- **REFACTOR-406** (NEW 2026-05-19O): Cognito `clientId` lookup has NO null-guard — `CognitoLogoutSuccessHandler.java:42` (`.queryParam("client_id", provider.getClientId())`) — if `clientId` is somehow null (theoretically rejected by `ODDOAuth2Properties.validate()` but a future refactor that removes that validator would expose this), the query string becomes `?client_id&logout_uri=...` (parameter name with no value). Cognito would reject this with an error
  - **Category**: missing-validation
  - **Surfaced by**:
    - `CognitoLogoutSuccessHandler.md:bugs_limitations_corner_cases.[4]` (LOW)
  - **Statement**: `CognitoLogoutSuccessHandler.java:42` reads `provider.getClientId()` and passes it directly to `UriComponentsBuilder.queryParam("client_id", value)`. If `clientId` is null (theoretically rejected by `ODDOAuth2Properties.validate()` at line 22-24 which throws IllegalStateException on empty clientId, but a future refactor that removes or weakens that validator would expose this), the URI builder produces the query string `?client_id&logout_uri=...` — parameter name with no value. Cognito's `/logout` endpoint would reject this with an error. Currently mitigated by the validator; the handler itself has no null-guard.
  - **Evidence**: `CognitoLogoutSuccessHandler.java:42` (no null-guard on clientId) + `ODDOAuth2Properties.java:22-24` (the validator that currently mitigates)
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-048 (narrow-validator scope at `@PostConstruct`) — the validator covers clientId. The handler doesn't need a separate guard while the validator is in place. The gap is defensive-coding hygiene.
  - **Proposed remedy**: Add a defensive null-guard at the top of the Cognito handle method: `if (StringUtils.isEmpty(provider.getClientId())) return Mono.empty();` — mirror the existing logoutUri guard at lines 33-35. Alternatively, leave as-is and rely on the validator (current state). The choice depends on whether the defensive code is worth the small maintenance cost.
  - **Severity rationale**: LOW — theoretically defensible by the validator; future-regression risk only.
  - **Suggested backlog grouping**: `OAuth2 hardening sprint` (defensive-coding family — paired with REFACTOR-400)
