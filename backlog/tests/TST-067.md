## Scope 1 — the lane that nothing runs (the substantive half)

`f855eeba` moved **IT-148** into a new `pending-merge` suite. The move was correct: a spec that asserts an
*unmerged* feature reddens every other stream's SUT, and lane-isolating it is what stopped six
`favorites-star-see-loop` cases from polluting neighbours' baselines (measured — `TST-059` records the
18 -> 12 drop).

The **graduation back** is the problem. It exists only as prose: two comments in `suites.yaml` and a
paragraph in the protocol. There is no owner:

- `integration-tests/run-regression.sh:31` — the default set is
  `feature-complete known-bugs multi-stack ingestion-e2e`. **`pending-merge` is never executed by anything.**
- `grep -rn "pending-merge" playbooks/ pillars/ .claude/skills/` -> **zero hits.** Neither `/review`,
  `/contribute`, `playbooks/release-train-merge.md` nor `playbooks/release-review.md` knows the lane exists;
  the release review's own suite list (check 2) does not include it.

So when #1841 merges, **IT-148 — the only end-to-end proof of the whole ST-7 slice — sits in a lane no gate
executes, permanently and silently.** That is the "graduate-or-die" failure the lane's own rationale invokes;
the probes it compares itself to have a stated rule at `pillars/tests/pillar.md:60`, and this lane has none.

### Acceptance (scope 1)

- [ ] IT-148 is back in `feature-complete` **and** `ui-e2e` once odd-platform#1875 is merged, and a full
      `feature-complete` run executes it (cite the run-log line, not the yaml).
- [ ] `pillars/tests/pillar.md` gives `pending-merge` the same **graduate-or-die** status the probes have, so
      the *next* stream to use the lane is caught by the framework rather than by a reviewer.
- [ ] The stale lane comments are corrected in both directions: `suites.yaml:22-28` still carries IT-148's
      full 7-line description under `feature-complete`, and `:141`'s `ui-e2e` comment still names
      *"IT-148 Favorites star->find-it-again via the search filter"* — while `yaml.safe_load` shows IT-148 in
      **`pending-merge` only**. A reader of the file is told the opposite of what it does.
