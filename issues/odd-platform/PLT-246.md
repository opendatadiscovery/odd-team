## Description

While resolving #1762 (a raw `IllegalArgumentException` from `PolicyJSONValidator` surfacing as HTTP 500
instead of 400), a sweep of all 45 `throw new IllegalArgumentException` sites in `odd-platform-api`
identified one other genuinely *input-reachable* class that was kept out of #1762's scope to keep that
PR bounded: the **ingestion-metric extractors**.

When a collector pushes a malformed metric payload, the extractors throw `IllegalArgumentException` for
input-shape violations — e.g. `GaugeMetricSeriesExtractor` ("Gauge value is null"),
`HistogramMetricSeriesExtractor` ("Histogram metric point must have at least one bucket"),
`SummaryMetricsSeriesExtractor` ("Summary metric point must have at least one quantile"),
`InternalIngestionMetricsServiceImpl` ("Label names must be unique", "All quantiles must be between 0 and 1").
With no `@ExceptionHandler(IllegalArgumentException.class)` on `ControllerAdvice`, these fall to the
catch-all `@ExceptionHandler(Exception.class)` → **HTTP 500 / SYS001 / "Internal Server Error"**. A
collector author sending a bad metric batch gets a server-error status with no actionable detail.

## Where

| File | Role |
|------|------|
| `service/ingestion/metric/extractors/internal/{Gauge,Histogram,Summary,Counter}MetricSeriesExtractor.java` | per-point shape validation throws IAE |
| `service/ingestion/metric/extractors/external/{Gauge,Histogram,Summary,Counter}TimeSeriesExtractor.java` | same, external metric family |
| `service/ingestion/metric/InternalIngestionMetricsServiceImpl.java` (~:254, :263) | label-uniqueness / quantile-range checks throw IAE |
| `controller/exception/ControllerAdvice.java` | no IAE handler → catch-all 500 |

## Suggested approach

Mirror the #1762 fix per the platform's typed-exception convention (ADR-0007): for genuine bad-input
cases, throw `BadUserRequestException` (→ 400) so the collector author gets an actionable error; leave
internal-invariant violations as 5xx. Decide per-site (the ingestion surface is machine-to-machine, so
4xx-vs-422 and the retry semantics for collectors are a product call — consult the ingestion docs). NOT a
class-wide `IllegalArgumentException → 400` handler (rejected in #1762 for blast-radius + paging + leak
reasons — see the #1762 thread). Pair with an integration test on the ingestion endpoint.

## Why it matters

Collector authors debugging a rejected metric batch see "Internal Server Error" rather than which field is
malformed — the same diagnostic-quality defect #1762 fixed for policies, on the ingestion surface.
