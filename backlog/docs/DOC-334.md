## Description

A recurring UI-robustness class: a route or panel has no rejected-fetch render branch, so a 404 / auth-expiry / transient 5xx shows a frozen empty page that no refresh recovers; and the generic error page offers no retry affordance. Confirmed across features:

- **Dictionary / term-search tab (F-024/H-008, F-024/H-012)** — no `getTermsSearch.rejected` reducer / no `.catch` / no error boundary; a stale 30-day session bookmark or a transient mount failure shows a frozen empty page. (Code fix tracked as PLT-138.)
- **Notification Settings (F-198/H-004)** — no FAILED-fetch render branch; a rejected populate-fetch drops to an empty form whose submit blanks all four halt columns via the unconditional upsert, silently re-arming every suppressed alert type. (Folds into PLT-053 as Defect 4 — code side.)
- **Error page (F-042/H-006)** — only "Return to the Home Page", which discards in-progress state on transient failures; no retry.
- **Register/edit modals (F-031/H-008)** — a backend-rejected register/edit closes the modal and discards everything typed; the only feedback is a transient toast.
- **AppInfoMenu (F-035/H-012)** — no loading/error state; a `/api/links` failure silently reduces the menu, indistinguishable from "no links configured".

This documents the operator-facing symptom (a frozen empty page after a session expiry or transient error is a known UI gap; reload/re-login to recover) and points to the tracked code fixes (PLT-138 for the Dictionary frozen page; PLT-053 for Notification Settings). The individual minor UI papercuts (error-page retry, AppInfoMenu) are noted; their code fixes are low-value follow-ups.
