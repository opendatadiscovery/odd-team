## Description

The probe-runtime runner (`lineage/_extractor/probe-runtime/runner.py`) captures docker-compose
`stderr`/`stdout` **verbatim** into the `stderr_tail` / `stdout_tail` fields of each committed probe-run
artefact. docker-compose emits the **host-absolute** compose-file path in its `version is obsolete` warning,
so every probe-run persists a line like:

```
/home/<user>/work/odd/odd-team/lineage/_extractor/probe-stacks/odd-minimal.docker-compose.yml: the attribute `version` is obsolete ...
```

This violates the workspace rule **"never hardcode absolute host paths in committed files"** — the workspace is
public OSS, so the leak (a) exposes the maintainer's home-directory layout and (b) breaks portability for any
adopter who bootstraps the methodology against their own checkout (the path is meaningless on their machine).

As of 2026-06-16, a repo-wide grep for the host-absolute prefix (`/home/<user>/...`) returns **46 tracked files**:
- **6** `lineage/odd-platform/probe-runs/2026-06-{10..15}-P-001.yaml` — the `stderr_tail` of the
  `docker-compose-up` step (~line 19; the `docker-compose-down` step's tail is already truncated past the path)
- **33** `lineage/odd-platform/test-map/detail/TEST-GAP-*.yaml`
- **3** `lineage/odd-platform/understanding/*.md` sidecars
- **2** `lineage/odd-platform/meta-reviews/{2026-05-21-a1,2026-05-22-a1}/raw/*.md`
- **1** `state/*`
- **1** `backlog/docs/DOC-435.md`

The **2026-06-16-P-001.yaml** probe-run committed alongside this item was **hand-redacted at commit time** — the
absolute prefix normalized to the repo-relative `lineage/_extractor/probe-stacks/odd-minimal.docker-compose.yml`
form already present on that file's `compose_file:` line (the docker warning's content is preserved; only the
host prefix was stripped). So the new artefact does **not** extend the leak — but the runner will regenerate it
on the next probe run, which is why the class fix is tracked here.

## Acceptance Criteria

- [ ] `runner.py` scrubs host-absolute paths from captured `stdout`/`stderr` before persisting (strip the
      repo-root prefix → repo-relative, or a `${REPO}`/`<repo>` placeholder), so no future probe-run artefact can
      contain an absolute host path. Add a self-check / unit assertion that the persisted trace has no `/home/`
      (or platform-equivalent absolute prefix).
- [ ] Sweep the 46 already-tracked files: replace the host prefix with the repo-relative path (or placeholder),
      preserving the surrounding message content. The TEST-GAP / understanding / meta-review / state / DOC-435
      occurrences are reviewed individually first — some may be intentional path *references* that should become
      repo-relative rather than be deleted.
- [ ] After the sweep, `git grep -lI "/home/"` returns **zero** matches across the repo (re-enumerate at fix
      time; the count may have moved).
- [ ] Confirm no other capture sites in the methodology write absolute paths (the doc/probe extractors,
      meta-review raw dumps) — scrub at the source, not only the probe runner, if the sweep finds non-probe leaks
      regenerate from other tools.

## Context

Found during `/review CTRIB-019` (2026-06-16) while committing the 2026-06-16-P-001 probe re-run: the new
artefact tripped the pre-commit no-absolute-path check, and a repo-wide grep showed it is a **pre-existing
systemic leak** (46 files) from the probe-runner's verbatim stderr capture, not a one-off. The new file was
redacted in-commit; this item tracks the class fix so the leak stops recurring.

**Non-urgent** — the 46 affected files are already public (already pushed), so the sweep removes no *new*
exposure; the value is (a) stopping the runner from regenerating the leak on every run and (b) restoring
portability for adopters. But it violates an explicit, recorded maintainer rule, so it should not sit
indefinitely. Failure shape: machine-captured environment data committed without scrubbing — the same class as
any tool that persists raw subprocess output into a public artefact.
