## Description

The Data Collaboration page is NOW LIVE (per F-038a STATE-UPDATE — substrate said 404 at 2026-05-25; live WebFetch 2026-05-27 returns 200 OK with rich content covering enable/setup/usage). The page is silent on **four load-bearing operator caveats** that the substrate's F-038 facet family identified. Doc-side ship adds these as known limitations / operator guidance; code-side fixes ship via PLT-054.

**F-038b — Slack signature verification absent (HIGH; strengthens DOC-GAP-032).** `EventApiController.java:22-27` deserializes raw body from `@RequestBody Mono<String>` and never reads any header. Grep across codebase for `X-Slack-Signature`, `signing.secret`, `signingSecret`, `verifySignature`, `HMAC.SHA256` returns ZERO matches. Slack's documented protocol mandates HMAC-SHA256 over `v0:{X-Slack-Request-Timestamp}:{raw body}` using the app signing secret — ODD does NONE of this. Endpoint accepts forged POSTs from any internet caller.

**F-038c — Slack OAuth bot token rotation/lifecycle/fail-closed contract undocumented (HIGH).** `datacollaboration.slack-oauth-token` is the bot OAuth token signing every outbound Slack call. Used to construct a SINGLETON AsyncMethodsClient at boot; reused across all requests. Spring's default Sanitizer masks `token`-suffixed property names — masking is the SOLE defence. NO env-var-rotation hook; NO token-lifecycle integration; NO fail-closed on token revocation. Any compromise of the platform process / `/actuator/env` / configured property leaks workspace channel enumeration + post-as-bot capability across the bot's scope (`channels:history`, `channels:read`, `chat:write`, `users:read`, `incoming-webhook`).

**F-038d — Slack at-least-once delivery materialises N child message rows (MEDIUM).** `message_provider_event` has no unique constraint on (provider, event_id); INSERT is plain — no ON CONFLICT. A duplicated Slack delivery for the same `event_ts` inserts N rows; the processor materialises N child message rows. Downstream `getUUIDByProviderInfo` lacks LIMIT 1 — multi-result returns an arbitrary first row (order-undefined). Live page documents retry behaviour ("retried up to N times") but is silent on idempotency, duplicate prevention, or at-least-once semantics.

**F-038f — 1-minute Caffeine cache on Slack channels (LOW).** `SlackMessageProviderClient.java:36-44` declares AsyncLoadingCache with `expireAfterWrite(1, MINUTES)` keyed on a fixed sentinel; freshly-invited bot-channel membership invisible to autocomplete for up to 60s. Operator inviting the bot to a new channel expects autocomplete to surface it immediately.
