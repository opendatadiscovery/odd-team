## What

Two published docs describe S2S filter registration in a way that implies `S2sAuthenticationFilter` does NOT
run under `auth.type=DISABLED`:

- **s2s.md (lines 87-89, the operator caveat):** "The DISABLED-mode security configuration does not read
  `auth.s2s.enabled`, so **the S2S filter is never wired into the chain in that mode** ... `X-API-Key` requests
  under DISABLED behave identically to unauthenticated requests."
- **ADR-0074 (line 30 + evidence line 45):** "Each of the three real modes layers the `S2sAuthenticationFilter`
  onto its chain when `auth.s2s.enabled` is set; **DISABLED, having no chain to protect, does not.**"

## Why it is imprecise (verified against code + a live run)

`S2sAuthenticationFilter` is `@Component implements WebFilter`. In Spring WebFlux a `WebFilter` bean is
auto-registered into the GLOBAL filter chain and runs on **every** request in **every** auth mode, independent
of any `SecurityWebFilterChain`. The `.addFilterAt(...)` calls in the three real-mode configs are a SECOND,
in-security-chain registration; their absence in `DisabledAuthSecurityConfiguration` does NOT stop the filter
from running globally.

The consequence the docs assert is therefore wrong for the latest published release (0.28.0): under DISABLED with
s2s unconfigured, an `X-API-Key` request did NOT "behave identically to unauthenticated requests" — it returned
**HTTP 500** (the PLT-001 NPE / unauthenticated DoS), verified live 2026-06-19. This "filter isn't wired under
DISABLED" framing is exactly the assumption that made PLT-001 originally mis-assessed as "unreachable in
production / severity low".

## Interaction with the PLT-001 fix (CTRIB-022, #1765, milestone 0.29.0)

CTRIB-022 null-guards `S2sTokenProvider.isValidToken`, so post-0.29.0 the filter ignores the key and passes
through — at which point s2s.md's operator-facing CONCLUSION ("X-API-Key under DISABLED behaves identically to
unauthenticated requests") finally becomes TRUE. **So the code fix needs no doc change; only the MECHANISM
explanation remains imprecise.**

## Suggested change

Replace "the S2S filter is never wired into the chain in that mode" (s2s.md) and "DISABLED ... does not [layer
the filter]" (ADR-0074) with an accurate statement: the filter is a global `WebFilter` that runs in every mode;
the `.addFilterAt` registration is a second, in-security-chain hook the real modes add when `auth.s2s.enabled` is
set. Under DISABLED with s2s unconfigured the global filter ignores the key and passes through (0.29.0+; before
0.29.0 it crashed — PLT-001). Route on `release/0.29.0` so the accurate post-fix form publishes with the fix.

## How discovered

G-C10 docs read during CTRIB-022. The fix made code match s2s.md's operator-facing promise; reading the page to
confirm "no doc change needed" surfaced the imprecise mechanism framing shared by s2s.md and ADR-0074.
