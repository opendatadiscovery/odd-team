## Description

Promote `ADR-CANDIDATE-008` into a published ADR. The decision: OpenAPI tags follow
URL-prefix scoping with a single tag per operation — every operation under a tag shares an
`/api/<plural-noun>` URL prefix — which makes the generator emit resource-shaped Java
interfaces (`AlertApi`, `DataEntityApi`, …). This is the corollary of the contract-first
layer (`ADR-0001`): the tag convention is *why* the generated `*Api` interfaces are
resource-shaped, so a contributor editing `openapi.yaml` knows the tag determines the
interface boundary.

## ⚠ Verification finding (2026-05-30) — the Description over-claims; reframe before authoring

A spec sweep was run during the HTTP+authz backbone `/implement` pass (substrate
`ede5d277`, `openapi.yaml` 4212 lines). It **confirms one universal and refutes another** —
this item was NOT authored this pass precisely because the drafted Description asserts the
refuted one, and shipping it would repeat the ADR-0001 "lone exception" overclaim.

- ✅ **Single-tag-per-operation — VERIFIED UNIVERSAL.** 0 of 194 operations carry more than
  one tag (and 0 carry none). The "an operation with two tags would be a counter-example"
  AC is satisfied — there are no counter-examples.
- ✅ **Tag → resource-shaped interface — holds.** 33 distinct tags; each maps to one
  generated `{Tag}Api` (alert→`AlertApi`, dataEntity→`DataEntityApi`, …).
- ❌ **"every operation under a tag shares an `/api/<plural-noun>` prefix" — NOT universal.**
  30 of 33 tags map to a clean shared `/api/<resource>` prefix; **3 do not** — their
  operations span multiple path roots so the only common prefix is `/api`:
  - `dataEntity` (37 ops) — the platform's largest tag, spans more than one path root.
  - `ownerAssociationRequest` (6 ops).
  - `dataCollaboration` (3 ops).

**Required reframe before publishing:** state the decision as "each operation carries exactly
one tag, and each tag maps to one resource-shaped `*Api` interface; most tags also share a
single `/api/<resource>` URL prefix, with a few (notably `dataEntity`) grouping a resource's
operations that span several path roots." Do NOT publish the absolute "every operation under a
tag shares an `/api/<plural-noun>` prefix" — it is false for 3 tags. Before authoring, read
what those 3 tags actually group (the sweep only collapsed their common prefix to `/api`; the
Evidence section needs the specific path roots named, re-verified at the substrate commit).

Sweep method (re-runnable): parse `openapi.yaml`, for each operation collect `tags`; assert
`len(tags)==1` for all; group paths by tag and compute each tag's common `/`-segment prefix.
