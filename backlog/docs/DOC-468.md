## Description

CTRIB-021 (opendatadiscovery/odd-platform#1725 + ADR `adrs/drafts/ml-entity-taxonomy.md`) makes `ML_MODEL` a
first-class **model-identity group** and settles ODD's ML entity taxonomy. **ODD ships ML entity types
(`ML_EXPERIMENT`, `ML_MODEL_TRAINING`, `ML_MODEL_INSTANCE`, `ML_MODEL_ARTIFACT`, and now `ML_MODEL`) with NO
published reference** — verified: `docs.opendatadiscovery.org/features/data-modelling` has zero ML vocabulary.
This is the root user-confusion source behind #1725 (a user couldn't tell which ML type to send). Author the
reference page so a Data Scientist / MLOps engineer meets each type by the analogy they already know.

## Drafted page (drop onto the train at the release gate)

```markdown
---
description: >-
  How Open Data Discovery models machine-learning entities — the model identity, its training jobs, versioned
  artifacts, and deployed instances — and how each maps to the concepts you know from MLflow, SageMaker, and DataHub.
---

# ML entities

Open Data Discovery represents the machine-learning lifecycle with a small set of **data entity types**, so an
ML model and the work around it become first-class, searchable, lineage-connected catalog entities — exactly
like a table or a job. If you come from MLflow, SageMaker, Vertex AI, or DataHub, each ODD type maps onto a
concept you already use.

## The types

| ODD type | What it is | The concept you know |
|---|---|---|
| **ML model** (`ML_MODEL`) | The **model identity** — the named, searchable model (e.g. "the churn model"). A *group* that ties together the model's training jobs, versioned artifacts, and deployed instances, with lineage across them. | MLflow **Registered Model** · SageMaker **Model Package Group** · DataHub **`mlModelGroup`** |
| **ML model training** (`ML_MODEL_TRAINING`) | A **training job/run** that produced a model — it reads features/datasets and emits a model (a *transformer* in lineage). | SageMaker **Training Job** · Vertex AI **Custom Job** · MLflow training **run** |
| **ML model artifact** (`ML_MODEL_ARTIFACT`) | A **trained model object / version** — the serialized model that consumes features at inference (a *data consumer*). | MLflow **Model Version** · SageMaker **Model Package** · DataHub **`mlModel`** |
| **ML model instance** (`ML_MODEL_INSTANCE`) | A **deployed/serving instance** of a model — what answers prediction requests in an environment. | SageMaker **Endpoint** · Vertex AI **DeployedModel** · DataHub **`mlModelDeployment`** · KServe **InferenceService** |
| **ML experiment** (`ML_EXPERIMENT`) | A **group of training runs** exploring one problem. | MLflow / SageMaker **Experiment** |

The lifecycle reads as: an **ML model** (identity) groups its **training jobs** → the **artifacts** they produce
→ the **instances** those are deployed as; **experiments** group the training runs.

## Ingesting an ML model

Send the **type that matches what the entity is** — ODD maps each ingestion type 1:1 to the model above (the
specification is the contract; the platform does not infer the type from the payload):

- **`ML_MODEL`** — the model identity; send it with a `data_entity_group` payload to register the model and group
  its lifecycle members;
- **`ML_MODEL_ARTIFACT`** — a trained model version (a data consumer); send it with a `data_consumer` payload
  (the common "register my model" case);
- **`ML_MODEL_TRAINING`** — a training job (a data transformer); send it with a `data_transformer` payload.

Because `ML_MODEL` is the model **identity (a group)**, sending `ML_MODEL` with a `data_consumer` payload is a
client error (`4xx`) — use `ML_MODEL_ARTIFACT`.

{% hint style="info" %}
`ML_MODEL_ARTIFACT` and `ML_MODEL_INSTANCE` are being added to the ingestion contract
(`opendatadiscovery-specification`) so collectors can send the full lifecycle; until that ships, a collector
sends `ML_MODEL` (the group) or `ML_MODEL_TRAINING`.
{% endhint %}
```
