## Description

The class-badge colour palette is **not bijective**: nine entity classes map to only **six** distinct colours, so colour alone cannot identify the class for the colliding ones. From `theme/palette.ts:104-112` (`entityClass` block):

| Class | Colour |
|---|---|
| `DATA_SET` | `red5` |
| `DATA_TRANSFORMER` | `purple5` |
| `DATA_CONSUMER` | `blue5` |
| `DATA_INPUT` | `green5` |
| `DATA_QUALITY_TEST` | `orange5` |
| `DATA_TRANSFORMER_RUN` | `purple5`  ← same as `DATA_TRANSFORMER` |
| `DATA_QUALITY_TEST_RUN` | `orange5`  ← same as `DATA_QUALITY_TEST` |
| `DATA_ENTITY_GROUP` | `lightGreen5` |
| `DATA_RELATIONSHIP` | `lightGreen5`  ← same as `DATA_ENTITY_GROUP` |

Six of the nine classes collapse onto three shared colours: `purple5` (Transformer + Transformer-run), `orange5` (Quality-test + Quality-test-run), and `lightGreen5` (Entity-group + Relationship).

The two `*_RUN` collisions are **defensible** — a run badge sharing its parent class's colour is a reasonable visual grouping, and run-class entities render no stats panel anyway (the page already documents that at `entity-detail-page.md:70`). The **`DATA_ENTITY_GROUP` = `DATA_RELATIONSHIP` collision is not defensible**: groups and relationships are two distinct top-level catalog primitives (each has its own Search tab — see the Catalog Search class tabs "… / Groups / Relationships"), yet they are visually indistinguishable in any badge row or class-coloured list.

**How this misleads an operator.** The shipped page (DOC-263) states at `entity-detail-page.md:81` that each class chip "is colour-coded per class (… the colour identifies the class at a glance once you've learned the mapping)" and at line 91 that "operators scanning a list distinguish entities by class colour at a glance." That promise is **false** for Groups vs Relationships and for the two run-pairs: an operator who has "learned the mapping" still cannot tell a Group from a Relationship by colour, and will mis-read a lightGreen5 chip. The page over-claims the colour encoding's discriminating power.

This is **distinct from PLT-094 D5**, which concerns the **type** badge being rendered with no colour at all (the uniform-background type chip — already documented at `entity-detail-page.md:91`). This item is about the **class** badge palette being non-injective.
