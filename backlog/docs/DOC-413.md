## Description

On a Term detail page, the **Linked Columns** tab carries a search box, but it does not behave like the type-to-filter search operators expect from the rest of the platform. The data hook that backs the tab (`terms.ts:36-42`) is declared with `enabled: false`:

```ts
export function useGetTermLinkedColumns(params: TermApiGetTermLinkedColumnsRequest) {
  return useQuery({
    queryKey: ['termLinkedColumns', params.termId],
    queryFn: () => termApi.getTermLinkedColumns(params),
    enabled: false,
    initialData: { pageInfo: { total: 0, hasNext: false }, items: [] },
  });
}
```

`enabled: false` means the query never fires automatically — it runs only when something explicitly triggers a refetch. The query key is also keyed solely on `params.termId`; there is no `query` term in the key (contrast `useGetTermLinkedTerms` at `terms.ts:79`, whose key includes `params.query` and which passes `query: params.query` to the API). So on the Linked Columns tab, **typing into the search box does not re-issue a filtered request and does not narrow the visible column list** — the search is explicit-trigger-only.

The business-glossary page documents several Linked-Columns behaviours (the 50-row cap at `business-glossary.md:181`) and documents that the *Linked Terms* tab "supports search" (`:177`), which sets up the reasonable but wrong expectation that the Linked Columns tab filters as you type. Nothing on any surface tells the operator that on this tab type-to-search is inert. An operator auditing every column linked to a sensitive term (`PII`) will type a filter, see the list not narrow, and may conclude the column is absent when it is simply unfiltered.

Note: PLT-058 Defect 7 concerns the sibling **LinkedTermsList** component, not this Linked Columns tab — so this is a distinct, untracked surface.

Canonical code truth (verified 2026-06-08):
- `terms.ts:36-42` — `useGetTermLinkedColumns` is `enabled: false` and its query key is keyed only on `termId` (no `query`), so type-to-search does not re-issue a filtered request.
- `terms.ts:79, 81-86` — by contrast `useGetTermLinkedTerms` keys on `params.query` and passes `query` to the API, so the Linked Terms tab *does* filter on input. The asymmetry is the source of the misleading expectation.
