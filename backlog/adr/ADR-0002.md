## Description

Promote `ADR-CANDIDATE-002` — the strongest authorization pattern in the catalog
(18-sidecar support, wisdom-test PASS) — into a published ADR.

The decision: all authorization rules live in one centralised `SECURITY_RULES` list
(path + HTTP-method + required permission), enforced by a single `AuthorizationCustomizer`,
**not** scattered as `@PreAuthorize` annotations on controller methods. Changing an
endpoint's authorization is a `SECURITY_RULES` edit; the model is centralised and
auditable in one file. Zero `@PreAuthorize` annotations exist in the codebase — the
absence is the evidence the choice is deliberate.
