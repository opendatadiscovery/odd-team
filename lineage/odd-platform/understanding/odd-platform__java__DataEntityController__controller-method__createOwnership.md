# DataEntityController#createOwnership — semantic understanding

## understanding

`createOwnership` is the reactive `POST /api/dataentities/{data_entity_id}/ownership` handler — five lines that read the request body as `Mono<OwnershipFormData>`, call `ownershipService.create(dataEntityId, form)`, and lift the resulting `Ownership` into `200 OK`. The endpoint closes the ownership lifecycle loop opened by `OwnerController.createOwner` (batch-E): once an Owner exists in the directory, this endpoint binds that Owner to a specific data entity with a free-text title (e.g. "Steward", "Owner"), producing one row in the `ownership` table whose `(data_entity_id, owner_id)` is database-unique. Authorization is enforced centrally by a `SecurityRule` for `POST /api/dataentities/{data_entity_id}/ownership` that demands the `DATA_ENTITY_OWNERSHIP_CREATE` permission, evaluated per-data-entity through the `DataEntityPermissionExtractor` Policy-resolution pipeline.

## bugs_limitations_corner_cases

- "Auto-create-on-miss for Owner — calling `POST /api/dataentities/{id}/ownership` with `owner_name: 'New Person'` (a name not yet in the `owner` directory) silently creates a fresh `OwnerPojo` via `OwnerService.getOrCreate(name)` (`OwnerServiceImpl.java:39-42` → `ownerRepository.create(new OwnerPojo().setName(name))`).
