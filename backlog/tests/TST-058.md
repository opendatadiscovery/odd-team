## Description

`integration-tests/run-suite.sh`'s **api-probe rail** shells out to
`(cd lineage/_extractor && uv run python probe-runtime/runner.py P-001 --allow-stale)`. `uv run` first builds the
local `lineage-extractor` package, and that build now **fails outright**:

```
x Failed to build `lineage-extractor @ file:///.../lineage/_extractor`
  ├─▶ The build backend returned an error
  ╰─▶ Call to `hatchling.build.build_editable` failed (exit status: 1)
      ValueError: Readme path must be within the project directory: ../README.md
```

`lineage/_extractor/pyproject.toml:9` declares `readme = "../README.md"` — a path **outside** the project
directory. Newer hatchling validates this and refuses to build. There is no `README.md` inside
`lineage/_extractor/` (verified: the directory holds only `probe-runtime/`, `probe-stacks/`, `registry-shard/`,
`src/`, `tests/`, `pyproject.toml`, `uv.lock`).

## Why it matters

- **A whole verification rail is silently dead.** `feature-complete` declares `api probes: P-001`; that probe has
  not executed. The suite still prints `outcome: api:FAIL e2e:...` and carries on, so the failure is easy to read
  as "the suite is a bit red" rather than "an entire rail never ran".
- **It contaminates every DoD gate record.** Any contributor reading `api:FAIL` on their own regression will
  spend time hunting an odd-platform cause that does not exist — exactly what happened on ctrib059.
- **Nothing in odd-platform is wrong.** This is an odd-team toolchain break, almost certainly from a hatchling
  version moving under the workspace during the 2026-07-03..2026-08-30 idle period (the same gap that produced
  the CTRIB-052..059 ledger hole).

## Acceptance Criteria
- [ ] `lineage/_extractor` builds again. Prefer **deleting the `readme` line** — it is optional metadata for an
  internal, never-published package, so removing it is strictly smaller than adding a new README file (and adding
  a file to satisfy a metadata field is the kind of artefact CLAUDE.md tells us not to create). Do NOT vendor a
  copy of the workspace README into the package directory.
- [ ] `cd lineage/_extractor && uv run python -c "import sys; print(sys.version)"` succeeds (the build step is
  what is broken; any trivial entry point proves it).
- [ ] `integration-tests/run-suite.sh <a suite with an api probe>` reports `api:PASS` (or a genuine probe result),
  not a build error.
- [ ] Consider making the rail **fail loudly**: a probe that cannot even build should be distinguishable in the
  outcome line from a probe that ran and failed — a silent-dead rail is worse than a red one.

## Context
- **Not attributable to CTRIB-059** — the probe never reached odd-platform; it died building a local Python
  package in odd-team.
- Surfaced together with `TST-057`'s third instance in the same run; unrelated cause, tracked separately because
  the remedy is a different file and a different failure mode (dead rail vs load-induced timeout).
- Deliberately NOT fixed inside the ctrib059 run: repairing it mid-regression would let P-001 start writing
  `lineage/**` (the R9 single-writer resource) during an in-flight attribution measurement.
