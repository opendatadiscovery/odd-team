## Description

CTRIB-013's GATE-1 plan (items 6 and 7) named two odd-team artefacts to move with the code; the commit
(odd-team `8aacfed`) updated the authoritative half of each but left the secondary half describing the
**pre-fix** REMOTE-region world. Neither ships a false user-facing claim (the e2e assertion is valid; the
sidecar accurately describes still-unmerged `main`), so this did NOT block the CTRIB-013 review flip —
but both are coherence drifts to reconcile, and the second is already on the merge-time re-enrich path.

1. **IT-008 e2e spec comments (plan item 6 — spec named, untouched).**
   `integration-tests/e2e/specs/attachment-remote-roundtrip.spec.ts` (lines ~19-25, ~85-87) still says
   "the missing `.region()` is papered over here", "the SDK auto-discovers the bucket region", and
   "the missing-.region() defect is pinned structurally". This **contradicts the same-commit protocol +
   compose** that CTRIB-013 updated: the protocol (`IT-008-attachment-remote-roundtrip.md`) now states
   the stack sets `ATTACHMENT_REMOTE_REGION=eu-west-1` and "signs for the store's region **explicitly**
   (not via auto-discovery)". The protocol is the source of truth (`run-suite.sh` header: "Protocol docs
   are the source of truth; the probe is the automation rail"), so the round-trip assertion stays valid —
   only the rail's explanatory prose drifted. Reframe the spec comments to match the protocol (the fix
   shipped; the stack now signs explicitly; LSN-002 remains a unit pin for the least-priv-IAM failure a
   local MinIO cannot reproduce).

2. **application.yml `attachment` config-prefix sidecar (plan item 7 — sidecar named, untouched).**
   `lineage/odd-platform/understanding/odd-platform__yaml__application_yml__config-prefix__attachment.md`
   still carries the LSN-002 region-absence claims (understanding L18; `requires-runtime` L31;
   `uncovered_behaviours` L36; `bugs_limitations` L76: "there is no way to fix it from the YAML"; the
   quoted now-retired known-limitation L57) with **no PENDING-CHANGE banner** — unlike the MinioConfig
   sidecar, which got one in the same commit. The PR adds `region:` to exactly this prefix, so this is the
   ontology node for the changed surface. Claims are accurate for unmerged `main`, and CTRIB-013's handoff
   already schedules a "full sidecar re-enrich on merge" that covers this node — so this is a missing
   forward-annotation, not a silent gap. Either add the same PENDING-CHANGE banner now, or ensure the
   merge-time re-enrich explicitly includes this sidecar.
