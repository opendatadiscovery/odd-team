## Description

The Business Glossary page's "Known operator caveats" section (added by DOC-233) publishes three caveats that
describe Term-Detail bugs **fixed by odd-platform#1754 / CTRIB-028** (milestone 0.29.0). Once 0.29.0 ships, those
caveats are FALSE, so they are removed on the documentation **`release/0.29.0`** train branch and publish — with
the caveats gone — at the 0.29.0 release gate (release-train doc gating; the live manual describes the latest
published release until then).

**Caveats retired (removed on `release/0.29.0`):**
- **D1 (Performance characteristics)** — *"Opening a Term detail page fires the same backend query twice."*
  Fixed: Overview now reads the shell's already-loaded term details (one fetch).
- **D2 (Visibility and cross-tab UX)** — *"the Linked Entities / Linked Columns / Linked Terms tabs are hidden
  when their respective counts are zero."* Fixed: the tabs are always shown (count badge incl. 0).
- **D4 (Visibility and cross-tab UX)** — *"The Term's Linked Columns tab silently caps the visible list at 50
  rows."* Fixed: the tab paginates fully and the backend `page_info` reports the real total/hasNext.

**Caveat KEPT (deferred — PLT-235):** the Overview-TERMS-panel vs Linked-Terms-tab dual-surface asymmetry
(Defect 3) is NOT fixed by #1754 and remains a valid caveat.
