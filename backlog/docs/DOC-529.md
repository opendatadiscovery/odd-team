## Description

ST-10 adds a **Last viewed** control to the Catalog search: it narrows the result list to the assets the reader
has opened, optionally inside a date window, and switches the ordering to newest-first. It also gives the home
page's Recently Viewed panel the **View all** link it never had (#1832). None of that is described anywhere in
the manual, and three of the pages that enumerate the Filters panel would have gone out of date the day 1.0.0
published.

Four things in this feature are **not** guessable from the UI, which is why the section is long rather than a
bullet:

1. **You pick local calendar days; the URL carries exact instants.** A shared link therefore means the same
   window everywhere, while the calendar day it was named after does not travel. Without this sentence a reader
   who sends a *Today* link to a colleague eleven hours away has no way to predict what they will see.
2. **A shared link resolves the recipient's history, never the sender's.** That is a privacy guarantee and a
   usability caveat at the same time, and only the docs can state it — the UI cannot show it.
3. **Retention silently bounds the window.** A date range reaching further back than the deployment keeps
   returns nothing, however certainly the asset was opened. The page links the two operator knobs rather than
   quoting numbers, because they are configurable.
4. **Two combinations narrow harder than expected** — a data-entity-only facet (Datasource / Type / Groups /
   Statuses) or a Popularity range drops the terms and query examples from a cross-kind list.

## In-slice scope extension — the housekeeping page

`configuration-and-deployment/odd-platform.md` described the housekeeping job as **five** cleanup tasks
consuming **three** TTL keys. Since odd-platform#1826 it has run **six** tasks consuming **five** keys: the
recently-viewed reaper (`RecentlyViewedHousekeepingJob`) enforces `recently_viewed_days` and
`recently_viewed_max_per_user`, and neither key appeared on the page, in the YAML tab, or in the environment-
variable tab.

That gap is #1816's, not ST-10's. It is fixed here anyway because ST-10's own prose **links an operator to that
section for the retention bound** — sending a reader to a section that omits the two keys they came for is a
defect this slice would be creating. (`feedback_class_extension_is_in_scope`; CLAUDE.md "Incorrect documentation
has higher priority than missing documentation".) The zero-default danger hint was widened in the same pass:
a partial `housekeeping:` overlay binds `recently_viewed_max_per_user` to `0`, which empties every user's
history outright on the next cycle — the same silent-wipe class the hint already warns about for the other keys.
