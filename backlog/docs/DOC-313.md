## Description

The search-result **highlight** endpoint (`GET /api/search/{search_id}/data_entities/{data_entity_id}/highlights`) builds raw SQL by string-interpolating the **user-supplied search query** (`tsQuery`) into a `ts_headline(...)` call with no escaping (`ReactiveDataEntityRepositoryImpl.java:801-802`, verified @ ede5d277: `"...to_tsquery('%s')...".formatted(text, tsQuery)`; `JooqFTSHelper.tsQuery()` never escapes quotes). The co-interpolated catalog `text` is quote-escaped (`searchableString()` doubles `'`) and is **not** injectable — only the query path. This is a genuine **SQL-injection** on the read connection, anonymously reachable under `auth.type=DISABLED`.

**CONFIRMED exploitable** — maintainer live PoC 2026-05-30 (time-based `pg_sleep` + UNION exfiltration of an ingestion token from the DB).

**This is primarily a CODE vulnerability** → upstream fix **PLT-109** (CONFIRMED; flagged for private security advisory).

**Responsible-disclosure constraint (load-bearing):** the documentation must **not** publish the injection vector or a payload before the code fix ships — doing so on `docs.opendatadiscovery.org` arms attackers. The doc-side action here is a *measured* caveat that improves operator posture without disclosing the bug.

**Failure shape**: security exposure in a default deployment (the missing doc would otherwise be critical) — but the doc fix is disclosure-constrained.
