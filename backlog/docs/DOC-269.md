## Description

`authorization/README.md` is 14 lines and consists of:

> # Authorization
>
> It is very important to have fine-grained access control in your data catalog. ODD Platform provides functionality of describing policies via [JSON schema](https://json-schema.org).
>
> This section explains how to set up policies and assign them to users.
>
> ### **Contents**
>
> * [Policies](policies.md)
> * [Permissions](permissions.md)
> * [Roles](roles.md)
> * [Owners](owners.md)
> * [User-owner association](user-owner-association.md)

After batch-12 (DOC-207..224) made three operator-critical realities explicit in the body pages:

1. **The read-collaborative posture** — every `GET /api/*` Management endpoint falls through to "any authenticated user" by design. Anyone with the ability to read the catalog can enumerate the Owner directory, the Namespace directory, the Datasource directory, the registered Collectors, and the resolved-associations log. (Permissions.md surfaces this in a warning admonition; it is NOT a quirk that can be tightened via the permission set.)

2. **Token rotation is immediate, with no grace period** — Collector and DataSource token regeneration invalidates the prior token at the moment of the call; the collector / push client must be redeployed with the new token BEFORE existing ingestion stops.

3. **DIRECT_OWNER_SYNC composes with freeSolo getOrCreate** — a holder of `DIRECT_OWNER_SYNC` can mint a brand-new Owner name AND self-bind to it in one POST, completely bypassing the request-approve cycle and the Owner directory's existing-name discipline.

These are three *posture-level* facts about the Authorization model — they shape every per-page choice an operator makes, and they are not derivable from any single page if you don't know to look for them. The README is where they should be named first.

The current README also doesn't:
- Define the per-page reading order (Permissions → Roles → Policies → Owners → User-owner association vs the alphabetical order shown today).
- Distinguish user identity (auth-time, from OIDC/LDAP/S2S) from owner identity (catalog-side).
- Cross-link the parent [Enable Security](../README.md) for the auth setup.
