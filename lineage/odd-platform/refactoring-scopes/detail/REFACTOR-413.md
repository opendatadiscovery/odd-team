- **REFACTOR-413** (NEW 2026-05-19O): Failed-auth attempts on `POST /ingestion/entities` are NOT LOGGED — neither `"Token is missed"` nor `"Token is not correct"` paths emit log calls. No metric counter on the failure path. Security incident review cannot establish "attacker probed endpoint N times" from application logs
  - **Category**: observability
  - **Surfaced by**:
    - `IngestionDataEntitiesFilter.md:bugs_limitations_corner_cases.[5]` (MEDIUM)
    - `IngestionDataEntitiesFilter.md:security.known_security_gaps.[4]` (MEDIUM)
  - **Statement**: `IngestionDataEntitiesFilter.java:55-58` throws `AccessDeniedException("Token is not correct")` and `AbstractIngestionFilter.java:48` throws `AccessDeniedException("Token is missed")` — the parent writes a 401 with the message verbatim (`writeResponse` at lines 66-72). NO log call on either path. NO metric counter. `@Slf4j` IS imported at AbstractIngestionFilter.java:10 but ONLY used by the `readBody` exception path at line 61 (the JSON parse failure). A security incident review of "how many failed-auth attempts in the last hour" cannot be answered from application logs.
  - **Evidence**: `IngestionDataEntitiesFilter.java:55-58` (no log) + `AbstractIngestionFilter.java:34-72` (no log on match OR writeResponse paths; @Slf4j IS imported at line 10 but only used by readBody exception at line 61)
  - **Existing-ADR-or-implied-prescription**: No existing ADR. The observability gap is consistent with the broader handler-family absence (REFACTOR-411 for OAuth handlers). The fix is to add log statements; not a structural change.
  - **Proposed remedy**: Add WARN-level log statements on both failure paths: `log.warn("Ingestion auth failed: reason={}, dataSourceOddrn={}, remoteIp={}", "TOKEN_MISMATCH", oddrn, remoteIp)` for token-mismatch; `log.warn("Ingestion auth failed: reason={}, remoteIp={}", "TOKEN_MISSING", remoteIp)` for missing token. Optionally add a Micrometer counter `ingestion.auth.failure{reason}` for metrics. Mask sensitive fields (don't log the actual token value).
  - **Severity rationale**: MEDIUM — observability gap; affects security-incident response. Symptom is invisible (no log → no investigation).
  - **Suggested backlog grouping**: `Observability hardening sprint` (paired with REFACTOR-411 OAuth handlers + REFACTOR-188 RBAC audit gap — the broader observability-gap family)
