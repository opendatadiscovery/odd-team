## Description

`data-discovery/statuses.md` carries a SQL legend that maps the integer ids stored in the entity-status column to status names so an operator can write a query against the database directly. The legend transposes three of the ids: the page states **2 = STABLE, 3 = DEPRECATED, 4 = DRAFT**, but the platform enum is **DRAFT(2), STABLE(3), DEPRECATED(4)**.

This is actively misleading (Critical per the Priority Order — incorrect documentation an operator copies). An operator who adapts the legend to target `STABLE`, `DRAFT`, or `DEPRECATED` rows directly in SQL hits the wrong rows: a query intended to find STABLE entities returns DRAFT ones, a DRAFT query returns DEPRECATED ones, and a DEPRECATED query returns STABLE ones. The error is silent — the query succeeds and returns plausible-looking results.

**Failure shape**: code-doc drift — a factual mapping table on the page disagrees with the enum the code enforces.
