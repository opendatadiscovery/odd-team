## Description

The published `oauth2-oidc.md` page tells operators that Okta, Keycloak and Custom OIDC providers have **"No admin path"** and that the generic `CustomOIDCUserHandler` **"does not consult `admin-groups`, `admin-principals`, or any provider-specific claim for ADMIN promotion."** That is wrong, and it contradicts both the code **and the page's own configuration examples** — the Okta and Keycloak YAML/env snippets on the same page include `admin-principals` (Okta lines ~437-438, Keycloak lines ~475-476), which the page then tells the reader does nothing.

Code truth (verified by reading source):

- `CustomOIDCUserHandler` (which Okta, Keycloak, and any non-enumerated provider fall through to — `shouldHandle` returns true for any provider not in the built-in set; `CustomOIDCUserHandler.java:28-34`) **extends** `AbstractOIDCUserHandler` and inherits its `enrichUserWithProviderInformation` (`CustomOIDCUserHandler.java:19`).
- `AbstractOIDCUserHandler.enrichUserWithProviderInformation` (`AbstractOIDCUserHandler.java:33-55`) **always** evaluates `admin-principals`: if `admin-principals` is non-empty it reads the `admin-attribute` (or `username-attribute`) claim and promotes to ADMIN when `containsIgnoreCase(adminPrincipals, value)` matches (`:33-43`). It also evaluates `admin-groups` **when a groups claim is resolvable** (`:44-55`).
- The nuance for **Custom OIDC** specifically: `getDefaultGroupsClaim()` returns `null` (`CustomOIDCUserHandler.java:42-44`), so `admin-groups` is inert **unless** the operator sets `groups-claim` explicitly. `admin-principals`, however, works with no extra configuration.

So the correct statement is: Okta / Keycloak / Custom OIDC **do** promote via `admin-principals` (case-insensitive full match, always), and **do** honour `admin-groups` **only if** `groups-claim` is set (because the handler has no default groups claim). With neither configured, every login is `USER` and promotion is a manual Owner-Role binding via the Management UI.

This exact, correct semantic is **already stated** on the sibling page `admin-promotion.md` (matrix row 24, gotcha line 36, decision-guide line 64). So this is a reconcile-to-the-already-correct-SoT: bring `oauth2-oidc.md` into line with `admin-promotion.md` and remove the in-page self-contradiction.
