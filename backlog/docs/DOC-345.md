## Description

The live published [Lookup Tables](https://docs.opendatadiscovery.org/master-data-management/lookup-tables) page carries a `{% hint style="danger" %}` block (`lookup-tables.md:174-180`) warning that deleting a Lookup Table's parent DataEntity "directly via `/api/dataentities/{id}` (the generic catalog-side delete)" or "via the entity-detail-page Delete affordance" leaves orphan rows in `lookup_tables_schema`, and it prescribes recovery SQL for that state.

This corrects a wrong claim on a live page: **neither the API endpoint nor the UI affordance the caveat warns against exists.** The block fabricates an API + a UI and then prescribes recovery SQL for an unreachable state — actively misleading documentation, our top-priority class. An operator who reads it will believe a destructive delete path exists, may hand-craft the "recovery" SQL against a state they can never actually produce through the product, or will mistrust the (correct) positive half once they discover the warned-against path is fictional.

Canonical code truth (verified this session by reading the files):
- `openapi.yaml:910-925` — `/api/dataentities/{data_entity_id}` exposes **only `get`** (`getDataEntityDetails`). There is no `delete` verb on the whole-DataEntity path (the next path block, `/description`, begins at `:927`). Note the real path segment is `{data_entity_id}`, not `{id}` as the caveat writes.
- `DataEntityController.java` — every `delete*` handler is a **sub-resource** delete (`deleteDataEntityMetadataFieldValue` `:130`, `deleteTermFromDataEntity` `:159`, `deleteOwnership` `:175`, `deleteDataEntityFromDataEntityGroup` `:343`, `deleteQueryExampleToDatasetRelationshipNew` `:448`). There is no whole-entity hard-delete handler.
- `DataEntityService.java:70` — the only `delete` on the service interface is `deleteMetadata`; `DataEntityServiceImpl.java:309` is its only impl. No whole-entity delete service method exists.
- `dataentities.thunks.ts` — only sub-resource delete thunks (`deleteDataEntityTerm` `:84`, `deleteDataEntityFromGroup` `:239`). There is no whole-DataEntity delete thunk, so no entity-detail-page Delete affordance is wired.

The **positive half is correct and must be kept**: `/api/referencedata/table/{lookup_table_id}` `DELETE` (`openapi.yaml:3880-3889`, `operationId: deleteLookupTable`) cleans up both halves — `ReferenceDataServiceImpl.deleteLookupTable` (`:154-158`) calls `ReferenceDataRepositoryImpl.deleteLookupTable` (`:266-277`) which drops the underlying `lookup_tables_schema` table + its sequences, then removes the platform-side registry row.
