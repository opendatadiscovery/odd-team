## Description

The Business Glossary "Known operator caveats" section (`business-glossary.md` lines 134-210) carries seven Security/RBAC caveat hints, several of which close with a bare *"until the … fix lands"* clause and **no way to map the caveat to a platform version**:

- The first `danger` hint (line 141) — the `DATA_ENTITY_ADD_TERM` / `DATA_ENTITY_DELETE_TERM` singular-vs-plural path bypass — ends *"do not rely on … until the platform-side path-rename fix lands"* with no issue link and no `fixed-in` / `open-as-of` marker.
- The Linked-Columns 50-row cap `warning` (line 181) ends *"until the upstream UI fix lands"*; the silent-save-failure and cache-invalidation hints (lines 195, 199) end *"until the upstream fix lands"* / *"Workaround until the upstream fix lands"*.

The audience for this section is explicitly RBAC auditors and compliance reviewers ("operators authoring deployment-time RBAC policies or compliance-grade audit procedures", line 136). That audience runs a **pinned platform version** and needs to answer "does this caveat apply to *my* build?" — which a bare "until the fix lands" cannot answer. The caveat reads as permanently-true even after a fix ships, or as already-fixed when it is not.

The platform-side bug behind the first (highest-severity) caveat is already pinned by a characterization test — `SecurityRulesAuthzGapsKnownBugsTest.java` (PLT-012) — which is the canonical "is this still broken?" signal. The doc never references it, so a reader has no pointer to the artefact that tells them whether the gap is still open. There is no cross-link to the Permissions page warnings either (DOC-GAP-077), so an auditor reading the `TERM_*` permission catalog on the Permissions page and the bypass caveat here cannot navigate between the two.

This misleads an operator two ways: (1) they cannot tell whether a given caveat still applies to their deployed version, so they either over-restrict (treat a fixed gap as still open) or under-protect (treat an open gap as fixed); (2) they have no path from the caveat to the test/issue that tracks the fix.
