- **DOC-GAP-109**: Alert `listByOwner` empty-result total uses platform-wide count, not owner-scoped count — the UI's pagination badge for the "My alerts" tab reports a non-zero count when the owner has zero alerts (MEDIUM)
  - **Category**: drift (the bug is a latent UX correctness regression in the alerting feature; no live doc page describes the bug, but the alerting page describes the "My alerts" tab as if its counters reflect the caller's owned alerts)
  - **Surfaced by**:

  - **Evidence**:
    - `ReactiveAlertRepositoryImpl.java:160-179` — `listByOwner(ownerId, page, size)` method body. Verbatim at line 177: `countAlertsWithStatusOpen()` is passed as the `emptyRecordTotalCounter` argument to `pageifyResult`. The expected method is `countAlertsWithStatusOpenByOwner(ownerId)` (line 269-279 — defined and tested elsewhere, but not invoked here).
    - `JooqQueryHelper.java:119-127` — `pageifyResult(records, recordMapper, emptyRecordTotalCounter)` semantics: when the result records list is non-empty, the total is computed from the COUNT(*) OVER () window function inside the records' SQL; when the result records list is EMPTY, `emptyRecordTotalCounter` is invoked instead. The empty branch is the buggy path.
    - The bug shape: a caller with zero owned alerts who visits the "My alerts" tab triggers `listByOwner(ownerId, 1, 20)` → records list is empty → the empty-counter is `countAlertsWithStatusOpen()` (all alerts platform-wide) → the `Page.total` field reports the platform-wide open count → the UI's pagination badge / "X total" indicator displays a non-zero number while the visible list is empty. Visually contradictory.
    - The performance angle (same root cause): the cheaper, owner-scoped `countAlertsWithStatusOpenByOwner` query (uses the OWNERSHIP join's index) is NOT invoked; instead the more expensive platform-wide COUNT is issued whenever the owner has zero alerts. Cross-link with REFACTOR-024 (cross-owner read pattern).

Per the batch-A inheritance, the page recommends each tab for a specific use case — for "My alerts" tab the framing is the user's owned alerts. The page does not surface the empty-state counter bug; it cannot, because the bug is not on the page's claims — it is on the SQL the page does not describe.
