## What

On the Search results page, clicking one of the entity-class tabs (Datasets / Transformers / Entity Groups / ...) narrows the results, but it does so **without changing the URL**. The class selection is applied as an in-place search-facet update, not pushed onto the browser history. As a result the active class tab is **not URL-addressable** - a user cannot bookmark or share "search X, Datasets tab" - and, more surprisingly, pressing the browser **Back** button does not return to the previous tab: because no history entry was pushed for the tab change, Back navigates away from `/search` entirely (to whatever page preceded the search), discarding the user's in-page context.

## Where

`odd-platform-ui/src/components/Search/Results/Results.tsx:83-100`

```tsx
const onSearchClassChange = React.useCallback(
  (tabValue: SearchClass | undefined) => {
    const newSearchClass = tabValue ? get(dataEntityClassesDict, `${tabValue}`) : null;
    const facetOptionId = newSearchClass?.id ?? tabValue;
    const facetOptionName = newSearchClass?.name ?? tabValue?.toString();

    dispatch(
      changeDataEntitySearchFacet({       // <-- facet update only; no navigate()/URL push
        facetName: 'entityClasses',
        facetOptionId,
        facetOptionName,
        facetOptionState: true,
        facetSingle: true,
      })
    );
  },
  [dataEntityClassesDict]
);
```

The handler dispatches `changeDataEntitySearchFacet` and nothing else - no `useNavigate`/`navigate(...)` call, no router push. The active class lives only in the in-memory search facet state, never reflected in the route.

## Why it matters

Silent (no error; the tab filtering works - what is missing is URL/history integration). Affects every user who uses the class tabs on the Search page and then relies on Back, bookmarking, or link-sharing to return to a specific tabbed view. The Back-button behaviour is the sharp edge: a user who clicks a tab and then hits Back expecting "previous tab" is instead thrown out of search, losing their query context - a recurrent navigation surprise. Medium: a real, repeatable UX/navigation defect, not data-loss or security.

## Suggested fix

Either (a) push the selected class into the URL (a query param or path segment) via the router so the tab is URL-addressable and participates in browser history - Back then restores the previous tab and the view is shareable/bookmarkable; or (b) if URL-addressability is explicitly out of scope, relabel/treat the tabs as a non-navigational in-page filter and ensure Back behaves coherently. Option (a) is preferred for parity with the rest of the search deep-linking story. Open to alternatives on the exact URL shape.
