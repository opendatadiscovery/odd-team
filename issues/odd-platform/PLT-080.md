## What

`application.yml:7` ships `spring.datasource.password=odd-platform-password` as the default DB password. An operator forgetting to override deploys with a public well-known credential.

Combined with `/actuator/env` exposure of the JDBC URL (PLT-078), deployments are one-operator-override-skip away from full PG compromise.

**LSN-001-pattern family**: silent insecure default, doc-only warning absent, no programmatic guardrail.

## Where

| File | Lines | Role |
|------|-------|------|
| `odd-platform-api/src/main/resources/application.yml` | 7 | `spring.datasource.password: odd-platform-password` shipped default |

## Why it matters

Sequence of failure: (a) operator runs trylocally docker-compose, sees it work; (b) operator follows the same compose file structure to deploy to a more-public environment; (c) operator overrides `host`, `port`, `username`, but not `password`; (d) the platform connects to the operator's Postgres using the literal `odd-platform-password` (which the operator has set on Postgres because they followed the trylocally guide); (e) attacker scrapes `/actuator/env`, learns JDBC URL + LDAP / OAuth schema, attempts the well-known password, gains DB shell.

Five-step chain, zero mistakes by the operator beyond "I forgot to set a password". Every step is documented; the trap is the COMPOSITION.

## Suggested fix

**Thread A - Drop the shipped default.**

```yaml
# application.yml - before
spring:
  datasource:
    password: odd-platform-password

# application.yml - after
spring:
  datasource:
    password: ${SPRING_DATASOURCE_PASSWORD}    # operator-required; no default
```

Spring will fail-fast at startup if `SPRING_DATASOURCE_PASSWORD` is unset. The trylocally compose file (`docker-compose.yaml` and friends) needs to set `SPRING_DATASOURCE_PASSWORD: odd-platform-password` explicitly so trylocally continues to work.

**Thread B - Startup self-check (defence-in-depth).**

```java
@PostConstruct
void warnIfWellKnownDbPassword() {
    if ("odd-platform-password".equals(dataSourceProperties.getPassword())) {
        log.warn("spring.datasource.password is set to the trylocally well-known default 'odd-platform-password'. Override before production deployment.");
    }
}
```

Or fail-fast if the deployment is running in a non-trylocally context (e.g., presence of `PROD=true` env var). Less invasive: warn only.

**Thread C - Audit other shipped credential defaults.**

`spring.custom-datasource.password` (the custom-datasource for direct DB access feature) - verify whether the same default ships there. If so, same fix.

Any other shipped credential defaults: ingestion-filter API key, S2S key, etc.
