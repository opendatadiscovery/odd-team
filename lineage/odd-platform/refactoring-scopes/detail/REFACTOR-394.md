- **REFACTOR-394** (NEW 2026-05-19O): GitHub WebClient is field-initialised, NOT Spring-managed — `WebClient.create("https://api.github.com")` bypasses Spring's WebClient.Builder bean and any operator-configured connection-pool / SSL-context / proxy settings. A platform deployment behind a corporate proxy needs proxy-aware HTTP — this WebClient has no such hook
  - **Category**: fragile-wiring
  - **Surfaced by**:
    - `GithubUserHandler.md:bugs_limitations_corner_cases.[6]` (LOW)
    - `GithubUserHandler.md:performance.resource_allocation.[0]` (informational)
  - **Statement**: `GithubUserHandler.java:39` initialises a WebClient via the static factory `WebClient.create("https://api.github.com")` at field-declaration time — bypassing Spring's `WebClient.Builder` bean (the project-canonical pattern for HTTP-client configuration). Consequences: (a) no operator-configurable connection pool size; (b) no operator-configurable SSL trust store (cannot trust a private CA without JVM-wide configuration); (c) no operator-configurable HTTP proxy (cannot route through a corporate egress proxy without JVM-wide `https.proxyHost`/`https.proxyPort`); (d) no operator-configurable response timeout (relies on Reactor Netty defaults). The pattern is consistent with the platform's no-cache stance for auth surfaces, but the LACK OF Spring-Builder injection is a code-quality smell — a future maintainer can't customize the WebClient without editing the handler class.
  - **Evidence**: `GithubUserHandler.java:39` (field-init via static factory, NO `WebClient.Builder` injection)
  - **Existing-ADR-or-implied-prescription**: ADR-CANDIDATE-135 NEW (GitHub OAuth2 + two-pass HTTP) — the two-pass architecture is the parent pattern; this gap is the WebClient construction detail. Adding `WebClient.Builder` injection is refactoring within existing structure.
  - **Proposed remedy**: Inject Spring's `WebClient.Builder` bean and construct the WebClient via the builder: `this.webClient = builder.baseUrl(apiBaseUrl).build();` where `apiBaseUrl` is read from the OAuth2Provider POJO (composes with REFACTOR-390). Operators can then customize via `application.yml`: `spring.webclient.connection-pool-size`, `spring.webclient.read-timeout`, etc. The fix is one constructor injection + one field assignment change.
  - **Severity rationale**: LOW — operationally unusual but real for enterprise deployments behind corporate proxies or with private CA roots. Not security-critical; deployment-friction-shaping.
  - **Suggested backlog grouping**: `OAuth2 hardening sprint` (composed with REFACTOR-390 — the WebClient builder pattern needs the operator-configurable base URL anyway)
