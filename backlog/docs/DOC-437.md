## Description

`Architecture.md`'s **Cross-cutting concerns** list (a "landing-level pointer per concern", line 37) enumerates Authentication, Alerting, Lineage, Search, Attachments, Data Collaboration, and GenAI proxy (lines 39-45) — but omits **Metrics Ingestion**, which `active-platform-features.md:20` presents as a peer first-class subsystem alongside Alerting, Notifications, Activity Feed, Data Collaboration, and GenAI.

The omission is misleading on two counts:

1. **Discoverability.** An operator reading the architecture landing page to learn what cross-cutting subsystems exist will not see Metrics Ingestion, even though it has its own canonical home (`active-platform-features/metrics-ingestion.md`), its own ingress (`POST /ingestion/metrics`), and its own per-entity UI surface (the Metrics tab). Every other active-platform subsystem with a perimeter concern (Alerting, Data Collaboration, GenAI) earns a bullet here; Metrics Ingestion is the only one that does not.
2. **Security parity.** The endpoint is **unauthenticated** at the application layer, exactly the class of perimeter-auth caveat that Architecture.md already surfaces for the AlertManager inbound webhook (line 40) and that `active-platform-features.md:20` flags ("the unauthenticated `/ingestion/metrics` endpoint requires perimeter authentication for any non-trusted network"). Leaving it off the cross-cutting list under-weights an operator-relevant security posture.
