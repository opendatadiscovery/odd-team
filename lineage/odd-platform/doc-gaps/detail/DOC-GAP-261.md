- **DOC-GAP-261**: Deleting a data source is documented only as the workflow phrase "remove a source no longer ingested" — the live `/features/management` page documents NONE of the four operationally load-bearing facts of `DELETE /api/datasources/{data_source_id}`: (a) the delete is BLOCKED with HTTP 400 (`CascadeDeleteException`) whenever a live `data_entity` child still references the data source — an operator clicking Delete on an actively-ingested source gets an error, not a deletion; (b) the delete is a SOFT-delete (`deleted_at = NOW()`), not a hard delete — the row, its token, and its entities persist in the database; (c) the Collector `token` row the data source pointed to is left ORPHANED and cannot even be soft-deleted (the `token` table has no `deleted_at` column); (d) the FTS `search_entrypoint` vector is NOT cleared on delete (unlike the `update` path), so the soft-deleted source can still surface in catalog search. The operator-surprising fact (a) — an actively-ingested data source is effectively undeletable because the collector re-creates `data_entity` children on its next ingest tick — has NO documented workaround (the only reliable delete path is to stop the collector first).
