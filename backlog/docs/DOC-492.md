# DOC-492 — document the Structure-tab column filter (#1679 / CTRIB-038)

CTRIB-038 (odd-platform #1679) adds a client-side **column filter** to the dataset **Structure** tab:
the tags present across the dataset's columns render as clickable chips (with a per-tag column count)
that filter the column list, and the existing data-type count chips become clickable filters too;
both combine with the name search; a Clear-all resets. It is a pure FE feature over the
already-loaded structure (no API change). **CTRIB-040 (#1679 follow-up)** labels the two chip rows
(**Filter by type** / **Filter by tag**) so the affordance is discoverable, and makes the filter reflect
an in-page column tag-add immediately (no reload) — both folded into the drafted content below. The
Structure-tab doc home is
`documentation/docs/data-discovery/per-column-annotation.md`; that page documents the columns table +
the per-column annotation editors but does not yet mention navigating/filtering the column list.

```markdown
## Filtering the column list

On a wide dataset the Structure tab's header carries two rows of one-click filter chips — a
**Filter by type** row and a **Filter by tag** row — that narrow the column list, the same
chip-and-filter gesture the catalog Overview uses for [tags](catalog-overview.md), scoped here to one
dataset's columns:

* **Tag chips** — every tag present across the dataset's columns appears as a chip showing how many
  columns carry it. Click a chip to show only the columns with that tag; click several to show columns
  carrying *any* of them (OR within the tag facet). Important tags sort first.
* **Type chips** — the existing per-type count chips (e.g. `128 Str`, `12 Dec`) are clickable too:
  click one to show only the columns of that type.
* The tag and type facets combine with each other and with the name **Search** box — a column must
  match *all* active facets (AND across facets) — and **Clear All** resets every in-page filter.

The filter is applied in the browser over the columns already loaded for the open revision; it does
not re-query the server, and it stays in step with the column tags as you edit them — tag a column and
its tag appears in the **Filter by tag** row immediately. Switching to a different schema revision clears
the active filters.
```
