## Description

Both the user-facing notifications page and the operator-side config reference claim that **every** outbound notification carries the entity owners and the affected downstream entities:

- `notifications.md` lines 13-21: "Every alert dispatched out of the platform carries: 1. The name of the entity... 2. The data source and namespace... 3. The owners attached to that entity... 4. Affected downstream entities..."
- `odd-platform.md` lines 390-395: "Such notifications contain information such as: 1. Name of the entity... 2. Data source and namespace... 3. Owners of an entity 4. Possibly affected entities".

This is true for Slack but **not** for email. The email template renders only ID, Name, Data Source, Namespace, Type, and Alert Description — it has **no owners line and no downstream/affected-entities section** (`email.ftlh` lines 39-44). The `EmailNotificationSender` populates only those keys into the FreeMarker model (`EmailNotificationSender.java:64-78`); it never puts owners or a downstream list into the model. By contrast, the Slack channel *does* render both: `SlackMessageGenerator` adds an owner context section (`resolveOwnerContextSection`, lines 89, 128-138) and an "Affected data entities" / downstream section (`resolveDownstreamSections`, lines 90, 160-184).

The operator harm is concrete: a team that runs an **email-only** on-call workflow reads "every outbound notification carries the owners and the affected downstream entities", builds an incident runbook on that promise, and during an incident the email arrives with neither the owner to page nor the blast-radius (downstream) list — exactly the two fields they expected for triage. The page over-promises content parity across channels that does not exist.

This is **distinct from DOC-180**, which documents the owner-list *PII passthrough* (owners are sent verbatim with no redaction — see the existing caveat at `notifications.md` lines 136-140). DOC-180 is about what Slack/webhook leak; this item is about what email *omits*. They are non-overlapping: DOC-180 hardens the redaction story, this item corrects the per-channel parity story.
