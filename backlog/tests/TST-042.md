## Description

The first two FULL `feature-complete` runs since the 2026-06-11 full-regression directive
(both on the #1764 fix SUT @ 93cb5252, sequential workers=1) each failed a DIFFERENT
small set of specs, every one of which passed solo and in the other full run:

- **Run 1 (269 passed / 2 failed, 4.5m):**
  1. `view-count-overview` (IT-002) — `Received: 0` ("page did not load the entity" per
     the spec's own taxonomy; NOT the +2 class). The spec runs LAST alphabetically, after
     ~270 DB-mutating cases on the one shared stack.
  2. `global-alerts-list` (IT-030) negative — a "Backwards incompatible schema" text was
     visible after `clearEntityAlerts()`: the helper deletes alerts for entity 2001's
     oddrn only, while the assertion demands ZERO such texts on the GLOBAL /alerts page;
     ingestion specs that run earlier (alphabetically before 'g') legitimately generate
     that alert type on other entities.
- **Run 2 (270 passed / 1 failed, 4.6m):** `data-entity-overview` (IT-013) negative —
  `goto /dataentities/999999/overview` then `waitForLoadState('networkidle')` timed out
  at 60s; the trace's page snapshot shows the app shell rendered (banner+tabs), so one
  in-flight/retrying request kept the network non-idle the whole budget.

- **Run 3 (maintainer's ui-e2e, 2026-06-12, 175 passed / 6 failed — 5 were the
  known-bug pins then still listed in the lane):** `catalog-search` (IT-022) positive —
  after a SUCCESSFUL (r.ok) results fetch, the non-matching `IT022OtherEntity` stayed
  visible for the full 10s window (24 stable polls — not timing). Mechanism candidate:
  `search()` waits for ANY ok `/api/search/{id}/results` response; `goto /search`
  auto-creates an EMPTY session (everything listed), so its unfiltered results fetch can
  satisfy the waiter ahead of the Enter-driven filtered fetch and the unfiltered render
  is what gets asserted. **Solo differential same stack/SUT/seeds: 2/2 passed (4.9s).**

Three distinct one-off failures across two identical runs = roaming load-window
fragility in wait strategies + shared-seed isolation, not a platform regression. This is
the same class the 2026-06-07/08 canonical-run lesson fixed in 3 other specs
(`waitForResponse(r.ok())` hangs on non-2xx; exact-count asserts order-dependent) —
these are the next instances, exposed because the full-regression directive now runs the
whole lane together every time, and IT-002's lane move shifted alphabetical order.

These flakes now gate the credibility of the full-regression gate itself (G-C2): a lane
that randomly drops 1-2 specs per run trains everyone to ignore red.

**Instance 2026-06-12 (CTRIB-007 full-regression run) — the INVERSE direction: an
expected-RED pin flickered GREEN under lane-composition change.** `known-bugs` run on the
CTRIB-007 fix SUT read **4 failed / 1 passed**: IT-003's catalog-search half (PLT-090)
passed in-suite while its dictionary half + IT-004/006/007 stayed RED. Isolation re-run
of IT-003 on the SAME SUT: **2/2 RED — both pins hold** (`run-log/2026-06-12-IT-003.md`),
and the CTRIB-007 diff (tag-ordering SQL) cannot touch tsquery behaviour. Root: IT-005
left the known-bugs lane that run (flipped by the fix) → the lane's spec set/sequencing
shifted, the same class as IT-002's lane move above. Clean re-run: 5 failed / 0 passed
as designed. Adds the expected-RED lane to this item's blast radius: sequencing flakes
don't just drop GREEN specs, they can flash a known-bug pin GREEN and trigger a false
"un-flipped fix" alarm (the G-C2 unexpected-GREEN check).

**Instance 2026-06-23 (CTRIB-030 #1758 feature-complete on the new isolated foundation) — the same class
under CROSS-STREAM contention.** The `ctrib030` isolated run (303 passed / 8 failed, 8.8m) overlapped a live
`ctrib031` stream (2 stacks + an e2e), and 7 of the 8 failures were this roaming-flake class — none touched by
the lineage_depth change, each a 3-15s element-wait timeout under CPU starvation: `term-detail-page` (×2),
`term-linked-terms-tab` (×3), `confirmation-dialog-thunk-arm` (×2). (The 8th, `lineage-depth-boundary`, was the
legitimate #1758 pin-flip, re-grounded in eaf3ae5.) Adds CPU contention from a concurrent stream to the blast
radius: even with full namespace isolation, a neighbour's load slows the backend enough to trip non-robust
waits. The heavy-e2e flock (`run-regression.sh`, adrs/drafts/parallel-stream-test-foundation.md) mitigates this
once ALL streams adopt it (ctrib031 was still on the bare run-suite.sh). Affected specs to harden:
term-detail-page, term-linked-terms-tab, confirmation-dialog-thunk-arm.
