## What

`ODDLDAPProperties.java:10, 14` carries `@Data` + a `password` field. `ODDOAuth2Properties.java:30, 34` carries `@Data` on `OAuth2Provider` with a `clientSecret` field. `@Data` generates a `toString()` including the credential verbatim. NO `@ToString.Exclude` on any password / secret / key / token field across `*Properties.java` files.

A future `log.info("loaded properties: {}", properties)` line — or an exception-handler emitting properties on boot failure — emits LDAP password / OAuth secrets cleartext into log infrastructure.

## Where

| File | Lines | Role |
|------|-------|------|
| `odd-platform-api/src/main/java/.../auth/properties/ODDLDAPProperties.java` | 10, 14 | `@Data` + `password` field |
| `odd-platform-api/src/main/java/.../auth/properties/ODDOAuth2Properties.java` | 30, 34 | `@Data` on OAuth2Provider + `clientSecret` field |
| (potentially more) | — | Other `*Properties.java` carrying `@Data` + credential fields |

## Why it matters

Defence-in-depth gap. The platform doesn't INTENTIONALLY log properties today, but the surface is open — exception handlers that serialise the context for diagnostics, future log lines added during incident debugging, and standard Spring Boot `--debug` flag dumping environment-bean state all emit `toString()` output. One added log line in a hot path leaks LDAP password / OAuth secrets to log aggregators.

This is the same family as PLT-080 (well-known DB default password) — credential hygiene defaults.

## Suggested fix

Class-wide pass via:

```bash
cd odd-platform-api
find . -name '*Properties.java' -exec grep -l '@Data' {} \;
# For each file, identify password / secret / key / token / credential fields
# Add @ToString.Exclude on each
```

Examples:

```java
// ODDLDAPProperties.java
@Data
public class ODDLDAPProperties {
    private String url;
    @ToString.Exclude  // NEW
    private String password;
    // …
}

// ODDOAuth2Properties.java
@Data
public class ODDOAuth2Properties {
    public static class OAuth2Provider {
        private String clientId;
        @ToString.Exclude  // NEW
        private String clientSecret;
        // …
    }
}
```

Also audit:
- Datasource properties (custom-datasource password)
- Mail / SMTP properties (smtp password)
- Slack / webhook properties (signing-secrets, bot-tokens)
- Any S3 / cloud-storage properties (access-key-id, secret-access-key)
- Custom collector / S2S keys

The class-wide pass should produce one PR touching ~5-10 properties files; small individual changes; bundled atomic commit.
