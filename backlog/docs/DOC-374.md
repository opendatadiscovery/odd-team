## Description

S2S authentication uses **one static, platform-wide shared secret**. There is no per-caller token, no scope, no expiry, and no live reload:

- `S2sTokenProvider.java:10` — a single `@Value("${auth.s2s.token:#{null}}")` field holds the one secret for the whole platform.
- `S2sTokenProvider.java:15-21` — `isValidToken` is a single `s2sToken.equals(token)` equality check against that one field; every caller that presents it authenticates as the built-in `ADMIN`.

Operational consequences: every CI job, automation script, and ingestion pipeline shares the same token; **one leak compromises every caller** and cannot be selectively revoked; rotation requires restarting the platform with a new `auth.s2s.token` (the field is bound once at startup, no live-reload); and there is no scope, so the token is full ADMIN on every endpoint.

The doc-disclosable **LIMITATION is already documented** — `s2s.md` "Security considerations" (lines 76-77) states the token is "not rotated, expired, or scoped" and that "rotating it requires restarting the platform," and warns to prefer "one token per trusted caller tier." DOC-003 and DOC-172 are the done items that established that page. So the doc side needs only a light reinforcement (make the **single-secret blast radius** — one leak compromises every caller — explicit). The genuinely-untracked piece is the **CODE enhancement**: per-caller, scoped, rotatable, live-reloadable S2S tokens. This item carries that enhancement as a REFACTOR candidate so it does not get lost; the doc edit is the small companion.
