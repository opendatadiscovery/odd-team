## Description

**Correction to the harvest line.** The 2026-06-08 harvest item framed this as "every live DQ doc page is silent on access control" and "no backlog item edits dashboard.md for this surface." That premise is **stale** for `dashboard.md`: the page already carries a thorough `{% hint style="info" %}` block (read 2026-06-08) stating the `/data-quality` route carries no per-permission gate, the aggregate requires only an authenticated caller, every signed-in user sees catalog-wide health, and **under `auth.type=DISABLED` the dashboard is open to anyone who can reach the platform**. So the who-can-view + DISABLED note the harvest asked for is **already shipped**. This item is therefore re-scoped from "add a missing note" to **verify the existing note is code-accurate and close the one genuine residual**.

**The genuine residual.** The existing hint covers the *aggregate read* but does not mention that the dashboard's five **filter autocompletes** (Namespace, Datasource, Owner, Title, Tag) each enumerate the full catalog's values to the same audience. The filter controllers carry **no method-level authorization** (`NamespaceController`, `OwnerController`, `TagController` implement their `*Api` interfaces with no `@PreAuthorize`/`@Secured`), so they inherit the chain-level posture: any authenticated user — and anonymously under `DISABLED` — can list **every owner name, every namespace, every tag** in the catalog through the dashboard's own filter dropdowns. For a deployment where the *set of teams / projects / tags* is itself sensitive, this is a directory-enumeration surface the current hint does not name.

How it misleads an operator: an operator reading the existing hint concludes "the dashboard shows health to everyone, fine" but may not realise the same un-gated audience can harvest the complete owner/namespace/tag vocabulary via the filter typeaheads — a broader disclosure than "sees the failing-dataset mix."
