## What

On a data entity's **Discussions** tab, when there are no messages the empty-state placeholder reads "No messages" - and that string is **hardcoded English**, not passed through the i18n translation function. Every other user-facing string in the surrounding Data Collaboration UI is translated; this one is not, so under a non-English locale the empty Discussions panel shows untranslated English while the rest of the page is localised.

## Where

`odd-platform-ui/src/components/DataEntityDetails/DataCollaboration/MessagesList/MessagesList.tsx:70`

```tsx
{isMessagesLoaded && !messagesLength && (
  <EmptyContentPlaceholder text='No messages' />   // <-- literal string, no t() wrap
)}
```

`MessagesList.tsx` does not import `useTranslation` at all, so the literal is the only option as written. Contrast the sibling component in the same `DataEntityDetails` tree, `LinkedItemsList/LinkedItemsList.tsx`, which DOES wrap its empty-state:

```tsx
// LinkedItemsList.tsx:4   import { useTranslation } from 'react-i18next';
// LinkedItemsList.tsx:19  const { t } = useTranslation();
// LinkedItemsList.tsx:86  <EmptyContentPlaceholder text={t('No linked entities')} />
```

The two empty-states are structurally identical (`EmptyContentPlaceholder text=...`); one is translated, one is not - a localisation drift between siblings.

Note on the placeholder itself: `EmptyContentPlaceholder` *does* call `useTranslation` internally, but only for its **default** fallback - it renders `text ?? t('No information to display')` (`components/shared/elements/EmptyContentPlaceholder/EmptyContentPlaceholder.tsx`). When a `text` prop is supplied it is rendered verbatim, so the caller must pass an already-`t()`-wrapped string. `MessagesList.tsx:70` passes the raw literal `'No messages'`, so it renders untranslated regardless of the placeholder's own i18n.

## User-facing impact

Static code trace, not driven under a non-English locale in this sweep. Verified by reading the source (2026-06-10): on a data entity's Discussions tab, when `isMessagesLoaded && !messagesLength` (`MessagesList.tsx:69`), the empty-state renders `<EmptyContentPlaceholder text='No messages' />` (`:70`) - a hardcoded English literal, and `MessagesList.tsx` imports no `useTranslation` (imports at `:1-10`). So under a non-English UI locale the Discussions empty panel shows English "No messages" while the surrounding collaboration UI is localised. Cosmetic/i18n only - no functional, data, or security impact; visible solely to non-default-locale operators in the empty state. Remaining check: confirm on a running stack under a non-English locale (the `multilingual-i18n.spec.ts` rail covers the i18n surface but does not assert this specific empty-state).

## Why it matters

Silent (no error; visible only to non-English users, and only in the empty state). Affects operators running the platform under a non-default locale: the Discussions panel leaks an untranslated English string, breaking the localisation contract that the rest of the collaboration UI honours. Real consistency/i18n defect but purely cosmetic - no functional, data, or security impact, and only in the empty state under a non-default locale. **Severity low** (regraded from medium 2026-06-10): per the workspace Priority Order a cosmetic/i18n string sits at Low; the draft's own assessment is "low functional impact," so medium overstated it. The fix is trivial.

## Suggested fix

Import `useTranslation` in `MessagesList.tsx`, pull `const { t } = useTranslation();`, and wrap the literal: `<EmptyContentPlaceholder text={t('No messages')} />` - mirroring `LinkedItemsList.tsx:86`. Add the corresponding key to the translation catalogues.
