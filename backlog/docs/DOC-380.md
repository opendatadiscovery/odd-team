## Description

The entity-detail-page header concentrates up to **eight** distinct affordances on a single `flexWrap='nowrap'` row, with only a coarse two-column split (`lg={7}` name group / `lg={5}` actions group) and no overflow menu, no categorisation, and no responsive collapse. On a narrow viewport (or a long internal name, or a multi-class entity) the row cannot wrap — it truncates, and per the code the visible name is the first thing compressed.

The eight affordances, from `DataEntityDetailsHeader.tsx:73-148`:

- **Name group (`lg={7}`, nowrap)** — (1) the entity name (`Typography variant='h0' noWrap`), (2) the class badges (one per class), (3) the type badge, (4) the "Add business name" / "Edit" business-name button.
- **Actions group (`lg={5}`, nowrap, right-justified)** — (5) the last-ingested-at / stale indicator, (6) the EntityStatus selector, (7) the "Edit group" button (DEG entities), (8) the "Share" (to Slack) button.

The shipped page (DOC-263, `entity-detail-page.md`) **already** documents one slice of this: line 93 notes that multi-class entities overflow horizontally and that "The 'Edit business name' button shares the same row, so heavy class overflow can compress the visible name" — that is the F-177c CLASS-badge overflow case. What is undocumented is the **broader header-density problem**: that the header is a flat concentration of up to eight controls with no progressive-disclosure mechanism, so the truncation risk is not limited to multi-class entities — a long name, a small viewport, or a DEG entity (which adds the "Edit group" button) all push controls off the visible row with no overflow affordance to recover them.

**How this misleads an operator.** An operator on a laptop or a split-screen who cannot find the Status selector, the Share button, or the business-name editor has no signal that the controls exist but are clipped — there is no "…" overflow menu and no wrap to a second line. They reasonably conclude the affordance is absent (a permissions or feature-flag issue) when it is in fact a layout truncation. The page should set the expectation and point at the levers (widen the viewport; the controls are right-justified in the actions group).
